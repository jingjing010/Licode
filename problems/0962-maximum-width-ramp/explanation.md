# 962. 最大宽度坡 —— 小白详细题解

> 单调栈的一个"变种"用法：栈不是边扫边弹，而是**先建好、再从另一头来消耗**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 找两个位置 `i < j`，要求左边的数**不大于**右边的数（`nums[i] <= nums[j]`），让它们**离得尽量远**，返回距离 `j - i`。

示例 1 `nums = [6,0,8,2,1,5]`：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 值 | 6 | **0** | 8 | 2 | 1 | **5** |

- (0, 2)：6 ≤ 8，宽 2
- (1, 5)：0 ≤ 5，宽 **4** ← 最大
- (0, 5)：6 ≤ 5？不成立

**几个需要注意的细节：**

1. 是 `<=`，相等也可以：`[3,3]` 答案是 1。
2. 不存在坡（数组严格递减）时返回 0。
3. n 最大 5×10⁴，O(n²) 约 1.25×10⁹ 次，会超时。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 按值排序下标

```c
int cmp(const void* a, const void* b) {
    int x = *(const int*)a, y = *(const int*)b;   // 把 void* 转回 int* 再取值
    return (x > y) - (x < y);                     // 负数：a 在前；正数：b 在前；0：相等
}
qsort(arr, n, sizeof(int), cmp);
```

`qsort` 是 `<stdlib.h>` 里的通用排序：参数依次是数组、元素个数、每个元素的大小、比较函数。但 C 标准不保证它的最坏时间复杂度；本题完整实现使用归并排序，保证特殊排列也能在 O(n log n) 内完成。归并的做法是分别排好左右两半，再把两段按顺序合并。

### 2. 排序时访问原数组

思路一要"按值排序下标"，归并函数拿到的是下标，可以通过一个**文件内静态指针**访问 `nums`：

```c
static int* g_nums;   // 全局变量，比较函数里可以用
```

### 3. 单调栈（存下标）

```c
int* st = (int*)malloc(sizeof(int) * n);
int top = 0;
st[top++] = i;    // 入栈
st[--top];        // 出栈
```

## 💡 第三步：思路一 —— 按值排序下标

### 思路

把所有下标按 `nums` 的值从小到大排序（值相同按下标从小到大）。
然后按这个顺序依次处理每个下标 `j`：排在它前面的下标，值都 ≤ `nums[j]`，都可以当左端点！
左端点越靠左越好，所以只需记住**前面出现过的最小下标** `minIdx`，用 `j - minIdx` 更新答案。

### 手动模拟（示例 1）

排序后的下标顺序（值）：1(0)、4(1)、3(2)、5(5)、0(6)、2(8)

| 处理下标 j | 值 | 之前的 minIdx | j - minIdx | 答案 | 新 minIdx |
|---|---|---|---|---|---|
| 1 | 0 | 无 | | 0 | 1 |
| 4 | 1 | 1 | 3 | 3 | 1 |
| 3 | 2 | 1 | 2 | 3 | 1 |
| 5 | 5 | 1 | **4** | 4 | 1 |
| 0 | 6 | 1 | -1 | 4 | 0 |
| 2 | 8 | 0 | 2 | 4 | 0 |

### 代码

```c
static int* g_nums;   // 排序时读取原数组，保持原数组不变

static void mergeIndices(int* idx, int* temp, int left, int right) {
    if (right - left <= 1) return;
    int mid = left + (right - left) / 2;
    mergeIndices(idx, temp, left, mid);
    mergeIndices(idx, temp, mid, right);
    int i = left, j = mid, k = left;
    while (i < mid && j < right) {
        // 值相同时按原下标升序，保证相等的值也能组成坡。
        int a = idx[i], b = idx[j];
        if (g_nums[a] < g_nums[b] || (g_nums[a] == g_nums[b] && a < b))
            temp[k++] = idx[i++];
        else
            temp[k++] = idx[j++];
    }
    while (i < mid) temp[k++] = idx[i++];
    while (j < right) temp[k++] = idx[j++];
    for (k = left; k < right; ++k) idx[k] = temp[k];
}

int maxWidthRamp(int* nums, int numsSize) {
    int* idx = (int*)malloc(sizeof(int) * numsSize);
    for (int i = 0; i < numsSize; i++) idx[i] = i;
    g_nums = nums;
    // 归并排序保证最坏 O(n log n)，避免部分运行库的 qsort 在特定排列上退化。
    int* temp = (int*)malloc(sizeof(int) * numsSize);
    mergeIndices(idx, temp, 0, numsSize);
    free(temp);

    int ans = 0;
    int minIdx = numsSize;                       // 已处理的下标中最小的那个
    for (int k = 0; k < numsSize; k++) {
        int j = idx[k];
        if (j - minIdx > ans) ans = j - minIdx;  // 前面的值都 <= nums[j]，取最靠左的
        if (j < minIdx) minIdx = j;
    }
    free(idx);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n log n)**：排序。
- **空间复杂度 O(n)**：下标数组。

## 🚀 第四步：思路二 —— 单调栈 O(n)

### 关键观察：哪些位置值得当左端点？

如果 `i1 < i2` 并且 `nums[i1] <= nums[i2]`，那么 i2 当左端点**永远不如** i1：i1 更靠左、值还更小（更容易满足 ≤）。

所以候选左端点只剩下"**比它左边所有数都小**"的位置（前缀最小值），它们的值从左到右**严格递减**。示例 1 中是下标 0(6)、1(0)。

### 两步走

1. **从左到右建栈**：`nums[i]` 比栈顶的值小，就把 i 压栈。栈里就是所有候选左端点，值从底到顶递减。
2. **从右往左扫 j**：只要 `nums[栈顶] <= nums[j]`，就用 `j - 栈顶` 更新答案，然后**弹出**栈顶。

❓ **为什么可以弹出？** 对这个左端点 i 来说，j 是从右往左遇到的**第一个**能配对的位置，也就是最远的。以后的 j 只会更靠左，宽度只会更小，所以 i 已经没用了。

### 手动模拟（示例 2：`[9,8,1,0,1,9,4,0,4,1]`）

建栈：9(下标0) → 8(1) → 1(2) → 0(3)，之后没有更小的了。栈（底→顶）：`0(9) 1(8) 2(1) 3(0)`

| j | nums[j] | 弹出并计算 | 答案 | 栈（底→顶） |
|---|---|---|---|---|
| 9 | 1 | 3(0)：9-3=6；2(1)：9-2=**7** | 7 | 0(9) 1(8) |
| 8 | 4 | 8 > 4，不弹 | 7 | 0(9) 1(8) |
| 7 | 0 | 不弹 | 7 | 0(9) 1(8) |
| 6 | 4 | 不弹 | 7 | 0(9) 1(8) |
| 5 | 9 | 1(8)：5-1=4；0(9)：5-0=5 | 7 | 空 |

答案 7 ✅

### 代码

```c
int maxWidthRamp(int* nums, int numsSize) {
    int* st = (int*)malloc(sizeof(int) * numsSize);   // 候选左端点（下标）
    int top = 0;

    // 1. 从左到右：只保留"比之前所有数都小"的位置，栈中值严格递减
    for (int i = 0; i < numsSize; i++) {
        if (top == 0 || nums[i] < nums[st[top - 1]]) {
            st[top++] = i;
        }
    }

    // 2. 从右到左：为每个候选左端点找最远的 j
    int ans = 0;
    for (int j = numsSize - 1; j >= 0; j--) {
        while (top > 0 && nums[st[top - 1]] <= nums[j]) {
            int w = j - st[top - 1];   // 这个左端点能配到的最远位置就是 j
            if (w > ans) ans = w;
            top--;                     // 用完就扔
        }
    }
    free(st);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：建栈一遍，扫描一遍，每个下标最多弹出一次。
- **空间复杂度 O(n)**：栈。

---

## ⚠️ 第五步：小白常见错误

1. **建栈时把所有下标都压进去** → 栈不再单调，第二步"栈顶不满足就停"的逻辑失效，会漏掉藏在栈下面、本可以配对的左端点。只能压"比栈顶更小"的下标。
2. **第二步从左往右扫 j** → 那样找到的不是最远的 j，弹出后就丢掉了更优解。必须**从右往左**。
3. **像普通单调栈一样边扫边弹** → 本题的栈在第一步只压不弹，第二步才弹，两个阶段不能混在一起。
4. **思路一排序时值相同不按下标排** → `qsort` 不稳定，相同值的下标顺序是乱的，可能漏掉 `nums[i] == nums[j]` 的坡。
5. **比较函数里写 `return g_nums[i] - g_nums[j];`** → 本题值域小不会溢出，但养成用 `(x > y) - (x < y)` 的习惯更安全。
