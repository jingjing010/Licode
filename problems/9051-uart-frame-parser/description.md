MCU 通过串口和上位机/模块通信时，串口只是一个"字节流"，并不知道一条消息从哪里开始、到哪里结束。所以双方会约定一个**帧格式**，接收方逐字节解析，把一帧帧完整的数据拆出来。

本题的帧格式如下：

| 帧头 1 | 帧头 2 | 长度 LEN | 数据 DATA | 校验 CHK |
|---|---|---|---|---|
| `0xAA` (170) | `0x55` (85) | 1 字节，`0 ~ 255` | `LEN` 个字节 | 1 字节 |

其中 `CHK = (LEN + DATA[0] + DATA[1] + ... + DATA[LEN-1]) & 0xFF`，即长度和全部数据字节之和的低 8 位。

给你接收到的字节流 `buf`（可能夹杂着噪声、错误帧、不完整的帧），请**按顺序逐字节**解析，返回所有**校验正确**的帧的数据部分。解析规则（逐字节、不回退）：

1. **等待帧头 1**：收到 `0xAA` 进入"等待帧头 2"，否则丢弃该字节。
2. **等待帧头 2**：收到 `0x55` 进入"接收长度"；收到 `0xAA` 则**仍然停留**在"等待帧头 2"（把它当作新的帧头 1）；收到其它字节回到"等待帧头 1"。
3. **接收长度**：该字节就是 `LEN`。`LEN > 0` 时进入"接收数据"，`LEN == 0` 时直接进入"接收校验"。
4. **接收数据**：依次收下 `LEN` 个字节（**无论其值是什么**，包括 `0xAA`），收满后进入"接收校验"。
5. **接收校验**：若该字节等于 `CHK`，这一帧有效，记录它的数据部分；否则丢弃整帧。无论对错，都回到"等待帧头 1"，**从下一个字节**继续解析（已经消耗的字节不会被重新检查）。

字节流结束时还没收完的帧直接丢弃。

### 示例 1

```
输入：buf = [170,85,2,16,32,50,0,170,85,1,7,8]
输出：[[16,32],[7]]
解释：
第 1 帧：AA 55 | LEN=2 | 16 32 | CHK=50（2+16+32=50，正确）
接着的 0 是噪声，被丢弃
第 2 帧：AA 55 | LEN=1 | 7 | CHK=8（1+7=8，正确）
```

### 示例 2

```
输入：buf = [170,85,1,5,0,170,85,1,5,6]
输出：[[5]]
解释：第 1 帧校验应为 6，收到 0，整帧丢弃；第 2 帧正确。
```

### 示例 3

```
输入：buf = [170,170,85,1,3,4,170,85,3,1,2]
输出：[[3]]
解释：
第 1 个 AA 之后又来了 AA，仍停在"等待帧头 2"，随后的 55 让第 2 个 AA 成为真正的帧头，解析出 [3]。
最后一帧 LEN=3，但只收到 2 个数据字节就结束了，不完整，丢弃。
```

### 提示

- `0 <= len <= 10^5`
- `0 <= buf[i] <= 255`

### 函数说明

```c
int** parseFrames(const uint8_t* buf, size_t len, int* returnSize, int** returnColumnSizes);
```

- 返回值：`malloc` 申请的二维数组，第 `i` 行是第 `i` 个有效帧的数据部分（`LEN = 0` 的有效帧对应一个空行）
- `*returnSize`：有效帧的个数
- `*returnColumnSizes`：`malloc` 申请的数组，第 `i` 个元素是第 `i` 帧的数据长度

### 自定义输入格式

```
[170,85,2,16,32,50,0,170,85,1,7,8]
```

一行，接收到的字节流（十进制）。
