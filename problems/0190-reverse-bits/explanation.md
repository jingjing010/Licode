# 190. 颠倒二进制位 —— 小白详细题解

> 把一个 32 位数的二进制"照镜子"：最低位变最高位，最高位变最低位。这道题是练习**移位、掩码**的绝佳入门题，最后还会学到一个不用循环、只用 5 行的"分治交换"技巧。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把 `n` 写成 32 位二进制（不够 32 位前面补 0），然后**从右往左**重新读一遍，得到的新数就是答案。

拿示例 1 来说：

```
n      = 00000010100101000001111010011100   (43261596)
结果   = 00111001011110000010100101000000   (964176192)
```

原来的第 `i` 位（从右往左数，最右边是第 0 位）跑到了第 `31 - i` 位。

**几个需要注意的细节：**

1. **一定是 32 位**：哪怕 `n = 1`，也要看成 `000……0001`，颠倒后是 `1000……0000 = 2147483648`。不能只颠倒"有效位"`1`。
2. 结果可能大于 `2^31 - 1`（示例 2），所以返回类型是 **无符号** 的 `uint32_t`，不要用 `int` 存。
3. 输入输出都是十进制，题解里画二进制只是为了方便理解。

---

## 🧰 第二步：需要的 C 语言知识

### 1. `uint32_t` 是什么？

`<stdint.h>` 里定义的"恰好 32 位的无符号整数"，范围 `0 ~ 4294967295`。和 `unsigned int` 在常见平台上是一回事，但名字明确告诉你它有几位，嵌入式开发里非常常用。

### 2. 取最低位、去掉最低位

```c
n & 1      // 取出最低位（0 或 1）
n >>= 1    // 右移一位，相当于扔掉最低位；无符号数左边补 0
```

### 3. 在最低位"追加"一位

```c
res = (res << 1) | bit;   // res 整体左移一位，空出的最低位填上 bit
```

### 4. 掩码 `0x55555555` 这类数字

| 掩码 | 二进制（低 8 位） | 选中的位 |
|---|---|---|
| `0x55555555` | `0101 0101` | 每 2 位一组中的低 1 位 |
| `0x33333333` | `0011 0011` | 每 4 位一组中的低 2 位 |
| `0x0F0F0F0F` | `0000 1111` | 每 8 位一组中的低 4 位 |
| `0x00FF00FF` | 低 16 位是 `0000 0000 1111 1111` | 每 16 位一组中的低 8 位 |

## 💡 第三步：思路一 —— 逐位搬运

### 思路

循环 32 次：每次取出 `n` 的最低位，追加到 `res` 的最低位，然后 `n` 右移一位。

- 第 1 次取出的是原来的第 0 位，它在 `res` 里被左移了 31 次，最终落在第 31 位；
- 第 32 次取出的是原来的第 31 位，最终落在第 0 位。

这正好就是颠倒！

### 手动模拟（只看 4 位的例子：`n = 1011`，颠倒后应为 `1101`）

| 第几次 | n & 1 | res（追加后） | n（右移后） |
|---|---|---|---|
| 1 | 1 | 1 | 101 |
| 2 | 1 | 11 | 10 |
| 3 | 0 | 110 | 1 |
| 4 | 1 | **1101** | 0 |

32 位的情况完全一样，只是要循环 32 次。

### 代码

```c
uint32_t reverseBits(uint32_t n) {
    uint32_t res = 0;
    for (int i = 0; i < 32; i++) {     // 必须正好 32 次，不能在 n 变成 0 时提前停
        res = (res << 1) | (n & 1);    // 把 n 的最低位追加到 res 的最低位
        n >>= 1;                       // 扔掉 n 的最低位
    }
    return res;
}
```

### 复杂度分析

- **时间复杂度 O(32)**：固定 32 次循环。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 分治交换（无循环）

### 思路

想象 32 个人排成一排要"倒过来站"。与其一个个搬，不如：

1. **先把 32 位分成高 16 位和低 16 位，互换**；
2. 每个 16 位里再分成两个 8 位，互换；
3. 每个 8 位里两个 4 位互换；
4. 每个 4 位里两个 2 位互换；
5. 每个 2 位里两个 1 位互换。

5 步之后整体就倒过来了。顺序反过来做（先换 1 位，最后换 16 位）结果一样。

每一步怎么交换？以"相邻 1 位互换"为例：

```c
n = ((n >> 1) & 0x55555555u) | ((n & 0x55555555u) << 1);
```

- `(n & 0x55555555u) << 1`：取出每组的低位，挪到高位上；
- `(n >> 1) & 0x55555555u`：取出每组的高位，挪到低位上；
- 两者合并，每组的两位就互换了。

### 手动模拟（8 位的例子：`n = 1011 0001`，颠倒后应为 `1000 1101`）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 原始 | | `10 11 00 01` |
| 第 1 步 | 每 2 位里交换 | `01 11 00 10` |
| 第 2 步 | 每 4 位里两个 2 位交换 | `1101 1000` |
| 第 3 步 | 两个 4 位交换 | **`1000 1101`** ✅ |

### 代码

```c
uint32_t reverseBits(uint32_t n) {
    n = ((n >> 1) & 0x55555555u) | ((n & 0x55555555u) << 1);   // 相邻 1 位互换
    n = ((n >> 2) & 0x33333333u) | ((n & 0x33333333u) << 2);   // 相邻 2 位互换
    n = ((n >> 4) & 0x0F0F0F0Fu) | ((n & 0x0F0F0F0Fu) << 4);   // 相邻 4 位互换
    n = ((n >> 8) & 0x00FF00FFu) | ((n & 0x00FF00FFu) << 8);   // 相邻 8 位互换
    return (n >> 16) | (n << 16);                              // 高低 16 位互换
}
```

### 复杂度分析

- **时间复杂度 O(1)**：约 20 条位运算指令，没有循环和分支。
- **空间复杂度 O(1)**。

> 💬 **进阶问题"多次调用怎么优化"**：可以预先算好 256 项的表 `rev8[b]`（每个字节颠倒后的值），把 32 位拆成 4 个字节，查 4 次表再拼起来。ARM 处理器甚至有一条 `RBIT` 指令直接完成颠倒。

## ⚠️ 第五步：小白常见错误

1. **`while (n)` 提前结束**：`n` 变成 0 时停下，`res` 就少左移了若干次。比如 `n = 1` 会返回 `1` 而不是 `2147483648`。必须固定循环 32 次。
2. **用 `int` 存结果**：示例 2 的答案 `3221225471` 超过 `INT_MAX`，存进 `int` 会变成负数。
3. **先追加再左移**：写成 `res |= n & 1; res <<= 1;`，最后多左移了一次，原来的第 0 位被移出去丢了。
4. **分治时掩码和移位方向不配对**：`(n & 0x55555555u) >> 1` 会把低位往更低处移，直接丢掉。记住：**取低位的掩码配左移，先右移再配掩码取高位**。
5. **用 `%` 和 `/` 代替位运算**：`n % 2`、`n / 2` 对无符号数结果也对，但没体现位运算思想，面试时会被追问。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位搬运 | O(32) | O(1) | ⭐ | 最容易写对，先掌握它 |
| 分治交换 | O(1) | O(1) | ⭐⭐⭐ | 无分支，理解掩码的经典例子 |
| 查表法 | O(4) | 256 字节表 | ⭐⭐ | 多次调用时最实用 |
