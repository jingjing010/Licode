# 二进制缓冲区查找：题解

## 📖 先读懂题目

返回pattern在data中首次匹配的字节下标，不存在返回−1，空pattern返回0。两个长度0到1024，可包含零字节。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[1,0,2,0,3] / [0,2]` | `1` |
| 2 | `[0,1] / [2]` | `-1` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

字节缓冲区不能用strlen或strstr，因为0也是普通数据。使用明确长度并在比较前检查剩余空间。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int findBinaryPattern(const uint8_t *data, size_t len, const uint8_t *pattern, size_t patternSize) {
    if (patternSize == 0)
        return 0;
    if (patternSize > len)
        return -1;
    for (size_t i = 0; i <= len - patternSize; ++i) {
        size_t j = 0;
        while (j < patternSize && data[i + j] == pattern[j])
            ++j;
        if (j == patternSize)
            return (int)i;
    }
    return -1;
}
```

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
