固件升级（OTA / Bootloader）时，设备要确认收到的整个固件镜像没有损坏后才能写入并跳转执行；以太网帧、ZIP、PNG 文件也都用同一种 32 位 CRC 做完整性校验。它就是最常见的 **CRC-32**（也叫 CRC-32/ISO-HDLC，即 IEEE 802.3 使用的 CRC）。

请实现 **CRC-32**，参数如下：

| 参数 | 值 | 含义 |
|---|---|---|
| 宽度 width | 32 | 校验值 32 位 |
| 多项式 poly | `0x04C11DB7` | IEEE 802.3 标准多项式 |
| 初值 init | `0xFFFFFFFF` | 计算开始前 crc 寄存器的值 |
| 输入反射 refin | 是 | 每个字节从**最低位**开始处理 |
| 输出反射 refout | 是 | 结果按位反转 |
| 输出异或 xorout | `0xFFFFFFFF` | 最终结果再异或 `0xFFFFFFFF` |
| 校验值 check | `0xCBF43926` | 字符串 `"123456789"` 的 CRC 结果 |

等价的**右移算法**：crc 初值为 `0xFFFFFFFF`；对每个字节，先 `crc ^= byte`，再重复 8 次：若 crc 最低位为 1，则 `crc = (crc >> 1) ^ 0xEDB88320`，否则 `crc = crc >> 1`（`0xEDB88320` 是 `0x04C11DB7` 按 32 位反转后的值）。全部字节处理完后，返回 `crc ^ 0xFFFFFFFF`。

### 示例 1

```
输入：buf = [49,50,51,52,53,54,55,56,57]
输出：3421780262
解释：这是字符串 "123456789" 的 ASCII 码，结果为 0xCBF43926 = 3421780262，即标准校验值。
```

### 示例 2

```
输入：buf = [97]
输出：3904355907
解释：字符串 "a" 的 CRC-32 为 0xE8B7BE43 = 3904355907。
```

### 示例 3

```
输入：buf = []
输出：0
解释：没有数据时 crc 仍为初值 0xFFFFFFFF，异或 0xFFFFFFFF 后为 0。
```

### 提示

- `0 <= len <= 2 * 10^5`
- `0 <= buf[i] <= 255`

### 函数说明

```c
uint32_t crc32(const uint8_t* buf, size_t len);
```

- 返回 CRC-32 结果，判题程序以十进制（无符号）输出

### 自定义输入格式

```
[49,50,51,52,53,54,55,56,57]
```

一行字节数组（每个元素 `0 ~ 255`）。
