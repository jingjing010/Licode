# 169. 多数元素 —— 小白详细题解

> 这道题有好几种解法：排序、哈希计数、分治……最惊艳的是**摩尔投票法**，只用两个变量、扫一遍就能找到答案。我们从最容易理解的排序法开始。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 数组里有一个数出现的次数**超过一半**（严格大于 `n / 2`），把它找出来。

拿示例 2 `nums = [2,2,1,1,1,2,2]` 来说：`n = 7`，`n / 2 = 3`（整数除法向下取整）。

| 数值 | 出现次数 | 大于 3？ |
|---|---|---|
| 2 | 4 | ✅ |
| 1 | 3 | ❌ |

答案是 2。

**几个需要注意的细节：**

1. 是"**超过**一半"，不是"最多"。题目保证这样的数一定存在，而且只可能有一个。
2. 数值范围是 `-10^9 ~ 10^9`，**不能**用数组下标直接计数（数组开不了这么大）。
3. 数组长度最多 5×10⁴。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `qsort` 排序

C 标准库 `<stdlib.h>` 提供了快速排序函数：

```c
qsort(数组首地址, 元素个数, 每个元素的字节数, 比较函数);
```

比较函数要自己写，规则是：返回负数表示 a 应该排在 b 前面，返回正数表示 a 排在 b 后面，0 表示相等。

```c
static int cmp(const void* a, const void* b) {
    int x = *(const int*)a;     // void* 先转成 int*，再取值
    int y = *(const int*)b;
    return (x > y) - (x < y);   // x<y 返回 -1，x>y 返回 1，相等返回 0
}
```

> ⚠️ 不要养成写 `return x - y;` 的习惯！本题数值在 ±10⁹ 内，相减最大是 2×10⁹，刚好没超过 `int` 的上限 2147483647；但只要数值范围再大一点（比如 `INT_MAX` 和 `-1`），减法就会溢出变成负数，排序结果全乱。用比较的写法永远安全。

### 2. `const void*` 是什么？

`qsort` 不知道你要排的是 int 还是字符串，所以统一用"无类型指针" `void*` 传给比较函数，你需要自己把它转换成正确的类型再取值。

## 💡 第三步：思路一 —— 排序后取中间

### 思路

多数元素出现了超过 `n / 2` 次。把数组排好序后，相同的数挨在一起，形成一段长度超过一半的连续区间。**无论这段区间在哪，它一定会覆盖正中间的位置 `n / 2`**。

### 手动模拟

| 原数组 | 排序后 | 中间下标 n/2 | 中间的数 |
|---|---|---|---|
| [3,2,3] | [2,**3**,3] | 1 | 3 |
| [2,2,1,1,1,2,2] | [1,1,1,**2**,2,2,2] | 3 | 2 |

再试一个多数元素是最小值的情况：`[1,1,1,2,3]` → 中间下标 2 是 1 ✅。多数元素是最大值：`[1,2,3,3,3]` → 中间下标 2 是 3 ✅。

### 代码

```c
static int cmpInt(const void* a, const void* b) {
    int x = *(const int*)a;
    int y = *(const int*)b;
    return (x > y) - (x < y);            // 安全的比较写法，不会溢出
}

int majorityElement(int* nums, int numsSize) {
    qsort(nums, numsSize, sizeof(int), cmpInt);   // 从小到大排序
    return nums[numsSize / 2];                    // 正中间的一定是多数元素
}
```

### 复杂度分析

- **时间复杂度 O(n log n)**：排序的代价。
- **空间复杂度 O(log n)**：快速排序的递归栈。

## 🚀 第四步：思路二 —— 摩尔投票（O(n) 时间，O(1) 空间）

### 思路

想象一场"擂台赛"：

- 擂台上站着一个**候选人** `cand`，他有一些**血量** `cnt`。
- 来了一个和他相同的数：队友，血量 +1。
- 来了一个和他不同的数：两人**同归于尽**，血量 -1。
- 血量变成 0：擂台空了，下一个来的数直接上台当新候选人。

为什么最后站在台上的一定是多数元素？因为每次"同归于尽"都消耗**一个多数元素和一个非多数元素**（或两个非多数元素）。多数元素比其他所有数加起来还多，就算其他数全都拿来和它拼命，它也不可能被消耗完。

### 手动模拟（示例 2：`[2,2,1,1,1,2,2]`）

| 当前数 | cnt 为 0？ | 操作 | cand | cnt |
|---|---|---|---|---|
| 2 | 是 → 上台 | 相同 +1 | 2 | 1 |
| 2 | | 相同 +1 | 2 | 2 |
| 1 | | 不同 -1 | 2 | 1 |
| 1 | | 不同 -1 | 2 | 0 |
| 1 | 是 → 1 上台 | 相同 +1 | 1 | 1 |
| 2 | | 不同 -1 | 1 | 0 |
| 2 | 是 → 2 上台 | 相同 +1 | **2** | 1 |

最后候选人是 2 ✅。注意中途候选人曾经变成 1，但最终还是被多数元素"夺回"了擂台。

### 代码

```c
int majorityElement(int* nums, int numsSize) {
    int cand = 0;   // 当前候选人
    int cnt = 0;    // 候选人的"血量"

    for (int i = 0; i < numsSize; i++) {
        if (cnt == 0) {
            cand = nums[i];          // 擂台空了，当前数上台
        }
        if (nums[i] == cand) {
            cnt++;                   // 队友，血量 +1
        } else {
            cnt--;                   // 对手，同归于尽，血量 -1
        }
    }
    return cand;                     // 题目保证有多数元素，最后的候选人就是它
}
```

> 💬 如果题目**不保证**一定存在多数元素，最后还要再扫一遍，数一数 `cand` 出现的次数是否真的超过一半。

### 复杂度分析

- **时间复杂度 O(n)**：扫描一遍。
- **空间复杂度 O(1)**：只用了两个变量。

## ⚠️ 第五步：小白常见错误

1. **想用数组下标计数** `cnt[nums[i]]++` → 数值可达 ±10⁹，既有负数又远超数组能开的大小。
2. **比较函数写成 `return x - y;`** → 本题范围内碰巧不溢出，但换到 `int` 全范围的题目（如 `INT_MAX - (-1)`）就会溢出，排序结果错乱。
3. **摩尔投票中先判断相同、后判断 `cnt == 0`** → 顺序反了的话，`cnt` 为 0 时新数还没上台就被当成"不同"减成了 -1。
4. **排序后返回 `nums[0]` 或 `nums[numsSize - 1]`** → 多数元素不一定是最小或最大的，必须取中间。
5. **以为"出现次数最多"就是"多数元素"** → 本题保证超过一半；如果只是最多（比如 `[1,1,2,2,3]`），摩尔投票不保证正确。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 排序取中间 | O(n log n) | O(log n) | ⭐ | 最容易写对 |
| 哈希表计数 | O(n) | O(n) | ⭐⭐⭐ | C 语言要手写哈希表，比较麻烦 |
| 摩尔投票 | O(n) | O(1) | ⭐⭐ | 进阶要求的答案，推荐 |
