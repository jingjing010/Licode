# 33. 搜索旋转排序数组 —— 小白详细题解

> 数组被"转了一下"就不完全有序了，还能二分吗？能！关键在于发现：**从中间切开，总有一半是有序的**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 本来是一排从小到大的数，有人把**前面一段剪下来接到了后面**。现在给你这个"转过的"数组，找 `target` 的下标，找不到返回 `-1`。

示例 1：原数组 `[0,1,2,4,5,6,7]`，把前 3 个 `[0,1,2]` 挪到后面，变成：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 数值 | 4 | 5 | 6 | 7 | **0** | 1 | 2 |

`target = 0` 在下标 4。`target = 3` 不存在，返回 `-1`。

**几个需要注意的细节：**

1. 旋转后的数组由**两段升序**拼成：左段 `[4,5,6,7]`、右段 `[0,1,2]`，左段的每个数都比右段大。
2. 也可能 `k = 0`，即根本没转，整个数组都是升序的。
3. 元素**互不相同**，这让判断"哪一半有序"变得简单。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 闭区间二分的写法

```c
int lo = 0, hi = numsSize - 1;   // 在 [lo, hi] 里找
while (lo <= hi) {               // 区间不为空就继续
    int mid = lo + (hi - lo) / 2;
    ...                          // 每次让 lo = mid + 1 或 hi = mid - 1
}
```

### 2. `&&` 组合判断区间

"`target` 在 `[a, b)` 里" 在 C 语言要写成 `a <= target && target < b`，**不能**写成数学上的 `a <= target < b`（C 会先算 `a <= target` 得到 0 或 1，再拿 0/1 和 b 比，结果完全不对）。

---

## 💡 第三步：思路一 —— 顺序查找（最容易想到）

### 代码

```c
int search(int* nums, int numsSize, int target) {
    for (int i = 0; i < numsSize; i++) {   // 一个一个看
        if (nums[i] == target) {
            return i;                      // 找到返回下标
        }
    }
    return -1;                             // 没找到
}
```

### 复杂度分析

- **时间复杂度 O(n)**：n ≤ 5000 能过，但不满足题目 `O(log n)` 的要求。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（判断哪一半有序）

### 思路

在 `[lo, hi]` 中取中点 `mid`。数组是"两段升序"，所以 `mid` 要么在左段，要么在右段：

- **如果 `nums[lo] <= nums[mid]`**：说明 `[lo, mid]` 这一半是有序的。
  - 若 `nums[lo] <= target < nums[mid]`，target 一定在这有序的一半里 → `hi = mid - 1`
  - 否则去另一半 → `lo = mid + 1`
- **否则**：`[mid, hi]` 这一半是有序的。
  - 若 `nums[mid] < target <= nums[hi]`，target 在这一半 → `lo = mid + 1`
  - 否则 → `hi = mid - 1`

为什么只在"有序的那一半"里判断？因为有序区间里，**只看两端**就能知道 target 在不在里面；无序的那一半做不到。

### 手动模拟（示例 1，`nums = [4,5,6,7,0,1,2], target = 0`）

| 轮次 | lo | hi | mid | nums[mid] | 哪半有序 | target 在有序半里吗？ | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 7 | 左半 [4..7] | 0 不在 [4,7) | lo = 4 |
| 2 | 4 | 6 | 5 | 1 | 左半 [0..1] | 0 在 [0,1) | hi = 4 |
| 3 | 4 | 4 | 4 | 0 | | **相等** | 返回 4 ✅ |

### 代码

```c
int search(int* nums, int numsSize, int target) {
    int lo = 0, hi = numsSize - 1;           // 闭区间 [lo, hi]
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) {
            return mid;                      // 直接命中
        }
        if (nums[lo] <= nums[mid]) {
            // 左半 [lo, mid] 有序
            if (nums[lo] <= target && target < nums[mid]) {
                hi = mid - 1;                // target 在左半
            } else {
                lo = mid + 1;                // 否则在右半
            }
        } else {
            // 右半 [mid, hi] 有序
            if (nums[mid] < target && target <= nums[hi]) {
                lo = mid + 1;                // target 在右半
            } else {
                hi = mid - 1;                // 否则在左半
            }
        }
    }
    return -1;                               // 区间空了，没找到
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：每轮丢掉一半。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **`nums[lo] <= nums[mid]` 写成 `<`** → 当 `lo == mid`（区间只剩 1~2 个数）时，左半只有一个数也算有序；用 `<` 会判断成"右半有序"，例如 `[3,1]` 找 `1` 会出错。
2. **区间判断写成 `nums[lo] <= target < nums[mid]`** → C 语言不支持连写比较，必须用 `&&`。
3. **边界开闭搞错**：左半判断时 `target < nums[mid]` 用 `<`（因为 `mid` 已经比较过了），`nums[lo] <= target` 用 `<=`（`lo` 还没比较过）。把 `lo` 写成 `<` 会漏掉 `target == nums[lo]` 的情况。
4. **先找旋转点再二分，但找旋转点用了线性扫描** → 整体又变回 O(n)。
5. **`hi` 初始化为 `numsSize`** → 本解法用闭区间，`nums[hi]` 会越界。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 顺序查找 | O(n) | O(1) | ⭐ | 理解题意 |
| 二分（判断有序半边） | O(log n) | O(1) | ⭐⭐⭐ | 题目要求 |
