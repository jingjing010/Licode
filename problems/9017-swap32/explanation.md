# 9017. 32 位字节序交换 —— 小白详细题解

> 9016 交换的是 2 个字节，这一题是 4 个字节整体倒序。它就是网络编程里 `ntohl()` / `htonl()` 在小端 CPU 上做的事情，也是面试里出现频率最高的位运算题之一。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把一个 32 位整数看成 4 个字节，**第 1 个和第 4 个对调，第 2 个和第 3 个对调**。

拿示例 1 来说：`x = 305419896 = 0x12345678`

| 字节位置 | B3（最高，bit31~24） | B2（bit23~16） | B1（bit15~8） | B0（最低，bit7~0） |
|---|---|---|---|---|
| 交换前 | `12` | `34` | `56` | `78` |
| 交换后 | `78` | `56` | `34` | `12` |

结果 `0x78563412 = 2018915346`。

**几个需要注意的细节：**

1. 输入、输出都是**十进制**，十六进制只是方便我们理解。
2. 结果可能大于 `2^31 - 1`（例如 `0x000000FF` 交换后是 `0xFF000000 = 4278190080`），必须用**无符号** `uint32_t` 保存，用 `int` 会变成负数。
3. 交换两次等于没换：`swap32(swap32(x)) == x`，可以用来自查。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用"掩码 + 移位"取出某个字节

```c
uint32_t x = 0x12345678;
(x >> 0)  & 0xFF   // 0x78  B0
(x >> 8)  & 0xFF   // 0x56  B1
(x >> 16) & 0xFF   // 0x34  B2
(x >> 24) & 0xFF   // 0x12  B3
```

`>>` 把想要的字节挪到最低 8 位，`& 0xFF` 把其它位清零。

### 2. 用 `|` 把几块拼起来

各个字节移到目标位置后互不重叠，按位或 `|` 就能把它们"拼"成一个整数：

```
0x78000000
0x00560000
0x00003400
0x00000012
---------- 按位或
0x78563412
```

### 3. 为什么必须用无符号数

对**有符号**负数右移，大多数编译器做的是**算术右移**（高位补 1）：`(int)0x80000000 >> 24` 得到的是 `0xFFFFFF80`，而不是 `0x80`。另外 `0xFF << 24` 如果按 `int` 计算会溢出到符号位，属于未定义行为。用 `uint32_t` 和 `0xFFu` 这样的无符号常量，就不会有这些坑。

---

## 💡 第三步：思路一 —— 逐个字节取出再拼装

### 思路

先把 4 个字节分别取出来放进变量，再按相反顺序移回去。步骤最直白，适合刚接触位运算的同学。

### 手动模拟（示例 1：`x = 0x12345678`）

| 变量 | 计算 | 值 | 放回的位置 | 移位后 |
|---|---|---|---|---|
| `b0` | `x & 0xFF` | `0x78` | 最高字节 | `0x78000000` |
| `b1` | `(x >> 8) & 0xFF` | `0x56` | 次高字节 | `0x00560000` |
| `b2` | `(x >> 16) & 0xFF` | `0x34` | 次低字节 | `0x00003400` |
| `b3` | `(x >> 24) & 0xFF` | `0x12` | 最低字节 | `0x00000012` |

按位或得到 `0x78563412` ✅

### 代码

```c
uint32_t swap32(uint32_t x) {
    uint32_t b0 = x & 0xFFu;            // 最低字节
    uint32_t b1 = (x >> 8) & 0xFFu;
    uint32_t b2 = (x >> 16) & 0xFFu;
    uint32_t b3 = (x >> 24) & 0xFFu;    // 最高字节

    // 倒序放回：原来的最低字节变成最高字节
    return (b0 << 24) | (b1 << 16) | (b2 << 8) | b3;
}
```

> 💬 `b0` 等变量声明成 `uint32_t` 而不是 `uint8_t`，是为了保证 `b0 << 24` 在 32 位无符号范围内计算。

### 复杂度分析

- **时间复杂度 O(1)**，**空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 先掩码再移位（一行写法，Linux 内核同款）

### 思路

不用先把字节"取到最低位"，而是**原地掩码，再直接移到目标位置**：

- B0 在 bit7~0，要去 bit31~24：左移 24
- B1 在 bit15~8，要去 bit23~16：左移 8
- B2 在 bit23~16，要去 bit15~8：右移 8
- B3 在 bit31~24，要去 bit7~0：右移 24

### 手动模拟（示例 2：`x = 0xFF000000`）

| 项 | 掩码结果 | 移位 | 结果 |
|---|---|---|---|
| `x & 0x000000FF` | `0x00000000` | `<< 24` | `0x00000000` |
| `x & 0x0000FF00` | `0x00000000` | `<< 8` | `0x00000000` |
| `x & 0x00FF0000` | `0x00000000` | `>> 8` | `0x00000000` |
| `x & 0xFF000000` | `0xFF000000` | `>> 24` | `0x000000FF` |

结果 `0xFF = 255` ✅

### 代码

```c
uint32_t swap32(uint32_t x) {
    return ((x & 0x000000FFu) << 24) |   // B0 -> 最高字节
           ((x & 0x0000FF00u) << 8)  |   // B1 -> 次高字节
           ((x & 0x00FF0000u) >> 8)  |   // B2 -> 次低字节
           ((x & 0xFF000000u) >> 24);    // B3 -> 最低字节
}
```

> 💬 GCC 看到这种写法，在 ARM Cortex-M3/M4 上通常会直接编译成**一条 `REV` 指令**，和调用 `__builtin_bswap32` 一样快。

## 🔌 嵌入式实战

在 STM32 + W5500 / LwIP 的项目里，你会经常看到这样的代码：

```c
uint32_t ip = swap32(hdr->src_addr);   // 网络字节序（大端） -> 本机字节序（小端） ...
```

- `ntohl` = network to host long，`htonl` = host to network long。在小端 MCU 上它们都等于 `swap32`，在大端 MCU 上它们什么都不做。
- 更推荐的做法是像 9018 那样**直接从字节流按大端拼装**，这样代码与 CPU 字节序无关，根本不需要"交换"。

---

## ⚠️ 第五步：小白常见错误

1. **用 `int` 做参数或返回值**：`0xFF000000` 存进 `int` 是负数，再右移会补 1，结果全错。
2. **掩码和移位方向搭配错**：比如写成 `(x & 0x00FF0000u) << 8`，B2 被移到了最高字节，结果错乱。每一项都要想清楚"从哪来、到哪去"。
3. **忘了掩码**：`(x << 8)` 不加 `& 0x00FF0000` 时，B0 和 B1 都会被带过去，与其它项"或"在一起就乱了。
4. **只交换了一半**：写成 `(x << 16) | (x >> 16)`，那是交换高低 16 位（`0x56781234`），不是字节倒序。
5. **打印时用 `%d`**：`printf("%d", 4278190080u)` 会显示负数，无符号 32 位要用 `%u`（或像本 OJ 一样转成 `long long` 再打印）。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| 逐个字节取出再拼装 | O(1) | O(1) | 步骤直白，适合入门 |
| 先掩码再移位 | O(1) | O(1) | 一行搞定，编译器可优化成 `REV` |
| `__builtin_bswap32` | O(1) | O(1) | 最快但依赖 GCC，本题禁止 |
