Modbus RTU 是工业现场（PLC、变频器、电表、温控器）最常用的串口通信协议。每一帧数据的最后两个字节是 **CRC-16/MODBUS** 校验码，接收方算出的 CRC 与帧尾不一致就丢弃这一帧。

请实现 **CRC-16/MODBUS**，参数如下：

| 参数 | 值 | 含义 |
|---|---|---|
| 宽度 width | 16 | 校验值 16 位 |
| 多项式 poly | `0x8005` | 即 x¹⁶ + x¹⁵ + x² + 1 |
| 初值 init | `0xFFFF` | 计算开始前 crc 寄存器的值 |
| 输入反射 refin | 是 | 每个字节从**最低位**开始处理 |
| 输出反射 refout | 是 | 结果按位反转 |
| 输出异或 xorout | `0x0000` | 结果不异或 |
| 校验值 check | `0x4B37` | 字符串 `"123456789"` 的 CRC 结果 |

由于输入、输出都要反射，实际实现时通常使用等价的**右移算法**：crc 初值为 `0xFFFF`；对每个字节，先 `crc ^= byte`，再重复 8 次：若 crc 最低位为 1，则 `crc = (crc >> 1) ^ 0xA001`，否则 `crc = crc >> 1`。其中 `0xA001` 是 `0x8005` 按 16 位反转后的值。全部字节处理完后的 crc 即为结果。

### 示例 1

```
输入：buf = [49,50,51,52,53,54,55,56,57]
输出：19255
解释：这是字符串 "123456789" 的 ASCII 码，结果为 0x4B37 = 19255，即标准校验值。
```

### 示例 2

```
输入：buf = [1,3,0,0,0,1]
输出：2692
解释：这是 Modbus 请求"读 1 号从机、地址 0 开始的 1 个保持寄存器"的前 6 个字节，CRC = 0x0A84 = 2692。
     Modbus 规定 CRC 低字节在前发送，所以完整的帧是 01 03 00 00 00 01 84 0A。
```

### 示例 3

```
输入：buf = []
输出：65535
解释：没有数据时结果就是初值 0xFFFF。
```

### 提示

- `0 <= len <= 10^5`
- `0 <= buf[i] <= 255`

### 函数说明

```c
uint16_t crc16Modbus(const uint8_t* buf, size_t len);
```

- 返回 CRC 结果，判题程序以十进制输出

### 自定义输入格式

```
[1,3,0,0,0,1]
```

一行字节数组（每个元素 `0 ~ 255`）。
