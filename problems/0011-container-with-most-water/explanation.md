# 11. 盛最多水的容器 —— 小白详细题解

> 这道题是**相向双指针**的代表作。代码只有几行，难点在于想明白"为什么移动矮的那一边不会错过答案"。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 地上竖着一排高矮不同的木板，第 `i` 块木板高 `height[i]`。任选两块木板当容器的左右两壁，问最多能装多少水。

水的高度由**较矮的那块板**决定（再高就从矮板那边溢出去了），宽度是两块板的**下标之差**：

```
面积 = (j - i) × min(height[i], height[j])
```

示例 1 `height = [1,8,6,2,5,4,8,3,7]` 中，选下标 1 和 8：

| 选择 | 宽度 j - i | 较矮的高度 | 面积 |
|---|---|---|---|
| i = 1, j = 8 | 7 | min(8, 7) = 7 | **49** |
| i = 1, j = 6 | 5 | min(8, 8) = 8 | 40 |
| i = 0, j = 8 | 8 | min(1, 7) = 1 | 8 |

**几个需要注意的细节：**

1. 中间的木板**不会挡水**，只看选中的两块。
2. 高度可以是 `0`，这时面积就是 0。
3. 最大面积约 10⁴ × 10⁵ = 10⁹，没有超过 `int` 的上限（约 2.1 × 10⁹）。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 求两个数的较小值

C 语言标准库没有 `min` 函数（`fmin` 是给浮点数用的），常用**三目运算符**：

```c
int h = a < b ? a : b;   // a < b 成立取 a，否则取 b
```

### 2. 用下标当"指针"

这里说的"双指针"其实只是两个 `int` 下标 `l` 和 `r`，并不是 C 语言里的 `int*` 指针，别被名字吓到。

---

## 💡 第三步：思路一 —— 暴力枚举（会超时）

### 思路

把所有 `(i, j)` 组合都算一遍面积，取最大值。

### 代码

```c
// ❌ 思路正确，但 n = 10^5 时要算约 50 亿次，会超时（Time Limit Exceeded）
int maxArea(int* height, int heightSize) {
    int best = 0;
    for (int i = 0; i < heightSize; i++) {
        for (int j = i + 1; j < heightSize; j++) {
            int h = height[i] < height[j] ? height[i] : height[j];   // 较矮的板
            int area = h * (j - i);
            if (area > best) best = area;
        }
    }
    return best;
}
```

### 复杂度分析

- **时间复杂度 O(n²)**：n = 10⁵ 时约 5 × 10⁹ 次，远超每秒约 10⁸ 次的计算量。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 相向双指针（最优）

### 思路

1. 左指针 `l = 0`，右指针 `r = n - 1`，这是**最宽**的容器。
2. 算一下当前面积，更新答案。
3. **把较矮的那一边往里移一格**，重复，直到 `l == r`。

### ❓ 为什么移动矮的那一边是对的？

假设 `height[l] < height[r]`。考虑所有"以 `l` 为左壁"、右壁在 `l+1 .. r-1` 的容器：

- 宽度一定**比现在小**；
- 高度 = min(height[l], 新右壁) **≤ height[l]**，也不会比现在高。

所以它们的面积**都不可能超过当前面积**。也就是说，`l` 这块矮板已经"用完了"，可以放心丢掉，`l++`。

反过来如果移动高的那一边，矮板还在，高度上限依然被它卡住，宽度却变小了——只会更差。

### 手动模拟（示例 1：`[1,8,6,2,5,4,8,3,7]`）

| l | r | height[l] | height[r] | 面积 | best | 移动 |
|---|---|---|---|---|---|---|
| 0 | 8 | 1 | 7 | 8 × 1 = 8 | 8 | 左边矮，l++ |
| 1 | 8 | 8 | 7 | 7 × 7 = 49 | 49 | 右边矮，r-- |
| 1 | 7 | 8 | 3 | 6 × 3 = 18 | 49 | r-- |
| 1 | 6 | 8 | 8 | 5 × 8 = 40 | 49 | 一样高，r-- |
| 1 | 5 | 8 | 4 | 4 × 4 = 16 | 49 | r-- |
| 1 | 4 | 8 | 5 | 3 × 5 = 15 | 49 | r-- |
| 1 | 3 | 8 | 2 | 2 × 2 = 4 | 49 | r-- |
| 1 | 2 | 8 | 6 | 1 × 6 = 6 | 49 | r-- |

`l == r` 时结束，答案 49。

### 代码

```c
int maxArea(int* height, int heightSize) {
    int l = 0;                      // 左指针，从最左边开始
    int r = heightSize - 1;         // 右指针，从最右边开始
    int best = 0;                   // 目前见过的最大面积

    while (l < r) {
        // 1. 当前容器的高度由较矮的板决定
        int h = height[l] < height[r] ? height[l] : height[r];
        int area = h * (r - l);
        if (area > best) best = area;

        // 2. 移动较矮的一边（一样高时移哪边都行）
        if (height[l] < height[r]) {
            l++;
        } else {
            r--;
        }
    }
    return best;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每一步 `l` 和 `r` 的距离减 1，最多 n - 1 步。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **移动了较高的那一边** → 会错过答案。例如示例 1 第一步若移动右边（高 7），就再也算不到 49。
2. **高度用了 `max` 而不是 `min`** → 水会从矮的那边溢出，必须取较小值。
3. **宽度写成 `r - l + 1`** → 宽度是两条线之间的距离，`[1,1]` 的答案是 1 而不是 2。
4. **每一步 `l++` 和 `r--` 同时做** → 一次丢掉两块板，可能把属于最优答案的那块高板也丢掉了。每步只能移动一边。
5. **把暴力法当最终答案提交** → n = 10⁵ 时一定超时，要会估算 n² 的量级。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 能否通过 | 建议 |
|---|---|---|---|---|
| 暴力枚举 | O(n²) | O(1) | ❌ 超时 | 帮助理解面积公式 |
| 相向双指针 | O(n) | O(1) | ✅ | 必须掌握，并能讲清"为什么移动矮边" |
