# 9037. 实现 strncpy —— 小白详细题解

> 面试官："strncpy 是安全的 strcpy 吗？" 很多人会回答"是"——**错**。strncpy 有两个反直觉的行为：源串太长时**不加 `'\0'`**，源串太短时**补一大堆 `'\0'`**。这道题让你亲手实现它，从此再也不会用错。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 不管三七二十一，**正好往 `dst` 写 `n` 个字节**。先抄 `src` 的字符；`src` 抄完了还没到 `n` 个，就用 `'\0'` 填满；`src` 太长，抄到第 `n` 个就停，不管有没有 `'\0'`。

把三个示例放在一起看（`*` 是判题程序预先填的、`n` 之后不该被修改的字节）：

| 示例 | src | n | dst 的 n + 3 个字节 | 说明 |
|---|---|---|---|---|
| 1 | `"hi"` | 5 | `h i \0 \0 \0 * * *` | 不足 n，补 3 个 `\0` |
| 2 | `"hello"` | 3 | `h e l * * *` | 太长，截断，**没有 `\0`** |
| 3 | `"abc"` | 4 | `a b c \0 * * *` | 不足 n，补 1 个 `\0` |

**几个需要注意的细节：**

1. 写入的字节数**永远是 `n`**，不多也不少。下标 `>= n` 的字节（那几个 `*`）绝对不能动。
2. `strlen(src) >= n` 时 dst **不以 `'\0'` 结尾**（示例 2），这不是 bug，而是标准规定的行为。
3. `n = 0` 时什么都不写。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. strncpy 当初是为什么设计的？

它诞生于早期 UNIX，用来写**定长字段**，比如目录项里 14 字节的文件名：名字短就补 0，名字正好 14 个字符就不需要结束符。所以它的语义是"填满一个定长字段"，而不是"安全地复制字符串"。

今天嵌入式里仍然有类似的场景：协议里的定长字段、Flash 里定长的配置项（比如 32 字节的 WiFi SSID），用 strncpy 写进去，未使用的部分全是 0，方便比较和校验。

### 2. 两段式循环：共用一个下标

```c
size_t i = 0;
for (; i < n && src[i] != '\0'; i++) { /* 第一段 */ }
for (; i < n; i++)                   { /* 第二段，从第一段停下的地方继续 */ }
```

`for` 的初始化部分可以留空，`i` 定义在外面，第二个循环就能接着第一个循环的进度。

### 3. 条件的顺序：`i < n && src[i] != '\0'`

`&&` 是**短路**的：左边为假时右边不再计算。把 `i < n` 写在前面，保证 `i == n` 时不会再去读 `src[i]`——当 `n` 很小而 `src` 不是合法字符串时（比如只有 `n` 个字节的定长字段），这能避免越界读。

## 💡 第三步：思路一 —— 两段式下标循环（标准答案）

### 思路

1. 第一段：`i` 从 0 开始，**还没写满 n 个**并且 **`src[i]` 不是 `'\0'`**，就复制 `dst[i] = src[i]`
2. 第二段：从第一段停下的位置开始，**还没写满 n 个**就写 `'\0'`
3. 返回 `dst`

### 手动模拟（示例 1：`src = "hi"`，`n = 5`）

| 阶段 | i | 条件 | 动作 | dst 前 5 字节 |
|---|---|---|---|---|
| 第一段 | 0 | 0 < 5 且 'h' | dst[0] = 'h' | `h****` |
| 第一段 | 1 | 1 < 5 且 'i' | dst[1] = 'i' | `hi***` |
| 第一段 | 2 | src[2] 是 '\0' | 退出第一段 | |
| 第二段 | 2 | 2 < 5 | dst[2] = '\0' | `hi\0**` |
| 第二段 | 3 | 3 < 5 | dst[3] = '\0' | `hi\0\0*` |
| 第二段 | 4 | 4 < 5 | dst[4] = '\0' | `hi\0\0\0` |
| 结束 | 5 | 5 < 5 不成立 | 返回 dst | |

示例 2（`"hello"`，`n = 3`）：第一段在 `i = 3` 时因为 `i < n` 不成立而退出，第二段条件一开始就不成立，一个 `'\0'` 都不写。

### 代码

```c
char* my_strncpy(char* dst, const char* src, size_t n) {
    size_t i = 0;

    // 第一段：复制 src 的字符，直到写满 n 个或者遇到 src 的 '\0'
    for (; i < n && src[i] != '\0'; i++) {
        dst[i] = src[i];
    }

    // 第二段：如果还没写满 n 个，剩下的全部补 '\0'
    for (; i < n; i++) {
        dst[i] = '\0';
    }

    return dst;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：恰好写 `n` 个字节。注意即使 `src` 只有 1 个字符，`n = 10^5` 时也要写 10^5 次——这是 strncpy 的特性。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 指针写法（库函数风格）

### 思路

逻辑完全相同，用指针 `d` 代替下标，用 `n` 本身当剩余计数器。读起来更像真实的库代码。

### 代码

```c
char* my_strncpy(char* dst, const char* src, size_t n) {
    char* d = dst;

    // 第一段：还有剩余名额，并且 src 还没结束
    while (n > 0 && *src != '\0') {
        *d++ = *src++;
        n--;
    }

    // 第二段：剩余名额全部写 '\0'
    while (n > 0) {
        *d++ = '\0';
        n--;
    }

    return dst;
}
```

### 复杂度分析

- **时间复杂度 O(n)**。
- **空间复杂度 O(1)**。

## 🔌 嵌入式实战：用 strncpy 一定要手动补 `'\0'`

```c
char ssid[33];                                  // WiFi SSID 最长 32 字节 + '\0'
strncpy(ssid, user_input, sizeof(ssid) - 1);    // 最多复制 32 个字符
ssid[sizeof(ssid) - 1] = '\0';                  // 保证一定有结束符
```

这是 strncpy 唯一推荐的用法：**少复制一个 + 手动在最后放 `'\0'`**。如果只是想安全地复制字符串，更推荐 `snprintf(dst, size, "%s", src)`，它总是以 `'\0'` 结尾，也不会浪费时间补零。

## ⚠️ 第五步：小白常见错误

1. **源串太长时自作主张补 `'\0'`**：

   ```c
   dst[n] = '\0';   // ❌ 写到了下标 n，超出了允许的范围（示例 2 的第一个 * 会被改掉）
   ```

   或者 `dst[n - 1] = '\0'`，把第 n 个字符吃掉了。标准 strncpy **不加**。
2. **源串太短时不补 `'\0'`**：只复制 `"hi"` 加一个 `'\0'` 就停，示例 1 后面两个字节还是 `*`。
3. **条件顺序写反**：`src[i] != '\0' && i < n` 在 `i == n` 时会多读一个 `src[i]`，`src` 是定长字段时就越界读了。
4. **`n` 为 0 时仍然写了一个字节**：用 `do { ... } while (--n)` 之类的写法，`n = 0` 时会先执行一次，并且 `--n` 让无符号的 `n` 变成超大的数。
5. **以为 strncpy 后 dst 一定是合法字符串**：接着 `printf("%s", dst)` 或 `strlen(dst)`，在示例 2 那种情况下会一路读出界。
6. **把 n 当成 src 的长度**：`strncpy(dst, src, strlen(src))` 一个 `'\0'` 都不会复制，等于亲手制造了没有结束符的字符串。`n` 应该是**目标缓冲区**的大小。

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 两段式下标循环 | O(n) | O(1) | ⭐⭐ | 最清晰，推荐面试时写 |
| 指针 + 剩余计数 | O(n) | O(1) | ⭐⭐ | 库函数风格 |
