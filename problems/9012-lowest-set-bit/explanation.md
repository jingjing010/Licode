# 9012. 最低置位位 —— 小白详细题解

> "找最低的 1 在第几位"在英文里叫 **count trailing zeros（ctz，数末尾的 0）**。中断分发、RTOS 调度器、位图分配器都离不开它。本题介绍逐位扫描、二分查找两种写法，以及大名鼎鼎的 `x & -x`。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 从最右边（第 0 位）往左看，**第一个 1** 在第几号位置？一个 1 都没有就返回 -1。

拿示例 1（`pending = 12`）来说：

| 位号 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|
| 12 | 1 | **1** | 0 | 0 |

从右往左，第 0、1 位是 0，第 2 位是第一个 1，答案是 `2`。换个说法：**末尾有几个 0，答案就是几**。

**几个需要注意的细节：**

1. 要的是**位号**（0~31），不是"只保留最低位 1 之后的值"（那是 `4`）。
2. `pending = 0` 时必须返回 `-1`（示例 3），否则逐位扫描会扫完 32 位都找不到，二分法会算出 32 这样的错误值。
3. 最高位（第 31 位）也要能找到（示例 2）。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 读取第 i 位：`(x >> i) & 1u`

老朋友了，不再赘述。

### 2. ⭐ `x & (~x + 1)`：只保留最低的 1

补码里 `-x = ~x + 1`。看看它和 `x` 相与会怎样：

```
x          = 0110 1100
~x         = 1001 0011
~x + 1     = 1001 0100     ← 加 1 时，末尾的 1 一路进位，正好停在 x 最低的 1 的位置
x & (~x+1) = 0000 0100     ← 只剩 x 最低的那个 1
```

原理：`~x` 末尾那段 `…0 1 1`（对应 `x` 的 `…1 0 0`）加 1 后变成 `…1 0 0`，和 `x` 在这一段完全相同；更高的位则和 `x` 正好相反，与完全变 0。

对 `uint32_t` 也可以直接写 `x & -x`（无符号取负是有定义的，等于 `2³² − x`），但有的编译器会给出警告，写成 `~x + 1u` 更清楚。

### 3. 二分思想

32 位里找第一个 1，可以先问"低 16 位里有没有 1？"——没有的话答案一定 ≥ 16，把 `x` 右移 16 位，问题规模减半。再问低 8 位、低 4 位……5 次就能确定。

---

## 💡 第三步：思路一 —— 从低到高逐位扫描（最朴素）

### 思路

`i` 从 0 到 31，遇到第一个为 1 的位就返回 `i`；全部扫完都没有，返回 -1。

### 手动模拟（示例 1：`pending = 12`）

| i | (12 >> i) & 1 | 动作 |
|---|---|---|
| 0 | 0 | 继续 |
| 1 | 0 | 继续 |
| 2 | 1 | 返回 **2** |

### 代码

```c
int lowest_set_bit(uint32_t pending) {
    for (int i = 0; i < 32; i++) {       // 从最低位往最高位找
        if ((pending >> i) & 1u) {       // 第 i 位是 1
            return i;                    // 第一个找到的就是最低的
        }
    }
    return -1;                           // 32 位全是 0
}
```

### 复杂度分析

- **时间复杂度 O(32)**：最坏情况（只有第 31 位是 1）要循环 32 次。中断分发是对时间非常敏感的地方，这个最坏情况往往不能接受。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（固定 5 步）

### 思路

1. 先特判 `pending == 0`。
2. 如果低 16 位全为 0，答案加 16，`x` 右移 16 位；
3. 如果低 8 位全为 0，答案加 8，`x` 右移 8 位；
4. 依次检查低 4 位、低 2 位、低 1 位。

### 手动模拟（示例 1：`pending = 12 = 0b1100`）

| 检查 | x（低 8 位） | 低 k 位全 0？ | n |
|---|---|---|---|
| 低 16 位 | `0000 1100` | 否 | 0 |
| 低 8 位 | `0000 1100` | 否 | 0 |
| 低 4 位 | `0000 1100` | 否（`1100`） | 0 |
| 低 2 位 | `0000 1100` | 是（`00`），x >>= 2 | 2 |
| 低 1 位 | `0000 0011` | 否 | **2** |

### 代码

```c
int lowest_set_bit(uint32_t pending) {
    if (pending == 0) {
        return -1;                                        // 没有 1，先排除
    }
    int n = 0;                                            // 已经确认的末尾 0 的个数
    uint32_t x = pending;
    if ((x & 0x0000FFFFu) == 0) { n += 16; x >>= 16; }    // 低 16 位全 0：答案在高 16 位
    if ((x & 0x000000FFu) == 0) { n += 8;  x >>= 8; }     // 低 8 位全 0
    if ((x & 0x0000000Fu) == 0) { n += 4;  x >>= 4; }     // 低 4 位全 0
    if ((x & 0x00000003u) == 0) { n += 2;  x >>= 2; }     // 低 2 位全 0
    if ((x & 0x00000001u) == 0) { n += 1; }               // 最低位是 0，那第 1 位一定是 1
    return n;
}
```

### 复杂度分析

- **时间复杂度 O(log 32) = 5 步**，耗时几乎固定。
- **空间复杂度 O(1)**。

### 变体：先隔离最低的 1，再数位号

`low = x & (~x + 1)` 是一个 2 的幂，它的位号等于 `low - 1` 里 1 的个数（`low - 1` 是低位全 1，例如 `0b100 - 1 = 0b011`，两个 1，位号 2）：

```c
int lowest_set_bit(uint32_t pending) {
    if (pending == 0) {
        return -1;
    }
    uint32_t low = pending & (~pending + 1u);   // 只保留最低的 1，例如 0b1100 -> 0b0100
    uint32_t below = low - 1u;                  // 它下面全是 1，例如 0b0011
    int count = 0;
    while (below) {                             // 数 below 里有几个 1（9006 的 Kernighan 法）
        below &= below - 1u;
        count++;
    }
    return count;
}
```

## ⚠️ 第五步：小白常见错误

1. **忘记处理 0**：
   ```c
   int n = 0;
   while (((pending >> n) & 1u) == 0) n++;   // ❌ pending = 0 时 n 一直加到 32 以上，移位越界 + 死循环
   ```
2. **返回值而不是位号**：`return pending & (~pending + 1);` 返回的是 `4`，题目要的是 `2`。
3. **从高位往低位找**：那样找到的是**最高**的 1（示例 1 会返回 3），那是另一个操作（clz）。
4. **二分法里 `x` 没有右移**：只加了 `n`，后续检查的还是原来的低位，结果错乱。
5. **用 `log2(pending)` 求位号**：那求的是最高位，而且是浮点运算，又慢又可能有误差。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位扫描 | O(32) | O(1) | ⭐ | 最容易写对，但最坏情况慢 |
| 二分查找 | O(5) | O(1) | ⭐⭐ | 耗时固定，适合中断上下文 |
| 隔离最低位 + 计数 | O(位号) | O(1) | ⭐⭐ | 练习 `x & -x` |
| 硬件指令 / `__builtin_ctz` | O(1) | O(1) | ⭐ | 实际项目首选 |

## 🔌 嵌入式实战

- **GCC 内建函数**：`__builtin_ctz(x)` 返回末尾 0 的个数，`x = 0` 时**未定义**，必须先判断：

```c
int lowest_set_bit(uint32_t pending) {
    return pending ? __builtin_ctz(pending) : -1;   // __builtin_ctz(0) 无定义，先排除
}
```

- **ARM 上的实现**：Cortex-M3/M4 没有 ctz 指令，但有 `RBIT`（位反转）和 `CLZ`（数前导零），`ctz(x) = clz(rbit(x))`，两条指令搞定。Cortex-M0 只能用软件二分。
- **中断分发循环**（示意）：

```c
uint32_t pend = IRQ_PENDING;
while (pend) {
    int irq = lowest_set_bit(pend);
    irq_handlers[irq]();          /* 调用对应的中断服务函数 */
    pend &= pend - 1u;            /* 清掉刚处理的最低位，继续找下一个 */
}
```

- **FreeRTOS** 的就绪表在 ARM 上用 `CLZ` 找优先级最高的就绪任务（它的约定是数字越大优先级越高，所以找最高位），思路和本题完全一样。
