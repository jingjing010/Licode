串口、I2C、SPI 传输数据时可能因为干扰出现比特翻转。发送方在数据后面附加一个**CRC（循环冗余校验）**值，接收方用同样的算法重算一遍并比较，就能发现绝大多数传输错误。很多温湿度传感器（如 SHT3x 用的是 CRC-8 的变种）、SMBus 都使用 8 位 CRC。

请实现最常见的 **CRC-8**（也叫 CRC-8/SMBUS），参数如下：

| 参数 | 值 |
|---|---|
| 宽度 | 8 位 |
| 多项式 Poly | `0x07`（即 x⁸ + x² + x + 1） |
| 初值 Init | `0x00` |
| 输入反射 RefIn | 否（每个字节从最高位开始处理） |
| 输出反射 RefOut | 否 |
| 结果异或 XorOut | `0x00` |
| 标准校验值 Check | 字符串 `"123456789"` 的 CRC 为 `0xF4`（十进制 244） |

计算过程（逐位法）：`crc = 0`；对每个字节 `b`，先 `crc ^= b`，再重复 8 次：如果 `crc` 的最高位（bit7）为 1，则 `crc = (crc << 1) ^ 0x07`，否则 `crc = crc << 1`（始终只保留低 8 位）。处理完所有字节后的 `crc` 就是结果。

给你一段数据 `buf`（长度 `len`），返回它的 CRC-8 值。

### 示例 1

```
输入：buf = [49,50,51,52,53,54,55,56,57]
输出：244
解释：这就是 ASCII 字符串 "123456789"，CRC-8 标准校验值为 0xF4 = 244。
```

### 示例 2

```
输入：buf = [1]
输出：7
解释：crc = 0x00 ^ 0x01 = 0x01，左移 7 次变成 0x80（最高位一直是 0，直接左移），
     第 8 次最高位为 1：(0x80 << 1) ^ 0x07 = 0x100 ^ 0x07，保留低 8 位得 0x07。
```

### 示例 3

```
输入：buf = []
输出：0
解释：没有数据，结果就是初值 0。
```

### 提示

- `0 <= len <= 10^5`
- `0 <= buf[i] <= 255`

### 函数说明

```c
uint8_t crc8(const uint8_t* buf, size_t len);
```

### 自定义输入格式

```
[49,50,51,52,53,54,55,56,57]
```

一行，数据的每个字节（十进制）。输出 CRC 值（十进制）。
