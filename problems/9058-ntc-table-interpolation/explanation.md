# 9058. NTC 温度查表插值 —— 小白详细题解

> "查表 + 线性插值"是嵌入式里处理**非线性传感器**的万能招式：NTC 热敏电阻、热电偶、电池电量（电压 → 百分比）、油门曲线……都这么做。这道题把它拆开讲透，顺便解决"负数四舍五入"这个隐藏的坑。

---

## 📖 第一步：先读懂题目

### 为什么要查表？

NTC 的温度公式（B 值方程）是：

```
1/T = 1/T0 + ln(R/R0) / B
```

又是对数又是除法，Cortex-M0 这类没有 FPU 的芯片算一次要几百微秒。而查表只需要几次比较和一次乘除。

### 线性插值是什么？

表里只有若干个点，两点之间的值用**连线**估计：

```
温度
 850 ●
      \
 625   ×  ← adc = 250，在 100 和 400 正中间，温度也取 850 和 400 的正中间
      \
 400    ●
     100  250  400   ADC
```

公式：`t = t0 + (t1 - t0) × (adc - x0) / (x1 - x0)`。

### 示例 1 逐个计算

| adc | 落在哪一段 | 增量 | 四舍五入 | 结果 |
|---|---|---|---|---|
| 50 | 小于表头 | — | — | 850 |
| 100 | 正好是表项 | (−450)×0/300 = 0 | 0 | 850 |
| 250 | [100, 400] | (−450)×150/300 = −225 | −225 | 625 |
| 550 | [400, 700] | (−250)×150/300 = −125 | −125 | 275 |
| 999 | [700, 1000] | (−350)×299/300 = −348.83 | −349 | −199 |
| 4000 | 大于表尾 | — | — | −200 |

**容易忽略的细节：**

1. 增量**可能是负数**（温度随 ADC 递减），负数的四舍五入要"远离 0"：−2.5 → −3，不是 −2。
2. 四舍五入的是**增量**，然后再加 t0（示例 2 的 5：`10 + round(−2.5) = 10 − 3 = 7`，如果先加再舍入会得到 `round(7.5) = 8`，不一样）。
3. 表只有 1 项时，任何输入都满足第 1 或第 2 条规则。

## 🧰 第二步：这道题需要的 C 语言知识

### 1. C 语言整数除法向 0 截断

```c
 7 / 2 ==  3      // 3.5 截断为 3
-7 / 2 == -3      // -3.5 截断为 -3（向 0），不是 -4
```

所以 `(num + den/2) / den` 这个四舍五入技巧**只对非负数成立**。负数的正确做法：**先对绝对值四舍五入，再加回符号**。

```c
int32_t absq = (2 * (num < 0 ? -num : num) + den) / (2 * den);   // |num| / den 四舍五入
int32_t q = (num < 0) ? -absq : absq;                            // 恢复符号
```

### 2. 无符号相减的陷阱

`adc` 和 `adcTable[i]` 都是 `uint16_t`。在 C 里它们会先提升为 `int` 再相减，所以 `adc - x0` 不会出问题；但如果它们是 `uint32_t`，`3 - 5` 会变成 42 亿。稳妥的做法是**先转成有符号类型再算**：

```c
int32_t x0 = adcTable[i];
int32_t dx = (int32_t)adc - x0;
```

### 3. 中间结果的范围

`(t1 - t0)` 最大约 1900，`(adc - x0)` 最大 4095，乘积约 `7.8 × 10^6`，`int32_t` 足够。**做定点运算前先估算范围**是好习惯。

## 💡 第三步：思路一 —— 顺序查找区间

### 代码

```c
int16_t ntcLookup(const uint16_t* adcTable, const int16_t* tempTable, size_t n, uint16_t adc) {
    if (adc <= adcTable[0]) return tempTable[0];             // 低于表头：取第一个
    if (adc >= adcTable[n - 1]) return tempTable[n - 1];     // 高于表尾：取最后一个

    size_t i = 0;
    while (adcTable[i + 1] <= adc) i++;                      // 找到 adcTable[i] <= adc < adcTable[i+1]

    int32_t x0 = adcTable[i], x1 = adcTable[i + 1];
    int32_t t0 = tempTable[i], t1 = tempTable[i + 1];
    int32_t num = (t1 - t0) * ((int32_t)adc - x0);           // 分子，可能为负
    int32_t den = x1 - x0;                                   // 分母，一定为正

    int32_t absNum = num < 0 ? -num : num;
    int32_t absq = (2 * absNum + den) / (2 * den);           // 对绝对值四舍五入
    int32_t delta = num < 0 ? -absq : absq;                  // 加回符号：.5 时远离 0
    return (int16_t)(t0 + delta);
}
```

### 复杂度分析

- 每次查询 **O(n)**。n = 256、10⁴ 次查询共约 2.5×10⁶ 次比较，可以通过。

## 🚀 第四步：思路二 —— 二分查找区间

### 为什么能优化？

`adcTable` 是有序的，找"最后一个 ≤ adc 的位置"是经典的二分查找，每次查询只需 `log₂256 = 8` 次比较。在 MCU 上，温度采样可能 1ms 一次、多个通道一起查，省下的时间很可观。

维护不变式：`adcTable[lo] <= adc < adcTable[hi]`。初始 `lo = 0`、`hi = n - 1`（两端已经在前面特判过，所以不变式成立），每次取中点缩小一半，直到 `hi == lo + 1`。

| 步骤（示例 1，adc = 999） | lo | hi | mid | adcTable[mid] | 判断 |
|---|---|---|---|---|---|
| 初始 | 0 | 3 | 1 | 400 | 400 ≤ 999 → lo = 1 |
| 2 | 1 | 3 | 2 | 700 | 700 ≤ 999 → lo = 2 |
| 结束 | 2 | 3 | | | 区间 [700, 1000] |

### 代码

```c
int16_t ntcLookup(const uint16_t* adcTable, const int16_t* tempTable, size_t n, uint16_t adc) {
    if (adc <= adcTable[0]) return tempTable[0];
    if (adc >= adcTable[n - 1]) return tempTable[n - 1];

    size_t lo = 0, hi = n - 1;                   // 不变式：adcTable[lo] <= adc < adcTable[hi]
    while (hi - lo > 1) {
        size_t mid = lo + (hi - lo) / 2;         // 防溢出的中点写法
        if (adcTable[mid] <= adc) lo = mid;
        else hi = mid;
    }

    int32_t x0 = adcTable[lo], x1 = adcTable[hi];
    int32_t t0 = tempTable[lo], t1 = tempTable[hi];
    int32_t num = (t1 - t0) * ((int32_t)adc - x0);
    int32_t den = x1 - x0;
    int32_t absq = (2 * (num < 0 ? -num : num) + den) / (2 * den);
    return (int16_t)(t0 + (num < 0 ? -absq : absq));
}
```

### 复杂度分析

- 每次查询 **O(log n)**，空间 O(1)。

### 🔌 嵌入式实战：等间距表，O(1) 定位

如果表是自己生成的，可以让 ADC **等间距**取点（例如每 128 一个点，共 33 个），这样连查找都省了：

```c
#define STEP_SHIFT 7                                   // 间距 128 = 2^7
static const int16_t NTC_T[33] = { /* 在 PC 上用 B 值方程算好 */ 0 };

int16_t ntc_fast(uint16_t adc) {
    uint16_t i = adc >> STEP_SHIFT;                   // 直接算出段号
    if (i >= 32) return NTC_T[32];
    int32_t frac = adc & ((1 << STEP_SHIFT) - 1);     // 段内偏移 0 ~ 127
    int32_t num = (NTC_T[i + 1] - NTC_T[i]) * frac;
    return (int16_t)(NTC_T[i] + num / (1 << STEP_SHIFT));   // 分母是 2 的幂（这里为简洁直接截断）
}
```

代价是：NTC 曲线两端（极冷、极热）弯曲很厉害，等间距表在这些区域误差较大，所以对精度要求高的项目还是用**不等间距表 + 二分查找**（本题的做法）。

## ⚠️ 第五步：小白常见错误

1. **负数直接用 `(num + den/2) / den`** → C 除法向 0 截断，−2.5 会得到 −2（示例 2 的 5 会输出 8）。
2. **先把 t0 加进去再四舍五入** → 与题目定义不同，结果可能差 1。
3. **用 `uint16_t` 存 `t1 - t0`** → 温度差是负数时变成很大的正数。
4. **忘了处理表的两端** → `adc < adcTable[0]` 时找不到区间，数组越界。
5. **二分写成 `mid = (lo + hi) / 2` 再配 `lo = mid + 1`** → 找"最后一个 ≤"时这种写法容易死循环或错位，按"不变式"来写最稳。

---

## 📊 第六步：方法对比

| 方法 | 每次查询 | 表的要求 | 说明 |
|---|---|---|---|
| 顺序查找 | O(n) | 有序 | 表小（< 20 项）时最简单 |
| 二分查找 | O(log n) | 有序 | 通用，推荐 |
| 等间距直接定位 | O(1) | ADC 等间距 | 最快，但曲线两端精度差 |
| 实时用公式计算 | 一次 log + 除法 | 无 | 有 FPU 时可以考虑 |
