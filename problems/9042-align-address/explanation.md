# 9042. 地址对齐 align_up / align_down —— 小白详细题解

> `(x + a - 1) & ~(a - 1)` —— 这个公式在 Linux 内核、FreeRTOS、各种内存分配器和启动代码里随处可见。这道题从最朴素的除法写法出发，一步步推导出这个位运算公式，让你真正理解它，而不是死记硬背。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把数轴按 `align` 切成一格一格，`align_down` 是 `addr` 所在格子的**左边界**，`align_up` 是**右边界**（`addr` 正好在边界上时就是它自己）。

拿示例 1 来说（`addr = 13`，`align = 8`）：

```
0       8       16      24
|-------|-------|-------|
            ↑
           13
        ↑       ↑
   align_down  align_up
       = 8      = 16
```

**几个需要注意的细节：**

1. 已经对齐的地址，向上、向下对齐都是它**自己**（示例 2），而不是"下一个"边界。
2. `align = 1` 时任何数都已对齐。
3. `align` 保证是 2 的幂（1、2、4、8……4096），这是位运算写法成立的前提。
4. 地址可能超过 `2^31`（比如 `0x80000001`），要用无符号的 `uintptr_t`，不能用 `int`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `uintptr_t`：能装下指针的整数

指针不能直接做 `&`、`%` 等运算。`<stdint.h>` 提供了 `uintptr_t`，保证能装下一个指针的值，常这样用：

```c
uint8_t* p = ...;
uintptr_t a = (uintptr_t)p;                    // 指针 → 整数
uint8_t* q = (uint8_t*)align_up(a, 8);         // 整数 → 指针
```

### 2. 2 的幂和掩码

`align = 2^k` 时，`align - 1` 的二进制是**低 k 位全 1**；按位取反 `~(align - 1)` 则是**低 k 位全 0、其余全 1**：

| align | 二进制 | align - 1 | ~(align - 1)（8 位示意） |
|---|---|---|---|
| 4 | `0000 0100` | `0000 0011` | `1111 1100` |
| 8 | `0000 1000` | `0000 0111` | `1111 1000` |

- `x & (align - 1)`：只留低 k 位 → **余数**
- `x & ~(align - 1)`：把低 k 位清零 → **去掉余数**，也就是向下对齐

### 3. 判断是否为 2 的幂

`(x & (x - 1)) == 0`（且 `x != 0`）。原理：2 的幂只有 1 个 bit 是 1，减 1 后这个 bit 变 0、低位全变 1，两者相与为 0。判题程序就用这个检查输入。

## 💡 第三步：思路一 —— 除法 / 取余（最朴素）

### 思路

- **向下对齐**：`addr / align` 是"第几格"（整数除法自动舍去小数），再乘回 `align`：`addr / align * align`
- **向上对齐**：先加上 `align - 1` 再向下对齐。为什么？如果 `addr` 不在边界上，加上 `align - 1` 一定会跨过下一个边界（但不会跨过两个）；如果正好在边界上，加上 `align - 1` 还没到下一个边界，向下对齐后还是自己。

### 手动模拟（示例 1：`addr = 13`，`align = 8`）

| 函数 | 计算 | 结果 |
|---|---|---|
| align_down | 13 / 8 = 1，1 × 8 | 8 |
| align_up | (13 + 7) / 8 = 20 / 8 = 2，2 × 8 | 16 |

示例 2（`addr = 16`）：`(16 + 7) / 8 = 2`，`2 × 8 = 16` ✅，没有跳到 24。

### 代码

```c
uintptr_t align_up(uintptr_t addr, size_t align) {
    // 先加 align - 1，保证"不在边界上"的地址能跨过下一个边界，再向下取整
    return (addr + align - 1) / align * align;
}

uintptr_t align_down(uintptr_t addr, size_t align) {
    // 整数除法舍去余数，再乘回去
    return addr / align * align;
}
```

### 复杂度分析

- **时间复杂度 O(1)**，但用到了除法。Cortex-M0 没有硬件除法指令，一次除法要调用库函数，几十个时钟周期。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 位运算（工程标准写法）

### 思路

`align` 是 2 的幂，除以 `align` 再乘回来，等价于"**把低 k 位清零**"：

- `align_down(addr) = addr & ~(align - 1)`
- `align_up(addr) = (addr + align - 1) & ~(align - 1)`

### 手动模拟（示例 3：`addr = 0x20000001`，`align = 4`）

| 步骤 | 二进制（只看低 8 位） | 十六进制 |
|---|---|---|
| addr | `...0000 0001` | `0x20000001` |
| ~(4 - 1) | `...1111 1100` | `0xFFFFFFFC` |
| align_down = addr & mask | `...0000 0000` | `0x20000000` |
| addr + 3 | `...0000 0100` | `0x20000004` |
| align_up = (addr + 3) & mask | `...0000 0100` | `0x20000004` |

### 代码

```c
uintptr_t align_up(uintptr_t addr, size_t align) {
    uintptr_t mask = (uintptr_t)align - 1;   // 低 k 位全 1
    return (addr + mask) & ~mask;            // 先进位到下一个边界，再清掉低 k 位
}

uintptr_t align_down(uintptr_t addr, size_t align) {
    // 直接清掉低 k 位
    return addr & ~((uintptr_t)align - 1);
}
```

> ⚠️ 先把 `align` 转成 `uintptr_t` 再取反。如果某个平台上 `size_t` 比 `uintptr_t` 窄，`~(align - 1)` 会先在窄类型里取反，再零扩展，高位就被意外清零了。

### 复杂度分析

- **时间复杂度 O(1)**：一次加法、一次取反、一次与运算，都是单周期指令。
- **空间复杂度 O(1)**。

## 🔌 嵌入式实战

**1. 从一块原始内存里切出对齐的 DMA 缓冲区：**

```c
static uint8_t raw[256 + 31];
uint8_t* dma_buf = (uint8_t*)align_up((uintptr_t)raw, 32);   // 32 字节对齐（Cache Line）
```

多申请 `align - 1` 个字节，保证对齐后仍有 256 字节可用。

**2. 计算 Flash 擦除范围：** 要写 `[addr, addr + len)`，必须先擦除覆盖它的所有页：

```c
uintptr_t start = align_down(addr, PAGE_SIZE);
uintptr_t end   = align_up(addr + len, PAGE_SIZE);
uint32_t pages  = (end - start) / PAGE_SIZE;
```

**3. 链接脚本 / 内核里的同名宏：** GNU ld 的 `ALIGN(8)`、Linux 的 `ALIGN(x, a)`、`round_up` / `round_down` 都是这个公式。

## ⚠️ 第五步：小白常见错误

1. **向上对齐写成 `addr + align` 再向下对齐**：已经对齐的 16 会变成 24（示例 2 错误）。必须加 `align - 1`。
2. **向上对齐写成 `addr / align * align + align`**：同样是已对齐时多加了一格。
3. **用 `int` 存地址**：

   ```c
   int a = 0x80000001;   // ❌ 超出 int 范围，变成负数，位运算和除法结果都不对
   ```

4. **掩码写反**：`addr & (align - 1)` 得到的是余数，不是对齐后的地址；向下对齐要用 `~(align - 1)`。
5. **`align` 不是 2 的幂还用位运算**：`align = 6` 时 `~5` 根本不是"清掉余数"的掩码，只能用除法写法。
6. **忘了溢出**：`addr` 很接近类型最大值时 `addr + align - 1` 会回绕成很小的数。本题限制了 `addr <= 0xFFFF0000` 来避免它，实际项目中要先检查。

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用范围 | 建议 |
|---|---|---|---|---|
| 除法 / 取余 | O(1)，需要除法 | O(1) | 任意正整数 align | 好理解 |
| 位运算 | O(1)，单周期 | O(1) | align 为 2 的幂 | 工程标准写法，务必记住 |

> 🎯 **学习建议**：在纸上用 8 位二进制把 `13`、`16`、`17` 三个数分别向上、向下对齐到 8，体会"加 7 进位、清低 3 位"的过程。
