# 9048. CRC-8 校验 —— 小白详细题解

> CRC 是嵌入式通信中最常用的校验算法。面试中"手写一个 CRC"、"CRC 查表法是怎么来的"出现频率极高。这道题从最基础的 8 位 CRC 讲起，弄懂它，CRC16 / CRC32 就只是换参数。

---

## 📖 第一步：先读懂题目

**CRC 的本质**：把整段数据看成一个超长的二进制数，用一个固定的"除数"（多项式）去做**模 2 除法**，余数就是 CRC。

"模 2 除法"和普通竖式除法一样，只是**减法换成了异或**（不借位）。来看一个小例子：数据 `0x01`（二进制 `00000001`），多项式 `0x07` 补上最高位就是 `1 0000 0111`（9 位，即 0x107）。

```
数据后面补 8 个 0：0000 0001 0000 0000
                          1 0000 0111   ← 除数对齐到最高的 1，异或
                   ─────────────────────
                          0 0000 0111   ← 余数 = 0x07
```

所以 `crc8([1]) = 7`，和示例 2 一致。

逐位法就是用程序模拟这个竖式：

| 步骤 | crc（二进制） | 最高位 | 操作 |
|---|---|---|---|
| crc ^= 0x01 | 0000 0001 | 0 | 左移 |
| 第 2~7 次 | …一直左移… | 0 | 左移 |
| 第 7 次后 | 1000 0000 | **1** | |
| 第 8 次 | (1000 0000 << 1) ^ 0000 0111 | | = 0000 0111（溢出的那位被丢弃） |

**容易忽略的细节：**

1. "最高位为 1 时异或多项式"，判断的是**移位之前**的最高位。
2. 左移后要**只保留低 8 位**：用 `uint8_t` 变量存，或者 `& 0xFF`。
3. 空数据的 CRC 就是初值 0。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 位运算速查

| 运算 | 含义 | 例子 |
|---|---|---|
| `a ^ b` | 异或：相同为 0，不同为 1 | `0b1100 ^ 0b1010 = 0b0110` |
| `a << 1` | 左移一位（相当于 ×2） | `0b0101 << 1 = 0b1010` |
| `a & 0x80` | 取出第 7 位（最高位） | 结果非 0 说明最高位是 1 |

### 2. 整数提升（坑！）

`uint8_t crc` 参与 `crc << 1` 运算时，C 语言会先把它**提升为 int**，所以 `0x80 << 1` 得到的是 `0x100` 而不是 0。再赋值回 `uint8_t` 时才会截掉高位。所以写成：

```c
crc = (uint8_t)((crc << 1) ^ 0x07);   // 强制转换回 8 位
```

### 3. `const uint8_t* buf, size_t len`

嵌入式中处理"一段二进制数据"的标准签名：`const` 表示函数不会修改数据；`size_t` 是表示长度/大小的无符号类型。循环变量也用 `size_t`，避免有符号/无符号比较警告。

## 💡 第三步：思路一 —— 逐位计算

### 思路

每个字节先异或进 crc 的高位，再一位一位地"做除法"：最高位是 1 就减去（异或）多项式，然后左移。

### 代码

```c
uint8_t crc8(const uint8_t* buf, size_t len) {
    uint8_t crc = 0x00;                          // 初值 Init = 0x00
    for (size_t i = 0; i < len; i++) {
        crc ^= buf[i];                           // 新字节"进入"除法的被除数
        for (int k = 0; k < 8; k++) {            // 处理这个字节的 8 个位
            if (crc & 0x80) {                    // 最高位是 1：能"减"多项式
                crc = (uint8_t)((crc << 1) ^ 0x07);
            } else {                             // 最高位是 0：只移位
                crc = (uint8_t)(crc << 1);
            }
        }
    }
    return crc;                                  // XorOut = 0x00，直接返回
}
```

### 复杂度分析

- **时间 O(8n)**：每个字节 8 次循环。
- **空间 O(1)**。

## 🚀 第四步：思路二 —— 查表法

### 为什么能优化？

观察内层循环：8 次移位/异或的结果**只取决于 `crc ^ buf[i]` 这一个字节**（0~255 共 256 种可能）。那就把这 256 种情况的结果**提前算好存进表里**，每个字节只需查一次表：

```
crc = table[crc ^ buf[i]];
```

速度提升约 8 倍，代价是 256 字节的表。真实项目中这张表是 `static const` 常量，直接放在 Flash 里（不占 RAM）。

### 代码

```c
static uint8_t crc8_table[256];
static bool crc8_table_ready = false;

static void crc8_build_table(void) {
    for (int v = 0; v < 256; v++) {
        uint8_t crc = (uint8_t)v;                // 假设 crc ^ byte 的结果为 v
        for (int k = 0; k < 8; k++) {            // 用逐位法算出 8 步之后的值
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
        }
        crc8_table[v] = crc;
    }
    crc8_table_ready = true;
}

uint8_t crc8(const uint8_t* buf, size_t len) {
    if (!crc8_table_ready) crc8_build_table();   // 第一次调用时建表
    uint8_t crc = 0x00;
    for (size_t i = 0; i < len; i++) {
        crc = crc8_table[crc ^ buf[i]];          // 一个字节一次查表
    }
    return crc;
}
```

### 🔌 嵌入式实战

- 表通常由脚本预先生成，写成 `static const uint8_t crc8_table[256] = { 0x00, 0x07, 0x0E, 0x09, ... };`，不在运行时计算。
- **收发双方参数必须完全一致**（多项式、初值、反射、异或输出），差一个就对不上。调试时先用 `"123456789"` 的标准校验值核对实现。
- 一个好用的性质：把"数据 + CRC"一起再算一遍 CRC，结果为 0（本题这组参数下成立），接收方可以直接用它判断帧是否正确。
- 很多 MCU（STM32 等）有**硬件 CRC 外设**，配置好多项式后写入数据即可得到结果，比软件快得多。

### 复杂度分析

- **时间 O(n)**（建表 O(256 × 8) 只做一次），**空间 O(256)**。

---

## ⚠️ 第五步：小白常见错误

1. **先左移再判断最高位** → 最高位已经被移出去了，永远判断不到。
2. **用 `int crc` 且不截断** → `crc << 1` 后高位一直保留，结果越来越大，最后要 `& 0xFF`。
3. **把多项式写成 `0x107` 去异或 8 位的 crc** → 0x107 是带最高位的完整写法，代码中异或的是去掉最高位的 `0x07`（最高位在左移时已经"消掉"了）。
4. **查表法写成 `table[buf[i]] ^ crc`** → 应该先异或再查表：`table[crc ^ buf[i]]`。
5. **driver 用 `%d` 打印 `uint8_t`**（自己测试时） → 一般没问题，但打印 `uint32_t` 时要用 `%u` 或 `%lu`，否则大数会显示成负数。

## 📊 第六步：方法对比

| 方法 | 时间 | 额外空间 | 适用 |
|---|---|---|---|
| 逐位法 | O(8n) | 无 | Flash 紧张、数据量小 |
| 查表法 | O(n) | 256 字节 | 数据量大、追求速度 |
| 硬件 CRC 外设 | 最快 | 无 | MCU 自带且参数匹配时 |
