给 MCU 烧录固件时，最常见的文件格式之一是 **Intel HEX**。它的每一行（记录）都像这样：

```
:0300300002337A1E
```

去掉开头的冒号后，每两个十六进制字符是一个字节：`03 00 30 00 02 33 7A` 是数据（长度、地址、类型、内容），最后的 `1E` 是**校验和**。Bootloader 收到一行后，会把所有字节（包括校验和）加起来，只保留低 8 位，结果为 `0` 才认为这一行没有在传输中出错。

所以校验和的定义是：使下式成立的那个字节 `C`（`0 ~ 255`）：

```
(buf[0] + buf[1] + ... + buf[len-1] + C) mod 256 == 0
```

也就是"所有字节之和的低 8 位"的**二进制补码**（取反加一）。

请实现函数 `checksum8`：计算 `buf[0] ~ buf[len-1]` 的 8 位补码校验和。

### 示例 1

```
输入：buf = [3,0,48,0,2,51,122]
输出：30
解释：这就是上面那行 Intel HEX 记录。3+0+48+0+2+51+122 = 226，256 - 226 = 30，即 0x1E。
```

### 示例 2

```
输入：buf = [255,1]
输出：0
解释：255 + 1 = 256，低 8 位已经是 0，校验和为 0（不是 256）。
```

### 示例 3

```
输入：buf = [200,100,50]
输出：162
解释：和为 350，低 8 位是 350 - 256 = 94，256 - 94 = 162。
```

### 提示

- `0 <= len <= 10000`（`len = 0` 时数据为空，校验和为 `0`）
- `0 <= buf[i] <= 255`

### 函数说明

```c
uint8_t checksum8(const uint8_t* buf, size_t len);
```

- `buf`：数据缓冲区首地址（只读）
- `len`：数据字节数
- 返回值：8 位补码校验和（`0 ~ 255`）

### 自定义输入格式

```
[3,0,48,0,2,51,122]
```

只有 1 行，是十进制的字节数组 `buf`。输出为校验和（十进制整数）。
