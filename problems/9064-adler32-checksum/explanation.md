# Adler-32 数据块校验：题解

## 📖 先读懂题目

计算Adler-32：a初值1，b初值0，每字节更新a=(a+x)%65521，b=(b+a)%65521，返回(b<<16)|a。长度0到1024，结果按无符号十进制输出。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[49,50,51,52,53,54,55,56,57]` | `152961502` |
| 2 | `[]` | `1` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

`uint32_t`运算按2^32取模。先转换为无符号类型再移位，避免负数左移；移位数必须小于类型位宽。超过INT_MAX的结果仍要按无符号值理解。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

与双累加校验类似，但模数为65521且第一个累加器初值为1。每步取模避免大块数据溢出。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
uint32_t adler32Block(const uint8_t *data, size_t len) {
    uint32_t a = 1, b = 0;
    for (size_t i = 0; i < len; ++i) {
        a = (a + data[i]) % 65521u;
        b = (b + a) % 65521u;
    }
    return (b << 16) | a;
}
```

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，额外空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 用有符号int承接无符号32位位模式，导致最高位被当成符号。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
