# 9005. 写入寄存器位域 —— 小白详细题解

> 这是嵌入式面试的**高频手写题**："写一个函数/宏，修改寄存器的第 a 到 b 位，且不影响其他位。" 能一次写对 "**先清后写 + 截断 val + width=32 特判**" 的人并不多。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 32 个开关里，从第 `pos` 号开始往左数 `width` 个，把这一段**整体改成** `val` 的样子；这一段之外的开关一个都不能碰。

拿示例 2（`reg = 180, pos = 2, width = 3, val = 2`）来说：

| 位号 | 7 | 6 | 5 | **4** | **3** | **2** | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| reg = 180 | 1 | 0 | 1 | **1** | **0** | **1** | 0 | 0 |
| val = 2 = `010` | | | | **0** | **1** | **0** | | |
| 结果 168 | 1 | 0 | 1 | **0** | **1** | **0** | 0 | 0 |

**几个需要注意的细节：**

1. 位域里原来的 1 要变成 0（第 2、4 位），原来的 0 要变成 1（第 3 位）——**光靠 `|` 是做不到的**，`|` 只能把 0 变 1。
2. `val` 可能比位域宽（示例 3 中 `val = 255`，但位域只有 4 位），多出来的位**必须丢掉**，否则会"溢出"到隔壁的位域，改坏别的配置。
3. `width` 最大可以是 32，这时 `1u << 32` 是未定义行为，要特判。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 读-改-写的标准模板

修改寄存器一部分位的通用套路叫 **read-modify-write**：

```c
uint32_t tmp = REG;          /* 1. 读 */
tmp &= ~FIELD_MSK;           /* 2. 把位域清零 */
tmp |= (val << FIELD_POS) & FIELD_MSK;   /* 3. 写入新值 */
REG = tmp;                   /* 4. 写回 */
```

本题函数做的就是第 2、3 步。

### 2. 两种掩码

设 `mask = (1u << width) - 1`，即低 `width` 位全是 1：

| 掩码 | 示例 2 中的值 | 作用 |
|---|---|---|
| `mask` | `0000 0111` | 截断 `val`：`val & mask` |
| `mask << pos` | `0001 1100` | 标出位域在寄存器中的位置 |
| `~(mask << pos)` | `1110 0011` | 清零位域：`reg & ~(mask << pos)` |

### 3. 为什么要先截断 `val`？

示例 3 中如果不截断：`0 | (255 << 0) = 255`，第 4~7 位也被写成了 1。在真实芯片上，这些位可能是别的外设的使能位，后果可能是"串口突然不工作了"，而且极难排查。

> 💡 先截断再移位 `(val & mask) << pos`，和先移位再截断 `(val << pos) & (mask << pos)` 都可以。但后者在 `val` 的高位被移出 32 位时同样安全，因为无符号左移溢出的位会被直接丢弃（这对**无符号数**是有定义的行为）。

### 4. 移位 >= 32 是未定义行为（复习）

`width = 32` 时 `(1u << 32) - 1` 是 UB，实测在 x86 上常常得到 `1 - 1 = 0`。所以：

```c
uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);
```

### 5. 真实单片机里的 `volatile` 和原子性

```c
TIM2->PSC_CR = (TIM2->PSC_CR & ~(0xFu << 4)) | ((5u & 0xFu) << 4);   /* 示意 */
```

- 寄存器是 `volatile` 的，每次读写都真实发生。所以**不要**写成两条语句 `REG &= ~m; REG |= v;`——中间有一个"位域为 0"的瞬间，硬件可能在那一刻按错误的配置工作。先在局部变量里算好，再**一次性**写回更安全。
- 读-改-写不是原子操作，如果中断里也会改同一个寄存器，需要关中断保护。

## 💡 第三步：思路一 —— 逐位写入（最朴素）

### 思路

一位一位处理：对位域里的第 `i` 位（`i = 0 .. width-1`），看 `val` 的第 `i` 位是 0 还是 1，分别对 `reg` 的第 `pos + i` 位做"清零"或"置位"。`val` 中第 `width` 位及以上的位根本不会被看到，自然就被"截断"了。

### 手动模拟（示例 2：`reg = 180, pos = 2, width = 3, val = 2 = 0b010`）

| i | val 的第 i 位 | 操作 | reg（二进制） |
|---|---|---|---|
| 初始 | | | 1011 0100 |
| 0 | 0 | 清零第 2 位 | 1011 0000 |
| 1 | 1 | 置位第 3 位 | 1011 1000 |
| 2 | 0 | 清零第 4 位 | 1010 1000 = **168** |

### 代码

```c
uint32_t set_bit_field(uint32_t reg, int pos, int width, uint32_t val) {
    for (int i = 0; i < width; i++) {
        uint32_t bit = (val >> i) & 1u;       // val 的第 i 位
        uint32_t m = 1u << (pos + i);         // reg 中对应的位置
        if (bit) {
            reg |= m;                         // 置 1
        } else {
            reg &= ~m;                        // 清 0
        }
    }
    return reg;                               // 位域之外的位从未被碰过
}
```

所有移位的位数都不超过 31，所以 `width = 32` 不需要特判。

### 复杂度分析

- **时间复杂度 O(width)**，最多 32 次循环。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 先清后写（标准答案）

### 思路

1. 构造低 `width` 位全 1 的 `mask`（`width = 32` 特判）。
2. `reg & ~(mask << pos)`：把位域整体清零。
3. `(val & mask) << pos`：截断 `val`，移到位域的位置。
4. 两者相或。

### 手动模拟（示例 1：`reg = 0xFFFFFFFF, pos = 4, width = 4, val = 0`）

| 步骤 | 十六进制 |
|---|---|
| mask | `0x0000000F` |
| mask << 4 | `0x000000F0` |
| ~(mask << 4) | `0xFFFFFF0F` |
| reg & 上一行 | `0xFFFFFF0F` |
| (val & mask) << 4 | `0x00000000` |
| 相或 | `0xFFFFFF0F` = **4294967055** |

### 代码

```c
uint32_t set_bit_field(uint32_t reg, int pos, int width, uint32_t val) {
    // 1. 低 width 位全为 1 的掩码（width == 32 时 1u << 32 是未定义行为，单独处理）
    uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);

    // 2. 把位域清零：第 pos ~ pos+width-1 位为 0，其余位为 1 的掩码与上去
    reg &= ~(mask << pos);

    // 3. 截断 val 只留低 width 位，挪到位域的位置，再或进去
    reg |= (val & mask) << pos;

    return reg;
}
```

### 复杂度分析

- **时间复杂度 O(1)**。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **只或不清**：
   ```c
   return reg | (val << pos);   // ❌ 位域里原来的 1 清不掉，示例 2 得到 0b1011_1100 = 188
   ```
2. **不截断 `val`**：`reg & ~(mask << pos) | (val << pos)`，示例 3 会得到 255，污染了第 4~7 位。
3. **`width = 32` 不特判**：掩码变成 0，位域不会被清零，`val` 也被截断成 0，结果等于原 `reg`。
4. **运算符优先级**：`reg & ~mask << pos` 会被解析成 `reg & ((~mask) << pos)`，清零的位置全错了。`a & b | c` 虽然因为 `&` 优先于 `|` 碰巧正确，但**请永远加括号**。
5. **用 `^` 代替先清后写**：`reg ^ (val << pos)` 只有在位域原本全为 0 时才正确。
6. **在真实寄存器上分两步写**：`REG &= ~m; REG |= v;` 会让外设短暂地处于"位域为 0"的配置，有些外设（比如时钟分频、PLL）这会引发故障。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位置位/清零 | O(width) | O(1) | ⭐⭐ | 帮助理解，天然处理截断和 32 位 |
| 先清后写 | O(1) | O(1) | ⭐⭐ | 面试标准答案 |

> 🎯 背下这一行：`reg = (reg & ~(mask << pos)) | ((val & mask) << pos);`

## 🔗 举一反三

- **9004. 读取寄存器位域**：`(reg >> pos) & mask`，本题的逆操作。
- **写成宏**：`#define REG_SET_FIELD(reg, msk, pos, v) ((reg) = ((reg) & ~(msk)) | (((uint32_t)(v) << (pos)) & (msk)))`。STM32 HAL 中的 `MODIFY_REG(REG, CLEARMASK, SETMASK)` 就是这个思路。
