# 658. 找到 K 个最接近的元素 —— 小白详细题解

> 这道题最妙的一步是：不去二分"x 在哪"，而是**二分"答案窗口从哪开始"**。理解了这个比较条件，你会发现二分可以用在很多意想不到的地方。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有一个排好序的数组，从中挑出 k 个**离 x 最近**的数，按从小到大返回。如果两个数离 x 一样近，**优先选小的那个**。

拿示例 1 `arr = [1,2,3,4,5], k = 4, x = 3` 来说：

| 数值 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 到 x=3 的距离 | 2 | 1 | 0 | 1 | 2 |

距离最小的是 3（0），然后是 2、4（都是 1），然后 1 和 5 都是 2——**一样近选小的**，所以选 1。答案 `[1,2,3,4]`。

**几个需要注意的细节：**

1. x **不一定**在数组里，甚至可能比所有数都小（示例 2 的 x = -1）。
2. 数组里**可以有重复的数**（示例 2 有两个 1）。
3. 因为数组有序，离 x 最近的 k 个数**一定是连续的一段**（不可能跳过一个更近的数去选一个更远的数）。
4. 返回的数组要用 `malloc`，还要设置 `*returnSize = k`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 返回数组：`malloc` + `*returnSize`

```c
int* res = (int*)malloc(sizeof(int) * k);   // 在堆上申请 k 个 int
*returnSize = k;                            // 告诉调用者返回了几个数
```

局部数组 `int res[k];` 在函数返回后就失效了，必须用 `malloc`。

### 2. `abs` 函数

`abs(x)` 返回 int 的绝对值，在 `<stdlib.h>` 中。本题数值范围小（±10⁴），相减不会溢出。

### 3. 不写 abs 也能比较距离

当 `a <= x <= b` 时，`|a - x| = x - a`，`|b - x| = b - x`。思路二会用到这个，不需要 `abs`。

---

## 💡 第三步：思路一 —— 双指针从两端删（O(n)）

### 思路

答案是连续的一段，那就先把**整个数组**当成候选窗口 `[left, right]`，每次比较两端：

- 如果左端 `arr[left]` 离 x **更远**（距离严格更大），删掉左端：`left++`
- 否则（右端更远，或者一样远——一样远时要保留更小的左端），删掉右端：`right--`

直到窗口里只剩 k 个数。

### 手动模拟（`arr = [1,2,3,4,5], k = 4, x = 3`）

| 轮次 | left | right | 左端距离 | 右端距离 | 操作 |
|---|---|---|---|---|---|
| 1 | 0 | 4 | \|1-3\| = 2 | \|5-3\| = 2 | 一样远，删右端，right = 3 |
| 结束 | 0 | 3 | | | 剩 4 个：[1,2,3,4] ✅ |

### 代码

```c
int* findClosestElements(int* arr, int arrSize, int k, int x, int* returnSize) {
    int left = 0, right = arrSize - 1;       // 候选窗口 [left, right]
    while (right - left + 1 > k) {           // 窗口比 k 大就继续删
        if (abs(arr[left] - x) > abs(arr[right] - x)) {
            left++;              // 左端严格更远，删左端
        } else {
            right--;             // 右端更远或一样远（一样远保留小的），删右端
        }
    }
    int* res = (int*)malloc(sizeof(int) * k);
    for (int i = 0; i < k; i++) res[i] = arr[left + i];
    *returnSize = k;
    return res;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最多删 n - k 次。
- **空间复杂度 O(1)**（返回数组不算）。

## 🚀 第四步：思路二 —— 二分窗口的左端点（O(log n + k)）

### 思路

答案是 `arr[left .. left+k-1]`，`left` 的取值范围是 `[0, n-k]`。我们直接二分 `left`！

对于候选起点 `mid`，比较窗口**左端** `arr[mid]` 和窗口**右边外面的第一个数** `arr[mid + k]`：

- 如果 `x - arr[mid] > arr[mid + k] - x`：`arr[mid]` 比 `arr[mid + k]` 离 x 更远，用 `arr[mid+k]` 替换 `arr[mid]` 更好，窗口应该**右移**，答案起点 `> mid`：`lo = mid + 1`
- 否则：`arr[mid]` 不比 `arr[mid + k]` 远（一样远时优先保留小的 `arr[mid]`），答案起点 `<= mid`：`hi = mid`

> 🤔 为什么不写 `abs`？
> - 如果 x 在 `arr[mid]` 和 `arr[mid+k]` 之间，`x - arr[mid]` 和 `arr[mid+k] - x` 就是两边的真实距离。
> - 如果 x 比 `arr[mid+k]` 还大，`arr[mid+k] - x` 是负数，`x - arr[mid]` 是正数，条件成立，窗口右移——正确！
> - 如果 x 比 `arr[mid]` 还小，`x - arr[mid]` 是负数，条件不成立，窗口左移——也正确！
>
> 用 `abs` 反而会在有重复元素时出错（比如 `arr[mid] == arr[mid+k]` 且都在 x 右边时）。

### 区间定义与循环条件

- 区间：闭区间 `[lo, hi] = [0, n - k]`，表示"答案起点的可能范围"。
- `while (lo < hi)`；条件成立 `lo = mid + 1`，否则 `hi = mid`。
- 因为 `mid < hi <= n - k`，所以 `mid + k < n`，访问 `arr[mid + k]` **不会越界**。
- `mid = lo + (hi - lo) / 2`。

### 手动模拟（`arr = [1,1,2,3,4,5], k = 4, x = -1`）

起点范围 `[0, 2]`。

| 轮次 | lo | hi | mid | x - arr[mid] | arr[mid+k] - x | 前者更大？ | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 2 | 1 | -1-1 = -2 | 4-(-1) = 5 | 否 | hi = 1 |
| 2 | 0 | 1 | 0 | -1-1 = -2 | 3-(-1) = 4 | 否 | hi = 0 |
| 结束 | 0 | 0 | | | | | 起点 0：[1,1,2,3] ✅ |

### 代码

```c
int* findClosestElements(int* arr, int arrSize, int k, int x, int* returnSize) {
    int lo = 0, hi = arrSize - k;            // 窗口起点的范围 [0, n-k]
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;        // mid < hi，所以 arr[mid + k] 不越界
        if (x - arr[mid] > arr[mid + k] - x) {
            lo = mid + 1;        // arr[mid] 更远：窗口右移
        } else {
            hi = mid;            // arr[mid] 不更远：起点 <= mid
        }
    }
    int* res = (int*)malloc(sizeof(int) * k);
    for (int i = 0; i < k; i++) res[i] = arr[lo + i];   // 复制窗口 [lo, lo+k-1]
    *returnSize = k;
    return res;
}
```

### 复杂度分析

- **时间复杂度 O(log(n - k) + k)**：二分 O(log(n-k))，复制结果 O(k)。
- **空间复杂度 O(1)**（返回数组不算）。

## ⚠️ 第五步：小白常见错误

1. **一样远时删掉了左端** → 题目规定一样近时选**更小的**，左端更小，应该保留左端、删右端。
2. **二分条件里用 `abs`** → `arr = [1,1,2,2,2,2,2,3,3]`, `k = 3`, `x = 3` 这类有重复元素的数据会出错，直接用 `x - arr[mid]` 与 `arr[mid+k] - x` 比较。
3. **二分起点范围写成 `[0, n-1]`** → 起点最大只能是 `n - k`，否则 `arr[mid + k]` 越界。
4. **把条件写成 `>=`** → 一样远时窗口右移，丢掉了更小的数，违反题目规则。
5. **忘了 `*returnSize = k`** → 判题程序以为你返回了 0 个数，输出 `[]`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 双指针从两端删 | O(n) | O(1) | ⭐⭐ | 直观，先掌握 |
| 二分窗口起点 | O(log(n-k) + k) | O(1) | ⭐⭐⭐ | 最优，比较条件要想清楚 |

> 🎯 **学习建议**：二分的对象不一定是"目标值的位置"，也可以是"**答案的某个参数**"（这里是窗口起点）。关键是找到让判断条件单调的比较方式。
