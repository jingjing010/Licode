# 使数组中所有元素都等于零：题解

## 📖 先读懂题目

一次操作选择不超过最小正元素的正整数x，从所有正元素中减x。返回全变0的最少操作次数。1 ≤ n ≤ 100，元素0到100。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[1,5,0,3,5]` | `3` |
| 2 | `[0]` | `0` |

## 🧰 需要的 C 语言知识

数组形参是指针，不能用`sizeof(指针)`推算元素个数，要使用单独传入的长度。下标从0开始，最后一个有效下标是长度减1。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

每次减去当前最小正数，消去一个不同的正值，答案是不同正数的个数。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int minimumOperations(int *nums, int numsSize) {
    bool seen[101] = {false};
    int answer = 0;
    /* 每次选择最小正值，恰好消去一个不同的正数层级。 */
    for (int i = 0; i < numsSize; ++i)
        if (nums[i] > 0 && !seen[nums[i]]) {
            seen[nums[i]] = true;
            ++answer;
        }
    return answer;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，空间 O(101) | 正式提交 |

## ⚠️ 常见错误

- 循环写成`i <= 长度`，访问数组末尾之后的内存。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
