# 9020. 解析有符号 int16 传感器数据 —— 小白详细题解

> 9018 读出来的是无符号数。但传感器的数据经常有正有负（加速度、角速度、温度……），这一题教你把"两个字节"正确地还原成**带符号**的整数——也就是搞懂**补码**和**符号扩展**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 每 2 个字节一组，前一个是高字节、后一个是低字节，拼成一个 16 位数；如果最高位是 1，它表示的是一个负数，要还原成真正的负数存进 `out`。

拿示例 1 `buf = [18,52,255,254,128,0]` 来说：

| 组 i | 字节 | 拼成 16 位 | 无符号值 | 最高位 | 真实值 |
|---|---|---|---|---|---|
| 0 | `0x12 0x34` | `0x1234` | 4660 | 0 | 4660 |
| 1 | `0xFF 0xFE` | `0xFFFE` | 65534 | 1 | 65534 − 65536 = **−2** |
| 2 | `0x80 0x00` | `0x8000` | 32768 | 1 | 32768 − 65536 = **−32768** |

**几个需要注意的细节：**

1. `len` 是**字节数**，数据个数是 `len / 2`；不要写到 `out[len/2]` 之外。
2. `out` 是 `int32_t`，如果直接把 `0xFFFE` 当无符号数存进去，得到的是 `65534`——这就是本题要避免的错误。
3. 范围：结果一定在 `-32768 ~ 32767` 之间。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 补码：负数在内存里长什么样

16 位有符号整数 `int16_t` 用补码表示，最高位（bit15）是符号位：

| 16 位二进制（十六进制） | 当无符号看 | 当 int16 看 |
|---|---|---|
| `0x0000` | 0 | 0 |
| `0x7FFF` | 32767 | 32767（最大值） |
| `0x8000` | 32768 | −32768（最小值） |
| `0xFFFE` | 65534 | −2 |
| `0xFFFF` | 65535 | −1 |

规律：**最高位为 1 时，真实值 = 无符号值 − 65536（即 2^16）**。

### 2. 符号扩展

把 16 位的 `-2`（`0xFFFE`）放进 32 位的 `int32_t`，应该变成 `0xFFFFFFFE`（高 16 位全部补 1），而不是 `0x0000FFFE`。这个"高位补符号位"的过程叫**符号扩展**。C 语言里，把 `int16_t` 赋值给 `int32_t` 时编译器会**自动**做符号扩展：

```c
int16_t s = (int16_t)0xFFFE;   // s == -2
int32_t v = s;                 // v == -2，即 0xFFFFFFFE
```

> 💬 严格来说，把 `65534` 这样超出范围的无符号数转成 `int16_t` 在 C 标准中是"实现定义"行为，但 GCC、Keil、IAR 等所有主流嵌入式编译器都按补码直接截断，结果就是 −2。追求 100% 可移植时，可以用思路一的"减 65536"写法。

### 3. 拼字节时的类型

`buf[2*i]` 是 `uint8_t`，`buf[2*i] << 8` 会先被提升成 `int` 再移位，最大 `0xFF00`，不会溢出。拼好后用 `uint16_t` 保存即可。

---

## 💡 第三步：思路一 —— 先拼无符号数，再按符号位修正

### 思路

1. `u = (buf[2i] << 8) | buf[2i+1]`，得到 0~65535
2. 如果 `u >= 32768`（即 `u & 0x8000` 不为 0），真实值是 `u - 65536`；否则就是 `u`

### 手动模拟（示例 2：`[64,0,192,0,0,16]`）

| i | 高字节 | 低字节 | u | `u >= 32768`？ | out[i] |
|---|---|---|---|---|---|
| 0 | `0x40` | `0x00` | 16384 | 否 | 16384 |
| 1 | `0xC0` | `0x00` | 49152 | 是 | 49152 − 65536 = −16384 |
| 2 | `0x00` | `0x10` | 16 | 否 | 16 |

### 代码

```c
void parse_s16_be(const uint8_t* buf, int len, int32_t* out) {
    int count = len / 2;                       // 数据个数 = 字节数 / 2
    for (int i = 0; i < count; i++) {
        // 大端：高字节在前
        uint16_t u = (uint16_t)((buf[2 * i] << 8) | buf[2 * i + 1]);
        if (u & 0x8000u) {
            out[i] = (int32_t)u - 65536;       // 符号位为 1：负数
        } else {
            out[i] = (int32_t)u;               // 符号位为 0：正数，原样保存
        }
    }
}
```

### 复杂度分析

- **时间复杂度 O(n)**，n 为字节数；**空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 借助 `int16_t` 自动符号扩展（项目常用）

### 思路

先把拼好的 16 位数强转成 `int16_t`，编译器就会按补码解释它；再赋值给 `int32_t`，自动完成符号扩展。代码更短，也是 MPU6050、BMI160 等驱动里最常见的写法。

### 手动模拟（示例 1 第 1 组 `0xFF 0xFE`）

| 步骤 | 表达式 | 结果 |
|---|---|---|
| 拼接 | `(0xFF << 8) \| 0xFE` | `0xFFFE`（int 类型的 65534） |
| 转 int16 | `(int16_t)0xFFFE` | −2 |
| 赋值给 int32 | `out[1] = -2` | `0xFFFFFFFE` = −2 ✅ |

### 代码

```c
void parse_s16_be(const uint8_t* buf, int len, int32_t* out) {
    for (int i = 0; i < len / 2; i++) {
        // 先转成 int16_t：最高位被当作符号位
        int16_t s = (int16_t)(((uint16_t)buf[2 * i] << 8) | buf[2 * i + 1]);
        out[i] = s;                            // int16 -> int32 自动符号扩展
    }
}
```

## 🔌 嵌入式实战

MPU6050 的驱动通常这样写：一次 I2C 连续读 14 个字节（加速度 XYZ、温度、角速度 XYZ），再逐个解析：

```c
uint8_t raw[14];
i2c_read(MPU6050_ADDR, 0x3B, raw, 14);  // 从 ACCEL_XOUT_H 开始连续读 ...
int32_t v[7];
parse_s16_be(raw, 14, v);
float ax_g = v[0] / 16384.0f;           // 量程 ±2g 时，16384 LSB = 1g
float temp = v[3] / 340.0f + 36.53f;    // 数据手册给出的温度换算公式
```

示例 2 里的 `16384` 和 `-16384` 正好就是 ±2g 量程下的 +1g 和 −1g——芯片水平静止时，Z 轴读数大约就是 16384。

## ⚠️ 第五步：小白常见错误

1. **不处理符号**：`out[i] = (buf[2*i] << 8) | buf[2*i+1];` 直接存，`0xFFFE` 变成 65534，示例 1 输出 `[4660,65534,32768]`。
2. **用 `uint16_t` 接收后直接赋给 `int32_t`**：`uint16_t` 转 `int32_t` 是**零扩展**，同样得到 65534。必须经过 `int16_t` 或手动减 65536。
3. **字节顺序弄反**：写成 `buf[2*i+1] << 8 | buf[2*i]`，那是小端解析，示例 1 第一个数会得到 `0x3412`。
4. **循环次数写成 `len`**：`for (i = 0; i < len; i++)` 会写 `out[len/2]` 之后的内存（越界），并且读 `buf[2*i]` 也越界。
5. **用 `char` 接收字节**：如果 `buf` 被声明成 `char*`，在 `char` 有符号的编译器上 `0xFE` 会变成 −2，`(-2) << 8 | ...` 结果完全错乱。原始字节一律用 `uint8_t`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| 判断符号位后减 65536 | O(n) | O(n) 输出 / O(1) 额外 | 完全符合 C 标准，原理清楚 |
| 强转 `int16_t` 自动符号扩展 | O(n) | O(n) 输出 / O(1) 额外 | 代码最短，驱动里最常见 |
