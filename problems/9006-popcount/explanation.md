# 9006. 统计置位个数 —— 小白详细题解

> "数一数一个整数里有几个 1"是位运算面试的常客。它有三种层层递进的写法：**逐位数 → `x & (x-1)` 消 1 → 分组并行求和**。第三种写法是很多编译器内建函数 `__builtin_popcount` 的软件实现，值得认真弄懂。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 32 个开关里，有几个是**开着的**？

拿示例 1（`x = 11`）来说：

| 位号 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|
| x = 11 | **1** | 0 | **1** | **1** |

一共 3 个 1，答案是 `3`。

**几个需要注意的细节：**

1. 答案的范围是 `0 ~ 32`：`x = 0` 时没有任何 1；`x = 0xFFFFFFFF` 时 32 位全是 1（示例 3）。
2. 第 31 位（最高位）也要算。如果你用 `int` 存 `x`，最高位为 1 时它会变成负数，后面的右移就出问题了。
3. 答案只跟"有几个 1"有关，跟 1 在哪个位置无关。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 读取第 i 位：`(x >> i) & 1u`

把第 `i` 位右移到最低位，再和 1 相与，得到 0 或 1。这是 9001~9004 里反复用过的写法。

### 2. 为什么必须是无符号数？

- 对**无符号数**右移，左边补 0，移够 32 次一定变成 0。
- 对**有符号负数**右移（算术右移），左边补的是 1。如果写 `while (x) { ...; x >>= 1; }`，负数会永远变不成 0，**死循环**。

所以参数是 `uint32_t`，循环里也不要把它转成 `int`。

### 3. ⭐ `x & (x - 1)`：消掉最右边的 1

`x - 1` 会把 `x` 最右边的 1 变成 0，并把它右边的 0 全部变成 1；左边的位不变。再和 `x` 相与，右边这一段全变成 0：

```
x           = 1011 0100
x - 1       = 1011 0011     ← 最右边的 1（第 2 位）借位变 0，它右边的 00 变成 11
x & (x - 1) = 1011 0000     ← 最右边的 1 被消掉了，其它 1 原样保留
```

这个技巧在 9008（判断 2 的幂）里还会用到。

### 4. 十六进制"魔法掩码"

| 掩码 | 二进制（低 8 位） | 含义 |
|---|---|---|
| `0x55555555` | `0101 0101` | 每 2 位一组，取低 1 位 |
| `0x33333333` | `0011 0011` | 每 4 位一组，取低 2 位 |
| `0x0F0F0F0F` | `0000 1111` | 每 8 位一组，取低 4 位 |

## 💡 第三步：思路一 —— 逐位检查（最朴素）

### 思路

从第 0 位到第 31 位，每一位读出来，是 1 就让计数器加 1。

### 手动模拟（示例 1：`x = 11 = 0b1011`）

| i | (x >> i) & 1 | count |
|---|---|---|
| 0 | 1 | 1 |
| 1 | 1 | 2 |
| 2 | 0 | 2 |
| 3 | 1 | 3 |
| 4 ~ 31 | 0 | **3** |

### 代码

```c
int popcount32(uint32_t x) {
    int count = 0;
    for (int i = 0; i < 32; i++) {   // 32 位一位都不漏
        if ((x >> i) & 1u) {         // 第 i 位是 1
            count++;
        }
    }
    return count;
}
```

### 复杂度分析

- **时间复杂度 O(32)**：不管 `x` 里有几个 1，都要循环 32 次。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— `x & (x - 1)` 逐个消 1（Brian Kernighan 算法）

### 思路

每做一次 `x &= x - 1`，`x` 里就少一个 1。做到 `x == 0` 为止，做了几次就有几个 1。循环次数 = 1 的个数，**1 越少越快**。

### 手动模拟（示例 1：`x = 11`）

| 第几次 | x（二进制） | x - 1 | x & (x - 1) | count |
|---|---|---|---|---|
| 1 | 1011 | 1010 | 1010 | 1 |
| 2 | 1010 | 1001 | 1000 | 2 |
| 3 | 1000 | 0111 | 0000 | **3** |

### 代码

```c
int popcount32(uint32_t x) {
    int count = 0;
    while (x != 0) {      // 还有 1 没被消掉
        x &= x - 1;       // 消掉最右边的那个 1
        count++;          // 每消一个计一次数
    }
    return count;
}
```

### 复杂度分析

- **时间复杂度 O(k)**，`k` 是 1 的个数，最坏 32 次。ADC 通道寄存器通常只选了几个通道，这种写法很快。
- **空间复杂度 O(1)**。

## 🚀 思路三 —— 分组并行求和（SWAR，无循环）

### 思路

把 32 位看成 32 个"只有 1 位的小计数器"，然后**两两合并**：

1. 每 2 位一组，算出这 2 位里有几个 1（结果 0~2，2 位放得下）；
2. 每 4 位一组，把相邻两个 2 位计数相加（结果 0~4）；
3. 每 8 位一组，把相邻两个 4 位计数相加（结果 0~8）；
4. 最后把 4 个字节的计数加起来（结果 0~32）。

每一步都是**所有组同时算**，所以只要固定的几条指令。

**第 1 步为什么是 `x - ((x >> 1) & 0x55555555)`？** 一个 2 位组的值是 `v = 2a + b`（`a` 是高位，`b` 是低位），而 1 的个数是 `a + b = v - a`。`(x >> 1) & 0x55555555` 正好把每组的高位 `a` 挪到了这组的低位上，相减就得到了每组的 `a + b`，而且不会向隔壁组借位（因为 `v >= a`）。

**第 4 步为什么是乘以 `0x01010101` 再右移 24？** 设 4 个字节分别是 `A B C D`（每个都 ≤ 8），乘 `0x01010101` 相当于把 `x`、`x << 8`、`x << 16`、`x << 24` 加起来，最高字节正好是 `A + B + C + D`。

### 手动模拟（示例 1：`x = 11`，只看低 8 位）

| 步骤 | 二进制 | 含义 |
|---|---|---|
| x | `00 00 10 11` | |
| 第 1 步 | `00 00 01 10` | 4 个 2 位组：0、0、1、2 |
| 第 2 步 | `0000 0011` | 2 个 4 位组：0、3 |
| 第 3 步 | `00000011` | 1 个字节：3 |
| 第 4 步 | | 4 个字节求和 = **3** |

### 代码

```c
int popcount32(uint32_t x) {
    // 第 1 步：每 2 位一组，组内变成"这 2 位里 1 的个数"
    x = x - ((x >> 1) & 0x55555555u);
    // 第 2 步：每 4 位一组，把相邻两个 2 位计数相加
    x = (x & 0x33333333u) + ((x >> 2) & 0x33333333u);
    // 第 3 步：每 8 位一组，把相邻两个 4 位计数相加（和最多是 8，4 位放得下，所以可以先加后与）
    x = (x + (x >> 4)) & 0x0F0F0F0Fu;
    // 第 4 步：4 个字节的计数加到最高字节上，再移下来
    return (int)((x * 0x01010101u) >> 24);
}
```

### 复杂度分析

- **时间复杂度 O(1)**：约 12 条指令，没有循环和分支，执行时间固定。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **用 `int` 存寄存器值再右移**：最高位为 1 时是负数，算术右移左边补 1，`while (x)` 永远不结束。
   ```c
   int v = (int)x;
   while (v) { count += v & 1; v >>= 1; }   // ❌ x >= 0x80000000 时死循环
   ```
2. **循环只到 31**：`for (i = 0; i < 31; i++)` 漏掉了最高位，示例 3 会输出 31。
3. **`x & x - 1` 的优先级**：`-` 比 `&` 优先级高，所以它碰巧等于 `x & (x - 1)`；但 `x & 1 == 0` 会被解析成 `x & (1 == 0)`，**位运算一律加括号**。
4. **SWAR 里少写了掩码**：第 2 步写成 `(x + (x >> 2)) & 0x33333333`，两个 2 位计数相加时会互相"串位"，结果错乱。只有第 3 步可以先加后与，因为单个 4 位组装得下 0~8。
5. **乘法溢出担心过度**：`x * 0x01010101u` 的高位会溢出，但**无符号乘法溢出是有定义的**（自动对 2³² 取模），我们只要最高字节，正好不受影响。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位检查 | O(32) | O(1) | ⭐ | 最容易写对 |
| `x & (x - 1)` 消 1 | O(1 的个数) | O(1) | ⭐⭐ | 面试最爱问，1 稀疏时最快 |
| 分组并行求和 | O(1) | O(1) | ⭐⭐⭐ | 无分支、耗时固定，适合中断等对时间敏感的场合 |

## 🔌 嵌入式实战

- **GCC 内建函数**：`__builtin_popcount(x)`。在带 `CNT`/`VCNT` 指令的 CPU 上会编译成一条指令；Cortex-M0/M3/M4 没有这条指令，编译器会调用一个软件函数（就是思路三那样的代码）。
- **查表法**：用 256 字节的表 `table[i]` 存好 0~255 中 1 的个数，32 位数拆成 4 个字节查 4 次相加。用 Flash 换速度，在 8 位单片机上很常见。
- **用途**：统计 ADC 扫描通道数、统计按键矩阵里同时按下了几个键（多于 2 个可能是"鬼键"）、计算两个数据的汉明距离 `popcount32(a ^ b)`（误码率统计）。

## 🔗 举一反三

- **9008. 判断 2 的幂**：2 的幂恰好只有一个 1，即 `x != 0 && (x & (x - 1)) == 0`。
- **9014. 奇偶校验位**：只关心 1 的个数是奇数还是偶数，即 `popcount32(x) & 1`，但还有更快的写法。
- **力扣 191. 位1的个数**、**力扣 338. 比特位计数**（`dp[i] = dp[i & (i - 1)] + 1`）。
- **思考题**：如果要统计一个 1KB 缓冲区里一共有多少个 1，怎样做最快？
