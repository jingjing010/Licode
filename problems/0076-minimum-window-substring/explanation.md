# 76. 最小覆盖子串 —— 小白详细题解

> 这是**可变长度滑动窗口**的"终极模板题"：右边界负责"找到一个可行解"，左边界负责"把可行解压到最短"。学会它，一大类"最短/最长子串"问题都能套用。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 在 `s` 里找一段**连续的**片段，要求 `t` 里的每个字符它都有（`t` 里某个字符出现几次，片段里就至少要有几次）。在所有满足要求的片段里，找**最短**的那个。

拿示例 1 `s = "ADOBECODEBANC", t = "ABC"` 来说，下面这些片段都包含 A、B、C：

| 片段 | 长度 |
|---|---|
| ADOBEC | 6 |
| DOBECODEBA | 10 |
| CODEBA | 6 |
| BANC | **4** |

最短的是 `"BANC"`。

**几个需要注意的细节：**

1. **重复字符要算个数**：示例 3 `t = "aa"`，片段里必须有**两个** a。`s = "a"` 只有一个，所以答案是 `""`。
2. **区分大小写**：`'a'` 和 `'A'` 是不同的字符。
3. 片段里可以有**多余的**字符，只要 t 需要的都够了就行（`"BANC"` 里的 N 就是多余的）。
4. 返回的是一个**新的字符串**，要 `malloc`，并且以 `'\0'` 结尾。没有答案时也要返回一个 `malloc` 出来的空串。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用字符当下标的计数数组

字母的 ASCII 码都小于 128，开一个 `int need[128]`，`need['A']` 就表示字符 A 还需要几个：

```c
int need[128] = {0};
for (int i = 0; t[i] != '\0'; i++) need[(int)t[i]]++;   // t = "ABC" → need['A'] = need['B'] = need['C'] = 1
```

### 2. 返回一段子串：`malloc` + `memcpy` + `'\0'`

```c
char* res = (char*)malloc(len + 1);   // 多 1 个字节放 '\0'
memcpy(res, s + start, len);          // 从 s[start] 开始复制 len 个字符
res[len] = '\0';                      // ⭐ 一定要手动加结尾
```

`s + start` 是指针运算，表示"从 `s` 的第 `start` 个字符开始的地址"。

### 3. 后置 `--` 的小技巧

```c
if (need[c]-- > 0) missing--;
```

等价于：

```c
if (need[c] > 0) missing--;   // 先用旧值判断
need[c]--;                    // 再减 1
```

## 💡 第三步：思路一 —— 枚举起点，向右扩展（最朴素）

### 思路

1. 枚举片段的起点 `i`。
2. 从 `i` 往右扩展终点 `j`，每加入一个字符就更新计数；用 `missing` 记录"t 里还有几个字符没凑齐"。
3. 一旦 `missing == 0`，`s[i..j]` 就是以 `i` 为起点的最短覆盖子串，和答案比较后**停止扩展**（再往右只会更长）。

### 代码

```c
// ❌ 会超时：m = 10^5 时最坏约 5×10^9 次操作，仅用于理解思路
char* minWindow(char* s, char* t) {
    int m = strlen(s);
    int bestL = 0, bestLen = -1;                // bestLen = -1 表示还没找到答案
    for (int i = 0; i < m; i++) {               // 1. 枚举起点
        int need[128] = {0};
        int missing = 0;
        for (int k = 0; t[k]; k++) { need[(int)t[k]]++; missing++; }
        for (int j = i; j < m; j++) {           // 2. 向右扩展
            if (need[(int)s[j]] > 0) missing--; // 这个字符正好是还缺的
            need[(int)s[j]]--;
            if (missing == 0) {                 // 3. 凑齐了
                if (bestLen < 0 || j - i + 1 < bestLen) {
                    bestLen = j - i + 1;
                    bestL = i;
                }
                break;                          // 再往右只会更长
            }
        }
    }
    if (bestLen < 0) bestLen = 0;
    char* res = (char*)malloc(bestLen + 1);
    memcpy(res, s + bestL, bestLen);
    res[bestLen] = '\0';
    return res;
}
```

### 复杂度分析

- **时间复杂度 O(m²)**：起点 m 个，每个起点最多扩展 m 步。m = 10⁵ 时会超时。
- **空间复杂度 O(Σ)**：Σ = 128 的计数数组。

问题在于：起点从 `i` 变成 `i+1` 时，终点又从头开始扩展，之前的工作全浪费了。

## 🚀 第四步：思路二 —— 滑动窗口（O(m + n)）

### 关键观察

设以 `i` 为起点的最短覆盖子串终点是 `j`。那么以 `i+1` 为起点时，终点一定 **≥ j**（少了一个字符，只可能需要更多）。

所以左右边界都**只往右走**，不需要回头——这就是滑动窗口。

### 思路

维护窗口 `s[left..r]` 和两个量：

- `need[c]`：字符 c **还需要**几个。初始是 t 中 c 的个数；字符进窗口时 `need[c]--`，出窗口时 `need[c]++`。
  - `need[c] > 0`：还缺 c；
  - `need[c] == 0`：c 刚好够；
  - `need[c] < 0`：c 多了（多余的可以扔掉）。
- `missing`：t 中还没凑齐的字符**总个数**。初始为 `strlen(t)`，`missing == 0` 就说明窗口覆盖了 t。

步骤：

1. **右边界 `r` 右移**，把 `s[r]` 放进窗口：如果 `need[s[r]] > 0`，说明它是"真正缺的"，`missing--`。然后 `need[s[r]]--`。
2. 如果 `missing > 0`，继续扩张。
3. 如果 `missing == 0`（覆盖了）：**收缩左边界**——只要 `need[s[left]] < 0`（左边这个字符是多余的），就把它扔掉、`left++`。
4. 此时 `s[left..r]` 是以 `r` 结尾的最短覆盖子串，更新答案。
5. 再把 `s[left]` 也扔掉（它是"刚好够"的，扔掉后就缺了，`missing++`），`left++`，回到第 1 步继续找下一个可行解。

### 手动模拟（示例 1：`s = "ADOBECODEBANC", t = "ABC"`）

只列出关键时刻：

| r | s[r] | 发生了什么 | 窗口 | missing | 答案 |
|---|---|---|---|---|---|
| 0 | A | A 是缺的 | A | 2 | |
| 3 | B | B 是缺的 | ADOB | 1 | |
| 5 | C | C 是缺的，凑齐！左边 A 不多余，不收缩 | **ADOBEC** | 0 | ADOBEC (6) |
| | | 扔掉 A，left = 1 | DOBEC | 1 | |
| 10 | A | A 是缺的，凑齐！收缩：D、O 多余，B 多余（后面还有一个 B），E 多余 | **CODEBA** | 0 | 6，不更新 |
| | | 扔掉 C，left = 6 | ODEBA | 1 | |
| 12 | C | C 是缺的，凑齐！收缩：O、D、E 多余 | **BANC** | 0 | **BANC (4)** |

最终答案 `"BANC"`。

### 代码

```c
char* minWindow(char* s, char* t) {
    // 1. 统计 t 中每个字符需要几个
    int need[128] = {0};
    int missing = 0;                         // 还缺的字符总个数
    for (int i = 0; t[i] != '\0'; i++) {
        need[(int)t[i]]++;
        missing++;
    }

    int bestL = 0, bestLen = -1;             // 最短答案的起点和长度，-1 表示还没找到
    int left = 0;                            // 窗口是 s[left..r]
    for (int r = 0; s[r] != '\0'; r++) {
        // 2. s[r] 进窗口：如果它是"还缺的"，缺口减一
        if (need[(int)s[r]] > 0) missing--;
        need[(int)s[r]]--;

        if (missing > 0) continue;           // 还没凑齐，继续扩张

        // 3. 凑齐了：把左边多余的字符（need < 0）扔掉
        while (need[(int)s[left]] < 0) {
            need[(int)s[left]]++;
            left++;
        }

        // 4. 现在 s[left..r] 是以 r 结尾的最短覆盖子串
        if (bestLen < 0 || r - left + 1 < bestLen) {
            bestLen = r - left + 1;
            bestL = left;
        }

        // 5. 再扔掉 s[left]（它是刚好够的那个），窗口变成"不覆盖"，继续找下一个
        need[(int)s[left]]++;
        missing++;
        left++;
    }

    // 6. 复制答案（没找到就返回空串）
    if (bestLen < 0) bestLen = 0;
    char* res = (char*)malloc(bestLen + 1);
    memcpy(res, s + bestL, bestLen);
    res[bestLen] = '\0';
    return res;
}
```

> ❓ **为什么第 3 步的 while 不会让 `left` 超过 `r`？** 刚刚让 `missing` 变成 0 的字符 `s[r]`，它的 `need` 从 1 变成了 0，也就是"刚好够"。左边界往右扔字符时，最晚走到位置 `r` 就会遇到它，`need[s[r]] == 0` 不满足 `< 0`，循环一定会停下。

> ❓ **为什么不用每次比较整个 `need` 数组来判断是否覆盖？** 有了 `missing`，判断"是否覆盖"只要 O(1)。`missing` 只在"真正缺的字符进来"和"刚好够的字符出去"时变化。

### 复杂度分析

- **时间复杂度 O(m + n)**：统计 t 用 O(n)；`r` 和 `left` 都只从左往右走一遍，各 O(m)。
- **空间复杂度 O(Σ)**：Σ = 128 的计数数组。

## ⚠️ 第五步：小白常见错误

1. **用"出现过没有"代替"出现几次"** → 示例 3 `s = "a", t = "aa"` 会错误地返回 `"a"`。重复字符必须计数。
2. **`missing` 的更新条件写错**：写成 `if (need[c] >= 0) missing--;`（在 `need[c]--` 之前判断）→ 多余的字符（`need[c] == 0` 时又来一个）也让 `missing` 减少，还没凑齐就以为凑齐了。正确的是"减之前 `> 0`"。
3. **返回的字符串忘了 `'\0'`** → `malloc` 出来的内存里是垃圾值，打印时会把后面的乱码一起输出。
4. **没找到答案时 `return NULL;` 或返回局部数组** → 题目要求返回空串 `""`。用 `malloc(1)` 放一个 `'\0'` 最稳。
5. **`need` 数组只开 26 个，用 `s[i] - 'a'` 做下标** → 本题有大写字母，`'A' - 'a'` 是负数，越界。直接开 128、用字符本身当下标。
6. **收缩后忘了更新答案就继续扩张，或者更新答案用了 `<=`** → 用 `<=` 会让后面同样长的窗口覆盖前面的答案；本题答案唯一不受影响，但写 `<` 能保证返回最靠左的那个。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 枚举起点 + 向右扩展 | O(m²) | O(Σ) | ⭐⭐ | 会超时，用来理解"覆盖"的判断 |
| 滑动窗口 + missing 计数 | O(m + n) | O(Σ) | ⭐⭐⭐ | 标准答案，必须掌握 |
