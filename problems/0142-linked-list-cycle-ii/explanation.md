# 142. 环形链表 II —— 小白详细题解

> 第 141 题只问"有没有环"，这道题要找出**环从哪里开始**。它是快慢指针最经典、也最需要一点数学推导的题目。别怕，推导只用到小学的"路程 = 速度 × 时间"。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 沿着 `next` 一直走，如果会走进一个"圈"，请返回**第一个进入圈的结点**（环的入口）；如果走到了 `NULL`，说明没有环，返回 `NULL`。

示例 1：`head = [3,2,0,-4], pos = 1`，尾结点 -4 的 `next` 指回下标 1 的结点 2：

```
3 -> 2 -> 0 -> -4
     ^          |
     +----------+
```

| 步数 | 0 | 1 | 2 | 3 | 4 | 5 | … |
|---|---|---|---|---|---|---|---|
| 走到的结点 | 3 | **2** | 0 | -4 | **2**（第二次来） | 0 | … |

第一个被"第二次走到"的结点是 2（下标 1），它就是环的入口，判题程序输出 `1`。

**几个需要注意的细节：**

1. 你要返回的是**结点指针**，不是下标。下标是判题程序帮你换算出来显示的。
2. `pos` **不会传给你的函数**，你只能拿到 `head`。
3. **不允许修改链表**：不能改 `val`，也不能改 `next`（判题程序会检查）。
4. 链表可能为空（`head == NULL`），这时返回 `NULL`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 返回结构体指针

```c
struct ListNode *detectCycle(struct ListNode *head)
```

返回值类型是 `struct ListNode *`，也就是"某个结点的地址"。直接 `return slow;` 就是把那个结点交出去；没有答案时 `return NULL;`。

### 2. 比较指针

```c
if (slow == fast)   // 指向同一个结点（地址相同）
```

和 `slow->val == fast->val`（值相同）完全不是一回事。链表里可能有很多值相同的结点。

### 3. 走两步之前的保护

```c
while (fast != NULL && fast->next != NULL) {
    fast = fast->next->next;
}
```

`&&` 有"短路"特性：左边为假时右边不执行，所以不会出现 `NULL->next` 导致崩溃。

---

## 💡 第三步：思路一 —— 标记走过的结点（最容易想到）

### 思路

"第一个被走到两次的结点就是入口"。所以只要**记住走过哪些结点**，每走到一个结点就查一下：之前来过吗？

C 语言没有现成的哈希表，但本题结点最多 10⁴ 个，可以用一个**指针数组**记录走过的结点，再每次线性查找……那是 O(n²)，10⁴ 的平方是 10⁸，有点慢。

更好的办法是自己写一个简单的哈希表：用**结点的地址**作为 key。地址本质上是一个整数，可以转成 `uintptr_t`（一种"能装下指针的无符号整数"）再算哈希。

### 手动模拟（示例 1）

| 走到 | 之前来过吗？ | 记录表 |
|---|---|---|
| 3 | 没有 | {3} |
| 2 | 没有 | {3, 2} |
| 0 | 没有 | {3, 2, 0} |
| -4 | 没有 | {3, 2, 0, -4} |
| 2 | **来过！** | 返回结点 2 |

### 代码

```c
#define HASH_SIZE 32768                  // 2 的幂，比结点数 10^4 大得多，冲突少

struct ListNode *detectCycle(struct ListNode *head) {
    // static：避免占用太多栈空间；每次调用要先清空
    static struct ListNode* table[HASH_SIZE];
    memset(table, 0, sizeof(table));     // 全部置为 NULL，表示"空格子"

    for (struct ListNode* p = head; p != NULL; p = p->next) {
        // 用结点地址算格子号（地址通常是 8 或 16 的倍数，右移几位让低位更分散）
        unsigned int h = (unsigned int)(((uintptr_t)p >> 4) * 2654435761u) & (HASH_SIZE - 1);
        while (table[h] != NULL) {       // 格子被占了：看看是不是 p 自己
            if (table[h] == p) {
                return p;                // 之前来过！它就是环的入口
            }
            h = (h + 1) & (HASH_SIZE - 1);   // 线性探测：看下一个格子
        }
        table[h] = p;                    // 第一次来，记下来
    }
    return NULL;                         // 走到了 NULL：没有环
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个结点最多处理一次，哈希查找平均 O(1)。
- **空间复杂度 O(n)**：哈希表记录了所有结点。

## 🚀 第四步：思路二 —— 快慢指针 + 数学推导（O(1) 空间）

### 第 1 阶段：判断有没有环（就是第 141 题）

慢指针 `slow` 每次走 1 步，快指针 `fast` 每次走 2 步。如果 `fast` 走到 `NULL` 就没有环；如果某时刻 `slow == fast`，就有环，并且它们相遇在环里的某个位置。

### 第 2 阶段：找入口 —— 推导

把链表分成三段：

```
head ---a--- 入口 ---b--- 相遇点
              ^              |
              +------c-------+
```

- `a`：从 `head` 到环入口的距离
- `b`：从入口到相遇点的距离
- `c`：从相遇点继续走回入口的距离
- 环长 `L = b + c`

相遇时：

- 慢指针走了 `a + b`（可以证明慢指针进环后**一圈之内**就会被追上）
- 快指针走了 `a + b + k·L`（比慢指针多绕了 k 圈，k ≥ 1）
- 快指针速度是慢指针的 2 倍，所以 **快的路程 = 2 × 慢的路程**：

```
a + b + k·L = 2(a + b)
        k·L = a + b
          a = k·L - b
          a = (k-1)·L + (L - b)
          a = (k-1)·L + c
```

最后这个式子的意思是：

> **从 `head` 走 `a` 步**，和**从相遇点走 `c` 步再绕 (k-1) 圈**，到达的是同一个地方——环的入口！

所以：相遇后，让一个指针 `p` 回到 `head`，`slow` 留在相遇点，两者**每次都走 1 步**，它们第一次相遇的地方就是入口。

### 手动模拟（示例 1：`[3,2,0,-4], pos = 1`，a = 1，L = 3）

第 1 阶段：

| 轮次 | slow | fast | 相遇？ |
|---|---|---|---|
| 开始 | 3 | 3 | （起点不算） |
| 1 | 2 | 0 | 否 |
| 2 | 0 | 2 | 否 |
| 3 | -4 | -4 | ✅ 相遇在 -4 |

第 2 阶段：

| 轮次 | p（从 head 出发） | slow（从相遇点出发） | 相遇？ |
|---|---|---|---|
| 开始 | 3 | -4 | 否 |
| 1 | 2 | 2 | ✅ 入口是结点 2 |

验证公式：b = 2（2→0→-4），c = 1（-4→2），a = 1 = c ✔。

### 代码

```c
struct ListNode *detectCycle(struct ListNode *head) {
    struct ListNode* slow = head;
    struct ListNode* fast = head;

    // 第 1 阶段：快慢指针判断是否有环
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;           // 慢指针走 1 步
        fast = fast->next->next;     // 快指针走 2 步
        if (slow == fast) {          // 相遇了：一定有环
            // 第 2 阶段：p 从 head 出发，slow 从相遇点出发，都每次走 1 步
            struct ListNode* p = head;
            while (p != slow) {
                p = p->next;
                slow = slow->next;
            }
            return p;                // 再次相遇的地方就是环的入口
        }
    }
    return NULL;                     // fast 走到了 NULL：没有环
}
```

### 复杂度分析

- **时间复杂度 O(n)**：第 1 阶段慢指针最多走 n 步，第 2 阶段最多走 a ≤ n 步。
- **空间复杂度 O(1)**：只用了三个指针。

## ⚠️ 第五步：小白常见错误

1. **先判断相遇再移动**：`slow` 和 `fast` 一开始都在 `head`，如果在循环开头判断 `slow == fast`，会立刻误以为相遇了。必须**先走再判断**。
2. **第 2 阶段让快指针继续走 2 步**：推导要求两个指针**速度相同**（都走 1 步），否则不会在入口相遇。
3. **把 `fast` 初始化为 `head->next`**：第 141 题这样写能判断有没有环，但本题的推导基于"两者同时从 `head` 出发"，起点错开一步后，第 2 阶段的相遇点就不是入口了。
4. **循环条件只写 `fast->next != NULL`**：空链表时 `fast` 本身就是 `NULL`，访问 `fast->next` 会崩溃。
5. **通过修改结点做标记**（比如把走过的结点 `val` 改成一个特殊值，或者把 `next` 改掉）：本题明确不允许修改链表，判题程序会检查出来。
6. **返回下标而不是指针**：函数返回类型是 `struct ListNode *`，返回 `1` 这种整数是错的。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 哈希表记录走过的结点 | O(n) | O(n) | ⭐⭐ | 思路直观，但 C 语言要自己写哈希表 |
| 快慢指针 + 推导 | O(n) | O(1) | ⭐⭐⭐ | **标准答案**，代码短，面试必考 |
