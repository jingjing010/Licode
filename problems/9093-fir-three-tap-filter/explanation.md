# 三抽头 FIR 低通滤波：题解

## 📖 先读懂题目

零初始历史，y[n]=trunc((x[n]+2x[n−1]+x[n−2])/4)，负数向零截断。输入int16范围，0到1000采样，返回整数滤波序列。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[4,4,4,0]` | `[1,3,4,3]` |
| 2 | `[8,0,0,0]` | `[2,4,2,0]` |

## 🧰 需要的 C 语言知识

数组形参是指针，不能用`sizeof(指针)`推算元素个数，要使用单独传入的长度。下标从0开始，最后一个有效下标是长度减1。

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

当前输入权重1，前一个权重2，再前一个权重1，权重和为4；只需保存两个历史采样。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *firThreeTap(int *samples, int samplesSize, int *returnSize) {
    int *out = malloc((samplesSize + 1) * sizeof(int)), p1 = 0, p2 = 0;
    for (int i = 0; i < samplesSize; ++i) {
        out[i] = (samples[i] + 2 * p1 + p2) / 4;
        p2 = p1;
        p1 = samples[i];
    }
    *returnSize = samplesSize;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，输出之外空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 循环写成`i <= 长度`，访问数组末尾之后的内存。
- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
