# 852. 山脉数组的峰顶索引 —— 小白详细题解

> 一座山，先一路上坡，到了山顶再一路下坡。找山顶在哪——这是"在**非有序**数组上二分"最直观的例子。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 数组先严格递增、再严格递减（像一座山），而且一定有上坡和下坡。返回最高点的**下标**。

拿示例 3 `arr = [0,10,5,2]` 来说：

| 下标 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 数值 | 0 | **10** | 5 | 2 |
| 坡度 | 上坡 → | 山顶 | ↘ 下坡 | ↘ |

山顶在下标 1。

**几个需要注意的细节：**

1. 返回的是**下标**，不是峰值本身。
2. 题目保证是山脉，所以峰顶**不会**是第一个或最后一个元素（`0 < i < n-1`）。
3. 严格递增/递减，没有相邻相等的情况。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 访问 `arr[mid + 1]` 前确保不越界

数组下标范围是 `0 ~ arrSize - 1`。比较 `arr[mid]` 和 `arr[mid + 1]` 时，必须保证 `mid + 1 <= arrSize - 1`。二分时如果 `mid < hi <= arrSize - 1`，就一定安全。

### 2. 中点写法

```c
int mid = lo + (hi - lo) / 2;   // 向下取整，lo <= mid < hi（当 lo < hi 时）
```

---

## 💡 第三步：思路一 —— 从左往右找第一个下坡

### 思路

从左往右走，第一次出现 `arr[i] > arr[i + 1]`（开始下坡），i 就是山顶。

### 手动模拟（`arr = [0,2,1,0]`）

| i | arr[i] | arr[i+1] | arr[i] > arr[i+1] ? |
|---|---|---|---|
| 0 | 0 | 2 | 否 |
| 1 | 2 | 1 | **是** → 返回 1 |

### 代码

```c
int peakIndexInMountainArray(int* arr, int arrSize) {
    for (int i = 0; i + 1 < arrSize; i++) {
        if (arr[i] > arr[i + 1]) {
            return i;            // 第一次开始下坡，i 就是山顶
        }
    }
    return arrSize - 1;          // 题目保证是山脉，不会走到这里
}
```

### 复杂度分析

- **时间复杂度 O(n)**：n ≤ 10⁵ 能过，但不满足题目 O(log n) 的要求。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（题目要求）

### 思路

山脉数组不是有序的，但它有一个**单调的性质**：

```
下标:            0   1   2   3   4   5   6
arr:             1   3   5   9   7   4   2
arr[i]<arr[i+1]: 是  是  是  否  否  否
                             ↑ 第一个"否"就是山顶
```

`arr[i] < arr[i+1]`（上坡）在山顶左边全是"是"，从山顶开始全是"否"。找**第一个"否"**——又是"找第一个满足条件的位置"模板！

- `arr[mid] < arr[mid + 1]`：mid 在上坡，山顶在 mid 右边：`lo = mid + 1`
- 否则 mid 在下坡（或就是山顶），山顶在 mid 或左边：`hi = mid`

### 区间定义与循环条件

- 区间：**闭区间 `[lo, hi]`**，含义"山顶一定在这里面"。因为山顶不会是两端，所以可以初始化 `lo = 1, hi = arrSize - 2`（用 `lo = 0, hi = arrSize - 1` 也对）。
- `while (lo < hi)`：`lo == hi` 时就是山顶。
- 不越界：`lo < hi` 时 `mid < hi <= arrSize - 2`，所以 `mid + 1 <= arrSize - 1`。
- `mid = lo + (hi - lo) / 2`。

### 手动模拟（`arr = [1,3,5,9,7,4,2]`）

| 轮次 | lo | hi | mid | arr[mid] | arr[mid+1] | 判断 | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 1 | 5 | 3 | 9 | 7 | 下坡 | hi = 3 |
| 2 | 1 | 3 | 2 | 5 | 9 | 上坡 | lo = 3 |
| 结束 | 3 | 3 | | | | | 返回 3 ✅ |

### 代码

```c
int peakIndexInMountainArray(int* arr, int arrSize) {
    int lo = 1;                  // 山顶不可能在两端，闭区间 [1, n-2]
    int hi = arrSize - 2;

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;    // mid < hi，arr[mid + 1] 不越界
        if (arr[mid] < arr[mid + 1]) {
            lo = mid + 1;        // 上坡：山顶在右边
        } else {
            hi = mid;            // 下坡：山顶是 mid 或在左边
        }
    }
    return lo;                   // lo == hi，就是山顶
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：10⁵ 个数最多约 17 轮。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **用 `while (lo <= hi)` 搭配 `hi = mid`** → `lo == hi` 时 hi 不变，死循环。
2. **下坡时写 `hi = mid - 1`** → mid 可能就是山顶，被排除了。比如 `[0,2,1,0]`，mid=1 是山顶，hi 变成 0 后就找不到了。
3. **和 `arr[mid - 1]` 比较却没检查 `mid > 0`** → 越界。统一和 `arr[mid + 1]` 比较并保证 `mid < hi` 最省心。
4. **返回 `arr[lo]`** → 题目要的是下标，不是峰值。
5. **以为"不有序就不能二分"** → 二分只需要"能根据 mid 判断答案在哪一边"，山脉数组的上坡/下坡就是这个判断依据。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 顺序扫描 | O(n) | O(1) | ⭐ | 最直观 |
| 二分查找 | O(log n) | O(1) | ⭐⭐ | 题目要求 |
