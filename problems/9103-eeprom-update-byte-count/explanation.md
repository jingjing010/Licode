# EEPROM 按需写入字节数：题解

## 📖 先读懂题目

同长度数据返回不同字节位置数，不同长度返回−1。长度0到1024，字节值0..255。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[1,2,3] / [1,9,3]` | `1` |
| 2 | `[0] / [255]` | `1` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

先比较再写入可减少EEPROM擦写次数；统计实际发生变化的字节位置即可。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int eepromChangedBytes(const uint8_t *before, size_t beforeSize, const uint8_t *after,
                       size_t afterSize) {
    if (beforeSize != afterSize)
        return -1;
    int count = 0;
    for (size_t i = 0; i < beforeSize; ++i)
        if (before[i] != after[i])
            ++count;
    return count;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。

## 🔗 举一反三

尝试把同一处理过程改成逐个输入的流式接口，思考需要保留哪些状态。用空边界、最小值、最大值和重复值检查自己的实现。
