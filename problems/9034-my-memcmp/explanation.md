# 9034. 实现 memcmp —— 小白详细题解

> `memcmp` 的逻辑和"查字典"一样：从第一个字母开始比，第一个不同的字母决定谁排前面。代码不难，但面试官真正想考的是：**你知不知道要按 `unsigned char` 比较？** 这一点写错，处理二进制数据时就会出现"200 小于 100"的怪事。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 两段内存从头开始逐字节比较，最多比 `n` 个。遇到第一个不同的字节，谁的字节值大谁就"大"；`n` 个都一样就是相等。

拿示例 1 来说（`a = [1,2,3]`，`b = [1,2,4]`，`n = 3`）：

| 下标 | 0 | 1 | 2 |
|---|---|---|---|
| a | 1 | 2 | **3** |
| b | 1 | 2 | **4** |
| 比较 | 相同 | 相同 | 3 < 4 → **负数** |

**几个需要注意的细节：**

1. 只看**正负**，不要求返回 `-1`/`1`。标准库很多实现返回的就是两个字节的差。
2. 字节按**无符号**解释（0 ~ 255），示例 3 中 200 > 100。
3. `memcmp` **不是字符串函数**：字节 0 只是普通的值，遇到它不会停（`a = [0,0,1]` 和 `b = [0,0,0]` 不相等）。
4. `n = 0` 时直接返回 0。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 有符号 `char` 的坑

`char` 到底有没有符号，C 标准没有规定：x86 上的 GCC 默认**有符号**（-128 ~ 127），ARM 上的 GCC 默认**无符号**（0 ~ 255）。

字节 `0xC8`（200）当成有符号 `char` 是 **-56**：

| 字节 | 当作 unsigned char | 当作 signed char |
|---|---|---|
| `0xC8` | 200 | **-56** |
| `0x64` | 100 | 100 |
| 比较结果 | 200 > 100 ✅ | -56 < 100 ❌ |

同一份代码在 PC 上和在单片机上结果不同——这是最难查的 bug 之一。所以**比较原始字节一律用 `unsigned char`**。

### 2. 用 `(int)a[i] - (int)b[i]` 当返回值

两个 `unsigned char` 的取值都在 0 ~ 255，相减的范围是 -255 ~ 255，`int` 完全装得下，而且正负正好表示大小关系。

> ⚠️ 这个技巧**不能**用在两个 `int` 上：`INT_MAX - (-1)` 会溢出。比较 `int` 要用 `(x > y) - (x < y)`。

### 3. `const void*`：两个参数都只读

比较不会修改内存，所以两个参数都是 `const void*`，转换时也要带上 `const`：

```c
const unsigned char* a = (const unsigned char*)s1;
```

---

## 💡 第三步：思路一 —— 逐字节比较（面试标准答案）

### 思路

1. 两个指针都转成 `const unsigned char*`
2. 下标 `i` 从 0 到 `n-1`，遇到 `a[i] != b[i]` 立刻返回 `a[i] - b[i]`
3. 循环正常结束说明前 `n` 个字节都相同，返回 0

### 手动模拟（示例 3：`a = [200,0]`，`b = [100,0]`，`n = 2`）

| i | a[i] | b[i] | 是否相同 | 动作 |
|---|---|---|---|---|
| 0 | 200 | 100 | 否 | 返回 200 - 100 = **100**（正数） |

判题程序把 100 规范化成 `1` 输出。

### 代码

```c
int my_memcmp(const void* s1, const void* s2, size_t n) {
    // 1. 按无符号字节访问，保留 const
    const unsigned char* a = (const unsigned char*)s1;
    const unsigned char* b = (const unsigned char*)s2;

    // 2. 逐字节比较，第一个不同的字节决定结果
    for (size_t i = 0; i < n; i++) {
        if (a[i] != b[i]) {
            return (int)a[i] - (int)b[i];   // 差值的正负就是大小关系
        }
    }
    // 3. 前 n 个字节全部相同
    return 0;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最坏情况比较 `n` 个字节；遇到不同的字节会提前结束。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 按字快速跳过相同部分（进阶）

### 思路

两段内存经常有很长的相同部分（比如比较两份配置，只有一个字段不同）。如果两个指针都 4 字节对齐，可以一次比较一个 `uint32_t`：

- 4 个字节**全部相同**：直接跳过，一次走 4 步
- **有不同**：退出按字比较，回到逐字节比较，找出具体是哪个字节不同

> ❓ 为什么"有不同"时不能直接比较两个 `uint32_t` 的大小？因为 x86 和大部分 ARM 是**小端**（低地址存低字节），`uint32_t` 的大小由**最高地址**的字节决定，而 memcmp 要求由**最低地址**的字节决定，两者顺序是反的。

### 代码

```c
int my_memcmp(const void* s1, const void* s2, size_t n) {
    const unsigned char* a = (const unsigned char*)s1;
    const unsigned char* b = (const unsigned char*)s2;

    // 1. 两个地址都 4 字节对齐时，先按字跳过相同的部分
    if ((((uintptr_t)a | (uintptr_t)b) & 3) == 0) {
        const uint32_t* wa = (const uint32_t*)a;
        const uint32_t* wb = (const uint32_t*)b;
        while (n >= 4 && *wa == *wb) {
            wa++;
            wb++;
            n -= 4;
        }
        a = (const unsigned char*)wa;
        b = (const unsigned char*)wb;
    }

    // 2. 剩下的部分（或者发现不同的那个字）逐字节比较
    for (size_t i = 0; i < n; i++) {
        if (a[i] != b[i]) return (int)a[i] - (int)b[i];
    }
    return 0;
}
```

### 复杂度分析

- **时间复杂度 O(n)**，相同部分的比较次数约为思路一的 1/4。
- **空间复杂度 O(1)**。

## 🔌 嵌入式实战：校验帧头与"常数时间比较"

```c
static const uint8_t HEADER[2] = {0xAA, 0x55};

if (memcmp(rx_buf, HEADER, sizeof(HEADER)) == 0) {
    // 帧头正确，开始解析
}
```

**安全场景要注意**：比较密码、HMAC、签名时，memcmp 一遇到不同就返回，攻击者可以通过**测量响应时间**逐字节猜出正确值（时序攻击）。安全代码会用"常数时间比较"，无论哪里不同都把 n 个字节比完：

```c
int secure_equal(const uint8_t* x, const uint8_t* y, size_t n) {
    uint8_t diff = 0;
    for (size_t i = 0; i < n; i++) diff |= x[i] ^ y[i];   // 不提前退出
    return diff == 0;
}
```

它只能判断"是否相等"，不能判断大小，所以不能替代 memcmp。

## ⚠️ 第五步：小白常见错误

1. **用 `char*` 比较**：

   ```c
   const char* a = (const char*)s1;   // ❌ x86 上 char 有符号，200 会被当成 -56
   ```

   示例 3 会输出 `-1`。
2. **遇到 0 就停**：把 memcmp 写成了 strcmp，`[0,0,1]` 和 `[0,0,0]` 会被判成相等。
3. **比完了不返回 0**：`for` 循环之后忘了 `return 0;`，函数返回一个随机值。
4. **只返回 -1/0/1 却写反了符号**：`return a[i] < b[i] ? 1 : -1;` 把大小关系弄反。用差值 `a[i] - b[i]` 最不容易出错。
5. **用 memcmp 比较结构体**：结构体里有**填充字节**（见 9043），内容是随机的，两个字段完全相同的结构体 memcmp 也可能不相等。要么先 `memset` 清零再赋值，要么逐字段比较。
6. **按字比较后直接比 `uint32_t` 大小**：小端机器上顺序是反的，结果可能错误。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐字节比较 | O(n) | O(1) | ⭐ | 面试标准答案 |
| 按字跳过相同部分 | O(n)，约快 4 倍 | O(1) | ⭐⭐ | 追问优化时回答，记得讲清大小端 |

> 🎯 **学习建议**：记住一句话——"**原始字节，unsigned char**"。memcmp、strcmp、校验和、CRC 都适用。
