# 230. 二叉搜索树中第 K 小的元素 —— 小白详细题解

> 一句话题解：**二叉搜索树的中序遍历是升序的**，第 k 个访问到的就是答案。这道题帮你把这个性质用熟。

---

## 📖 第一步：先读懂题目

给你一棵二叉搜索树（BST），找出所有结点值里**第 k 小**的那个（k 从 1 开始数）。

示例 2 `[5,3,6,2,4,null,null,1]`，`k = 3`：

```
        5
       / \
      3   6
     / \
    2   4
   /
  1
```

把所有值从小到大排好：

| 第几小 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 值 | 1 | 2 | **3** | 4 | 5 | 6 |

第 3 小是 `3`。

**几个需要注意的细节：**

1. k 从 **1** 开始，`k = 1` 是最小值，不是第二小。
2. 题目保证 `1 <= k <= n`，一定能找到。
3. BST 中左子树都比根小，右子树都比根大——这是能"不排序就知道顺序"的关键。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 在递归中共享计数器

递归找第 k 个时，需要一个"已经数到第几个了"的计数器，所有递归层共享。和之前一样，传它的**地址**：

```c
void dfs(struct TreeNode* node, int* k, int* ans);   // *k 表示还差几个
```

### 2. 用数组模拟栈

```c
stack[top++] = x;   // 压栈
x = stack[--top];   // 弹栈
```

---

## 💡 第三步：思路一 —— 递归中序遍历 + 计数

### 思路

1. 中序遍历（左 → 根 → 右）BST，访问顺序就是从小到大。
2. 每访问一个结点，`*k` 减 1；减到 0 时，当前结点就是第 k 小，记下答案。
3. 找到答案之后就不用再往下遍历了（`*k` 变成 0 以后直接返回）。

### 手动模拟（示例 2，k = 3）

| 访问顺序 | 结点 | 访问后 k | 是答案吗？ |
|---|---|---|---|
| 1 | 1 | 2 | 否 |
| 2 | 2 | 1 | 否 |
| 3 | 3 | 0 | **是，答案 3** |

后面的 4、5、6 不再访问。

### 代码

```c
// 中序遍历，*k 表示"还要再数几个"，数到 0 时把答案写进 *ans
void dfs(struct TreeNode* node, int* k, int* ans) {
    if (node == NULL || *k == 0) return;     // 空结点，或者已经找到答案了
    dfs(node->left, k, ans);                 // 1. 先数左子树（更小的数）
    if (*k == 0) return;                     //    左子树里已经找到了，直接返回
    (*k)--;                                  // 2. 数上自己
    if (*k == 0) {
        *ans = node->val;                    //    正好是第 k 个
        return;
    }
    dfs(node->right, k, ans);                // 3. 再数右子树
}

int kthSmallest(struct TreeNode* root, int k) {
    int ans = -1;
    dfs(root, &k, &ans);                     // 把 k 的地址传下去，所有递归层共享
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(h + k)**：先往左走到最小值（h 步），再数 k 个。最坏 O(n)。
- **空间复杂度 O(h)**：递归栈。

## 🚀 第四步：思路二 —— 迭代中序遍历（找到就停）

### 思路

和第 94 题的迭代中序遍历完全一样，只是每弹出一个结点就 `k--`，减到 0 立刻返回。用自己的栈，不怕递归太深。

### 代码

```c
int kthSmallest(struct TreeNode* root, int k) {
    // 结点最多 10^4 个，栈开这么大足够
    struct TreeNode** stack = (struct TreeNode**)malloc(sizeof(struct TreeNode*) * 10000);
    int top = 0;
    int ans = -1;
    struct TreeNode* cur = root;

    while (cur != NULL || top > 0) {
        while (cur != NULL) {            // 一路向左，把沿途结点压栈
            stack[top++] = cur;
            cur = cur->left;
        }
        cur = stack[--top];              // 弹出的是"当前最小的未访问结点"
        k--;
        if (k == 0) {                    // 第 k 个
            ans = cur->val;
            break;
        }
        cur = cur->right;                // 转向右子树
    }

    free(stack);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(h + k)**，**空间复杂度 O(h)**。

### 关于进阶问题

如果树经常被修改、又要频繁查询，可以在每个结点里额外记录**以它为根的子树结点数** `size`。查询时：设左子树有 `L` 个结点，若 `k <= L` 去左边找；若 `k == L + 1` 就是当前结点；否则去右边找第 `k - L - 1` 小。这样每次查询只需 O(h)。插入/删除时顺路更新 `size` 即可。

---

## ⚠️ 第五步：小白常见错误

1. **把 `k` 按值传给递归函数**：每层的 `k--` 都只改自己的副本，数不准。必须传 `int*`。
2. **从 0 开始数**：第 1 小对应"数到 1"，写成 `if (count == k - 1)` 之类时容易差一。
3. **找到后不停止**：思路一中如果找到答案后还继续遍历，`*k` 会变成负数，若判断条件写的是 `*k <= 0` 就会被后面的结点覆盖答案。
4. **先把整棵树存进数组再排序**：能过，但 O(n log n)，完全没利用 BST 的性质。
5. **栈开得太小**：链状树深度可达 10⁴，`struct TreeNode* stack[100]` 会越界。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 递归中序 + 计数 | O(h + k) | O(h) | ⭐⭐ | 理解中序 = 升序 |
| 迭代中序，找到即停 | O(h + k) | O(h) | ⭐⭐ | 面试推荐 |
| 结点记录子树大小 | 每次查询 O(h) | O(n) | ⭐⭐⭐ | 进阶：频繁修改和查询 |
