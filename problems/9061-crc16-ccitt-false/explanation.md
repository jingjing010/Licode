# CRC16 CCITT-FALSE：题解

## 📖 先读懂题目

计算CRC-16/CCITT-FALSE：poly=0x1021，init=0xFFFF，refin/refout=false，xorout=0。输入0到1024字节，返回0到65535。ASCII 123456789校验值为0x29B1。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[49,50,51,52,53,54,55,56,57]` | `10673` |
| 2 | `[]` | `65535` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

先把字节异或到CRC高8位，然后执行8次移位和条件异或。初值、反射方式和输出异或值都是协议参数。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
uint16_t crc16Ccitt(const uint8_t *data, size_t len) {
    uint16_t crc = 0xffff;
    for (size_t i = 0; i < len; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        /* 非反射算法：从最高位移出，生成多项式为0x1021。 */
        for (int bit = 0; bit < 8; ++bit)
            crc = (uint16_t)((crc & 0x8000) ? (crc << 1) ^ 0x1021 : crc << 1);
    }
    return crc;
}
```

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
