# 新手指南

欢迎使用 **C 语言刷题 OJ**！这是一个完全在你电脑上运行的练习平台，题目来自力扣（LeetCode），判题方式和力扣一样：**你只需要实现题目给出的函数**。

---

## 🚀 快速上手

1. 在 **题库** 里点开一道题（推荐从 `1. 两数之和` 开始）
2. 左边读题，右边的编辑器里已经写好了函数框架
3. 在函数体里写代码
4. 点 **▶ 运行**：只跑公开样例，能看到每个样例的输入、你的输出、预期输出
5. 样例都对了，点 **⬆ 提交**：跑全部隐藏测试点，全部通过就是 **Accepted** 🎉
6. 卡住了？看看题目下方的 **💡 提示**，或者切到 **题解** 标签页

| 快捷键 | 作用 |
|---|---|
| `Ctrl + Enter` | 运行样例 |
| `Ctrl + Shift + Enter` | 提交 |
| `Ctrl + /` | 注释 / 取消注释当前行（或选中的多行） |
| `Tab` / `Shift + Tab` | 缩进 / 取消缩进 |

> [!TIP]
> 代码会**自动保存**在浏览器里，关掉页面再打开也不会丢。想重新开始可以点编辑器上方的 **↺ 重置**，想留存代码可以点 **⤓ 导出** 下载成 `.c` 文件。

## ⚠️ 最重要的一条：不要写 `main` 函数

本 OJ 和力扣一样采用"**核心代码模式**"：

```c
// ✅ 正确：只写题目要求的函数
int* twoSum(int* nums, int numsSize, int target, int* returnSize) {
    ...
}
```

```c
// ❌ 错误：不要写 main，也不要自己用 scanf 读输入
int main() {
    int n;
    scanf("%d", &n);
    ...
}
```

系统会自动帮你：读取输入 → 调用你的函数 → 打印你的返回值。

另外：

- **不要修改函数签名**（函数名、参数、返回值类型），否则会编译错误
- 常用头文件已经自动包含了：`stdio.h`、`stdlib.h`、`string.h`、`stdbool.h`、`limits.h`、`math.h`、`ctype.h`、`stdint.h`，你写了也没关系
- 链表 / 二叉树题的 `struct ListNode` / `struct TreeNode` 已经定义好，**不要重复定义**
- 可以在函数外面写自己的辅助函数，但要写在**调用它的函数前面**

## 🐞 怎么调试？

想看中间变量的值，用 **`fprintf(stderr, ...)`**，不要用 `printf`：

```c
fprintf(stderr, "i = %d, sum = %d\n", i, sum);
```

- `stderr` 的内容会显示在运行结果的 **标准错误** 区域，**不影响判题**
- `printf` 会混进你的输出里，导致 **答案错误**

还可以使用 **自定义输入**：在"测试用例"里选 **自定义输入**，按题目描述末尾的"自定义输入格式"写好数据，勾选"运行时附带自定义输入"，再点运行。

## 📋 判题结果是什么意思？

| 结果 | 含义 | 常见原因 |
|---|---|---|
| **Accepted (AC)** | 通过 🎉 | — |
| **Wrong Answer (WA)** | 答案错误 | 思路有漏洞；没考虑空数组、负数、重复元素等边界情况；用 `printf` 打印了调试信息 |
| **Compilation Error (CE)** | 编译错误 | 语法错误；用了中文标点；写了 `main`；改了函数签名 |
| **Runtime Error (RE)** | 运行时崩溃 | 数组越界；对 `NULL` 指针使用了 `->` 或 `*`；除以 0；递归没有出口 |
| **Time Limit Exceeded (TLE)** | 超时 | 算法复杂度太高；死循环（比如忘了 `i++`） |
| **Output Limit Exceeded (OLE)** | 输出太多 | 在循环里疯狂打印 |

提交时测试点是**按顺序**跑的，遇到第一个没通过的就停下，并把那个测试点的输入、你的输出、预期输出展示给你。

> [!NOTE]
> 编译错误里形如 `solution.c:5:12` 的位置表示**你代码的第 5 行第 12 列**，点击它可以直接跳到编辑器对应的行。

## 📥 输入输出格式

和力扣一样，每个参数占一行：

| 类型 | 写法 |
|---|---|
| 整数 | `9` |
| 整数数组 | `[2,7,11,15]` |
| 二维数组 | `[[1,2],[3,4]]` |
| 字符串 | `"hello"` |
| 字符串数组 | `["ab","cd"]` |
| 布尔值 | `true` / `false` |
| 链表 | `[1,2,4]`（空链表写 `[]`） |
| 二叉树 | `[3,9,20,null,null,15,7]`（层序遍历，空位写 `null`） |

判题时会**忽略每行末尾的空格和最后的空行**。

## 🧠 力扣 C 语言的几个"潜规则"

### 1. `int* returnSize` 是干什么的？

函数要返回一个数组时，C 语言没法同时告诉调用者"这个数组有多长"，所以多了一个参数让你**写入长度**：

```c
*returnSize = 2;    // ✅ 改的是指针指向的变量
returnSize = 2;     // ❌ 改的是指针本身，调用者看不到
```

### 2. 返回的数组必须用 `malloc`

```c
int res[2];                                  // ❌ 局部数组，函数返回后就失效了
int* res = (int*)malloc(sizeof(int) * 2);    // ✅ 堆上的内存，返回后依然有效
```

### 3. 返回二维数组时还有 `int** returnColumnSizes`

它需要你 `malloc` 一个数组记录每一行的长度，然后写进 `*returnColumnSizes`。遇到这类题时，题目的"函数说明"里会详细解释。

### 4. 字符串以 `'\0'` 结尾

自己 `malloc` 字符串时，要多申请 1 个字节放 `'\0'`：

```c
char* s = (char*)malloc(len + 1);
s[len] = '\0';
```

## 🛠️ 环境问题

### 提示"未找到 gcc 编译器"

本 OJ 需要 gcc 编译你的代码。Windows 用户推荐安装 **MinGW-w64**（例如通过 MSYS2 或 Dev-C++ / Code::Blocks 自带的版本），安装后任选一种方式让 OJ 找到它：

1. 把 gcc 所在的 `bin` 目录加入系统环境变量 `PATH`（推荐）
2. 在项目根目录新建 `config.json`：

   ```json
   { "gcc": "C:\\mingw64\\bin\\gcc.exe" }
   ```

3. 设置环境变量 `OJ_GCC` 为 gcc 的完整路径

改完后重新启动 `server.py`。

### 第一次运行特别慢 / 超时

杀毒软件可能会扫描新生成的 exe。可以把项目文件夹加入杀毒软件的白名单。
