# 4. 寻找两个正序数组的中位数 —— 小白详细题解

> 这是力扣 Hot 100 里最有名的"困难"题之一。我们先用最直接的合并法拿下它，再一步步理解 O(log) 的"切分"二分法。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有两排已经从小到大排好的数，把它们**合在一起**看，最中间的那个数（或者中间两个数的平均值）是多少？

**中位数**：把所有数排好序后，

- 总个数是**奇数**：正中间那个，比如 `[1,2,3]` 的中位数是 2；
- 总个数是**偶数**：中间两个的平均，比如 `[1,2,3,4]` 的中位数是 `(2+3)/2 = 2.5`。

| 示例 | nums1 | nums2 | 合并后 | 中位数 |
|---|---|---|---|---|
| 1 | [1,3] | [2] | [1,2,**3**] → [1,**2**,3] | 2.00000 |
| 2 | [1,2] | [3,4] | [1,**2**,**3**,4] | 2.50000 |

**几个需要注意的细节：**

1. 其中一个数组可能是**空的**（长度 0）。
2. 返回值是 `double`。`(2 + 3) / 2` 在 C 里是整数除法，结果是 **2** 而不是 2.5！
3. 题目要求 `O(log(m+n))`，但 m、n ≤ 1000，O(m+n) 的做法也能通过，先把它写对。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 整数除法 vs 浮点除法

```c
int a = 2, b = 3;
double x = (a + b) / 2;        // ❌ 先算整数 5/2 = 2，再转成 2.0
double y = (a + b) / 2.0;      // ✅ 2.0 是 double，整个表达式按浮点算，得 2.5
```

只要除号两边**有一个是浮点数**，就会按浮点除法计算。

### 2. `INT_MIN` / `INT_MAX`

来自 `<limits.h>`（本 OJ 已自动包含），分别是 int 能表示的最小值和最大值。二分法里我们用它们当"哨兵"：表示"左边没有数了"就当作负无穷，"右边没有数了"就当作正无穷。

### 3. 三目运算符

```c
int l1 = (i == 0) ? INT_MIN : nums1[i - 1];
// 等价于：if (i == 0) l1 = INT_MIN; else l1 = nums1[i - 1];
```

## 💡 第三步：思路一 —— 双指针"走"到中间（最容易想到）

### 思路

像归并排序合并两个有序数组那样，用两个指针 `i`、`j` 每次取较小的那个数，但**不用真的存下来**，只要记住"刚刚取的数"和"上一次取的数"。总共取 `total/2 + 1` 次：

- 奇数个：最后一次取到的数就是中位数；
- 偶数个：最后两次取到的数的平均就是中位数。

### 手动模拟（示例 2：`nums1 = [1,2], nums2 = [3,4]`，total = 4，要取 3 次）

| 第几次 | i | j | 比较 | 取出 | prev | cur |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 1 < 3 | 1 | - | 1 |
| 2 | 1 | 0 | 2 < 3 | 2 | 1 | 2 |
| 3 | 2 | 0 | nums1 用完 | 3 | 2 | 3 |

偶数个，答案 `(prev + cur) / 2.0 = (2 + 3) / 2.0 = 2.5` ✅

### 代码

```c
double findMedianSortedArrays(int* nums1, int nums1Size, int* nums2, int nums2Size) {
    int total = nums1Size + nums2Size;
    int i = 0, j = 0;          // 两个数组各自的指针
    int prev = 0, cur = 0;     // 上一次取的数、这一次取的数
    for (int step = 0; step <= total / 2; step++) {
        prev = cur;
        // nums2 用完了，或者 nums1 还有且更小 → 取 nums1
        if (j >= nums2Size || (i < nums1Size && nums1[i] <= nums2[j])) {
            cur = nums1[i++];
        } else {
            cur = nums2[j++];
        }
    }
    if (total % 2 == 1) return cur;     // 奇数：正中间那个
    return (prev + cur) / 2.0;           // 偶数：注意除以 2.0
}
```

### 复杂度分析

- **时间复杂度 O(m+n)**：最多走 (m+n)/2 + 1 步。
- **空间复杂度 O(1)**：没有开新数组。

## 🚀 第四步：思路二 —— 在短数组上二分"切分位置"

### 思路

想象把两个数组各切一刀：

```
nums1:  [ ... nums1[i-1] | nums1[i] ... ]     左边拿 i 个
nums2:  [ ... nums2[j-1] | nums2[j] ... ]     左边拿 j 个
```

如果满足下面两个条件，那**左边这堆数**恰好是合并后的前一半：

1. 左边一共 `i + j = (m + n + 1) / 2` 个（奇数时左边多一个）；
2. 左边最大的数 ≤ 右边最小的数，即 `nums1[i-1] <= nums2[j]` **且** `nums2[j-1] <= nums1[i]`。

此时：

- 奇数个：中位数 = 左边最大值 `max(nums1[i-1], nums2[j-1])`；
- 偶数个：中位数 = (左边最大值 + 右边最小值 `min(nums1[i], nums2[j])`) / 2。

因为 `j` 由 `i` 决定，我们只需要在 `[0, m]` 上**二分 i**：

- `nums1[i-1] > nums2[j]`：nums1 左边拿多了 → i 往左（`hi = i - 1`）；
- `nums2[j-1] > nums1[i]`：nums1 左边拿少了 → i 往右（`lo = i + 1`）。

为了让 `j` 不会变成负数，**总是在较短的数组上二分**（长的放 nums2）。切到边界外的位置用 `INT_MIN` / `INT_MAX` 代替。

### 手动模拟（`nums1 = [1,3]`, `nums2 = [2]`，交换后 nums1 = [2], nums2 = [1,3]，half = 2）

| 轮次 | lo | hi | i | j | l1 | r1 | l2 | r2 | 判断 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 0 | 1 | 0 | 2 | -∞ | 2 | 3 | +∞ | l2=3 > r1=2，i 往右 |
| 2 | 1 | 1 | 1 | 1 | 2 | +∞ | 1 | 3 | 满足 ✅ |

总数 3 是奇数，答案 `max(l1, l2) = max(2, 1) = 2` ✅

### 代码

```c
double findMedianSortedArrays(int* nums1, int nums1Size, int* nums2, int nums2Size) {
    // 保证 nums1 是较短的那个，二分范围更小，j 也不会越界
    if (nums1Size > nums2Size) {
        return findMedianSortedArrays(nums2, nums2Size, nums1, nums1Size);
    }
    int m = nums1Size, n = nums2Size;
    int half = (m + n + 1) / 2;          // 左半部分应有的元素个数
    int lo = 0, hi = m;                  // i 的取值范围 [0, m]
    while (lo <= hi) {
        int i = lo + (hi - lo) / 2;      // nums1 左边拿 i 个
        int j = half - i;                // nums2 左边拿 j 个
        int l1 = (i == 0) ? INT_MIN : nums1[i - 1];   // 切口左右的 4 个数
        int r1 = (i == m) ? INT_MAX : nums1[i];
        int l2 = (j == 0) ? INT_MIN : nums2[j - 1];
        int r2 = (j == n) ? INT_MAX : nums2[j];
        if (l1 > r2) {
            hi = i - 1;                  // nums1 拿多了
        } else if (l2 > r1) {
            lo = i + 1;                  // nums1 拿少了
        } else {
            int leftMax = l1 > l2 ? l1 : l2;
            if ((m + n) % 2 == 1) return leftMax;
            int rightMin = r1 < r2 ? r1 : r2;
            return (leftMax + (double)rightMin) / 2.0;
        }
    }
    return 0.0;                          // 输入合法时不会走到这里
}
```

### 复杂度分析

- **时间复杂度 O(log(min(m, n)))**：只在短数组上二分。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **`(a + b) / 2` 整数除法** → 示例 2 会输出 `2.00000` 而不是 `2.50000`。要写 `/ 2.0`。
2. **不交换数组，在长数组上二分** → `j = half - i` 可能是负数，`nums2[j - 1]` 越界。
3. **边界不用哨兵**：`i == 0` 时还去读 `nums1[i - 1]`，即 `nums1[-1]` → 越界读到垃圾值。
4. **合并法里忘了某个数组已经用完**：`nums1[i] <= nums2[j]` 之前必须先判断 `i < nums1Size`、`j < nums2Size`，空数组时尤其容易错。
5. **真的 malloc 一个 m+n 的数组再 qsort** → 能过，但白白浪费了"已经有序"这个条件，复杂度 O((m+n)log(m+n))。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 合并后排序 | O((m+n)log(m+n)) | O(m+n) | ⭐ | 不推荐 |
| 双指针走到中间 | O(m+n) | O(1) | ⭐⭐ | 先写这个 |
| 二分切分位置 | O(log min(m,n)) | O(1) | ⭐⭐⭐⭐ | 题目要求，面试常考 |
