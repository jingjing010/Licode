# 9025. 实现 atoi（串口命令参数解析）—— 小白详细题解

> 把字符串变成整数，看起来简单，真正的难点在**边界**：空格、正负号、垃圾字符、以及最容易翻车的**溢出**。外部输入永远不可信，嵌入式里这类函数必须"什么输入都不崩、结果可预测"。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 从左往右扫：先跳过空格，再看有没有一个正负号，然后尽可能多地读数字，读到不是数字的字符就收工。太大就封顶，太小就封底。

拿示例 2 `"  -42mV"` 来说：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 字符 | `' '` | `' '` | `'-'` | `'4'` | `'2'` | `'m'` | `'V'` |
| 阶段 | 跳过空格 | 跳过空格 | 符号：负 | 数字 | 数字 | **停止** | 忽略 |

结果 `-42`。

**容易忽略的细节：**

| 输入 | 输出 | 原因 |
|---|---|---|
| `""` / `"   "` | 0 | 没有数字 |
| `"+-2"` | 0 | 只允许一个符号，`'-'` 不是数字 |
| `" + 5"` | 0 | 符号后面是空格，不是数字 |
| `"\t5"` | 0 | 只跳过空格，制表符不跳过 |
| `"2147483648"` | 2147483647 | 超过 `INT32_MAX`，饱和 |
| `"-2147483648"` | -2147483648 | 恰好是 `INT32_MIN`，合法 |
| `"99999999999999999999999"` | 2147483647 | 远超范围，也不能崩 |

## 🧰 第二步：需要的 C 语言知识

### 1. 用指针遍历字符串

```c
while (*s == ' ') s++;    // *s 是当前字符，s++ 指向下一个字符
```

`s` 是函数参数（指针的副本），移动它不会影响调用者。字符串结尾是 `'\0'`，它不是空格也不是数字，所有循环都会自然停在这里。

### 2. 数字字符转数值

`'0'~'9'` 的 ASCII 码连续（48~57），所以 `c - '0'` 就是这个数字的值。

### 3. ⭐ 有符号溢出是未定义行为

```c
int32_t v = 2147483647;
v = v * 10 + 8;    // ❌ 有符号溢出：未定义行为，结果可能是任何值
```

C 标准规定有符号整数溢出是**未定义行为（UB）**，编译器开了优化后甚至可能把你的溢出检查直接删掉。所以必须**在溢出发生之前**判断，或者用更宽的类型（`int64_t`）来计算。

### 4. `INT32_MAX` / `INT32_MIN`

来自 `<stdint.h>`：`INT32_MAX = 2147483647`，`INT32_MIN = -2147483648`。注意负数那边多一个：`-2147483648` 的绝对值 `2147483648` 放不进 `int32_t`。

## 💡 第三步：思路一 —— 用 int64_t 累加，再夹到范围内

### 思路

1. 跳过空格
2. 读符号
3. 在 `int64_t` 里累加绝对值；一旦超过 `2147483648` 就提前退出（否则 30 位数字连 `int64_t` 也会溢出）
4. 加上符号，再夹到 `[INT32_MIN, INT32_MAX]`

### 手动模拟（`"-2147483649"`）

| 阶段 | 读到 | v（绝对值） |
|---|---|---|
| 符号 | `'-'` | neg = 1 |
| 数字 ×10 次 | `2147483649` | 2147483649 > 2147483648，退出 |
| 加符号 | | −2147483649 |
| 夹范围 | 小于 `INT32_MIN` | **−2147483648** ✅ |

### 代码

```c
int32_t my_atoi(const char* s) {
    // 1. 跳过前导空格（只有空格）
    while (*s == ' ') s++;

    // 2. 可选的一个符号
    int neg = 0;
    if (*s == '+' || *s == '-') {
        neg = (*s == '-');
        s++;
    }

    // 3. 读数字，用 64 位保存，避免 32 位溢出
    int64_t v = 0;
    while (*s >= '0' && *s <= '9') {
        v = v * 10 + (*s - '0');
        if (v > 2147483648LL) break;    // 已经确定会饱和，没必要继续读
        s++;
    }

    // 4. 加符号并饱和
    if (neg) v = -v;
    if (v > INT32_MAX) return INT32_MAX;
    if (v < INT32_MIN) return INT32_MIN;
    return (int32_t)v;
}
```

### 复杂度分析

- **时间复杂度 O(n)**，**空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 只用 32 位，在乘 10 之前判断溢出

### 思路

有些 8/16 位单片机上 64 位运算很慢（甚至编译器支持得不好），可以只用 32 位无符号数，**在乘 10 加数字之前**判断会不会超过上限：

- 正数上限 `limit = 2147483647`，负数上限 `limit = 2147483648`（用 `uint32_t` 能放下）
- 如果 `v > (limit - d) / 10`，说明 `v * 10 + d > limit`，直接返回饱和值

### 手动模拟（`"2147483648"`，limit = 2147483647）

| 当前 v | 新数字 d | `(limit - d) / 10` | 判断 | 动作 |
|---|---|---|---|---|
| 214748364 | 8 | (2147483647 − 8) / 10 = 214748363 | 214748364 > 214748363 | 返回 2147483647 ✅ |

### 代码

```c
int32_t my_atoi(const char* s) {
    while (*s == ' ') s++;

    int neg = 0;
    if (*s == '+' || *s == '-') {
        neg = (*s == '-');
        s++;
    }

    // 正数最多 2147483647，负数绝对值最多 2147483648
    uint32_t limit = neg ? 2147483648u : 2147483647u;
    uint32_t v = 0;
    while (*s >= '0' && *s <= '9') {
        uint32_t d = (uint32_t)(*s - '0');
        if (v > (limit - d) / 10) {               // v * 10 + d 会超过 limit
            return neg ? INT32_MIN : INT32_MAX;   // 饱和
        }
        v = v * 10 + d;
        s++;
    }

    if (neg) {
        // v 最大 2147483648：先转成 int64_t 再取负，避免 -(int32_t)2147483648 溢出
        return (int32_t)(-(int64_t)v);
    }
    return (int32_t)v;
}
```

> 💬 判断写成 `v > (limit - d) / 10` 而不是 `v * 10 + d > limit`，是因为后者**本身就会溢出**，检查就失去了意义。"在运算之前，用除法把不等式变形"是防溢出的通用技巧。

## 🔌 嵌入式实战

一个简易命令解析器：

```c
// 收到 "SPEED -1500\r\n"
if (strncmp(line, "SPEED ", 6) == 0) {
    int32_t rpm = my_atoi(line + 6);              // 遇到 '\r' 自动停止 ...
    if (rpm < -3000 || rpm > 3000) {
        uart_puts("ERR: out of range\r\n");       // 业务层再做一次范围检查
    } else {
        motor_set_speed(rpm);
    }
}
```

本题的 `my_atoi` 有个局限：`"abc"` 和 `"0"` 都返回 0，调用者分不清"没有数字"和"数字就是 0"。真实项目里更好的接口是 `bool parse_int(const char* s, int32_t* out)`，用返回值表示成功与否。

## ⚠️ 第五步：小白常见错误

1. **用 `int32_t` 直接累加**：`"2147483648"` 时有符号溢出（UB），常见结果是变成负数 −2147483648。
2. **只用 `int64_t` 却不提前退出**：`"99999999999999999999999"`（23 位）连 `int64_t` 都会溢出。
3. **跳过了所有空白字符**：用 `isspace` 会把 `'\t'` 也跳过，与题目规则不符（`"\t5"` 应返回 0）。
4. **允许多个符号**：`"+-2"`、`"--5"` 应返回 0。
5. **符号后跳空格**：`" + 5"` 应返回 0，符号和数字之间不能有空格。
6. **负数边界**：`-(int32_t)2147483648u` 本身就是溢出；处理 `INT32_MIN` 要在更宽的类型里取负，或者直接返回 `INT32_MIN`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| int64_t 累加 + 提前退出 | O(n) | O(1) | 简单直观 |
| 32 位 + 运算前溢出判断 | O(n) | O(1) | 不依赖 64 位，适合小 MCU |
| 标准库 `atoi` | O(n) | O(1) | 溢出行为未定义，不推荐 |
