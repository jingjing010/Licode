# 124. 二叉树中的最大路径和 —— 小白详细题解

> Hot 100 里的树形"困难"题，但它和第 543 题（直径）几乎是同一个模板：**递归返回"单边"信息给父亲，同时在当前结点用"两边"信息更新答案**。难点在于负数的处理。

---

## 📖 第一步：先读懂题目

**路径**：沿着树边走，每个结点最多经过一次，至少包含 1 个结点；可以从任意结点开始、在任意结点结束，**可以拐弯**（比如 左孩子 → 父亲 → 右孩子）。
**路径和**：路径上所有结点值的和。求最大的路径和。

示例 2 `[-10,9,20,null,null,15,7]`：

```
  -10
  /  \
 9   20
    /  \
   15   7
```

| 路径 | 和 |
|---|---|
| 15 → 20 → 7 | **42** |
| 9 → -10 → 20 → 15 | 34 |
| 20 → 15 | 35 |
| 9 | 9 |

答案 `42`，这条路径**不经过根**。

**几个需要注意的细节：**

1. 路径不能"分叉"：一个结点往下最多只能选**一边**继续走（除非它是路径的最高点，可以两边都走）。
2. 结点值可能**全是负数**，比如 `[-1,-2,-3]`，答案是 `-1`（只选一个结点）。所以答案的初始值不能是 0。
3. 负数的子树"贡献"还不如不要：如果从某个孩子往下走的最大和是负的，就干脆不走那边。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `INT_MIN`

`<limits.h>` 中的 `INT_MIN` 是 `int` 能表示的最小值。用它作答案的初始值，第一次比较时一定会被真实的路径和替换掉。

### 2. 用指针参数在递归中维护"全局最优"

和第 543 题一样：递归函数的返回值留给父结点用，额外的"全局答案"通过 `int* best` 传进去修改。

### 3. 值的范围

最多 3×10⁴ 个结点、每个最多 1000，路径和最多 3×10⁷，`int` 放得下。

---

## 💡 第三步：思路一 —— 枚举最高点 + 单独计算单边最大和（会超时）

### 思路

任何路径都有一个**最高点**（离根最近的结点）`x`，路径 = 从 `x` 向左下走的一段 + `x` + 从 `x` 向右下走的一段（两段都可以为空）。

定义 `gain(node)`：从 `node` 出发，**只往下走、只能选一边**，能得到的最大路径和：

```
gain(node) = node->val + max(0, gain(左孩子), gain(右孩子))
```

（`max` 里的 0 表示"下面都不走"。）

那么以 `x` 为最高点的最大路径和 = `x->val + max(0, gain(x->left)) + max(0, gain(x->right))`。对每个结点都算一次，取最大值。

### 手动模拟（示例 2）

| 结点 | gain(左) | gain(右) | 以它为最高点 | gain(它) |
|---|---|---|---|---|
| 9 | 0 | 0 | 9 | 9 |
| 15 | 0 | 0 | 15 | 15 |
| 7 | 0 | 0 | 7 | 7 |
| 20 | 15 | 7 | 20 + 15 + 7 = **42** | 20 + 15 = 35 |
| -10 | 9 | 35 | -10 + 9 + 35 = 34 | 25 |

### 代码（思路正确，但大数据会超时）

```c
// ❌ 时间 O(n²)：每个结点都重新计算一遍子树的 gain，链状树 3×10^4 个结点会超时
int gain(struct TreeNode* node) {
    if (node == NULL) return 0;
    int l = gain(node->left), r = gain(node->right);
    int m = l > r ? l : r;
    if (m < 0) m = 0;                       // 下面都是负的，就不往下走
    return node->val + m;
}

void visit(struct TreeNode* node, int* best) {
    if (node == NULL) return;
    int l = gain(node->left), r = gain(node->right);   // 每次都重新算，很慢
    if (l < 0) l = 0;
    if (r < 0) r = 0;
    if (node->val + l + r > *best) *best = node->val + l + r;
    visit(node->left, best);
    visit(node->right, best);
}

int maxPathSum(struct TreeNode* root) {
    int best = INT_MIN;
    visit(root, &best);
    return best;
}
```

### 复杂度分析

- **时间复杂度 O(n²)**（最坏）：`visit` 每个结点都调用 `gain`，而 `gain` 又要遍历整棵子树。
- **空间复杂度 O(h)**。

---

## 🚀 第四步：思路二 —— 一次后序遍历（最优）

### 思路

思路一里，`gain` 被重复计算了很多遍。其实在计算 `gain(node)` 的过程中，我们**已经拿到了** `gain(左)` 和 `gain(右)`，正好可以顺手算出"以 `node` 为最高点的路径和"！

所以只写一个递归函数 `gain(node, &best)`：

1. 递归拿到左、右孩子的单边最大和 `l`、`r`，负数当 0（不选那边）。
2. **更新答案**：`node->val + l + r`（以 `node` 为最高点，两边都可以走）。
3. **返回给父亲**：`node->val + max(l, r)`（父亲要继续往上连，所以只能选一边）。

### 手动模拟（示例 1：`[1,2,3]`）

| 结点 | l | r | 以它为最高点 | best | 返回 |
|---|---|---|---|---|---|
| 2 | 0 | 0 | 2 | 2 | 2 |
| 3 | 0 | 0 | 3 | 3 | 3 |
| 1 | 2 | 3 | 1 + 2 + 3 = **6** | **6** | 4 |

### 代码

```c
// 返回：从 node 出发只往下走（只选一边）的最大路径和
// 顺便：用"以 node 为最高点"的路径和更新 *best
int gain(struct TreeNode* node, int* best) {
    if (node == NULL) return 0;               // 空结点贡献 0

    int l = gain(node->left, best);           // 左边往下最多能拿多少
    int r = gain(node->right, best);          // 右边往下最多能拿多少
    if (l < 0) l = 0;                         // 负贡献不如不要
    if (r < 0) r = 0;

    int through = node->val + l + r;          // 以 node 为最高点：左右两边都可以走
    if (through > *best) *best = through;

    return node->val + (l > r ? l : r);       // 往上交给父亲：只能选一边
}

int maxPathSum(struct TreeNode* root) {
    int best = INT_MIN;                       // 结点可能全为负数，不能初始化为 0
    gain(root, &best);
    return best;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个结点访问一次。
- **空间复杂度 O(h)**：递归栈。

---

## ⚠️ 第五步：小白常见错误

1. **`best` 初始化为 0**：`[-3]` 会输出 0，但正确答案是 -3（路径至少包含一个结点）。
2. **返回给父亲时把两边都加上**：`return node->val + l + r;` 这样往上连就"分叉"了，不是一条合法路径。
3. **没有把负的贡献截成 0**：`[2,-1]` 中，如果强行带上 -1，以 2 为最高点会算成 1，答案应该是 2。
4. **只考虑经过根的路径**：示例 2 的答案 42 就不经过根。
5. **把截断写在返回值上而不是孩子贡献上**：`return max(node->val + max(l, r), 0);` 看似等价，但若在更新 `best` 时也用了被截断的值，全负的树就会得到 0。最稳妥的写法是只截断"孩子贡献" `l`、`r`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 能否 AC |
|---|---|---|---|---|
| 枚举最高点 + 重复计算 gain | O(n²) | O(h) | ⭐⭐ | 大数据超时 |
| 一次后序遍历 | O(n) | O(h) | ⭐⭐⭐ | ✅ |
