固件升级（OTA / Bootloader）时，设备需要确认收到的固件镜像完整无误后才能跳转运行，最常用的手段就是 **CRC-32**。以太网帧、ZIP、PNG 也都用同一个算法（CRC-32/IEEE 802.3）。

请实现标准 CRC-32，参数如下：

| 参数 | 值 |
|---|---|
| 宽度 | 32 位 |
| 多项式 Poly | `0x04C11DB7`；因为输入反射，代码中使用按位倒序后的 `0xEDB88320` |
| 初值 Init | `0xFFFFFFFF` |
| 输入反射 RefIn | 是（每个字节从**最低位**开始处理） |
| 输出反射 RefOut | 是 |
| 结果异或 XorOut | `0xFFFFFFFF` |
| 标准校验值 Check | 字符串 `"123456789"` 的 CRC 为 `0xCBF43926`（十进制 3421780262） |

计算过程（逐位法）：`crc = 0xFFFFFFFF`；对每个字节 `b`，先 `crc ^= b`，再重复 8 次：如果 `crc` 的最低位为 1，则 `crc = (crc >> 1) ^ 0xEDB88320`，否则 `crc = crc >> 1`。处理完所有字节后，返回 `crc ^ 0xFFFFFFFF`。

给你一段数据 `buf`（长度 `len`），返回它的 CRC-32 值。

### 示例 1

```
输入：buf = [49,50,51,52,53,54,55,56,57]
输出：3421780262
解释：ASCII 字符串 "123456789" 的标准校验值 0xCBF43926 = 3421780262。
```

### 示例 2

```
输入：buf = [97]
输出：3904355907
解释：字符串 "a" 的 CRC-32 为 0xE8B7BE43 = 3904355907。
```

### 示例 3

```
输入：buf = []
输出：0
解释：没有数据，crc 保持初值 0xFFFFFFFF，最后异或 0xFFFFFFFF 得 0。
```

### 提示

- `0 <= len <= 2 * 10^5`
- `0 <= buf[i] <= 255`

### 函数说明

```c
uint32_t crc32(const uint8_t* buf, size_t len);
```

### 自定义输入格式

```
[49,50,51,52,53,54,55,56,57]
```

一行，数据的每个字节（十进制）。输出 CRC 值（十进制，无符号）。
