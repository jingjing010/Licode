# 201. 数字范围按位与 —— 小白详细题解

> 把一整段连续整数全部"与"起来。直接算会超时，关键是发现一个规律：**结果就是 `left` 和 `right` 二进制的公共前缀，后面补 0**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 算 `left & (left+1) & (left+2) & …… & right`。

拿示例 1（`left = 5, right = 7`）来说：

| 数 | 二进制 |
|---|---|
| 5 | 1 0 1 |
| 6 | 1 1 0 |
| 7 | 1 1 1 |
| **5 & 6 & 7** | **1 0 0** = 4 |

**几个需要注意的细节：**

1. **区间可以非常长**：示例 3 从 1 到 2147483647，一个个与要做 21 亿次，会超时。
2. **`&` 只会让 1 变少**：一个位只要在任何一个数里是 0，结果这一位就是 0。
3. `left == right` 时，答案就是它本身。
4. 循环变量要小心：`for (int i = left; i <= right; i++)` 当 `right = 2147483647` 时，`i++` 会溢出，**死循环**。

---

## 🧰 第二步：需要的 C 语言知识

### 1. 按位与 `&`

两个数的每一位分别做"与"：都是 1 才得 1。

### 2. 右移 `>>` 和左移 `<<`

- `x >> 1`：扔掉最低位，其余位整体右移；
- `x << k`：整体左移 `k` 位，右边补 `k` 个 0。

本题所有数都是非负数，`int` 的移位不会有符号问题。

### 3. `x & (x - 1)`：消掉最右边的 1

```
x           = 0110 1000
x - 1       = 0110 0111
x & (x - 1) = 0110 0000    ← 最右边的 1 没了
```

---

## 💡 第三步：思路一 —— 公共前缀（同时右移）

### 先看最笨的方法（会超时）

```c
// ❌ 区间长度可达 2^31，太慢；而且 right = INT_MAX 时 i++ 溢出
int res = left;
for (int i = left + 1; i <= right; i++) res &= i;
```

### 关键观察

把 `left` 和 `right` 写成二进制并左对齐，从最高位往下找到**第一个不同的位**：

```
left  = 1 0 1 | 0 1 1      (这里举例 43)
right = 1 0 1 | 1 0 0      (这里举例 44)
        ~~~~~   ↑ 第一个不同的位
        公共前缀
```

- 在这一位上，`left` 是 0，`right` 是 1。从 `left` 数到 `right` 的过程中，一定会经过 `1 0 1 | 1 0 0` 这个数（低位全 0），也一定经过 `1 0 1 | 0 1 1`（低位全 1）。
- 所以**这一位以及它右边的所有位**，在区间内都既出现过 0 也出现过 1，与起来全是 0。
- 而公共前缀部分，区间里所有数都一样，与起来保持不变。

**结论：答案 = 公共前缀 + 后面补 0。**

### 怎么求公共前缀？

把 `left` 和 `right` **同时右移**，直到两者相等，此时剩下的就是公共前缀；记住移了几次 `shift`，最后再左移回去。

### 手动模拟（示例 1：`left = 5, right = 7`）

| 第几次 | left | right | 相等吗 | shift |
|---|---|---|---|---|
| 初始 | 101 | 111 | 否 | 0 |
| 1 | 10 | 11 | 否 | 1 |
| 2 | 1 | 1 | **是** | 2 |

公共前缀是 `1`，左移 2 位得到 `100 = 4`。

### 代码

```c
int rangeBitwiseAnd(int left, int right) {
    int shift = 0;
    // 同时右移，直到两数相等，剩下的就是公共前缀
    while (left < right) {
        left >>= 1;
        right >>= 1;
        shift++;
    }
    // 把公共前缀移回原位，低位补 0
    return left << shift;
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：最多右移 31 次。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 不断消掉 right 最右边的 1

### 思路

公共前缀之后的位最终都是 0。另一种做法是：**不断把 `right` 最右边的 1 消掉**（`right &= right - 1`），直到 `right <= left`。

为什么对？

- 只要 `right > left`，`right` 最右边那个 1 一定落在"公共前缀之后"的区域（如果它在公共前缀里，`right` 后面全是 0 就不可能比 `left` 大）。消掉它只会去掉不属于答案的位。
- 当 `right <= left` 时，`right` 只剩下公共前缀部分（低位全 0），正是答案。

### 手动模拟（示例 1：`left = 5 = 101, right = 7 = 111`）

| 第几次 | right | right > left ? | right & (right - 1) |
|---|---|---|---|
| 1 | 111 | 是 | 110 |
| 2 | 110 | 是 | 100 |
| 3 | 100 = 4 | 否，停 | |

答案是 `4`。

### 代码

```c
int rangeBitwiseAnd(int left, int right) {
    // right 还比 left 大，说明最右边的 1 不属于公共前缀，消掉它
    while (left < right) {
        right &= right - 1;
    }
    return right;
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：每次消掉一个 1，最多 31 次。通常比思路一更少。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **暴力从 left 与到 right**：区间长度最大 2^31，超时；而且 `i <= right` 在 `right = INT_MAX` 时永远成立，`i++` 溢出变负数，死循环。
2. **以为答案就是 `left & right`**：示例 1 中 `5 & 7 = 5`，但正确答案是 4，因为中间的 6 把最低位与成了 0。
3. **思路二消错了数**：写成 `left &= left - 1`，消掉的是 `left` 的位，`left` 会越来越小，永远追不上 `right`，结果错误。
4. **思路一忘了左移回去**：直接返回公共前缀 `left`，示例 1 会输出 1 而不是 4。
5. **循环条件写成 `left != right` 并配合思路二**：`right` 消 1 后可能变得比 `left` 还小（比如 `left = 5, right = 8`，`8 & 7 = 0`），用 `!=` 的话 `right` 变成 0 后仍不等于 `left`，而 `0 & (0 - 1)` 还是 0，**死循环**。必须用 `left < right`。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 暴力逐个与（❌） | O(right - left) | O(1) | ⭐ | 会超时 |
| 公共前缀（同时右移） | O(log n) | O(1) | ⭐⭐ | 最好理解 |
| 消掉 right 的最低 1 | O(log n) | O(1) | ⭐⭐ | 代码最短 |
