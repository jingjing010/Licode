# 1. 两数之和 —— 小白详细题解

> 这是力扣的第 1 题，也是几乎所有人刷题的起点。别担心，我们从最笨的方法开始，一步一步来。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 给你一排数字，再给你一个目标数 `target`。请你从这排数字里**挑出两个**，让它们**加起来正好等于** `target`，然后告诉我这两个数字分别**排在第几个**（下标）。

拿示例 1 来说：

| 下标 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 数值 | 2 | 7 | 11 | 15 |

`target = 9`，我们发现 `2 + 7 = 9`，而 2 在下标 0，7 在下标 1，所以答案是 `[0, 1]`。

**几个需要注意的细节：**

1. 返回的是**下标**（位置），不是数值本身。答 `[2, 7]` 是错的！
2. "不能使用两次相同的元素" 指的是**同一个位置**不能用两次。比如 `nums = [3, 2, 4], target = 6`，你不能用下标 0 的 3 加它自己得到 6；但示例 3 `[3, 3]` 中两个 3 位置不同，是可以的。
3. 题目保证**一定有且只有一个答案**，所以不用考虑"找不到"的情况。

---

## 🧰 第二步：这道题需要的 C 语言知识

力扣的 C 语言题有一个让新手很困惑的地方——**函数签名**。我们把它拆开看：

```c
int* twoSum(int* nums, int numsSize, int target, int* returnSize)
```

| 部分 | 含义 |
|---|---|
| `int*`（最前面） | 函数返回一个"指向 int 的指针"，也就是**一个数组** |
| `int* nums` | 传进来的数组（数组名本质上就是首元素的地址） |
| `int numsSize` | 数组有多少个元素。C 语言的数组**不知道自己多长**，所以必须额外传长度 |
| `int target` | 目标和 |
| `int* returnSize` | ⭐ 重点！一个指针，你需要通过它**告诉调用者你返回的数组有多长** |

### ❓ 为什么需要 `returnSize`？

因为 C 语言函数只能返回一个值。我们返回了数组的地址，但调用者拿到地址后**不知道数组有多长**。所以力扣约定：你把长度写到 `*returnSize` 里。

```c
*returnSize = 2;   // 正确：修改指针指向的那个变量
returnSize = 2;    // 错误！这是把指针本身改成了 2，调用者完全看不到
```

### ❓ 为什么必须用 `malloc`？

```c
int* twoSum(...) {
    int res[2];        // ❌ 局部数组，函数结束后这块内存就被回收了
    return res;        //    返回它等于返回一个"已经拆掉的房子的地址"
}
```

```c
int* twoSum(...) {
    int* res = (int*)malloc(sizeof(int) * 2);   // ✅ 在堆上申请，函数结束后依然有效
    return res;
}
```

`malloc(sizeof(int) * 2)` 的意思是：申请能放下 2 个 `int` 的内存空间。

## 💡 第三步：思路一 —— 暴力枚举（最容易想到）

### 思路

既然要找两个数，那就把**所有可能的两两组合**都试一遍：

- 第一个数选下标 `i`，第二个数选下标 `j`
- 为了不重复、也不用同一个元素两次，让 `j` 总是从 `i + 1` 开始
- 如果 `nums[i] + nums[j] == target`，就找到答案了

### 手动模拟（示例 2：`nums = [3,2,4], target = 6`）

| 步骤 | i | j | nums[i] + nums[j] | 等于 6 吗？ |
|---|---|---|---|---|
| 1 | 0 | 1 | 3 + 2 = 5 | ❌ |
| 2 | 0 | 2 | 3 + 4 = 7 | ❌ |
| 3 | 1 | 2 | 2 + 4 = 6 | ✅ 返回 [1, 2] |

### 代码

```c
int* twoSum(int* nums, int numsSize, int target, int* returnSize) {
    // 1. 申请一个能放 2 个 int 的数组，用来存答案
    int* res = (int*)malloc(sizeof(int) * 2);
    *returnSize = 2;                         // 告诉调用者：我返回的数组长度是 2

    // 2. 外层循环：选第一个数
    for (int i = 0; i < numsSize; i++) {
        // 3. 内层循环：选第二个数，从 i+1 开始，避免重复使用同一个元素
        for (int j = i + 1; j < numsSize; j++) {
            if (nums[i] + nums[j] == target) {
                res[0] = i;
                res[1] = j;
                return res;                  // 找到了，直接返回
            }
        }
    }

    // 4. 题目保证有解，理论上不会走到这里；但 C 语言要求有返回值
    *returnSize = 0;
    return res;
}
```

### 复杂度分析

- **时间复杂度 O(n²)**：两层循环，最坏情况下要比较约 n²/2 次。n = 10⁴ 时大约 5000 万次，本题能过。
- **空间复杂度 O(1)**：只用了几个变量（返回数组不算）。

> 💬 **小白提示**：O(n²) 是什么意思？粗略地说，数据量 n 翻一倍，运行时间变成 4 倍。一般 OJ 每秒能跑约 10⁸ 次简单运算，你可以用这个估算会不会超时。

## 🚀 第四步：思路二 —— 哈希表（进阶，一遍扫描）

### 思路

暴力法慢在哪？对于每个 `nums[i]`，我们都要在后面**一个一个地找**有没有 `target - nums[i]`。

换个角度想：

> 遍历到 `nums[i]` 时，我需要的"另一半"是确定的：`need = target - nums[i]`。
> 如果我能**瞬间**知道 `need` 之前有没有出现过、在哪个下标，那一遍就够了！

能做到"瞬间查找"的数据结构就是**哈希表**。可惜 C 语言没有自带哈希表（不像 C++ 有 `unordered_map`、Python 有 `dict`），我们需要自己写一个简单版本。

### 哈希表是怎么工作的？（简化理解）

想象有一排很多很多个格子（一个大数组）：

1. **存**：想存数字 `x` 时，用一个公式（哈希函数）算出它该放进几号格子，比如 `x % 格子数`。
2. **查**：想找数字 `x` 时，用同一个公式算出格子号，直接去那个格子看。
3. **冲突**：两个不同的数可能算出同一个格子号。我们用最简单的办法：**这个格子被占了，就看下一个格子**（叫"线性探测"）。

### 手动模拟（示例 1：`nums = [2,7,11,15], target = 9`）

| i | nums[i] | need = 9 - nums[i] | 哈希表里有 need 吗？ | 操作 | 哈希表内容（值→下标） |
|---|---|---|---|---|---|
| 0 | 2 | 7 | 没有 | 把 2→0 存进去 | {2:0} |
| 1 | 7 | 2 | **有！下标 0** | 返回 [0, 1] | |

只看了两个数就找到了答案！

> ❓ **为什么"先查再存"？** 如果先存再查，当 `nums[i] * 2 == target` 时（比如 `[3,2,4]` 中的 3，target = 6），就会查到自己，错误地用了同一个元素两次。

### 代码

```c
#define HASH_SIZE 32768   // 格子数量：选 2 的幂（方便用 & 代替 %），且比元素个数大得多

int* twoSum(int* nums, int numsSize, int target, int* returnSize) {
    // static：放在静态区，不占用栈空间；每次调用需要手动清空 used
    static long long keys[HASH_SIZE];   // 格子里存的数值
    static int vals[HASH_SIZE];         // 这个数值对应的下标
    static bool used[HASH_SIZE];        // 这个格子有没有被占用
    memset(used, 0, sizeof(used));      // 全部标记为"空"

    int* res = (int*)malloc(sizeof(int) * 2);
    *returnSize = 2;

    for (int i = 0; i < numsSize; i++) {
        // 用 long long 防止 target - nums[i] 溢出（两者都可能达到 ±10^9）
        long long need = (long long)target - nums[i];

        // ===== 查找 need =====
        unsigned int h = (unsigned int)(need * 2654435761LL) & (HASH_SIZE - 1);  // 哈希函数
        while (used[h]) {                     // 只要格子非空就继续找
            if (keys[h] == need) {            // 找到了！
                res[0] = vals[h];
                res[1] = i;
                return res;
            }
            h = (h + 1) & (HASH_SIZE - 1);    // 被别人占了，看下一个格子（到末尾就绕回 0）
        }

        // ===== 没找到，把 nums[i] 存进去 =====
        h = (unsigned int)((long long)nums[i] * 2654435761LL) & (HASH_SIZE - 1);
        while (used[h] && keys[h] != nums[i]) h = (h + 1) & (HASH_SIZE - 1);
        used[h] = true;
        keys[h] = nums[i];
        vals[h] = i;
    }

    *returnSize = 0;
    return res;
}
```

**代码中几个可能看不懂的地方：**

- `& (HASH_SIZE - 1)`：当 `HASH_SIZE` 是 2 的幂时，`x & (HASH_SIZE - 1)` 等价于 `x % HASH_SIZE`，而且结果一定非负（负数取模在 C 里会得到负数，会导致数组越界！）。
- `2654435761`：一个常用的"魔法数"，乘上它能让数值在格子里分布得更均匀，减少冲突。你也可以先不深究，把它当成固定写法。
- `static`：如果写成普通局部数组 `long long keys[32768]`，会占用约 256KB 栈空间，有栈溢出风险。

### 复杂度分析

- **时间复杂度 O(n)**：每个元素只处理一次，哈希表查找平均 O(1)。
- **空间复杂度 O(n)**：哈希表存了最多 n 个元素。

> 这就是经典的 **"用空间换时间"**。

## ⚠️ 第五步：小白常见错误

1. **把 `*returnSize = 2` 写成 `returnSize = 2`** → 编译警告/错误，或者输出为空。
2. **返回局部数组** `int res[2]; return res;` → 结果是乱码或运行错误。
3. **内层循环 `j` 从 0 开始** → 可能出现 `i == j`，把同一个元素用了两次（比如 `[3,2,4]` 会错误地返回 `[0,0]`）。
4. **返回了数值而不是下标** → `res[0] = nums[i]` 是错的，应该是 `res[0] = i`。
5. **哈希值为负数导致越界** → 用 `%` 取模时，负数结果仍是负数，作为数组下标会崩溃（Runtime Error）。
6. **写了 `main` 函数** → 本 OJ 和力扣一样，只需要写函数，`main` 系统会提供。
