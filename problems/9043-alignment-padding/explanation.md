# 9043. 判断地址对齐并计算填充字节 —— 小白详细题解

> "`struct { char a; int b; char c; }` 的 `sizeof` 是多少？" 这是嵌入式面试的高频题，答案不是 6 而是 12。多出来的 6 个字节就是**填充字节**。这道题让你亲手写出编译器计算填充用的两个小工具，然后用它们推算结构体布局。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> - `is_aligned`：`addr` 能不能被 `align` 整除？
> - `align_padding`：`addr` 再往后走几步，才能走到下一个 `align` 的倍数？（已经是倍数就是 0 步）

拿示例 2 来说（`addr = 13`，`align = 4`）：

```
12  13  14  15  16
|   ↑           |
    addr        下一个 4 的倍数
    └── 走 3 步 ──┘
```

13 不是 4 的倍数 → `false`；走到 16 需要 3 步 → 填充 `3`。

**几个需要注意的细节：**

1. 已经对齐时填充是 **0**，不是 `align`（示例 1）。
2. 填充一定满足 `0 <= p < align`。
3. `align = 1` 时任何地址都对齐，填充永远是 0。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 结构体为什么会有填充字节？

编译器要保证结构体里**每个成员都按它自己的大小对齐**（`char` 1 字节、`short` 2 字节、`int`/`float` 4 字节、`double` 8 字节——这是常见 32/64 位平台的规则），这样 CPU 访问成员时不会出现非对齐访问（在 Cortex-M0 上非对齐访问会直接 HardFault）。

```c
struct A {
    char a;   // 偏移 0
              // 偏移 1~3：填充 3 字节，让 b 落在 4 的倍数上
    int  b;   // 偏移 4~7
    char c;   // 偏移 8
              // 偏移 9~11：尾部填充 3 字节，让整个结构体大小是 4 的倍数
};            // sizeof(struct A) == 12
```

用本题的函数来"当一回编译器"：

| 成员 | 当前偏移 | 成员对齐 | align_padding | 成员放在 | 放完后偏移 |
|---|---|---|---|---|---|
| `char a` | 0 | 1 | 0 | 0 | 1 |
| `int b` | 1 | 4 | **3** | 4 | 8 |
| `char c` | 8 | 1 | 0 | 8 | 9 |
| 尾部 | 9 | 4（最大成员对齐） | **3** | — | **12** |

**尾部填充**是为了让结构体数组 `struct A arr[2]` 中的 `arr[1].b` 仍然对齐。

> 💡 **优化技巧**：把成员按大小从大到小排列，`struct B { int b; char a; char c; }` 的大小就只有 8。在 RAM 只有几 KB 的 MCU 上，这能省下不少内存。

### 2. `addr & (align - 1)` 就是 `addr % align`

`align` 是 2 的幂时，`align - 1` 是一个低位全 1 的掩码，`&` 运算只保留低位，正好就是除以 `align` 的余数：

| addr | 二进制 | & (4 - 1) = & 0b11 | 余数 |
|---|---|---|---|
| 12 | `0b1100` | `0b00` | 0 → 对齐 |
| 13 | `0b1101` | `0b01` | 1 → 不对齐 |

### 3. 无符号数的"取负"

对无符号数 `x`，`0 - x`（或 `-x`）不会得到负数，而是**回绕**成 `2^N - x`（N 是位数）。这个特性正好可以用来算填充，见思路二。

---

## 💡 第三步：思路一 —— 余数法（最直观）

### 思路

1. 求余数 `r = addr % align`
2. `is_aligned`：`r == 0`
3. `align_padding`：`r == 0` 时为 0，否则为 `align - r`

### 手动模拟（示例 3：`addr = 0x20000001`，`align = 8`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| 余数 | `0x20000001 % 8` | 1 |
| 是否对齐 | `1 == 0`？ | `false` |
| 填充 | `8 - 1` | 7 |

### 代码

```c
bool is_aligned(uintptr_t addr, size_t align) {
    // 能被 align 整除就是对齐的
    return addr % align == 0;
}

size_t align_padding(uintptr_t addr, size_t align) {
    size_t r = (size_t)(addr % align);   // 超出上一个对齐地址多少
    if (r == 0) {
        return 0;                        // 已经对齐，不需要填充
    }
    return align - r;                    // 还差多少走到下一个对齐地址
}
```

### 复杂度分析

- **时间复杂度 O(1)**，但 `%` 需要除法，在没有硬件除法器的 Cortex-M0 上很慢。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 位运算（无分支）

### 思路

- **是否对齐**：`(addr & (align - 1)) == 0`
- **填充字节**：`(0 - addr) & (align - 1)`

第二个公式为什么对？`0 - addr` 在无符号运算里等于 `2^N - addr`。因为 `2^N` 是 `align` 的倍数，所以：

```
(2^N - addr) % align  ==  (-addr) % align  ==  "addr 离下一个 align 倍数的距离"
```

而 `% align` 又可以换成 `& (align - 1)`。当 `addr` 已经对齐时，`0 - addr` 也是 `align` 的倍数，结果是 0——**不需要 if 判断**。

### 手动模拟（示例 2：`addr = 13`，`align = 4`，以 8 位为例）

| 步骤 | 二进制 | 十进制 |
|---|---|---|
| addr | `00001101` | 13 |
| 0 - addr | `11110011` | 243 = 256 - 13 |
| & (4 - 1) = & `00000011` | `00000011` | **3** ✅ |

### 代码

```c
bool is_aligned(uintptr_t addr, size_t align) {
    // align - 1 是低位全 1 的掩码；低位全为 0 说明是 align 的倍数
    return (addr & (align - 1)) == 0;
}

size_t align_padding(uintptr_t addr, size_t align) {
    // 无符号取负：0 - addr == 2^N - addr，再取低位，就是到下一个对齐地址的距离
    // addr 已经对齐时结果自然是 0，不需要分支
    return (size_t)((0 - addr) & (align - 1));
}
```

> 💬 另一个常见写法是 `align_up(addr, align) - addr`，借用 9042 的向上对齐函数，意思更直白。

### 复杂度分析

- **时间复杂度 O(1)**：几条单周期指令，没有分支（对 CPU 流水线友好）。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **已经对齐时返回了 `align`**：直接写 `return align - addr % align;`，示例 1 会返回 4 而不是 0。
2. **用有符号数取负**：

   ```c
   int a = 13;
   return -a & 3;   // ❌ 在补码机器上碰巧也是 3，但 addr 超过 INT_MAX 时 int 存不下
   ```

   地址统一用 `uintptr_t`，无符号取负是标准定义好的行为。
3. **忘记括号**：`addr & align - 1 == 0` 中 `==` 和 `-` 的优先级都比 `&` 高，实际计算的是 `addr & ((align - 1) == 0)`，结果完全错误。位运算一定要加括号：`(addr & (align - 1)) == 0`。
4. **`align` 不是 2 的幂时用了位运算**：比如 `align = 6`，`addr & 5` 根本不是余数。
5. **以为 `sizeof(struct)` 等于成员大小之和**：`struct { char a; int b; char c; }` 是 12 不是 6，用 `memcpy` 把结构体直接发到串口时，填充字节也会被发出去（而且内容不确定）。
6. **滥用 `__attribute__((packed))`**：去掉填充后成员可能非对齐，在 Cortex-M0 上通过指针访问 `&s.b` 会 HardFault。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 适用范围 | 建议 |
|---|---|---|---|---|
| 余数法 | O(1)，需要除法 | O(1) | 任意 align | 直观，适合理解 |
| 位运算 | O(1)，无分支 | O(1) | align 为 2 的幂 | 工程常用 |

> 🎯 **学习建议**：拿几个结构体，用本题的 `align_padding` 手算一遍偏移和 `sizeof`，再用 `printf("%d", (int)sizeof(struct A))` 和 `offsetof` 验证。

## 🔗 举一反三

- **9042. 地址对齐 align_up / align_down**：`align_padding(addr, a) == align_up(addr, a) - addr`。
- **`offsetof(type, member)`**（`<stddef.h>`）：获取成员在结构体中的偏移。试着推算 `struct { char a; double d; short s; }` 的每个成员偏移和总大小，再用 `offsetof` 验证。
- **通信协议打包**：协议帧通常是紧凑排列的（没有填充），所以不要直接把结构体 `memcpy` 到发送缓冲区，而是逐字段写入，或者使用 `packed` 并注意访问方式。
- **思考题**：如果要写一个"简易内存分配器"，每次分配的大小都向上对齐到 8 字节，为什么可以用 `(size + 7) & ~7`？这和 `align_padding` 有什么关系？
