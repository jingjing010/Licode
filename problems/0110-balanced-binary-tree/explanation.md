# 110. 平衡二叉树 —— 小白详细题解

> 这道题是"自底向上递归"的经典练习：让一个函数**同时**返回两种信息（高度 + 是否平衡），把 O(n²) 优化成 O(n)。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 对树里的**每一个**结点，看它的左子树有多高、右子树有多高，两边差距不能超过 1。全部满足才算平衡。

高度 = 从这个结点往下走到最远叶子，经过的结点个数；空树高度为 0。

示例 2：`[1,2,2,3,3,null,null,4,4]`

```
          1
         / \
        2   2
       / \
      3   3
     / \
    4   4
```

| 结点 | 左子树高度 | 右子树高度 | 差 | 平衡吗 |
|---|---|---|---|---|
| 4（两个） | 0 | 0 | 0 | ✅ |
| 3（下面挂 4 的） | 1 | 1 | 0 | ✅ |
| 2（左边那个） | 2 | 1 | 1 | ✅ |
| 2（右边那个） | 0 | 0 | 0 | ✅ |
| 1（根） | 3 | 1 | **2** | ❌ |

根结点不平衡，所以答案是 `false`。

**几个需要注意的细节：**

1. 要求的是**每个结点**都平衡，不只是根。比如 `[1,2,2,3,null,null,3,4,null,null,4]`：根的左右高度都是 3，根是平衡的，但下面的结点 2 左边高 2、右边高 0，所以整棵树**不平衡**。
2. 空树是平衡的，返回 `true`。
3. 结点最多 5000 个，可能是一条链，递归深度最多 5000，没问题。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 递归求高度

```c
int height(struct TreeNode* node) {
    if (node == NULL) return 0;
    int l = height(node->left);
    int r = height(node->right);
    return (l > r ? l : r) + 1;
}
```

这就是第 104 题"最大深度"。

### 2. 绝对值

`abs(x)` 在 `<stdlib.h>` 里（本 OJ 已包含）。也可以直接写 `l - r > 1 || r - l > 1`，不用函数。

### 3. 用"特殊返回值"传递额外信息

高度永远 ≥ 0，所以可以约定**返回 -1 表示"这棵子树不平衡"**。这样一个 `int` 就带了两种信息，不用额外开变量或指针。

### 4. `static` 辅助函数

写在题目函数外面的辅助函数，前面加 `static` 表示"只在这个文件里用"，是个好习惯，可以避免和别的函数重名。

## 💡 第三步：思路一 —— 自顶向下（直接按定义）

### 思路

把定义原样翻译：一棵树平衡，当且仅当

1. 根结点左右子树高度差 ≤ 1；
2. 左子树平衡；
3. 右子树平衡。

求高度用第 104 题的函数。

### 手动模拟（示例 1：`[3,9,20,null,null,15,7]`）

| 检查的结点 | height(左) | height(右) | 差 ≤ 1 吗 |
|---|---|---|---|
| 3 | 1（9） | 2（20） | ✅ |
| 9 | 0 | 0 | ✅ |
| 20 | 1（15） | 1（7） | ✅ |
| 15、7 | 0 | 0 | ✅ |

全部满足，返回 `true`。

### 代码

```c
// 求以 node 为根的子树高度
static int height(struct TreeNode* node) {
    if (node == NULL) return 0;
    int l = height(node->left);
    int r = height(node->right);
    return (l > r ? l : r) + 1;
}

bool isBalanced(struct TreeNode* root) {
    if (root == NULL) return true;                    // 空树平衡
    int l = height(root->left);
    int r = height(root->right);
    if (l - r > 1 || r - l > 1) return false;         // 根本身不平衡
    return isBalanced(root->left) && isBalanced(root->right);   // 左右子树也都要平衡
}
```

### 复杂度分析

- **时间复杂度 O(n²)**（最坏）：每个结点都会调用一次 `height`，而 `height` 要走遍整棵子树。一条链时，深度为 d 的结点的 `height` 会被计算 d 次。
  不过链状的树在根结点就会被判为不平衡并立刻返回，实际上平衡的树高度是 O(log n)，所以这个方法通常是 O(n log n)。
- **空间复杂度 O(h)**：递归栈。

## 🚀 第四步：思路二 —— 自底向上（一边求高度一边检查）

### 思路

思路一的浪费在于：`isBalanced(root)` 算了一遍左子树高度，接着 `isBalanced(root->left)` 又把左子树下面的高度**重新算一遍**。

改进：只写一个函数 `height`，从下往上算，**算高度的同时检查平衡**：

1. 空树返回 0。
2. 先拿左子树的结果 `l`，如果是 -1（左子树已经不平衡）直接返回 -1。
3. 再拿右子树的结果 `r`，同理。
4. 如果 `|l - r| > 1`，当前结点不平衡，返回 -1。
5. 否则返回真正的高度 `max(l, r) + 1`。

最后看根的结果是不是 -1 就行。每个结点只被访问一次。

### 手动模拟（示例 2）

从下往上：

| 结点 | l | r | 返回 |
|---|---|---|---|
| 4、4 | 0 | 0 | 1 |
| 3（左下） | 1 | 1 | 2 |
| 3（右边那个叶子） | 0 | 0 | 1 |
| 2（左） | 2 | 1 | 3 |
| 2（右） | 0 | 0 | 1 |
| 1（根） | 3 | 1 | 差为 2 → **-1** |

根返回 -1，答案 `false`。

### 代码

```c
// 返回子树高度；如果子树不平衡，返回 -1
static int height(struct TreeNode* node) {
    if (node == NULL) return 0;
    int l = height(node->left);
    if (l < 0) return -1;                    // 左子树不平衡，没必要再算了
    int r = height(node->right);
    if (r < 0) return -1;                    // 右子树不平衡
    if (l - r > 1 || r - l > 1) return -1;   // 当前结点不平衡
    return (l > r ? l : r) + 1;              // 平衡：返回真实高度
}

bool isBalanced(struct TreeNode* root) {
    return height(root) >= 0;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个结点只访问一次。
- **空间复杂度 O(h)**：递归栈深度。

## ⚠️ 第五步：小白常见错误

1. **只检查了根结点**：
   ```c
   bool isBalanced(struct TreeNode* root) {   // ❌
       if (root == NULL) return true;
       int l = height(root->left), r = height(root->right);
       return l - r <= 1 && r - l <= 1;       // 没有检查下面的结点
   }
   ```
   `[1,2,2,3,null,null,3,4,null,null,4]` 会被误判为 `true`。
2. **用"最深叶子 - 最浅叶子 ≤ 1"来判断**：这是另一个更严格的概念。例如每个结点都是"左子树比右子树高 1"的最瘦平衡树，最深和最浅的叶子可以差好几层，但它仍然是平衡的。一定要按定义比较**每个结点左右子树的高度**。
3. **在自底向上写法里忘了传递 -1**：只在当前结点不平衡时返回 -1，但没检查 `l < 0`、`r < 0`，结果下面子树的 -1 被当成高度参与比较（比如 `l = -1, r = 0`，差为 1，又被当成平衡了）。
4. **空树返回 false**：题目示例 3 明确空树是平衡的。
5. **差值写成 `l - r > 1`** 忘了另一个方向：右子树比左子树高很多时检测不出来。用 `abs(l - r) > 1` 或两个方向都写。

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 自顶向下 | O(n²)（最坏） | O(h) | ⭐ | 直接按定义写，好理解 |
| 自底向上（-1 标记） | O(n) | O(h) | ⭐⭐ | **首选**，面试标准答案 |
