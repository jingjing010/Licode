# 235. 二叉搜索树的最近公共祖先 —— 小白详细题解

> 一句话题解：**从根往下走，p、q 都小就往左，都大就往右，一旦"分道扬镳"，当前结点就是答案。** 这是 BST 的大小关系带来的"免费午餐"。

---

## 📖 第一步：先读懂题目

**祖先**：从根走到某个结点，沿途经过的所有结点（**包括它自己**）。
**最近公共祖先（LCA）**：同时是 p、q 祖先的结点里，离根最远的那个。

示例树（BST：左子树都比根小，右子树都比根大）：

```
          6
        /   \
       2     8
      / \   / \
     0   4 7   9
        / \
       3   5
```

| p | q | p 的祖先 | q 的祖先 | 最近公共祖先 |
|---|---|---|---|---|
| 2 | 8 | 6, 2 | 6, 8 | **6** |
| 2 | 4 | 6, 2 | 6, 2, 4 | **2**（自己也是自己的祖先） |
| 3 | 5 | 6, 2, 4, 3 | 6, 2, 4, 5 | **4** |

**几个需要注意的细节：**

1. `p`、`q` 是**结点指针**，取值要写 `p->val`。
2. 一个结点可以是自己的祖先，所以 p 是 q 的祖先时，答案就是 p。
3. 结点最多 10⁵ 个，树可能退化成一条链，深度可达 10⁵。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 通过指针访问成员

`p` 的类型是 `struct TreeNode*`，读它的值用箭头：`p->val`，等价于 `(*p).val`。

### 2. 返回指针

函数返回 `struct TreeNode*`，直接 `return cur;` 返回树中某个结点的地址即可，不需要 `malloc` 新结点。

### 3. 用 `while` 代替递归

"每一步只往一个方向走"的递归（尾递归）都可以改成 `while` 循环：用一个变量 `cur` 表示当前位置，每轮决定 `cur = cur->left` 还是 `cur = cur->right`。这样不占用递归栈，链很深也不怕。

---

## 💡 第三步：思路一 —— 当成普通二叉树（第 236 题的做法）

### 思路

完全不管 BST 的性质，用第 236 题的递归：

1. `root` 为空，或者 `root` 就是 p 或 q，返回 `root`。
2. 分别在左、右子树里找，得到 `l`、`r`。
3. `l`、`r` 都非空：p、q 分在两边，`root` 就是 LCA；否则返回非空的那一个。

### 手动模拟（p = 2, q = 4）

| 调用 | 结果 | 原因 |
|---|---|---|
| LCA(2) | 返回 2 | 2 就是 p |
| LCA(8) | 左右都返回 NULL → NULL | 8 的子树里没有 p、q |
| LCA(6) | l = 2, r = NULL → 返回 2 | 只有左边找到 |

### 代码

```c
struct TreeNode* lowestCommonAncestor(struct TreeNode* root, struct TreeNode* p, struct TreeNode* q) {
    if (root == NULL || root == p || root == q) return root;       // 空，或自己就是 p/q
    struct TreeNode* l = lowestCommonAncestor(root->left, p, q);   // 去左子树找
    struct TreeNode* r = lowestCommonAncestor(root->right, p, q);  // 去右子树找
    if (l != NULL && r != NULL) return root;                       // 分在两边：root 是答案
    return (l != NULL) ? l : r;                                    // 只有一边有结果，往上传
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最坏要遍历整棵树。
- **空间复杂度 O(h)**：递归栈，链状树时 h 可达 10⁵（本 OJ 栈够用，但没有利用 BST 性质）。

---

## 🚀 第四步：思路二 —— 利用 BST 性质一路往下走

### 为什么能优化

站在某个结点 `cur` 上看 p、q：

| 情况 | 说明 | 怎么走 |
|---|---|---|
| `p->val < cur->val` 且 `q->val < cur->val` | p、q 都在左子树 | `cur = cur->left` |
| `p->val > cur->val` 且 `q->val > cur->val` | p、q 都在右子树 | `cur = cur->right` |
| 其他（一左一右，或其中一个等于 `cur`） | 在这里分叉了 | **`cur` 就是答案** |

为什么分叉处就是最近公共祖先？因为如果再往左走，就"丢掉"了右边的那个结点；再往右走，就丢掉了左边的。所以 `cur` 是最深的、同时能"罩住"p 和 q 的结点。

整个过程只沿着一条路径往下走，不需要回溯，也不需要遍历整棵树。

### 手动模拟

| p, q | cur | 比较 | 动作 |
|---|---|---|---|
| 2, 8 | 6 | 2 < 6 < 8，分叉 | 返回 **6** |
| 2, 4 | 6 | 都小于 6 | 往左 |
| | 2 | p 等于 2 | 返回 **2** |
| 3, 5 | 6 | 都小于 6 | 往左 |
| | 2 | 都大于 2 | 往右 |
| | 4 | 3 < 4 < 5，分叉 | 返回 **4** |

### 代码

```c
struct TreeNode* lowestCommonAncestor(struct TreeNode* root, struct TreeNode* p, struct TreeNode* q) {
    struct TreeNode* cur = root;
    while (cur != NULL) {
        if (p->val < cur->val && q->val < cur->val) {
            cur = cur->left;                  // 两个都比 cur 小：都在左子树
        } else if (p->val > cur->val && q->val > cur->val) {
            cur = cur->right;                 // 两个都比 cur 大：都在右子树
        } else {
            return cur;                       // 一左一右，或者 cur 就是其中之一
        }
    }
    return NULL;                              // 题目保证 p、q 在树中，不会走到这里
}
```

### 复杂度分析

- **时间复杂度 O(h)**：只走一条从根往下的路径，平衡时 O(log n)，链状时 O(n)。
- **空间复杂度 O(1)**：只用了一个指针变量。

---

## ⚠️ 第五步：小白常见错误

1. **把 `p` 当数值比较**：写成 `p < cur->val` 是拿指针和整数比较，编译会警告，结果毫无意义。要写 `p->val < cur->val`。
2. **只判断了 p**：

   ```c
   if (p->val < cur->val) cur = cur->left;   // ❌ q 可能在右边
   ```

   必须 **p 和 q 都** 小于才往左、**都** 大于才往右。
3. **用 `<=` 代替 `<`**：`p->val <= cur->val && q->val <= cur->val` 时若 p 就是 `cur`，会错误地继续往左走，把 `cur` 本身这个答案跳过了。
4. **忘了"自己也是自己的祖先"**：示例 2 的答案是 2 本身，而不是 6。
5. **用 `int` 做差判断方向**：有人写 `(p->val - cur->val) * (q->val - cur->val) > 0` 来判断"同侧"，值的范围是 ±10⁹，相减再相乘会溢出 `int`。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 通用二叉树 LCA（递归） | O(n) | O(h) | ⭐⭐ | 任何二叉树都能用 |
| BST 一路往下走（迭代） | O(h) | O(1) | ⭐ | 推荐，充分利用 BST |
