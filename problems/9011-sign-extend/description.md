许多传感器输出的是 **非标准位宽的有符号数**：例如 24 位 ADC（如 ADS1220）的转换结果是 24 位补码，某些温度传感器的读数是 13 位补码，三轴加速度计的某些型号输出 12 位补码。单片机通过 SPI/I2C 把这些位读出来、拼进一个 `uint32_t` 后，只有低 `bits` 位是有效数据，高位都是 0。

如果直接把它当成 `int32_t` 使用，负数就会变成一个很大的正数——例如 12 位补码 `0xFFF` 本来表示 `-1`，却会被当成 `4095`。正确的做法是 **符号扩展**：把第 `bits - 1` 位（符号位）复制到第 `bits ~ 31` 位上，得到等值的 32 位有符号整数。

给定原始数据 `raw`（只有低 `bits` 位有效）和位宽 `bits`，请把 `raw` 视为 `bits` 位的 **补码**，返回它表示的有符号整数值。

### 示例 1

```
输入：raw = 4095, bits = 12
输出：-1
解释：4095 = 0xFFF，12 位补码的符号位（第 11 位）为 1，表示 -1。
```

### 示例 2

```
输入：raw = 2047, bits = 12
输出：2047
解释：2047 = 0x7FF，符号位为 0，是正数，值不变。这也是 12 位补码能表示的最大值。
```

### 示例 3

```
输入：raw = 8388608, bits = 24
输出：-8388608
解释：8388608 = 0x800000，24 位补码中只有符号位为 1，是 24 位补码能表示的最小值 -2^23。
```

### 提示

- `1 <= bits <= 32`
- `0 <= raw < 2^bits`（即 `raw` 中第 `bits` 位及以上全为 0）

### 函数说明

```c
int32_t sign_extend(uint32_t raw, int bits);
```

- `raw`：传感器原始数据，只有低 `bits` 位有效
- `bits`：补码的位宽
- 返回值：符号扩展后的 32 位有符号整数

### 自定义输入格式

```
4095
12
```

第 1 行是 `raw`，第 2 行是 `bits`，均为十进制整数。输出为有符号整数值（十进制）。
