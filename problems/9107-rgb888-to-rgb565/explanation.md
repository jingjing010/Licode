# RGB888 压缩为 RGB565：题解

## 📖 先读懂题目

r/g/b各0..255，丢弃低位进行RGB565打包：R在位15..11，G在10..5，B在4..0。返回16位无符号整数。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `255 / 0 / 0` | `63488` |
| 2 | `0 / 255 / 0` | `2016` |

## 🧰 需要的 C 语言知识

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

红蓝保留高5位，绿色保留高6位，再放入16位像素的对应位置；结果是逻辑数值，线缆字节序另行处理。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
uint16_t rgb565(int red, int green, int blue) {
    return (uint16_t)(((red >> 3) << 11) | ((green >> 2) << 5) | (blue >> 3));
}
```

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(1)，空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
- 修改函数签名或参数顺序，导致判题驱动无法正确调用。
