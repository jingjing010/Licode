# 9004. 读取寄存器位域 —— 小白详细题解

> 读芯片手册（datasheet）时你会看到大量这样的描述："`CR1[4:2]` PSC：分频系数"。意思是第 2 到第 4 位共同表示一个数。本题就是把这个数"抠"出来。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 32 个开关里，从第 `pos` 号开始往左数 `width` 个，把这一段**单独拿出来**当成一个数，告诉我它是多少。

拿示例 2（`reg = 180, pos = 2, width = 3`）来说：

| 位号 | 7 | 6 | 5 | **4** | **3** | **2** | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| reg = 180 | 1 | 0 | 1 | **1** | **0** | **1** | 0 | 0 |

第 2~4 位是 `101`，所以答案是 `0b101 = 5`。

**几个需要注意的细节：**

1. 结果要**移到最低位**再返回。`180 & 0b11100 = 20` 是"原地取出"，但题目要的是 `5`。
2. `width` 最大可以是 **32**（示例 3），这是本题最大的陷阱。
3. 题目保证 `pos + width <= 32`，位域不会越过最高位。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 右移 `>>`：把目标挪到最低位

对**无符号数**右移，左边补 0，右边移出去的位直接丢掉：

```
reg        = 1011 0100
reg >> 2   = 0010 1101    (最右边的 00 被丢掉了)
```

现在我们要的 `101` 已经在最低 3 位了，但它左边还有 `101` 这些"垃圾"。

### 2. 低 width 位全 1 的掩码：`(1u << width) - 1`

```
1u << 3        = 0000 1000
(1u << 3) - 1  = 0000 0111    ← 低 3 位全是 1
```

这是个非常常用的技巧：2ʷ − 1 的二进制正好是 w 个 1。拿它和 `reg >> pos` 做 `&`，就只剩下最低 `width` 位了。

### 3. ⭐ 移位数 >= 32 是未定义行为

C 标准规定：**移位的位数必须小于被移位数的位宽**。对 32 位的 `unsigned int`，`1u << 32` 是未定义行为（UB）。

很多人以为 `1u << 32` 等于 0，那么 `0 - 1 = 0xFFFFFFFF` 正好是想要的掩码。但实际上在 x86 和 ARM 上，CPU 执行移位指令时只取位数的低 5 位，`1u << 32` 往往变成 `1u << 0 = 1`，掩码就变成了 0！

所以 `width == 32` 必须**单独处理**：

```c
uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);
```

### 4. 真实项目中的写法

芯片厂商的头文件里会为每个位域定义 `_Pos` 和 `_Msk` 两个宏（以 STM32 为例，示意）：

```c
#define RCC_CFGR_HPRE_Pos  4u
#define RCC_CFGR_HPRE_Msk  (0xFu << RCC_CFGR_HPRE_Pos)       /* 0x000000F0 */

uint32_t hpre = (RCC->CFGR & RCC_CFGR_HPRE_Msk) >> RCC_CFGR_HPRE_Pos;
```

注意这里是"**先与后移**"：掩码是已经移到位域位置上的。和本题"先移后与"效果一样。

---

## 💡 第三步：思路一 —— 逐位拼接（最朴素）

### 思路

一位一位地读出来，再一位一位地放到结果里：

- 对 `i = 0, 1, ..., width-1`：读出 `reg` 的第 `pos + i` 位，如果是 1，就把结果的第 `i` 位置 1。

### 手动模拟（示例 2：`reg = 180, pos = 2, width = 3`）

| i | 读第 pos+i 位 | 该位的值 | result |
|---|---|---|---|
| 0 | 第 2 位 | 1 | 0b001 |
| 1 | 第 3 位 | 0 | 0b001 |
| 2 | 第 4 位 | 1 | 0b101 = **5** |

### 代码

```c
uint32_t get_bit_field(uint32_t reg, int pos, int width) {
    uint32_t result = 0;
    for (int i = 0; i < width; i++) {
        uint32_t bit = (reg >> (pos + i)) & 1u;   // 读出 reg 的第 pos+i 位（0 或 1）
        if (bit) {
            result |= (1u << i);                  // 放到结果的第 i 位
        }
    }
    return result;
}
```

`pos + i` 最大是 `pos + width - 1 <= 31`，`i` 最大是 31，所以所有移位都是合法的，`width = 32` 也不用特殊处理。

### 复杂度分析

- **时间复杂度 O(width)**，最多循环 32 次。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 先右移，再与掩码（标准答案）

### 思路

两步完成：

1. `reg >> pos`：把位域挪到最低位。
2. `& mask`：只保留低 `width` 位。

### 手动模拟（示例 1：`reg = 0xABCD1234, pos = 8, width = 8`）

| 步骤 | 十六进制 |
|---|---|
| reg | `0xABCD1234` |
| reg >> 8 | `0x00ABCD12` |
| mask = (1u << 8) − 1 | `0x000000FF` |
| 相与 | `0x00000012` = **18** |

> 💬 用十六进制看位运算非常直观：右移 8 位 = 去掉最右边 2 个十六进制位；`& 0xFF` = 只留最右边 2 个十六进制位。

### 代码

```c
uint32_t get_bit_field(uint32_t reg, int pos, int width) {
    // 低 width 位全为 1 的掩码；width == 32 时 1u << 32 是未定义行为，必须单独处理
    uint32_t mask = (width >= 32) ? 0xFFFFFFFFu : ((1u << width) - 1u);
    return (reg >> pos) & mask;   // 先把位域挪到最低位，再去掉高处的其它位
}
```

### 另一种不需要特判的写法：左右两次移位

先左移把位域**上面**的位挤掉，再右移把位域**下面**的位挤掉：

```c
uint32_t get_bit_field(uint32_t reg, int pos, int width) {
    // 第 1 步：左移 32-pos-width 位，位域的最高位到达第 31 位，它上面的位被挤出去
    uint32_t t = reg << (32 - pos - width);
    // 第 2 步：右移 32-width 位，位域落到最低位，它下面的位被挤出去（无符号右移，左边补 0）
    return t >> (32 - width);
}
```

由于 `1 <= width` 且 `pos + width <= 32`，两次移位的位数都在 `0 ~ 31` 之间，不会触发未定义行为。

### 复杂度分析

- **时间复杂度 O(1)**。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **`width = 32` 时直接用 `(1u << width) - 1`**：
   ```c
   uint32_t mask = (1u << width) - 1u;   // ❌ width = 32 时是未定义行为，实测常常得到 0
   ```
   示例 3 会输出 0 而不是 4294967295。
2. **先与后忘了移**：`reg & (mask << pos)` 得到的是"留在原位置"的值，示例 2 会输出 20 而不是 5。
3. **掩码写成 `1u << width`（少了 `- 1`）**：`1u << 3 = 0b1000`，这只有一个 1，并且还在错误的位置上。
4. **用有符号数右移**：如果 `reg` 是 `int` 并且最高位为 1，右移时左边会补 1（算术右移），读出的高位全是垃圾。寄存器一律用 `uint32_t`。
5. **`-` 和 `<<` 的优先级**：`1u << width - 1` 会被解析成 `1u << (width - 1)`——**加减法的优先级比移位高**！一定要写成 `(1u << width) - 1u`。
6. **把 `pos` 当成位域的最高位**：手册里写的 `[4:2]` 是"高位:低位"，`pos` 应该取较小的那个数 2，`width = 4 - 2 + 1 = 3`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位拼接 | O(width) | O(1) | ⭐ | 帮助理解 |
| 右移 + 掩码 | O(1) | O(1) | ⭐⭐ | 标准写法，记得特判 32 |
| 左移再右移 | O(1) | O(1) | ⭐⭐ | 巧妙，不需要特判 |
