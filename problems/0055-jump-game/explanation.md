# 55. 跳跃游戏 —— 小白详细题解

> 这道题是**贪心**的经典入门题：不用关心"具体怎么跳"，只关心"最远能到哪"。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 你站在下标 0。每个格子上写着一个数字，表示**从这里最多能往右跳几格**（可以少跳）。问能不能跳到最后一格？

拿示例 2 `nums = [3,2,1,0,4]` 来说：

| 下标 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 最多跳 | 3 | 2 | 1 | **0** | 4 |
| 最远能到 | 3 | 3 | 3 | 3 | — |

不管从 0、1、2 怎么跳，最远都只能到下标 3，而下标 3 上是 0，跳不动了，所以答案是 `false`。

**几个需要注意的细节：**

1. `nums[i]` 是**最大**跳跃长度，`nums[i] = 3` 时可以跳 1、2 或 3 格。
2. 只有一个元素时（如 `[0]`），你已经站在最后一个下标上了，答案是 `true`。
3. 跳得超过最后一格也算到达。

---

## 🧰 第二步：这道题需要的 C 语言知识

1. **`bool` 类型**：来自 `<stdbool.h>`，取值 `true` / `false`（本 OJ 已自动包含该头文件）。
2. **`calloc`**：`calloc(n, sizeof(bool))` 申请 n 个元素并**全部清零**，适合做"标记数组"。用完记得 `free`。
3. **提前 `return`**：一旦能确定答案，就可以直接返回，不用把循环走完。

---

## 💡 第三步：思路一 —— 标记每个位置能否到达（动态规划）

### 思路

用 `reach[i]` 表示"下标 i 能不能到达"：

- `reach[0] = true`
- 对于第 `j` 个位置：只要它前面有某个**能到达**的 `i`，并且 `i + nums[i] >= j`，那 `j` 就能到达。

### 手动模拟（示例 1：`[2,3,1,1,4]`）

| j | 检查前面的 i | reach[j] |
|---|---|---|
| 0 | 起点 | true |
| 1 | i=0：0+2 ≥ 1 ✅ | true |
| 2 | i=0：0+2 ≥ 2 ✅ | true |
| 3 | i=0：2 < 3；i=1：1+3 ≥ 3 ✅ | true |
| 4 | i=0：2；i=1：1+3 ≥ 4 ✅ | **true** |

### 代码

```c
bool canJump(int* nums, int numsSize) {
    // reach[i] 表示下标 i 能否到达，calloc 会把所有元素初始化为 0（false）
    bool* reach = (bool*)calloc(numsSize, sizeof(bool));
    reach[0] = true;                                  // 起点一定能到

    for (int j = 1; j < numsSize; j++) {
        // 看看 j 前面有没有一个能到达、并且能跳到 j 的位置
        for (int i = 0; i < j; i++) {
            if (reach[i] && i + nums[i] >= j) {
                reach[j] = true;
                break;                                // 找到一个就够了
            }
        }
    }

    bool ans = reach[numsSize - 1];
    free(reach);                                      // 用完释放
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n²)**：两层循环，n = 10⁴ 时约 5×10⁷ 次，勉强能过。
- **空间复杂度 O(n)**：`reach` 数组。

## 🚀 第四步：思路二 —— 贪心：只记"最远能到哪"

### 思路

观察思路一会发现：**能到达的位置一定是从 0 开始连续的一段**。因为如果能到下标 5，那么跳的过程中可以选择少跳，0~5 之间的每个位置都能到。

所以只需要一个变量 `far` 表示"目前最远能到的下标"：

- 从左往右走到 `i`，如果 `i > far`，说明 `i` 根本到不了，后面也都到不了 → `false`
- 否则从 `i` 出发最远能到 `i + nums[i]`，用它更新 `far`
- 一旦 `far >= numsSize - 1`，就能到终点 → `true`

### 手动模拟（示例 2：`[3,2,1,0,4]`）

| i | nums[i] | i > far？ | i + nums[i] | far（更新后） |
|---|---|---|---|---|
| 0 | 3 | 0 > 0 否 | 3 | 3 |
| 1 | 2 | 否 | 3 | 3 |
| 2 | 1 | 否 | 3 | 3 |
| 3 | 0 | 否 | 3 | 3 |
| 4 | 4 | **4 > 3 是** | — | 返回 false |

### 代码

```c
bool canJump(int* nums, int numsSize) {
    int far = 0;                          // 目前能到达的最远下标
    for (int i = 0; i < numsSize; i++) {
        if (i > far) return false;        // 连 i 都到不了，更别说终点了
        if (i + nums[i] > far) {
            far = i + nums[i];            // 从 i 出发能跳得更远
        }
        if (far >= numsSize - 1) return true;   // 已经能覆盖终点
    }
    return true;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：只扫描一遍。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **以为 `nums[i]` 是"必须跳几格"** → 其实是"最多跳几格"，少跳也可以。按"必须跳"去模拟会得出错误答案。
2. **遇到 0 就返回 false** → `[2,0,0]` 可以从下标 0 直接跳到终点，0 不一定是死路，要看能不能"跳过去"。
3. **忘记判断 `i > far`** → 只更新 `far` 不检查是否可达，会把到不了的位置的跳跃能力也算进去，`[0,1]` 会错误地返回 true。
4. **只有一个元素时返回 false** → `[0]` 本来就在终点，应返回 true。
5. **思路一忘了 `free`** → 本题不影响结果，但养成申请内存后释放的好习惯。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 |
|---|---|---|---|
| 标记数组（DP） | O(n²) | O(n) | ⭐ |
| 贪心（最远可达） | O(n) | O(1) | ⭐⭐ |
