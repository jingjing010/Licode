# 9024. 字节数组转十六进制字符串 —— 小白详细题解

> 上一题把文本变成字节，这一题把字节变成文本。这道题的重点是：**`malloc` 字符串时别忘了 `'\0'`**，以及嵌入式里非常经典的**查表法**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把每个字节写成两位大写十六进制，按顺序连在一起，组成一个新字符串返回。

拿示例 2 `[0,255,10]` 来说：

| 字节（十进制） | 十六进制 | 高 4 位 → 字符 | 低 4 位 → 字符 | 输出 |
|---|---|---|---|---|
| 0 | `0x00` | 0 → `'0'` | 0 → `'0'` | `"00"` |
| 255 | `0xFF` | 15 → `'F'` | 15 → `'F'` | `"FF"` |
| 10 | `0x0A` | 0 → `'0'` | 10 → `'A'` | `"0A"` |

结果 `"00FF0A"`。

**几个需要注意的细节：**

1. **前导 0 不能省**：10 必须输出 `"0A"` 而不是 `"A"`，否则接收方无法两两配对解析。
2. **大写字母**：`0xab` 要输出 `"AB"`。
3. **空数组**要返回空字符串 `""`——仍然要 `malloc` 1 个字节放 `'\0'`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 字符串需要多少空间？

`len` 个字节 → `2 * len` 个字符 → 再加 **1 个 `'\0'`** 结束符：

```
"00FF0A" 在内存中：  '0' '0' 'F' 'F' '0' 'A' '\0'
                     共 2 × 3 + 1 = 7 个字节
```

如果只申请 `2 * len` 个字节，`'\0'` 就会写到申请范围之外——这是**堆越界写**，可能暂时看不出问题，但会悄悄破坏其它数据，是嵌入式里最难查的 bug 之一。

### 2. 为什么返回的字符串必须 `malloc`？

```c
char* bytes_to_hex(const uint8_t* buf, int len) {
    char s[2001];        // ❌ 局部数组在函数返回后就失效了
    ...
    return s;
}
```

局部数组放在**栈**上，函数一返回，这块栈空间就会被后续函数调用覆盖。`malloc` 申请的内存在**堆**上，直到调用者 `free` 之前都有效。

> 💬 真实嵌入式项目里通常**不鼓励** `malloc`（堆碎片、实时性差），更常见的接口是让调用者传入缓冲区：`int bytes_to_hex(const uint8_t* buf, int len, char* out, int out_size)`。本题为了与力扣风格一致使用了 `malloc`。

### 3. 查表法

把 16 个字符按顺序放进一个字符串，用数值当下标直接取：

```c
const char digits[] = "0123456789ABCDEF";
digits[0]   // '0'
digits[10]  // 'A'
digits[15]  // 'F'
```

这比 `if (v < 10) ... else ...` 更快、更简洁，而且没有分支——在嵌入式里，查表法是**用一点 Flash 空间换速度**的经典手段（CRC 计算、正弦波生成、数码管段码都用它）。加上 `static const`，表格会放在 Flash（只读区）里，不占 RAM。

## 💡 第三步：思路一 —— 分支判断转字符

### 思路

对每个字节：

1. 高 4 位 `hi = b >> 4`，低 4 位 `lo = b & 0x0F`
2. 每个半字节 `v`：如果 `v < 10` 输出 `'0' + v`，否则输出 `'A' + (v - 10)`

### 手动模拟（示例 1：`[18,52,171,205]`）

| i | 字节 | hi | lo | 写入 `s[2i]`、`s[2i+1]` |
|---|---|---|---|---|
| 0 | `0x12` | 1 | 2 | `'1'` `'2'` |
| 1 | `0x34` | 3 | 4 | `'3'` `'4'` |
| 2 | `0xAB` | 10 | 11 | `'A'` `'B'` |
| 3 | `0xCD` | 12 | 13 | `'C'` `'D'` |

最后 `s[8] = '\0'`，得到 `"1234ABCD"`。

### 代码

```c
// 把 0~15 转换成大写十六进制字符
static char nibble_to_char(uint8_t v) {
    if (v < 10) return (char)('0' + v);         // 0~9  -> '0'~'9'
    return (char)('A' + (v - 10));              // 10~15 -> 'A'~'F'
}

char* bytes_to_hex(const uint8_t* buf, int len) {
    // 每个字节 2 个字符，再加 1 个 '\0'
    char* s = (char*)malloc(len * 2 + 1);
    if (s == NULL) return NULL;                 // 好习惯：检查 malloc 是否成功

    for (int i = 0; i < len; i++) {
        s[2 * i]     = nibble_to_char(buf[i] >> 4);     // 高 4 位在前
        s[2 * i + 1] = nibble_to_char(buf[i] & 0x0F);   // 低 4 位在后
    }
    s[2 * len] = '\0';                          // 千万别忘了结束符
    return s;
}
```

### 复杂度分析

- **时间复杂度 O(n)**，**空间复杂度 O(n)**（返回的字符串）。

## 🚀 第四步：思路二 —— 查表法（项目常用）

### 思路

用 `"0123456789ABCDEF"` 做查找表，半字节的值直接当下标，省掉 `if` 判断。另外用一个移动指针 `p` 依次写入，代码更紧凑。

### 代码

```c
char* bytes_to_hex(const uint8_t* buf, int len) {
    static const char digits[] = "0123456789ABCDEF";   // 查找表，放在只读区
    char* s = (char*)malloc(len * 2 + 1);
    if (s == NULL) return NULL;

    char* p = s;                         // p 指向下一个要写的位置
    for (int i = 0; i < len; i++) {
        *p++ = digits[buf[i] >> 4];      // 高 4 位
        *p++ = digits[buf[i] & 0x0F];    // 低 4 位
    }
    *p = '\0';                           // 此时 p 正好指向 s[2 * len]
    return s;
}
```

> 💬 `*p++ = x;` 的含义：先把 `x` 写到 `p` 指向的位置，然后 `p` 后移一格。这是 C 语言里处理缓冲区最常见的惯用法。

---

## ⚠️ 第五步：小白常见错误

1. **忘了给 `'\0'` 留空间**：`malloc(len * 2)`，写 `s[2*len]` 时越界。
2. **忘了写 `'\0'`**：`malloc` 出来的内存内容是随机的，不写结束符，打印时会带出一串乱码，直到碰巧遇到一个 0。
3. **用 `sprintf(s + 2*i, "%02X", buf[i])`**：功能对，但题目禁止；在单片机上 `sprintf` 很占 Flash 和栈，而且最后一次调用写 `'\0'` 也需要 `2*len+1` 的空间。
4. **字母从 `'A'` 开始却没减 10**：`'A' + v` 当 `v = 10` 时得到 `'K'`。
5. **空数组返回 `NULL`**：题目要求返回 `""`。`malloc(1)` 再写 `s[0] = '\0'` 即可，上面的代码在 `len = 0` 时自然满足。
6. **高低位顺序反了**：先写低 4 位，`0x12` 变成 `"21"`。
