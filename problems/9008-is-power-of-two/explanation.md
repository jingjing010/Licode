# 9008. 判断 2 的幂 —— 小白详细题解

> `(x & (x - 1)) == 0` 是嵌入式代码里出镜率极高的一行，环形缓冲区、内存池、DMA 对齐检查里都能见到它。本题弄懂它为什么对、以及它唯一的"坑"——`x = 0`。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 判断 `x` 是不是 1、2、4、8、16、……、2³¹ 中的某一个。

先看看 2 的幂长什么样：

| x | 二进制 | 是 2 的幂？ |
|---|---|---|
| 1 | `0000 0001` | ✔ (2⁰) |
| 8 | `0000 1000` | ✔ (2³) |
| 64 | `0100 0000` | ✔ (2⁶)，示例 1 |
| 96 | `0110 0000` | ✘，示例 3 |
| 0 | `0000 0000` | ✘，示例 2 |

规律一目了然：**2 的幂的二进制里恰好有一个 1**。

**几个需要注意的细节：**

1. `1 = 2⁰` 是 2 的幂。
2. `0` 不是 2 的幂——它一个 1 都没有。这是本题最大的坑。
3. 最大的 2 的幂是 `2³¹ = 2147483648`，`0xFFFFFFFF` 不是。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `bool` 类型

`bool` 来自 `<stdbool.h>`，取值 `true` / `false`。C 语言里比较运算 `==`、`!=` 和逻辑运算 `&&` 的结果本身就是 0 或 1，可以直接 `return`。

### 2. ⭐ `x & (x - 1)`：消掉最右边的 1

（9006 里讲过，这里复习一下。）`x - 1` 会把 `x` 最右边的 1 变成 0，它右边的 0 全变成 1：

```
x           = 0100 0000   (64)
x - 1       = 0011 1111   (63)
x & (x - 1) = 0000 0000   ← 唯一的 1 被消掉，变成 0 了

x           = 0110 0000   (96)
x - 1       = 0101 1111   (95)
x & (x - 1) = 0100 0000   ← 还剩一个 1，不是 0
```

所以：**消掉一个 1 之后变成 0** ⟺ **原来恰好只有一个 1** ⟺ 是 2 的幂（`x != 0` 时）。

### 3. 无符号数 `0 - 1` 不是 -1

`x = 0` 时 `x - 1u` 对 `uint32_t` 来说是 `0xFFFFFFFF`（无符号减法自动对 2³² 取模，**有定义**），`0 & 0xFFFFFFFF = 0`。所以单靠 `(x & (x - 1)) == 0` 会把 0 误判成 2 的幂，必须额外检查 `x != 0`。

### 4. `&&` 的短路

`x != 0 && ...`：如果左边已经是 `false`，右边根本不会计算。这里即使计算了也没有危险，但养成"先排除特殊值"的习惯很好。

---

## 💡 第三步：思路一 —— 不断除以 2（最朴素）

### 思路

如果 `x` 是 2 的幂，就可以一直被 2 整除，最后变成 1；只要中途出现奇数（且不是 1），就不是。

### 手动模拟

| x = 96 | x = 64 |
|---|---|
| 96 偶数 → 48 | 64 → 32 |
| 48 → 24 | 32 → 16 |
| 24 → 12 | 16 → 8 |
| 12 → 6 | 8 → 4 |
| 6 → 3 | 4 → 2 |
| 3 是奇数，停 → 不等于 1，**false** | 2 → 1，停 → 等于 1，**true** |

### 代码

```c
bool is_power_of_two(uint32_t x) {
    if (x == 0) {
        return false;            // 0 不是 2 的幂，而且 0 会一直被 2 整除，导致死循环
    }
    while (x % 2 == 0) {         // 还能被 2 整除
        x /= 2;                  // 除掉一个因子 2
    }
    return x == 1;               // 只剩 1 说明全部因子都是 2
}
```

### 复杂度分析

- **时间复杂度 O(log x)**，最多 31 次循环，每次都有除法/取模（编译器通常会把 `% 2`、`/ 2` 优化成位运算，但写法本身不够"嵌入式"）。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— `x & (x - 1)`（标准答案）

### 思路

2 的幂 = 非零且恰好一个 1 = 非零且"消掉最右边的 1 之后变成 0"。

### 代码

```c
bool is_power_of_two(uint32_t x) {
    // x != 0：排除 0；(x & (x - 1)) == 0：只有一个 1
    return x != 0 && (x & (x - 1u)) == 0;
}
```

### 复杂度分析

- **时间复杂度 O(1)**：一次减法、一次与、两次比较。
- **空间复杂度 O(1)**。

### 另一种写法：`x & (~x + 1)`

`x & (~x + 1)` 会**只保留**最右边的 1（详见 9012）。如果保留下来的就是 `x` 本身，说明 `x` 只有一个 1：

```c
bool is_power_of_two(uint32_t x) {
    return x != 0 && (x & (~x + 1u)) == x;   // 最低位的 1 就是全部的 1
}
```

## ⚠️ 第五步：小白常见错误

1. **忘记排除 0**：
   ```c
   return (x & (x - 1)) == 0;    // ❌ x = 0 时返回 true，示例 2 错误
   ```
2. **优先级陷阱**：`x & x - 1 == 0` 会被解析成 `x & ((x - 1) == 0)`——**`==` 比 `&` 优先级高**！必须写成 `(x & (x - 1)) == 0`。
3. **用浮点数 `log2`**：`log2(x)` 再判断是不是整数，浮点误差可能导致误判，而且单片机上浮点运算很慢（没有 FPU 的芯片要用软件模拟）。
4. **思路一不判 0**：`0 % 2 == 0` 永远成立，`while` 死循环，程序卡死——在单片机上表现为"看门狗复位"。
5. **用 `int` 做参数**：`x = 0x80000000` 放进 `int` 会变成负数，`x - 1` 变成有符号溢出（UB）。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 不断除以 2 | O(log x) | O(1) | ⭐ | 帮助理解 |
| `x & (x - 1)` | O(1) | O(1) | ⭐ | 标准答案，背下来 |
| `x & (~x + 1)` | O(1) | O(1) | ⭐⭐ | 了解即可 |

## 🔌 嵌入式实战

环形缓冲区的初始化和下标回绕（示意）：

```c
typedef struct {
    uint8_t *buf;
    uint32_t size;      /* 必须是 2 的幂 */
    uint32_t head, tail;
} ring_t;

int ring_init(ring_t *r, uint8_t *buf, uint32_t size) {
    if (!is_power_of_two(size)) return -1;   /* 拒绝非法大小 */
    r->buf = buf; r->size = size; r->head = r->tail = 0;
    return 0;
}

/* 写入一个字节：idx & (size - 1) 等价于 idx % size，但只要一条 AND 指令 */
r->buf[r->head & (r->size - 1)] = byte;  r->head++;
```

- `head`、`tail` 可以一直自增、让它自然溢出回绕，元素个数就是 `head - tail`（无符号减法自动处理回绕）。这个技巧**也要求** `size` 是 2 的幂，否则 2³² 回绕时下标会跳。
- 同样的检查还用于：DMA 传输要求地址按 2 的幂对齐、内存池块大小、FFT 点数（必须是 2 的幂）。
