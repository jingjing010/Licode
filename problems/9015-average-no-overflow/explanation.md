# 9015. 无溢出求平均值 —— 小白详细题解

> `(a + b) / 2` 是一个"隐藏了几十年"的 bug：Java 标准库的二分查找就曾因为它出错（2006 年才被发现）。本题从"为什么会错"讲起，给出加宽类型、差值法、位运算三种正确写法。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 求两个数的平均数，小数部分直接舍掉。难点在于：**不能让中间结果超出 32 位**。

| a | b | 数学上的 (a+b)/2 | 向下取整 |
|---|---|---|---|
| 4 | 6 | 5 | **5**（示例 1） |
| 3 | 4 | 3.5 | **3**（示例 3） |
| 4294967295 | 4294967293 | 4294967294 | **4294967294**（示例 2） |

**为什么示例 2 是陷阱？** `uint32_t` 最大只能存 4294967295。`a + b = 8589934588`，超出范围后会对 2³² 取模（回绕），变成 `8589934588 − 4294967296 = 4294967292`，再除以 2 得到 `2147483646`——差了将近一半！

**几个需要注意的细节：**

1. 答案本身一定在 `uint32_t` 范围内（平均值不会比两个数中较大的那个大），出问题的只是**中间的和**。
2. 向下取整：两数之和为奇数时，舍掉 0.5。
3. `a` 和 `b` 的大小关系不确定，`a` 可能比 `b` 大。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 无符号整数溢出 = 回绕

对无符号数，C 标准规定运算结果对 2ⁿ 取模，这是**有定义**的，不会报错，也不会崩溃——所以这种 bug 特别隐蔽，程序"看起来"一直在正常运行。

（对**有符号**数，溢出是**未定义行为**，更危险。）

### 2. 加宽类型

`(uint64_t)a + b`：先把 `a` 转成 64 位，`b` 也会随之被转换，和最大约 2³³，64 位放得下。但在 8/16 位单片机（以及没有 64 位指令的 Cortex-M0）上，64 位加法、移位都要拆成多条指令，代价不小。

### 3. ⭐ 加法的位运算拆分：`a + b = 2 × (a & b) + (a ^ b)`

把两个数逐位相加，每一位只有三种情况：

| 这一位上 a、b 的情况 | 对和的贡献 | 由谁表示 |
|---|---|---|
| 都是 1 | 2 × 该位权重 | `a & b`（都为 1 的位），要乘 2 |
| 一个 1、一个 0 | 1 × 该位权重 | `a ^ b`（只有一个为 1 的位） |
| 都是 0 | 0 | |

所以 `a + b = 2 × (a & b) + (a ^ b)`，两边除以 2：

```
⌊(a + b) / 2⌋ = (a & b) + ⌊(a ^ b) / 2⌋ = (a & b) + ((a ^ b) >> 1)
```

`a & b` 和 `(a ^ b) >> 1` 是在不同的位上"分工"的，它们的和就是平均值，不会超过 `max(a, b)`，因此不会溢出。

---

## 💡 第三步：思路一 —— 先加宽再相加（最朴素）

### 思路

既然 32 位装不下和，就用 64 位来装，除完再转回 32 位。

### 手动模拟（示例 2）

| 步骤 | 值 |
|---|---|
| (uint64_t)a + b | 8589934588（64 位，放得下） |
| / 2 | 4294967294 |
| 转回 uint32_t | **4294967294** |

### 代码

```c
uint32_t average_u32(uint32_t a, uint32_t b) {
    uint64_t sum = (uint64_t)a + b;   // 先把 a 加宽到 64 位，再相加，不会溢出
    return (uint32_t)(sum / 2);       // 平均值一定 <= 0xFFFFFFFF，转回 32 位是安全的
}
```

### 复杂度分析

- **时间复杂度 O(1)**，但在 32 位以下的单片机上 64 位运算要多条指令。
- **空间复杂度 O(1)**。

> 💬 这种写法正确，但不满足"进阶"要求。

---

## 🚀 第四步：思路二 —— 小数加上差值的一半

### 思路

设 `lo = min(a, b)`、`hi = max(a, b)`，平均值 = `lo + (hi − lo) / 2`。

- `hi − lo` 不会溢出（`hi >= lo`）；
- `lo + (hi − lo) / 2 <= hi`，也不会溢出；
- 向下取整：`(hi − lo) / 2` 本身就是向下取整的，数学上 `lo + ⌊(hi−lo)/2⌋ = ⌊(lo+hi)/2⌋`。

### 手动模拟（示例 3：`a = 3, b = 4`）

| 步骤 | 值 |
|---|---|
| lo, hi | 3, 4 |
| hi − lo | 1 |
| (hi − lo) / 2 | 0 |
| lo + 0 | **3** |

### 代码

```c
uint32_t average_u32(uint32_t a, uint32_t b) {
    uint32_t lo = (a < b) ? a : b;    // 较小的数
    uint32_t hi = (a < b) ? b : a;    // 较大的数
    return lo + (hi - lo) / 2;        // hi - lo 不会溢出；结果不超过 hi
}
```

这就是二分查找里推荐的 `mid = left + (right - left) / 2`。

### 复杂度分析

- **时间复杂度 O(1)**，多一次比较。
- **空间复杂度 O(1)**。

---

## 🚀 思路三 —— 位运算拆分（推荐）

### 思路

直接套用第二步推出的公式：`(a & b) + ((a ^ b) >> 1)`。不需要比较大小，不需要 64 位。

### 手动模拟

| | a | b | a & b | a ^ b | (a ^ b) >> 1 | 结果 |
|---|---|---|---|---|---|---|
| 示例 1 | `100` | `110` | `100` = 4 | `010` = 2 | 1 | **5** |
| 示例 3 | `011` | `100` | `000` = 0 | `111` = 7 | 3 | **3** |

### 代码

```c
uint32_t average_u32(uint32_t a, uint32_t b) {
    // a & b：两个数都为 1 的位（在和里出现两次，平均后保留一次）
    // a ^ b：只有一个数为 1 的位（在和里出现一次，平均后要除以 2）
    return (a & b) + ((a ^ b) >> 1);
}
```

### 复杂度分析

- **时间复杂度 O(1)**：与、异或、移位、加法各一次，无分支。
- **空间复杂度 O(1)**。

### 另一种写法：各自除以 2 再补上

`a / 2 + b / 2` 会把两个 0.5 都丢掉；只有当 `a`、`b` 都是奇数时，两个 0.5 能凑成 1，需要补回来：

```c
uint32_t average_u32(uint32_t a, uint32_t b) {
    return (a >> 1) + (b >> 1) + (a & b & 1u);   // 两个都是奇数时补 1
}
```

## ⚠️ 第五步：小白常见错误

1. **直接相加**：
   ```c
   return (a + b) / 2;    // ❌ a + b 超过 0xFFFFFFFF 时回绕，示例 2 输出 2147483646
   ```
2. **加宽的位置不对**：
   ```c
   return (uint32_t)((uint64_t)(a + b) / 2);   // ❌ a + b 在 32 位里已经溢出了，再转 64 位也救不回来
   ```
   必须先转换**再**相加：`(uint64_t)a + b`。
3. **`a + (b - a) / 2` 不判断大小**：`a > b` 时 `b − a` 是一个巨大的无符号数（回绕），结果完全错误。
4. **`a / 2 + b / 2` 不补奇数**：示例 1 没问题，但 `a = 3, b = 5` 时得到 `1 + 2 = 3`，正确答案是 4。
5. **用浮点数**：`(uint32_t)(((double)a + b) / 2)` 在 PC 上能对，但单片机上没有 FPU 时极慢；改成 `float` 更糟——`float` 只有 24 位精度，大数会丢失低位。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 加宽到 64 位 | O(1) | O(1) | ⭐ | 简单直接，但小单片机上代价高 |
| `lo + (hi - lo) / 2` | O(1) | O(1) | ⭐ | 二分查找的标准写法 |
| `(a & b) + ((a ^ b) >> 1)` | O(1) | O(1) | ⭐⭐ | 无分支、无 64 位，推荐 |
| `a/2 + b/2 + (a & b & 1)` | O(1) | O(1) | ⭐⭐ | 同样无溢出，好理解 |

## 🔌 嵌入式实战

- **滑动平均滤波**：对 N 个 ADC 采样求平均时，要估算累加和的最大值。例如 12 位 ADC（最大 4095）累加 1024 次，最大 4095 × 1024 ≈ 4.2M，`uint32_t` 足够；但如果是 24 位 ADC 累加 1024 次，就会超过 2³²，要么用 64 位，要么边加边除。
- **定时器回绕**：计数器从 `0xFFFFFFFF` 回绕到 0 时，两次时间戳的差 `t2 - t1`（无符号减法）依然正确，但求两个时间戳的"中点"就要小心，不能简单地 `(t1 + t2) / 2`。
- **有符号数的平均值**：`int32_t` 的 `(a + b) / 2` 溢出是**未定义行为**，更要避免。可以用 `a + (b - a) / 2`（同号时安全）或转成 `int64_t`。
