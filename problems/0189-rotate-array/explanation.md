# 189. 轮转数组 —— 小白详细题解

> 这道题能用"新数组"轻松做出来，真正的考点是**不用额外数组**的"三次翻转"技巧。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把数组想象成一个圆圈，所有元素**一起往右挪 k 格**，从最右边挤出去的元素绕回到最左边。

示例 1：`nums = [1,2,3,4,5,6,7], k = 3`

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 轮转前 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| 轮转后 | **5** | **6** | **7** | 1 | 2 | 3 | 4 |

可以看到：**最后 k 个**元素 `5,6,7` 整体搬到了最前面，其余的整体往后挪。

**几个需要注意的细节：**

1. 函数返回 `void`，要**直接修改 `nums`**，不能返回新数组。
2. **`k` 可能比数组长度还大**！比如 `n = 3, k = 4`：转 3 次回到原样，所以只需转 `4 % 3 = 1` 次。
3. `k` 可能等于 0，此时数组不变。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 取余运算 `%`

```c
k = k % numsSize;   // 把 k 缩小到 0 ~ numsSize-1 的范围
(i + k) % n         // 下标"绕圈"：超过 n-1 就从 0 重新数
```

例如 `n = 7`：`(5 + 3) % 7 = 1`，下标 5 的元素轮转 3 步后到了下标 1。

### 2. 交换两个变量

```c
int t = a[l];   // 先把 a[l] 存起来，否则下一行会把它覆盖掉
a[l] = a[r];
a[r] = t;
```

### 3. 为什么函数里改 `nums`，外面能看到？

`nums` 是指针，`nums[i] = x;` 是直接修改调用者那块内存。但如果写 `nums = 新数组;`，只是改了函数里的局部指针，**调用者完全看不到**！

---

## 💡 第三步：思路一 —— 借助额外数组

### 思路

原来下标 `i` 的元素，轮转后应该在下标 `(i + k) % n`。所以：

1. 开一个新数组 `tmp`
2. `tmp[(i + k) % n] = nums[i]`
3. 把 `tmp` 拷贝回 `nums`

### 手动模拟（示例 2：`nums = [-1,-100,3,99], k = 2, n = 4`）

| i | nums[i] | 新位置 (i+2)%4 | tmp |
|---|---|---|---|
| 0 | -1 | 2 | [_, _, -1, _] |
| 1 | -100 | 3 | [_, _, -1, -100] |
| 2 | 3 | 0 | [3, _, -1, -100] |
| 3 | 99 | 1 | [3, 99, -1, -100] |

### 代码

```c
void rotate(int* nums, int numsSize, int k) {
    // 1. 申请一个和 nums 一样大的临时数组
    int* tmp = (int*)malloc(sizeof(int) * numsSize);

    // 2. 每个元素放到它轮转后的位置
    for (int i = 0; i < numsSize; i++) {
        tmp[(i + k) % numsSize] = nums[i];   // % 让下标绕圈；k 很大也没关系
    }

    // 3. 拷贝回 nums（注意：不能写 nums = tmp，外面看不到！）
    for (int i = 0; i < numsSize; i++) {
        nums[i] = tmp[i];
    }

    // 4. 用完释放
    free(tmp);
}
```

> 💬 `i + k` 最大约 `2 × 10^5`，不会溢出。拷贝也可以用 `memcpy(nums, tmp, sizeof(int) * numsSize);` 一行搞定。

### 复杂度分析

- **时间复杂度 O(n)**，**空间复杂度 O(n)**。

---

## 🚀 第四步：思路二 —— 三次翻转（原地，O(1) 空间）

### 思路

观察结果：轮转后 = **后 k 个** 放到前面 + **前 n-k 个** 放到后面。

翻转有个神奇的性质：

1. **整体翻转**：后 k 个跑到了前面，前 n-k 个跑到了后面——位置对了，但每一段内部是**倒着的**
2. **翻转前 k 个**：把第一段正过来
3. **翻转后 n-k 个**：把第二段正过来

### 手动模拟（示例 1：`[1,2,3,4,5,6,7], k = 3`）

| 步骤 | 操作 | 数组 |
|---|---|---|
| 0 | 原数组 | 1 2 3 4 \| 5 6 7 |
| 1 | 整体翻转 [0, 6] | 7 6 5 \| 4 3 2 1 |
| 2 | 翻转前 k 个 [0, 2] | **5 6 7** \| 4 3 2 1 |
| 3 | 翻转后 n-k 个 [3, 6] | 5 6 7 \| **1 2 3 4** |

### 代码

```c
// 把 a[l..r]（含两端）原地翻转：左右两头交换，往中间收
void reverseRange(int* a, int l, int r) {
    while (l < r) {
        int t = a[l];
        a[l] = a[r];
        a[r] = t;
        l++;
        r--;
    }
}

void rotate(int* nums, int numsSize, int k) {
    k = k % numsSize;                         // ⭐ 必须先取余，否则 k-1 可能越界
    reverseRange(nums, 0, numsSize - 1);      // 1. 整体翻转
    reverseRange(nums, 0, k - 1);             // 2. 翻转前 k 个（k = 0 时 l > r，什么都不做）
    reverseRange(nums, k, numsSize - 1);      // 3. 翻转剩下的 n - k 个
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个元素最多被交换 2 次。
- **空间复杂度 O(1)**：只用了一个临时变量 `t`。

---

## ⚠️ 第五步：小白常见错误

1. **忘记 `k %= n`** → 三次翻转时 `reverseRange(nums, 0, k - 1)` 会访问越界（比如 `n = 1, k = 100000`）。
2. **在函数里写 `nums = tmp;`** → 只改了局部指针，调用者的数组一点没变。必须逐个拷贝回去。
3. **一步一步地转 k 次**（每次把最后一个挪到最前面）→ 时间 O(n·k)，`n = k = 10^5` 时约 10^10 次操作，必定超时。
4. **原地写 `nums[(i + k) % n] = nums[i]`，不用临时数组** → 会把还没搬走的元素覆盖掉，结果出现重复数字。
5. **翻转区间的边界写错**：比如第三步写成 `reverseRange(nums, k + 1, n - 1)`，少翻了一个元素。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐步轮转 k 次 | O(n·k) | O(1) | ⭐ | 会超时，别用 |
| 额外数组 | O(n) | O(n) | ⭐ | 先把这个写对 |
| 三次翻转 | O(n) | O(1) | ⭐⭐ | 进阶要求的原地解法 |

> 还有第三种原地方法叫"环状替换"：从下标 0 出发，把元素直接送到 `(i + k) % n`，被挤出来的那个继续往下送，直到绕回起点；需要用最大公约数 `gcd(n, k)` 判断要绕几圈。思路巧妙但容易写错，有兴趣可以自己尝试。
