# 9057. PWM 周期与占空比寄存器计算 —— 小白详细题解

> 调 LED 亮度、电机转速、舵机角度，都离不开 PWM。会用 CubeMX 点一点不难，难的是**自己算出 PSC / ARR / CCR**——面试时经常让你当场口算"72MHz 时钟要输出 1kHz、占空比 25%，寄存器怎么配？"

---

## 📖 第一步：先读懂题目

### 定时器 PWM 的工作过程

```
定时器时钟 clk ──÷(PSC+1)──> 计数时钟 ──> 计数器 CNT: 0,1,2,...,ARR,0,1,2,...
                                                   │
                       CNT < CCR 输出高电平，否则输出低电平（PWM 模式 1）
```

- 一个 PWM 周期计数 `N = ARR + 1` 次。
- 高电平持续 `CCR` 次计数，所以占空比 = `CCR / N`。

### 示例 1 手算

| 量 | 计算 | 结果 |
|---|---|---|
| 计数频率 | 72 000 000 / (71 + 1) | 1 000 000 Hz |
| N | 1 000 000 / 1000 | 1000 |
| ARR | N - 1 | **999** |
| CCR | 1000 × 25 / 100 | **250** |

### 示例 3：不能整除时

计数频率 1MHz，要 3kHz：`1000000 / 3000 = 333.33`，四舍五入 N = 333 → ARR = 332。实际输出频率是 `1000000 / 333 = 3003Hz`，有 0.1% 的误差——这在真实项目中很常见。CCR = `333 × 0.5 = 166.5` → 167。

**容易忽略的细节：**

1. ARR 是 **N - 1**，不是 N。这是 STM32 新手最常见的 off-by-one 错误。
2. 两次四舍五入：先对 N 四舍五入，**再**用取整后的 N 算 CCR。
3. `duty = 100` 时 `CCR = N = ARR + 1`，计数值永远 < CCR，输出一直是高电平。

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用指针参数"返回"多个值

C 函数只能 `return` 一个值，要输出两个结果就传指针进来：

```c
uint32_t a, c;
pwmCalc(72000000, 71, 1000, 25, &a, &c);   // 调用者传地址
// 函数内部：*arr = 999;  *ccr = 250;     // 往地址里写
```

### 2. 整数四舍五入

`a / b` 四舍五入（a、b 非负）：

```c
(2 * a + b) / (2 * b)
```

原理：`a/b + 1/2 = (2a + b) / (2b)`，再向下取整。比 `(a + b/2) / b` 更严谨（b 为奇数时 `b/2` 有截断，不过对整数 a 结果其实相同）。

### 3. 为什么要用 `uint64_t`？

`(psc + 1) × freq` 最大约 `65536 × 5×10^8 ≈ 3.3×10^13`，远超 `uint32_t` 的上限 `4.29×10^9`。`2 × clk` 最大 `10^9` 虽然没超，但统一用 64 位最安全。

```c
uint64_t den = (uint64_t)(psc + 1) * freq;   // 先转换再乘！
```

注意 `(uint64_t)((psc + 1) * freq)` 是错的：括号里先按 32 位乘完、已经溢出了，再转换也救不回来。

### 4. 为什么不用浮点？

`round((double)clk / ...)` 在 PC 上也能得到正确答案，但：

- 很多 MCU（Cortex-M0/M3）没有 FPU，浮点运算靠软件模拟，慢而且占几 KB Flash。
- 浮点数有精度误差，`166.5` 可能被表示成 `166.49999...`，四舍五入就错了。

嵌入式里**能用整数就用整数**。

## 💡 第三步：思路一 —— 直接套公式（整数四舍五入）

### 代码

```c
void pwmCalc(uint32_t clk, uint32_t psc, uint32_t freq, uint32_t duty, uint32_t* arr, uint32_t* ccr) {
    uint64_t den = (uint64_t)(psc + 1) * freq;          // 分母：(PSC+1) × freq，用 64 位防溢出
    uint64_t n = (2ULL * clk + den) / (2 * den);        // N = round(clk / den)
    *arr = (uint32_t)(n - 1);                           // ARR = N - 1
    *ccr = (uint32_t)((2 * n * duty + 100) / 200);      // CCR = round(N × duty / 100)
}
```

`CCR = round(N × duty / 100)` 套用 `(2a + b) / (2b)`，a = N × duty，b = 100，就是 `(2 × N × duty + 100) / 200`。

### 复杂度分析

- 时间 O(1)，空间 O(1)。

---

## 🚀 第四步：思路二 —— 用"余数"判断是否进位

### 思路

另一种不容易出错的四舍五入写法：先做整数除法得到商 q 和余数 r，如果 `2r >= b`（余数至少是除数的一半）就进位。好处是**每一步都能看懂**，调试时也方便打印中间结果。

| 计算 | a | b | q = a / b | r = a % b | 2r ≥ b ? | 结果 |
|---|---|---|---|---|---|---|
| 示例 3 的 N | 16 000 000 | 16 × 3000 = 48 000 | 333 | 16 000 | 否 | 333 |
| 示例 3 的 CCR | 333 × 50 = 16 650 | 100 | 166 | 50 | **是** | 167 |

### 代码

```c
static uint64_t divRound(uint64_t a, uint64_t b) {
    uint64_t q = a / b;              // 商
    uint64_t r = a % b;              // 余数
    if (2 * r >= b) q++;             // 余数 ≥ 除数的一半 → 进位
    return q;
}

void pwmCalc(uint32_t clk, uint32_t psc, uint32_t freq, uint32_t duty, uint32_t* arr, uint32_t* ccr) {
    uint64_t n = divRound(clk, (uint64_t)(psc + 1) * freq);   // 一个周期的计数次数
    *arr = (uint32_t)(n - 1);
    *ccr = (uint32_t)divRound(n * duty, 100);
}
```

### 复杂度分析

- 时间 O(1)，空间 O(1)。

### 🔌 嵌入式实战：写进 STM32 寄存器

```c
void pwm_set(uint32_t freq, uint32_t duty) {
    uint32_t arr, ccr;
    pwmCalc(SystemCoreClock, TIM3->PSC, freq, duty, &arr, &ccr);
    TIM3->ARR  = arr;          // 周期
    TIM3->CCR1 = ccr;          // 通道 1 比较值
    TIM3->EGR  = TIM_EGR_UG;   // 产生更新事件，让新的 ARR 立即生效（否则等到当前周期结束）
}
```

**PSC 怎么选？** 原则是：先让 N 尽量大（占空比分辨率高，N = 1000 时能调到 0.1%），但不能超过 65536（16 位定时器）。例如 72MHz 输出 1kHz：PSC = 0 时 N = 72000 超了；PSC = 1 时 N = 36000，占空比分辨率 1/36000，非常细。

---

## ⚠️ 第五步：小白常见错误

1. **ARR 写成 N** → 实际周期多一个计数，频率偏低（1kHz 变成 999Hz）。
2. **`(uint64_t)((psc + 1) * freq)`** → 32 位乘法先溢出了，转换太晚。
3. **直接整数除法不四舍五入** → 示例 3 的 CCR 得到 166 而不是 167。
4. **用原始的小数 N 算 CCR** → `333.33 × 0.5 = 166.67 → 167` 碰巧一样，但别的数据会差 1；题目要求用取整后的 N。
5. **PSC 也当作分频系数直接除** → 实际分频是 `PSC + 1`，PSC = 0 表示不分频。

---

## 📊 第六步：方法对比

| 方法 | 四舍五入写法 | 优点 | 缺点 |
|---|---|---|---|
| 公式 `(2a+b)/(2b)` | 一行 | 简洁、快 | 要注意 2a 是否溢出 |
| 商 + 余数判断 | 三行 | 直观、好调试 | 多一次取模运算 |
| 浮点 `round()` | 一行 | 好写 | MCU 上慢，有精度风险 |
