# 9031. 实现 memcpy —— 小白详细题解

> "手写 memcpy" 是嵌入式面试的开胃菜。代码只有几行，但面试官借它考你：`void*` 怎么用、`const` 什么意思、`size_t` 有什么坑、内存重叠会怎样。我们一个一个讲清楚。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有两块内存，`src`（源）和 `dst`（目标）。把 `src` 里**前 `n` 个字节**一个不差地抄到 `dst` 里，然后把 `dst` 的地址原样还回去。

拿示例 1 来说（`src = [1,2,3,4,5]`，`n = 3`，`dst` 初始全 0）：

| 下标 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| src | 1 | 2 | 3 | 4 | 5 |
| dst（复制前） | 0 | 0 | 0 | 0 | 0 |
| dst（复制后） | **1** | **2** | **3** | 0 | 0 |

只抄前 3 个，后面 2 个**不能碰**。

**几个需要注意的细节：**

1. 单位是**字节**，不是"元素"。如果你要复制 10 个 `int`，调用时要写 `memcpy(d, s, 10 * sizeof(int))`。
2. 返回值是**原来的 `dst`**。循环里你会把指针一路往后挪，最后要返回的是"起点"，不是"终点"。
3. `n` 可能是 0，此时什么都不做，直接返回 `dst`。
4. 本题保证两块内存**不重叠**。重叠的情况交给下一题 `memmove`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `void*`：万能指针，但不能直接用

```c
void* my_memcpy(void* dst, const void* src, size_t n);
```

`memcpy` 要能复制任何类型的数据（`int` 数组、结构体、字节流……），所以参数类型是 `void*`——"指向某种东西，但不说是什么"。

代价是：**`void*` 不能解引用，标准 C 里也不能做加减运算**。因为编译器不知道它指向的东西有多大，`p + 1` 该跳几个字节？

```c
*dst = *src;   // ❌ 编译错误：不能解引用 void*
dst++;         // ❌ 标准 C 不允许（GCC 作为扩展允许，按 1 字节算，但别依赖它）
```

正确做法：**转成 `unsigned char*`**。`unsigned char` 正好 1 个字节，`p + 1` 就是下一个字节。

```c
unsigned char* d = (unsigned char*)dst;
const unsigned char* s = (const unsigned char*)src;
```

> ❓ **为什么是 `unsigned char` 而不是 `char`？** `char` 是否有符号由编译器决定（x86 上一般有符号，ARM 上一般无符号）。只是复制的话两者都行，但做比较时（如 `memcmp`）`char` 会把 `0xFF` 当成 `-1`，出错。养成习惯：**处理原始字节一律用 `unsigned char`（或 `uint8_t`）**。

### 2. `const void* src`：承诺"我只读不写"

`const` 表示通过这个指针**不能修改**它指向的内容。把 `src` 声明成 `const`，一是告诉调用者"放心，我不会改你的数据"，二是编译器会帮你检查：如果你不小心写了 `*s = 0`，直接编译报错。

转换类型时**要保留 `const`**：写成 `(const unsigned char*)src`，而不是 `(unsigned char*)src`（后者等于偷偷把承诺撕掉了）。

### 3. `size_t`：无符号的"大小"类型

`size_t` 是 `sizeof` 运算符的结果类型，专门表示"多少个字节"。它是**无符号**的（永远 ≥ 0），在 64 位系统上是 64 位。

无符号最大的坑是**倒着数**：

```c
for (size_t i = n - 1; i >= 0; i--)   // ❌ 死循环！i 是无符号，永远 >= 0；n = 0 时 n - 1 还会变成超大的数
```

本题用 `while (n--)` 就很安全：先判断 `n` 是否非 0，再减 1。`n = 0` 时一次都不进入循环。

> 本 OJ 的编译器（MinGW）打印 `size_t` 不能用 `%zu`，要转成 `(long long)` 再用 `%lld`。

### 4. `*d++ = *s++` 是什么意思？

后置 `++` 的优先级比 `*` 高，但"先用旧值再加"。所以这一句等价于：

```c
*d = *s;   // 把 s 指向的字节抄到 d 指向的位置
d = d + 1; // 两个指针都往后挪一个字节
s = s + 1;
```

## 💡 第三步：思路一 —— 逐字节复制（面试标准答案）

### 思路

1. 把 `void*` 转成 `unsigned char*`
2. 循环 `n` 次，每次复制 1 个字节，两个指针各前进 1
3. 返回**原始的** `dst`

### 手动模拟（示例 1：`src = [1,2,3,4,5]`，`n = 3`）

| 第几轮 | 进入时 n | `*d = *s` | 复制后 dst |
|---|---|---|---|
| 1 | 3 | dst[0] = 1 | [1,0,0,0,0] |
| 2 | 2 | dst[1] = 2 | [1,2,0,0,0] |
| 3 | 1 | dst[2] = 3 | [1,2,3,0,0] |
| — | 0 | 退出循环 | 返回 dst |

### 代码

```c
void* my_memcpy(void* dst, const void* src, size_t n) {
    // 1. void* 不能解引用，转成"按字节访问"的指针；src 只读，保留 const
    unsigned char* d = (unsigned char*)dst;
    const unsigned char* s = (const unsigned char*)src;

    // 2. 循环 n 次：先判断 n 是否为 0，再把 n 减 1
    while (n--) {
        *d++ = *s++;          // 复制一个字节，两个指针各前进 1 字节
    }

    // 3. 返回原始的 dst（d 已经走到末尾了，不能返回 d）
    return dst;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个字节复制一次。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 按字（4 字节）复制（进阶）

### 思路

32 位单片机一条指令就能搬 4 个字节，逐字节复制等于浪费了 3/4 的带宽。真正的库函数会**一次搬一个"字"**（word）。

但有一个大前提：**地址必须对齐**。很多 MCU（比如 Cortex-M0、早期 ARM）用 4 字节指令访问一个不是 4 的倍数的地址，会直接触发 **HardFault**（硬件异常，程序跑飞）。x86 和 Cortex-M3/M4 虽然允许非对齐访问，但也更慢。

所以做法是三段式：

1. **头部**：逐字节复制，直到 `d` 的地址是 4 的倍数
2. **中间**：如果此时 `s` 也恰好对齐，就按 `uint32_t` 每次搬 4 字节
3. **尾部**：剩下不足 4 字节的（或者 `s` 没对齐时的全部内容），逐字节复制

判断地址是否对齐：把指针转成整数 `uintptr_t`，看低 2 位是否为 0：`((uintptr_t)p & 3) == 0`。

### 代码

```c
void* my_memcpy(void* dst, const void* src, size_t n) {
    unsigned char* d = (unsigned char*)dst;
    const unsigned char* s = (const unsigned char*)src;

    // 1. 头部：逐字节复制，直到 d 对齐到 4 字节边界
    while (n > 0 && ((uintptr_t)d & 3) != 0) {
        *d++ = *s++;
        n--;
    }

    // 2. 中间：只有 s 也对齐时，才能安全地按 4 字节搬运
    if (((uintptr_t)s & 3) == 0) {
        uint32_t* dw = (uint32_t*)d;
        const uint32_t* sw = (const uint32_t*)s;
        while (n >= 4) {
            *dw++ = *sw++;        // 一次搬 4 个字节
            n -= 4;
        }
        d = (unsigned char*)dw;   // 把进度同步回字节指针
        s = (const unsigned char*)sw;
    }

    // 3. 尾部：剩下的逐字节复制
    while (n--) {
        *d++ = *s++;
    }
    return dst;
}
```

> 💬 真实的 `newlib` / `glibc` 实现还会处理"src 和 dst 对齐方式不同"的情况（读两个字再移位拼接），并且一次搬 16、32 字节。面试中能讲出"先对齐、再按字、最后收尾"就已经是加分项了。

### 复杂度分析

- **时间复杂度 O(n)**，但常数约为思路一的 1/4。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **直接对 `void*` 解引用或 `++`**：`*dst = *src;` 编译不过；`dst++` 在标准 C 中不合法。先转成 `unsigned char*`。
2. **返回了移动后的指针**：循环里写的是 `dst++`（GCC 扩展），最后 `return dst;` 返回的就是末尾地址，判题输出"返回值必须是 dst"。要么另用 `d`、`s` 两个指针，要么先保存 `void* ret = dst;`。
3. **用 `size_t` 倒序循环**：`for (size_t i = n - 1; i >= 0; i--)` 永远不会结束；`n = 0` 时 `n - 1` 还会变成 `18446744073709551615`，直接越界。
4. **把字节数当元素数**：调用时写 `memcpy(a, b, 10)` 想复制 10 个 `int`，实际只复制了 10 个字节（2.5 个 int）。应写 `10 * sizeof(int)`。
5. **转换时丢掉 `const`**：`unsigned char* s = (unsigned char*)src;` 能编译，但等于放弃了编译器的保护，之后误写 `*s = ...` 不会报错。
6. **对重叠内存用 memcpy**：比如想把数组整体右移一位 `memcpy(a + 1, a, n)`，从前往后复制会把 `a[0]` 一路"刷"满整个数组。C 标准规定重叠时 `memcpy` 的行为**未定义**，必须用 `memmove`（见 9032）。
7. **调用库函数 `memcpy` 交差**：判题能过，但面试官要看的就是你自己写的循环。

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐字节复制 | O(n) | O(1) | ⭐ | 面试时先写出这个，保证正确 |
| 按字复制 | O(n)，约快 4 倍 | O(1) | ⭐⭐⭐ | 作为"性能优化"的追问回答 |

> 🎯 **学习建议**：先把逐字节版本写到闭着眼都不会错，再理解"为什么要先对齐"——这个知识点在 9042（地址对齐）还会用到。
