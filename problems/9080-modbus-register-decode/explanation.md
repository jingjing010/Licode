# Modbus 大端寄存器解析：题解

## 📖 先读懂题目

输入已经通过帧与CRC检查的Modbus寄存器数据区，不含地址、功能码、字节数和CRC。长度为0到250的偶数；返回大端寄存器值数组。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[18,52,255,255]` | `[4660,65535]` |
| 2 | `[]` | `[]` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

每两个字节组成一个无符号16位寄存器，高字节先到，不能把字节缓冲区强转成uint16_t指针。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *decodeRegisters(const uint8_t *data, size_t len, int *returnSize) {
    int *out = malloc((len / 2 + 1) * sizeof(int));
    for (size_t i = 0; i < len / 2; ++i)
        out[i] = ((unsigned)data[2 * i] << 8) | data[2 * i + 1];
    *returnSize = (int)(len / 2);
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，输出空间 O(n) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
