# 9023. 十六进制字符串转字节数组 —— 小白详细题解

> 串口命令、配置文件、上位机工具……"文本形式的十六进制"无处不在。这道题练的是**字符与数值的换算**和**输入合法性检查**——嵌入式代码面对外部输入时，"先校验、再使用"是铁律。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 字符串两个字符一组，每组看成一个两位十六进制数，转成一个字节；有任何不对劲（长度为奇数、出现非法字符）就返回 -1。

拿示例 1 `"1234abCD"` 来说：

| 组 | 字符 | 高 4 位 | 低 4 位 | 字节 | 十进制 |
|---|---|---|---|---|---|
| 0 | `'1' '2'` | 1 | 2 | `0x12` | 18 |
| 1 | `'3' '4'` | 3 | 4 | `0x34` | 52 |
| 2 | `'a' 'b'` | 10 | 11 | `0xAB` | 171 |
| 3 | `'C' 'D'` | 12 | 13 | `0xCD` | 205 |

返回 4，`out = [18,52,171,205]`。

**几个需要注意的细节：**

1. **大小写都要支持**：`'a'` 和 `'A'` 都是 10。
2. **长度为奇数**（如 `"123"`）：最后一个字符凑不成一个字节，返回 -1。
3. **非法字符**：空格、`'x'`、`'G'`、`'+'` 等都不行，`"0x12"` 也算非法。
4. **空字符串**返回 0，不是 -1。

---

## 🧰 第二步：需要的 C 语言知识

### 1. 字符其实是数字（ASCII 码）

| 字符 | `'0'` | `'9'` | `'A'` | `'F'` | `'a'` | `'f'` |
|---|---|---|---|---|---|---|
| ASCII 码 | 48 | 57 | 65 | 70 | 97 | 102 |

数字字符、大写字母、小写字母在 ASCII 表里各自**连续排列**，所以：

```c
'7' - '0'        // = 55 - 48 = 7
'c' - 'a' + 10   // = 99 - 97 + 10 = 12
'C' - 'A' + 10   // = 67 - 65 + 10 = 12
```

注意 `'9'`(57) 和 `'A'`(65) 之间**不连续**，中间还隔着 `:;<=>?@`，所以不能简单写 `c - '0'` 处理所有字符。

### 2. 字符串以 `'\0'` 结尾

`const char* hex` 只是一个地址，字符串到哪里结束由 `'\0'` 决定。`strlen(hex)` 就是从头数到 `'\0'` 之前有多少个字符。

### 3. 用返回值报告错误

C 语言没有异常，嵌入式代码习惯用**返回负数表示失败**。调用者必须检查：

```c
int n = hex_to_bytes(cmd_arg, key);
if (n != 16) {          // 不是 16 字节的 AES-128 密钥
    uart_puts("ERROR\r\n");
    return;
}
```

## 💡 第三步：思路一 —— 先整体校验，再转换

### 思路

1. 求出长度 `len`，若为奇数返回 -1
2. 第一遍扫描：每个字符都必须是十六进制字符，否则返回 -1
3. 第二遍：两两转换写入 `out`

先校验再转换的好处是：**只要返回 -1，`out` 一定没被写过**，对调用者更友好。

### 手动模拟（示例 3：`"12G4"`）

| 步骤 | 检查 | 结果 |
|---|---|---|
| 长度 | 4 是偶数 | 继续 |
| 扫描 `'1'` | 合法 | 继续 |
| 扫描 `'2'` | 合法 | 继续 |
| 扫描 `'G'` | 不在 0-9/a-f/A-F 中 | 返回 -1 ✅ |

### 代码

```c
// 判断 c 是不是十六进制字符
static int is_hex(char c) {
    return (c >= '0' && c <= '9') || (c >= 'a' && c <= 'f') || (c >= 'A' && c <= 'F');
}

// 把一个（已确认合法的）十六进制字符转成 0~15
static uint8_t hex_digit(char c) {
    if (c <= '9') return (uint8_t)(c - '0');
    if (c <= 'F') return (uint8_t)(c - 'A' + 10);
    return (uint8_t)(c - 'a' + 10);
}

int hex_to_bytes(const char* hex, uint8_t* out) {
    int len = (int)strlen(hex);
    if (len % 2 != 0) return -1;              // 奇数个字符，凑不成整字节

    for (int i = 0; i < len; i++) {           // 第一遍：全部校验
        if (!is_hex(hex[i])) return -1;
    }

    for (int i = 0; i < len / 2; i++) {       // 第二遍：两两转换
        uint8_t hi = hex_digit(hex[2 * i]);       // 高 4 位
        uint8_t lo = hex_digit(hex[2 * i + 1]);   // 低 4 位
        out[i] = (uint8_t)((hi << 4) | lo);
    }
    return len / 2;
}
```

### 复杂度分析

- **时间复杂度 O(n)**（扫描两遍），**空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 一遍扫描，转换函数顺便报错

### 思路

让字符转换函数在遇到非法字符时**返回 -1**，这样校验和转换合并成一遍。代码更短，也是项目里最常见的写法。代价是：遇到非法字符时，前面的字节可能已经写进 `out`（本题允许）。

### 手动模拟（示例 2：`"00ff0A"`）

| i | 字符对 | hi | lo | `out[i/2]` |
|---|---|---|---|---|
| 0 | `'0' '0'` | 0 | 0 | 0 |
| 2 | `'f' 'f'` | 15 | 15 | 255 |
| 4 | `'0' 'A'` | 0 | 10 | 10 |

返回 `6 / 2 = 3` ✅

### 代码

```c
// 十六进制字符 -> 0~15；非法字符返回 -1
static int hex_val(char c) {
    if (c >= '0' && c <= '9') return c - '0';
    if (c >= 'a' && c <= 'f') return c - 'a' + 10;
    if (c >= 'A' && c <= 'F') return c - 'A' + 10;
    return -1;
}

int hex_to_bytes(const char* hex, uint8_t* out) {
    int len = (int)strlen(hex);
    if (len % 2 != 0) return -1;

    for (int i = 0; i < len; i += 2) {        // 每次处理 2 个字符
        int hi = hex_val(hex[i]);
        int lo = hex_val(hex[i + 1]);
        if (hi < 0 || lo < 0) return -1;      // 任意一个非法就失败
        out[i / 2] = (uint8_t)((hi << 4) | lo);
    }
    return len / 2;
}
```

> 💬 `hex_val` 的返回类型是 `int` 而不是 `uint8_t`，因为它需要表示 -1 这个"错误值"；`uint8_t` 存不了负数，`-1` 会变成 255。

## 🔌 嵌入式实战

AT 指令设置 LoRa 模块密钥：

```c
// 收到 "AT+KEY=00112233445566778899AABBCCDDEEFF"
uint8_t key[16];
const char* arg = line + 7;                   // 跳过 "AT+KEY=" ...
if (strlen(arg) != 32 || hex_to_bytes(arg, key) != 16) {
    uart_puts("ERROR\r\n");
} else {
    flash_save_key(key);
    uart_puts("OK\r\n");
}
```

注意先检查长度：`out` 只有 16 字节，如果对方发来 100 个字符而你不检查，就会**缓冲区溢出**——这是嵌入式设备最常见的安全漏洞之一。

## ⚠️ 第五步：小白常见错误

1. **只处理了大写或只处理了小写**：`"ab"` 和 `"AB"` 必须得到相同结果。
2. **用 `c - '0'` 处理字母**：`'A' - '0' = 17`，不是 10。
3. **忘了检查奇数长度**：`"123"` 时读 `hex[3]` 读到的是 `'\0'`，如果你的转换函数没把 `'\0'` 当非法字符，就会输出错误结果。
4. **高低位顺序反了**：`(lo << 4) | hi`，`"12"` 变成 `0x21`。
5. **用 `uint8_t` 接收 `hex_val` 的返回值**：`-1` 变成 255，`if (hi < 0)` 永远不成立，非法字符被当成合法的。
6. **空字符串返回 -1**：空串长度 0 是偶数、没有非法字符，应返回 0。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| 先校验再转换 | O(n)（两遍） | O(1) | 失败时 `out` 不被修改 |
| 一遍扫描 | O(n)（一遍） | O(1) | 代码短，项目常用 |
| `sscanf("%2hhx")` | O(n) | O(1) | 本题禁止；单片机上体积大、速度慢 |
