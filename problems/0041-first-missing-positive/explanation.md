# 41. 缺失的第一个正数 —— 小白详细题解

> 这道"困难"题的代码其实很短，难点在于想到一个关键观察：**答案一定在 1 ~ n+1 之间**。想通这一点，再学会"让每个数回家"的原地交换技巧，就能拿下。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 从 1 开始数 1, 2, 3, 4, ……，第一个**不在数组里**的数是几？

| 示例 | 数组 | 1 在吗 | 2 在吗 | 3 在吗 | 答案 |
|---|---|---|---|---|---|
| 1 | [1,2,0] | ✅ | ✅ | ❌ | **3** |
| 2 | [3,4,-1,1] | ✅ | ❌ | | **2** |
| 3 | [7,8,9,11,12] | ❌ | | | **1** |

**几个需要注意的细节：**

1. 0 和负数**不是正整数**，可以直接忽略。
2. 数组可能有**重复**元素，比如 `[1,1]`，答案是 2。
3. 数值范围是整个 `int`，可能有 `-2147483648`、`2147483647` 这种极端值，**不能**直接拿它们当数组下标。
4. 题目要求 **O(n) 时间 + O(1) 额外空间**，这才是"困难"的地方。

### ⭐ 关键观察：答案一定在 `1 ~ n+1` 之间

数组只有 n 个数。要让答案是 n+2，就必须 `1, 2, ..., n+1` 全都出现，一共 n+1 个不同的数——可数组只装得下 n 个，不可能。

所以：**只有 `1 ~ n` 范围内的数对答案有用**，其他的（负数、0、大于 n 的数）都可以无视。如果 `1 ~ n` 全都出现了，答案就是 `n+1`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `calloc`：申请并清零

```c
char* seen = (char*)calloc(n + 2, sizeof(char));   // n+2 个格子，全部初始化为 0
```

`calloc(个数, 每个的大小)` 和 `malloc` 的区别是它会把内存**清零**。用 `malloc` 的话里面是随机垃圾值，还得自己 `memset`。

### 2. 用值当下标前，一定要先检查范围

```c
if (x >= 1 && x <= n) seen[x] = 1;   // ✅ 先判断范围
seen[x] = 1;                          // ❌ x 可能是 -5 或 2147483647，直接越界崩溃
```

C 语言**不会**帮你检查数组越界，越界访问可能静悄悄地写坏别的数据，也可能直接崩溃。

### 3. 交换两个元素

```c
int t = nums[j];
nums[j] = nums[i];
nums[i] = t;
```

## 💡 第三步：思路一 —— 标记数组（O(n) 时间，O(n) 空间）

### 思路

根据关键观察，开一个长度 `n + 2` 的标记数组 `seen`：

1. 遍历 `nums`，遇到 `1 ~ n` 范围内的数 `x`，就标记 `seen[x] = 1`。
2. 从 1 开始找第一个 `seen[x] == 0` 的 `x`，就是答案。最多找到 `n+1`（`seen[n+1]` 永远是 0，自动兜底）。

### 手动模拟（示例 2：`nums = [3,4,-1,1]`，n = 4）

| nums[i] | 在 1~4 范围内？ | seen（下标 1~5） |
|---|---|---|
| 3 | ✅ | 0 0 1 0 0 |
| 4 | ✅ | 0 0 1 1 0 |
| -1 | ❌ 跳过 | 0 0 1 1 0 |
| 1 | ✅ | 1 0 1 1 0 |

从 1 开始找：`seen[1] = 1`，`seen[2] = 0` → 答案 **2**。

### 代码

```c
int firstMissingPositive(int* nums, int numsSize) {
    int n = numsSize;
    // 1. 标记数组：seen[x] = 1 表示 x 出现过；多开到 n+1 作为兜底
    char* seen = (char*)calloc(n + 2, sizeof(char));

    // 2. 只标记 1~n 范围内的数，其余的对答案没有影响
    for (int i = 0; i < n; i++) {
        if (nums[i] >= 1 && nums[i] <= n) {
            seen[nums[i]] = 1;
        }
    }

    // 3. 从 1 开始找第一个没出现的数（seen[n+1] 一定是 0，所以循环一定会停）
    int ans = 1;
    while (seen[ans]) ans++;

    free(seen);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：两次遍历。
- **空间复杂度 O(n)**：标记数组。不满足进阶要求，但这是理解本题的最好起点。

> 💬 还有一种更容易想到的方法：先排序，再从小到大扫一遍。时间 O(n log n)，同样能过，但不满足 O(n) 的要求。

## 🚀 第四步：思路二 —— 原地置换："让每个数回家"（O(1) 空间）

### 思路

思路一的 `seen` 数组只是用来记录"`x` 有没有出现"。能不能**借用 `nums` 自己**来记录？

规定：**数字 `x` 的"家"是下标 `x - 1`**。也就是 1 应该住在 `nums[0]`，2 住在 `nums[1]`……

1. 遍历每个位置 `i`，只要 `nums[i]` 是 `1 ~ n` 之间的数，并且它的家里住的**不是它自己**，就把它和家里的数**交换**，送它回家。被换出来的那个数又落到了位置 `i`，继续用 while 循环处理它。
2. 全部归位后，从左往右找第一个"住错人"的位置 `i`（`nums[i] != i + 1`），答案就是 `i + 1`；都住对了答案就是 `n + 1`。

> ❓ **为什么条件是 `nums[nums[i] - 1] != nums[i]`，而不是 `nums[i] != i + 1`？**
> 如果有重复，比如 `[1,1]`：处理 `i = 1` 时 `nums[1] = 1`，它的家 `nums[0]` 里已经住着 1 了。用 `nums[i] != i + 1` 判断会一直交换两个 1，**死循环**！而判断"家里是不是已经是它"就不会。

### 手动模拟（示例 2：`nums = [3,4,-1,1]`，n = 4）

| 步骤 | i | nums[i] | 家（下标） | 操作 | 数组 |
|---|---|---|---|---|---|
| 0 | | | | 初始 | [3, 4, -1, 1] |
| 1 | 0 | 3 | 2 | 和 nums[2] 交换 | [-1, 4, 3, 1] |
| 2 | 0 | -1 | — | 不在范围，看下一个 | [-1, 4, 3, 1] |
| 3 | 1 | 4 | 3 | 和 nums[3] 交换 | [-1, 1, 3, 4] |
| 4 | 1 | 1 | 0 | 和 nums[0] 交换 | [1, -1, 3, 4] |
| 5 | 1 | -1 | — | 不在范围，看下一个 | [1, -1, 3, 4] |
| 6 | 2 | 3 | 2 | 已经在家 | [1, -1, 3, 4] |
| 7 | 3 | 4 | 3 | 已经在家 | [1, -1, 3, 4] |

最后扫描：`nums[0] = 1` ✅，`nums[1] = -1 ≠ 2` → 答案 **2**。

### 代码

```c
int firstMissingPositive(int* nums, int numsSize) {
    int n = numsSize;

    // 1. 让每个 1~n 的数回到自己的"家"：数字 x 住在下标 x-1
    for (int i = 0; i < n; i++) {
        // 用 while：换过来的新数也可能需要回家
        // 先判断范围（否则 nums[i]-1 越界），再判断家里是不是已经是它（防止重复数字死循环）
        while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
            int j = nums[i] - 1;      // nums[i] 的家
            int t = nums[j];
            nums[j] = nums[i];        // 送它回家
            nums[i] = t;              // 把家里原来的数换过来，下一轮继续处理
        }
    }

    // 2. 找第一个住错人的位置
    for (int i = 0; i < n; i++) {
        if (nums[i] != i + 1) return i + 1;
    }

    // 3. 1~n 全部在家，答案是 n+1
    return n + 1;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：虽然 for 里套了 while，但**每次交换都会让一个数回到家**，回家后就再也不会被移动。总共最多 n 次交换，所以整体是 O(n)。
- **空间复杂度 O(1)**：只用了几个变量。

---

## ⚠️ 第五步：小白常见错误

1. **while 条件写成 `nums[i] != i + 1`** → 遇到重复数字（如 `[1,1]`）会无限交换，超时。
2. **while 里先写 `nums[nums[i] - 1]` 再判断范围** → 条件判断是从左到右的，`nums[i] = -5` 时会先访问 `nums[-6]`，越界。一定要把 `nums[i] >= 1 && nums[i] <= n` 写在**最前面**（利用 `&&` 的短路特性）。
3. **用 `if` 代替 `while`** → 换过来的数没有被处理。例如 `[3,4,-1,1]` 中 `i = 1` 时换回来的 1 就没有回家，最后会错答 1。
4. **交换时先改了 `nums[i]`，再用 `nums[nums[i] - 1]`** → 下标已经变了，换错位置。先用 `j = nums[i] - 1` 把下标存起来最稳。
5. **忘记 `n + 1` 的情况** → `[1,2,3]` 这种全部归位的数组要返回 4，不能返回 0 或 -1。
6. **想开 `seen[2147483648]` 这么大的标记数组** → 内存爆炸。根据"答案在 1~n+1"，开 `n + 2` 个就够。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 排序后扫描 | O(n log n) | O(log n) | ⭐ | 最容易想到，不满足题目要求 |
| 标记数组 | O(n) | O(n) | ⭐⭐ | 先理解"答案在 1~n+1" |
| 原地置换 | O(n) | O(1) | ⭐⭐⭐ | 满足进阶要求的标准答案 |
