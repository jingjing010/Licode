# 441. 排列硬币 —— 小白详细题解

> 这道题能用三种方法做：一行一行地摆、二分查找、数学公式。它是练习"**找最后一个满足条件的值**"二分模板的好题，同时还藏着一个溢出陷阱。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 第 1 行放 1 枚，第 2 行放 2 枚，第 3 行放 3 枚……一直放到硬币不够为止。问**能放满几行**？

拿示例 2 `n = 8` 来说：

| 行号 i | 这行需要 | 放完后累计用掉 | 还够吗？ |
|---|---|---|---|
| 1 | 1 | 1 | ✅ |
| 2 | 2 | 3 | ✅ |
| 3 | 3 | 6 | ✅ |
| 4 | 4 | 10 | ❌ 只剩 2 枚 |

能放满 3 行，答案 3。

换成数学语言：前 k 行一共需要 `1 + 2 + ... + k = k(k+1)/2` 枚，要找**最大的 k** 使得 `k(k+1)/2 <= n`。

**几个需要注意的细节：**

1. 最后一行不完整就不算。
2. `n` 最大是 `2^31 - 1`，答案最大约 65535。
3. 计算 `k * (k + 1)` 时，如果 k 用 `int` 而且 k 很大（二分时 k 可能取到 10 亿级别），乘法会溢出。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 乘法溢出与 `long long`

```c
int k = 100000;
int bad = k * (k + 1) / 2;              // ❌ k*(k+1) = 10000100000 > INT_MAX，溢出
long long ok = (long long)k * (k + 1) / 2;   // ✅ 先转成 long long 再乘
```

注意：`(long long)(k * (k + 1))` 是**错的**——括号里已经用 int 乘完、溢出了，再转换也救不回来。必须让**参与乘法的某一个数**先变成 `long long`。

### 2. `sqrt` 函数

`sqrt` 在 `<math.h>` 里（本 OJ 已自动包含），参数和返回值都是 `double`。把 `double` 转成 `int` 会**直接截掉小数部分**（向零取整）。

---

## 💡 第三步：思路一 —— 一行一行地摆（模拟）

### 思路

用一个变量 `row` 表示下一行要放几枚，只要剩下的硬币 `>= row`，就放这一行。

### 手动模拟（`n = 5`）

| row | 剩余 n | 够吗？ | 放完后剩余 |
|---|---|---|---|
| 1 | 5 | ✅ | 4 |
| 2 | 4 | ✅ | 2 |
| 3 | 2 | ❌ 停止 | |

放满了 2 行。

### 代码

```c
int arrangeCoins(int n) {
    int row = 1;                 // 下一行需要的硬币数
    int done = 0;                // 已经放满的行数
    while (n >= row) {           // 剩下的硬币够放这一行
        n -= row;                // 放上去
        done++;
        row++;
    }
    return done;
}
```

### 复杂度分析

- **时间复杂度 O(√n)**：行数 k 满足 `k² / 2 ≈ n`，所以最多约 65535 轮，很快。
- **空间复杂度 O(1)**。
- 这里用减法而不是累加，所以不会溢出。

---

## 🚀 第四步：思路二 —— 二分查找（找最后一个满足条件的 k）

### 思路

`f(k) = k(k+1)/2` 随 k 增大而增大。所有 k 分成两部分：

```
k:       1    2    3  |  4    5    6 ...
f(k)<=8: 是   是   是  |  否   否   否
```

要找的是"**最后一个是**"。这和"找第一个满足条件"的模板方向相反。

### 区间定义、循环条件与 mid 的取法

- 区间：**闭区间 `[lo, hi]`**，答案一定在里面。初始 `lo = 1`（n ≥ 1，至少放满 1 行），`hi = n`。
- `while (lo < hi)`，最后 `lo == hi` 就是答案。
- `f(mid) <= n`：mid 可行，答案 >= mid，**保留 mid**：`lo = mid`。
- 否则：mid 不可行，`hi = mid - 1`。
- ⭐ **mid 必须向上取整**：`mid = lo + (hi - lo + 1) / 2`。

为什么要向上取整？假设 `lo = 3, hi = 4`，如果用向下取整，`mid = 3`；若 3 可行，执行 `lo = mid = 3`，区间没变，**死循环**！向上取整得 `mid = 4`，不管哪个分支区间都会缩小。

> 口诀：**`lo = mid` 配向上取整，`hi = mid` 配向下取整。**

另外 `lo`、`hi`、`mid` 全部用 `long long`，因为 mid 可能高达 10 亿，`mid * (mid + 1)` 会溢出 int；`lo + hi` 也会溢出 int。

### 手动模拟（`n = 8`）

| 轮次 | lo | hi | mid（向上取整） | mid(mid+1)/2 | <= 8 ? | 操作 |
|---|---|---|---|---|---|---|
| 1 | 1 | 8 | 5 | 15 | 否 | hi = 4 |
| 2 | 1 | 4 | 3 | 6 | 是 | lo = 3 |
| 3 | 3 | 4 | 4 | 10 | 否 | hi = 3 |
| 结束 | 3 | 3 | | | | 返回 3 ✅ |

### 代码

```c
int arrangeCoins(int n) {
    long long lo = 1, hi = n;    // 答案在闭区间 [lo, hi]；用 long long 防止乘法溢出
    while (lo < hi) {
        long long mid = lo + (hi - lo + 1) / 2;   // 向上取整，避免 lo = mid 死循环
        if (mid * (mid + 1) / 2 <= n) {
            lo = mid;            // mid 行可以放满，答案 >= mid
        } else {
            hi = mid - 1;        // mid 行放不满，答案 < mid
        }
    }
    return (int)lo;
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：约 31 轮。
- **空间复杂度 O(1)**。

## 🧮 补充：思路三 —— 一元二次方程求根公式

解不等式 `k² + k - 2n <= 0`，正根是 `k = (√(8n+1) - 1) / 2`，答案就是它向下取整。

```c
int arrangeCoins(int n) {
    // 8.0 让整个表达式按 double 计算，避免 8 * n 在 int 里溢出
    return (int)((sqrt(8.0 * n + 1) - 1) / 2);
}
```

这个写法 O(1)，但依赖浮点数精度。本题 n ≤ 2^31-1，`double` 有约 15~16 位有效数字，足够精确；如果数据更大，浮点误差可能让结果差 1，所以**面试时二分写法更稳妥**。

---

## ⚠️ 第五步：小白常见错误

1. **用 `int` 算 `mid * (mid + 1)`** → 二分初期 mid 约 10 亿，乘法溢出成负数，`<= n` 判断错乱。
2. **`lo = mid` 却用向下取整的 mid** → `lo + 1 == hi` 时死循环，超时。
3. **写成 `(long long)(mid * (mid + 1))`** → 括号里已经用 int 溢出了，转换太晚。
4. **公式法写成 `sqrt(8 * n + 1)`** → `8 * n` 在 int 中先溢出，必须写 `8.0 * n` 或 `8LL * n`。
5. **模拟法用累加 `sum += row` 并判断 `sum <= n`** → `sum` 用 int 时，最后一次累加可能超过 `INT_MAX`。用减法或 `long long`。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐行模拟 | O(√n) | O(1) | ⭐ | 最直观 |
| 二分查找 | O(log n) | O(1) | ⭐⭐ | 练习"找最后一个满足条件"模板 |
| 求根公式 | O(1) | O(1) | ⭐⭐ | 最快，但要注意浮点精度 |
