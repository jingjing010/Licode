# 946. 验证栈序列 —— 小白详细题解

> 数据结构课的经典题："给定入栈顺序，问某个出栈顺序是否可能"。最好的办法就是**真的拿一个栈来试**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有一个空栈。你必须按 `pushed` 的顺序把数一个个压进去，但**任何时候**都可以选择弹出栈顶。问：能不能让弹出的顺序正好是 `popped`？

示例 1 `pushed = [1,2,3,4,5]`，`popped = [4,5,3,2,1]`：

| 步骤 | 操作 | 栈（底→顶） | 已弹出 |
|---|---|---|---|
| 1 | push 1 | 1 | |
| 2 | push 2 | 1 2 | |
| 3 | push 3 | 1 2 3 | |
| 4 | push 4 | 1 2 3 4 | |
| 5 | pop | 1 2 3 | 4 |
| 6 | push 5 | 1 2 3 5 | 4 |
| 7 | pop ×4 | 空 | 4 5 3 2 1 ✅ |

示例 2 `popped = [4,3,5,1,2]`：弹出 4、3、5 之后栈里是 `1 2`，栈顶是 2，想先弹 1 是不可能的 → `false`。

**几个需要注意的细节：**

1. 元素**互不相同**，所以"栈顶等于下一个要弹的数"的判断不会混淆。
2. `popped` 一定是 `pushed` 的排列，不用担心出现没压过的数。
3. 压入的顺序是固定的，只有"什么时候弹"可以选择。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `bool` 类型

```c
bool ok = true;      // 需要 <stdbool.h>，本 OJ 已自动包含
return j == poppedSize;   // 比较表达式本身就是 true/false，可以直接返回
```

### 2. 用数组模拟栈

```c
int* st = (int*)malloc(sizeof(int) * pushedSize);   // 栈最多同时放 pushedSize 个数
int top = 0;
st[top++] = x;       // push
st[top - 1]          // 看栈顶
top--;               // pop
```

### 3. `while` 中条件的顺序（短路求值）

```c
while (top > 0 && st[top - 1] == popped[j])
```

`&&` 左边为假时，右边**不会被执行**。所以必须先判断 `top > 0`，再访问 `st[top - 1]`，否则栈空时会访问 `st[-1]`。

---

## 💡 第三步：思路 —— 贪心模拟（能弹就弹）

### 思路

用指针 `j` 指向 `popped` 中**下一个应该弹出**的数。

1. 按顺序把 `pushed[i]` 压入栈。
2. 每压一个，就检查：栈顶是不是 `popped[j]`？是就弹出、`j++`，并继续检查新栈顶。
3. 全部压完后，如果 `j == n`（所有数都按顺序弹出了），返回 `true`。

### ❓ 为什么"能弹就弹"一定对？

如果栈顶正好是下一个要弹出的数 x，却不弹它，那么之后再压入任何数，x 都会被压在下面——想弹 x 就得先把上面的弹掉，但上面的数应该在 x **之后**才弹。所以此时**必须**弹出 x，不存在别的选择。

### 手动模拟（示例 2：`popped = [4,3,5,1,2]`）

| i | push | 连续弹出 | 栈（底→顶） | j（下一个要弹 popped[j]） |
|---|---|---|---|---|
| 0 | 1 | | 1 | 0（等 4） |
| 1 | 2 | | 1 2 | 0（等 4） |
| 2 | 3 | | 1 2 3 | 0（等 4） |
| 3 | 4 | 弹 4，弹 3 | 1 2 | 2（等 5） |
| 4 | 5 | 弹 5 | 1 2 | 3（等 1） |

压完了，栈顶是 2 ≠ 1，`j = 3 ≠ 5` → `false` ✅

### 代码

```c
bool validateStackSequences(int* pushed, int pushedSize, int* popped, int poppedSize) {
    int* st = (int*)malloc(sizeof(int) * pushedSize);   // 模拟用的栈
    int top = 0;
    int j = 0;                          // popped 中下一个应该弹出的位置

    for (int i = 0; i < pushedSize; i++) {
        st[top++] = pushed[i];          // 按顺序压入
        // 栈顶正好是下一个要弹的数：必须马上弹（可能连续弹好几个）
        while (top > 0 && j < poppedSize && st[top - 1] == popped[j]) {
            top--;
            j++;
        }
    }
    free(st);
    return j == poppedSize;             // 全部按顺序弹出了才合法
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个数入栈一次、出栈最多一次。
- **空间复杂度 O(n)**：栈。

## 🚀 第四步：优化 —— 复用 pushed 数组当栈（O(1) 额外空间）

`pushed[i]` 被压进栈之后就再也不会被读到了，所以可以直接把 `pushed` 的前 `top` 个位置当作栈用：

```c
bool validateStackSequences(int* pushed, int pushedSize, int* popped, int poppedSize) {
    int top = 0, j = 0;                 // pushed[0 .. top-1] 就是栈
    for (int i = 0; i < pushedSize; i++) {
        pushed[top++] = pushed[i];      // top <= i，写入的位置已经读过了，不会覆盖没读的数据
        while (top > 0 && pushed[top - 1] == popped[j]) {
            top--;
            j++;
        }
    }
    return top == 0;                    // 栈空 等价于 全部弹出
}
```

这里 `j < poppedSize` 可以省略：栈里还有元素时，`popped` 一定还有没匹配的数。

> 💬 这种写法会**修改输入数组**。面试中如果用，最好先说明一下。

---

## ⚠️ 第五步：小白常见错误

1. **用 `if` 代替 `while`** → 每次 push 后只弹一个，示例 1 中压入 5 后需要连续弹出 5、3、2、1，用 `if` 就只弹了 5，返回 `false`。
2. **`while` 条件里先访问 `st[top - 1]` 再判断 `top > 0`** → 栈空时越界访问。
3. **最后判断 `top == pushedSize`** 之类写错 → 正确是栈空（`top == 0`）或者 `j == n`。
4. **把 `popped` 当作要压入的序列** → 题目是按 `pushed` 压、核对 `popped`，搞反了结果完全不同。
5. **栈开得太小**（比如固定 `int st[100]`）→ n 最大 1000，会越界。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 额外空间 | 难度 | 说明 |
|---|---|---|---|---|
| 额外开一个栈模拟 | O(n) | O(n) | ⭐⭐ | 推荐 |
| 复用 pushed 当栈 | O(n) | O(1) | ⭐⭐ | 会修改输入 |
