# 9010. 交换高低半字节 —— 小白详细题解

> 题目本身一行就能写完，但它藏着 C 语言里最容易被忽视的一条规则：**整型提升**——`uint8_t` 一参与运算就会先变成 `int`。搞懂这一点，以后处理 8 位、16 位数据时就不会莫名其妙出错。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一个字节写成两位十六进制数，比如 `0xAB`，把这两位**左右对调**，变成 `0xBA`。

用二进制看示例 2（`x = 171 = 0xAB`）：

| | 高 4 位 | 低 4 位 |
|---|---|---|
| x = 0xAB | `1010`（A） | `1011`（B） |
| 结果 0xBA | `1011`（B） | `1010`（A） |

结果 `0xBA = 186`。

**几个需要注意的细节：**

1. 一个十六进制位正好是 4 位（一个半字节），所以用十六进制看这道题最直观。
2. 输入输出都是**十进制**，`18` 就是 `0x12`，答案 `0x21` 要打印成 `33`。
3. 结果必须还是一个字节（0~255），不能多出第 8 位以上的东西。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 取出高、低半字节

| 表达式 | 作用 | x = 0xAB 时 |
|---|---|---|
| `x & 0x0F` | 低 4 位 | `0x0B` |
| `x >> 4` | 高 4 位（移到低处） | `0x0A` |
| `(x & 0x0F) << 4` | 低 4 位移到高处 | `0xB0` |

### 2. ⭐ 整型提升（integer promotion）

C 语言规定：**比 `int` 窄的类型（`uint8_t`、`uint16_t`、`char`……）参与算术或位运算前，会先被转换成 `int`**。所以：

```
x       = 0xAB          (uint8_t)
x << 4  = 0x00000AB0    (int！高位的 A 没有被丢掉，而是跑到了第 8~11 位)
```

`x << 4` 并不会自动"溢出丢弃"，它是一个 12 位的 `int`。如果直接和别的东西比较或继续运算，那个多出来的 `A` 会捣乱。解决办法：

- 先 `& 0x0F` 再左移，或者
- 最后强制转换回 `(uint8_t)`，截掉第 8 位以上的部分。

本题函数返回类型是 `uint8_t`，`return` 时会自动截断，所以就算忘了也能"碰巧"对；但把同样的表达式写在 `if` 里比较时就会出错（见常见错误）。

### 3. 十进制和 BCD

BCD（Binary-Coded Decimal）用 4 位表示一个十进制数字 0~9。RTC 里 59 秒存成 `0x59`，而不是二进制的 `59 = 0x3B`。转换：

- BCD → 十进制：`(b >> 4) * 10 + (b & 0x0F)`
- 十进制 → BCD：`((d / 10) << 4) | (d % 10)`

## 💡 第三步：思路一 —— 用除法和取模（最朴素）

### 思路

一个字节 = 高半字节 × 16 + 低半字节，所以：

- 高半字节 `hi = x / 16`，低半字节 `lo = x % 16`；
- 交换后 = `lo × 16 + hi`。

### 手动模拟（示例 1：`x = 18`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| hi | 18 / 16 | 1 |
| lo | 18 % 16 | 2 |
| 交换 | 2 × 16 + 1 | **33** |

### 代码

```c
uint8_t swap_nibbles(uint8_t x) {
    uint8_t hi = x / 16;          // 高 4 位（十六进制的"十位"）
    uint8_t lo = x % 16;          // 低 4 位（十六进制的"个位"）
    return (uint8_t)(lo * 16 + hi);   // 对调后重新组合，lo * 16 <= 240，不会超过 255
}
```

### 复杂度分析

- **时间复杂度 O(1)**。编译器会把除以 16、模 16 优化成移位和按位与，但写成位运算更能体现意图。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 移位 + 按位或（标准答案）

### 思路

低 4 位左移 4 位到高处，高 4 位右移 4 位到低处，再拼起来：

```
x               = 1010 1011   (0xAB)
(x & 0x0F) << 4 = 1011 0000   (0xB0)
x >> 4          = 0000 1010   (0x0A)
相或             = 1011 1010   (0xBA = 186)
```

### 代码

```c
uint8_t swap_nibbles(uint8_t x) {
    uint8_t lo_to_hi = (uint8_t)((x & 0x0Fu) << 4);   // 低 4 位搬到高 4 位
    uint8_t hi_to_lo = (uint8_t)(x >> 4);             // 高 4 位搬到低 4 位
    return (uint8_t)(lo_to_hi | hi_to_lo);
}
```

也可以写成一行：`return (uint8_t)((x << 4) | (x >> 4));`——`x << 4` 多出来的高位由最外面的 `(uint8_t)` 截掉。

### 复杂度分析

- **时间复杂度 O(1)**：两次移位、一次与、一次或。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **以为 `uint8_t` 左移会自动丢掉高位**：
   ```c
   if (((x << 4) | (x >> 4)) == 0xBA) { }   // ❌ x = 0xAB 时左边是 0xABA，永远不等于 0xBA
   ```
   整型提升后结果是 `int`，必须截断：`(uint8_t)((x << 4) | (x >> 4)) == 0xBA`。
2. **用 `+` 代替 `|` 时没截断**：`(x << 4) + (x >> 4)` 对 `0xAB` 得到 `0xABA`，再做别的运算就错了。
3. **移位位数写成 8**：一个字节的一半是 **4 位**，不是 8 位。`x << 8` 对 `uint8_t` 来说相当于把整个字节挪走了。
4. **把半字节交换和位反转搞混**：`0x12` 的半字节交换是 `0x21`，位反转（9007 的 8 位版本）是 `0x48`。
5. **把 BCD 当二进制用**：RTC 读出来 `0x59` 直接当 59 用是错的（`0x59 = 89`），要先做 BCD 转换。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 除法 + 取模 | O(1) | O(1) | ⭐ | 帮助理解"高位 × 16 + 低位" |
| 移位 + 按位或 | O(1) | O(1) | ⭐ | 标准写法，注意整型提升 |

## 🔌 嵌入式实战

- **8051 有专门的指令**：`SWAP A` 一条指令完成累加器的半字节交换，可见这个操作在早期单片机里有多常用。AVR 也有 `SWAP` 指令。
- **HEX 显示**：把一个字节显示到两个数码管 / 串口打印成两个十六进制字符，需要分别取出高低半字节，再查表 `"0123456789ABCDEF"[nibble]`。
- **BCD 时间读写**（示意）：

```c
uint8_t raw = rtc_read_reg(0x00);                         /* 读秒寄存器，例如 0x59 */
uint8_t sec = (uint8_t)((raw >> 4) * 10 + (raw & 0x0F));  /* BCD -> 59 */
```
