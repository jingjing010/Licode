# 80. 删除有序数组中的重复项 II —— 小白详细题解

> 这是 26 题的升级版：从"每个数只留 1 个"变成"每个数最多留 2 个"。核心还是**快慢双指针**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 给你一排**从小到大排好**的数字。如果某个数出现了 3 次或更多，只保留**前 2 个**；出现 1 次或 2 次的照常保留。把保留下来的数按原顺序挪到数组**最前面**，返回一共保留了几个。

拿示例 2 来说：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 修改前 | 0 | 0 | 1 | 1 | ~~1~~ | ~~1~~ | 2 | 3 | 3 |
| 修改后 | **0** | **0** | **1** | **1** | **2** | **3** | **3** | ? | ? |

数字 1 出现了 4 次，只保留 2 个，其它数都不超过 2 次。保留下来 7 个数，返回 `7`。

**几个需要注意的细节：**

1. 要**原地修改** `nums`，判题程序会读取 `nums` 的前 `k` 个元素，并且**顺序必须和原来一致**。
2. 数组**有序**，所以相同的数一定挨在一起。
3. 题目要求 O(1) 额外空间，也就是不能开一个和原数组一样大的辅助数组（思路一只是帮助理解）。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 指针参数让"原地修改"生效

```c
int removeDuplicates(int* nums, int numsSize)
```

`nums` 存的是数组的地址，`nums[k] = x;` 直接改的是调用者那块内存，所以函数返回后调用者能看到修改。

### 2. 小心下标越界

这道题经常要访问 `nums[k - 2]` 这样的位置。如果 `k < 2`，`k - 2` 就是负数，`nums[-1]` 会读到数组前面的未知内存——**越界**！
所以要么保证 `k >= 2` 时才访问，要么先单独处理长度不超过 2 的数组。

### 3. 计数变量

```c
int cnt = 1;                 // 当前这个数已经出现了几次
if (nums[i] == nums[i - 1]) cnt++;   // 和前一个相同，次数 +1
else cnt = 1;                         // 换了一个新数，重新从 1 开始数
```

---

## 💡 第三步：思路一 —— 边扫描边计数（最直观）

### 思路

既然相同的数挨在一起，那就一边扫描一边数"当前这个数已经出现几次了"：

- 如果 `nums[i]` 和前一个数相同，计数 `cnt++`；否则 `cnt = 1`
- 只要 `cnt <= 2`，这个数就保留，写到 `nums[k]`，`k++`

> ⚠️ 注意：判断"和前一个是否相同"要用**原数组**里的前一个数。因为我们会往前面写数据，`nums[i - 1]` 可能已经被覆盖了，所以用一个变量 `prev` 记住上一个**读到的**数。

### 手动模拟（示例 1：`nums = [1,1,1,2,2,3]`）

| i | nums[i] | prev | cnt | 保留？ | k（操作后） | 前 k 个 |
|---|---|---|---|---|---|---|
| 0 | 1 | - | 1 | ✅ | 1 | [1] |
| 1 | 1 | 1 | 2 | ✅ | 2 | [1,1] |
| 2 | 1 | 1 | 3 | 跳过 | 2 | [1,1] |
| 3 | 2 | 1 | 1 | ✅ | 3 | [1,1,2] |
| 4 | 2 | 2 | 2 | ✅ | 4 | [1,1,2,2] |
| 5 | 3 | 2 | 1 | ✅ | 5 | [1,1,2,2,3] |

### 代码

```c
int removeDuplicates(int* nums, int numsSize) {
    int k = 0;              // 慢指针：下一个保留的数写到 nums[k]
    int cnt = 0;            // 当前这个数已经出现了几次
    int prev = 0;           // 上一个"读到"的数（原数组里的值）

    for (int i = 0; i < numsSize; i++) {
        int x = nums[i];                    // 先把要读的值存下来
        if (i > 0 && x == prev) {
            cnt++;                          // 和上一个数相同，次数 +1
        } else {
            cnt = 1;                        // 新的数，重新计数
        }
        prev = x;

        if (cnt <= 2) {                     // 前两次出现都保留
            nums[k] = x;
            k++;
        }
    }
    return k;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：扫描一遍。
- **空间复杂度 O(1)**：只用了几个变量。

这个方法已经满足题目要求了！但还要额外维护 `cnt` 和 `prev`，有没有更简洁的写法？

## 🚀 第四步：思路二 —— 与 `nums[k-2]` 比较（最简洁）

### 思路

`nums[0..k-1]` 是已经整理好的部分，它本身也是**有序**的，并且每个数最多出现 2 次。
现在来了一个新数 `nums[i]`，它能不能放进来？

- 如果 `nums[i] == nums[k-2]`：因为有序，`nums[k-2]`、`nums[k-1]` 和 `nums[i]` 三个数都相等（夹在中间的 `nums[k-1]` 只能等于它们）。再放进来就是**第 3 个**了，不行！
- 如果 `nums[i] != nums[k-2]`：说明这个数在已整理部分里最多出现 1 次，放进来没问题。

前两个数一定可以保留，所以 `k` 从 2 开始。

> 💡 把这里的 `2` 换成任意 `m`，就能解决"每个数最多保留 m 个"的问题。26 题就是 `m = 1` 的情况。

### 手动模拟（示例 2：`nums = [0,0,1,1,1,1,2,3,3]`）

`k` 从 2 开始，前 k 个是 `[0,0]`：

| i | nums[i] | nums[k-2] | 不同？ | 操作 | 前 k 个 |
|---|---|---|---|---|---|
| 2 | 1 | 0 | 是 | nums[2]=1, k=3 | [0,0,1] |
| 3 | 1 | 0 | 是 | nums[3]=1, k=4 | [0,0,1,1] |
| 4 | 1 | 1 | 否 | 跳过 | [0,0,1,1] |
| 5 | 1 | 1 | 否 | 跳过 | [0,0,1,1] |
| 6 | 2 | 1 | 是 | nums[4]=2, k=5 | [0,0,1,1,2] |
| 7 | 3 | 1 | 是 | nums[5]=3, k=6 | [0,0,1,1,2,3] |
| 8 | 3 | 2 | 是 | nums[6]=3, k=7 | [0,0,1,1,2,3,3] |

返回 `7`。

### 代码

```c
int removeDuplicates(int* nums, int numsSize) {
    if (numsSize <= 2) return numsSize;     // 不超过 2 个数，全部保留

    int k = 2;                              // 前两个数一定保留，nums[0..1] 已经整理好
    for (int i = 2; i < numsSize; i++) {    // 快指针从第 3 个数开始
        if (nums[i] != nums[k - 2]) {       // 不会成为某个数的"第 3 个"
            nums[k] = nums[i];              // 保留，写到慢指针位置
            k++;
        }
    }
    return k;
}
```

> ❓ **为什么比较的是 `nums[k-2]` 而不是 `nums[i-2]`？** `nums[i-2]` 是原数组的位置，可能已经被覆盖成别的值；而且我们关心的是"**已保留**的部分"里有几个相同的数，所以要看慢指针那一侧。

### 复杂度分析

- **时间复杂度 O(n)**：扫描一遍。
- **空间复杂度 O(1)**：只用了 `i`、`k`。

---

## ⚠️ 第五步：小白常见错误

1. **和 `nums[i-1]` 或 `nums[i-2]` 比较** → 慢指针写入后，原位置的值可能被改掉了。例如 `[1,1,1,2,2,2]`，用 `nums[i-2]` 判断时，`i = 4` 读到的 `nums[2]` 已经被改成了 2，于是第二个 2 被误删，结果变成 `[1,1,2]`（正确答案是 `[1,1,2,2]`）。
2. **`k` 从 0 开始还访问 `nums[k-2]`** → `nums[-2]` 越界。思路二要从 `k = 2` 开始，并先处理 `numsSize <= 2`。
3. **思路一里用 `nums[i-1]` 判断是否与前一个相同** → 同样可能读到已被覆盖的值，要用 `prev` 变量保存原值。
4. **返回值少算或多算** → 比如 `numsSize = 1` 时直接返回 2，就越界了。
5. **用"删除 + 后面整体前移"的方式** → 每删一次 O(n)，最坏 O(n²)，`3 * 10^4` 规模下容易超时，而且下标很容易写乱。
6. **只返回 `k` 却没把元素写到前面** → 判题程序读 `nums` 前 `k` 个会发现不对。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 边扫描边计数 | O(n) | O(1) | ⭐⭐ | 思路直观，容易想到 |
| 与 `nums[k-2]` 比较 | O(n) | O(1) | ⭐⭐ | 代码最短，可推广到"最多保留 m 个" |

> 🎯 **学习建议**：先用计数法 AC，再思考"已整理部分本身是有序的"这一点，推出 `nums[k-2]` 写法。
