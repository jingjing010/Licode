# DMA 传输分块长度：题解

## 📖 先读懂题目

把length字节顺序切成尽量大的非空块，每块≤maximum。length0..10^6，maximum1..65535，返回各块长度。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `1000 / 256` | `[256,256,256,232]` |
| 2 | `512 / 256` | `[256,256]` |

## 🧰 需要的 C 语言知识

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

每个DMA描述符最多容纳maximum字节，先安排完整块，最后追加不足一块的尾部；整除时不追加0长度块。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *dmaChunks(int length, int maximum, int *returnSize) {
    int n = (length + maximum - 1) / maximum, *out = malloc((n + 1) * sizeof(int));
    for (int i = 0; i < n; ++i) {
        out[i] = length > maximum ? maximum : length;
        length -= out[i];
    }
    *returnSize = n;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(块数)，输出空间 O(块数) | 正式提交 |

## ⚠️ 常见错误

- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
