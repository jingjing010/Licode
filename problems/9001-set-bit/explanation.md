# 9001. 置位指定位 —— 小白详细题解

> 这是嵌入式面试里出现频率最高的一道"送分题"：**怎么把寄存器的某一位置 1？** 面试官往往要求你当场手写，还会追问"为什么要写 `1u`"。
> 位运算系列（9001 ~ 9015）的基础知识都在这篇里，建议先认真读完。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 给你一个 32 位的数 `reg`，把它看成 32 个开关排成一排（第 0 号在最右边）。请你把第 `n` 号开关**打开**（变成 1），**别的开关一个都不许碰**。

拿示例 2（`reg = 5, n = 1`）来说，只看低 4 位：

| 位号 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|
| reg = 5 | 0 | 1 | **0** | 1 |
| 置位后 | 0 | 1 | **1** | 1 |

结果 `0b0111 = 7`。

**几个需要注意的细节：**

1. 位号从 **0** 开始，并且是从**右往左**数的。第 0 位代表 2⁰ = 1，第 3 位代表 2³ = 8。
2. 如果这一位**本来就是 1**（示例 3），结果不变——"置位"不是"翻转"。
3. `n` 最大是 31，也就是最高位。这是最容易出 bug 的地方，后面会讲。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 二进制和十六进制

嵌入式代码里寄存器的值几乎都写成十六进制，因为 **1 个十六进制位正好对应 4 个二进制位**：

| 十进制 | 二进制 | 十六进制 |
|---|---|---|
| 5 | 0101 | 0x5 |
| 8 | 1000 | 0x8 |
| 15 | 1111 | 0xF |
| 4294967295 | 32 个 1 | 0xFFFFFFFF |

本题输入输出用十进制，但你脑子里要习惯用二进制想问题。

### 2. `uint32_t` 是什么？

`uint32_t` 来自头文件 `<stdint.h>`，意思是 **"恰好 32 位的无符号整数"**（unsigned int 32）。

- 普通的 `int` 在不同芯片上可能是 16 位或 32 位，写驱动时很危险；`uint32_t` 在任何平台上都是 32 位，所以固件代码里到处都是它。
- 同理还有 `uint8_t`（1 字节）、`uint16_t`、`int32_t`（有符号 32 位）等。

### 3. 六个位运算符

| 运算符 | 名字 | 规则（逐位） | 记忆口诀 |
|---|---|---|---|
| `a & b` | 按位与 | 都是 1 才是 1 | 和 0 与 → 清零；和 1 与 → 不变 |
| `a \| b` | 按位或 | 有一个 1 就是 1 | 和 1 或 → 置 1；和 0 或 → 不变 |
| `a ^ b` | 按位异或 | 不同才是 1 | 和 1 异或 → 翻转；和 0 异或 → 不变 |
| `~a` | 按位取反 | 0 变 1，1 变 0 | |
| `a << k` | 左移 | 整体左移 k 位，右边补 0 | 相当于乘 2ᵏ |
| `a >> k` | 右移 | 整体右移 k 位 | 无符号数左边补 0，相当于除以 2ᵏ |

本题要用的就是表里加粗的那条思路：**"和 1 或 → 置 1；和 0 或 → 不变"**。

### 4. 掩码（mask）：`1u << n`

"掩码"就是一个用来"指定要操作哪些位"的数。只有第 `n` 位是 1 的掩码写作 `1u << n`：

```
1u << 0  = 0b0000...0001
1u << 3  = 0b0000...1000   (= 8)
1u << 31 = 0b1000...0000   (= 2147483648)
```

### 5. ⭐ 为什么必须写 `1u`，而不是 `1`？

- 字面量 `1` 的类型是 **`int`（有符号）**，`1 << 31` 会把 1 推到符号位上，结果超出了 `int` 的范围（最大 2147483647）。在 C 标准里这是 **未定义行为（Undefined Behavior，UB）**——编译器怎么处理都"不算错"，开了优化后可能出现非常诡异的结果。
- `1u` 的类型是 **`unsigned int`**，`1u << 31` 是完全合法的 `0x80000000`。

另外一条铁律：**移位的位数必须小于数据的位宽**。`1u << 32` 同样是 UB（不是你以为的 0！在 x86 上它往往等于 1，因为 CPU 只取位数的低 5 位）。本题 `n <= 31`，所以不会踩到，但 9004/9005 就要小心了。

### 6. 真实单片机里怎么写？

```c
#define GPIOA_ODR  (*(volatile uint32_t *)0x40020014u)   /* 示意：把寄存器地址当成指针 */

GPIOA_ODR |= (1u << 5);    /* 拉高 PA5：读出 → 或上掩码 → 写回 */
```

- `volatile` 告诉编译器："这个地址的值随时可能被硬件改变，每次都要真的去读/写，不许优化掉。"不加 `volatile`，编译器可能把多次写寄存器合并成一次，LED 就不闪了。
- `reg |= mask` 是"**读-改-写**"（read-modify-write）三步操作，本题的函数就是其中"改"的那一步：输入旧值，返回新值。

## 💡 第三步：思路一 —— 用算术运算（最朴素）

### 思路

还没学位运算也能做：第 `n` 位代表的数值是 2ⁿ。

1. 用循环算出 `mask = 2ⁿ`。
2. `reg / mask` 相当于把 `reg` 右移 n 位，再 `% 2` 就是第 `n` 位的值。
3. 如果这一位是 0，就给 `reg` 加上 `2ⁿ`——这一位从 0 变 1，而且**不会产生进位**，所以不影响其他位。

### 手动模拟（示例 2：`reg = 5, n = 1`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| 算掩码 | 2¹ | mask = 2 |
| 取第 1 位 | (5 / 2) % 2 = 2 % 2 | 0 |
| 这一位是 0，加上 mask | 5 + 2 | **7** |

### 代码

```c
uint32_t set_bit(uint32_t reg, int n) {
    uint32_t mask = 1;              // 从 2 的 0 次方开始
    for (int i = 0; i < n; i++) {
        mask = mask * 2;            // 循环 n 次后，mask = 2 的 n 次方
    }

    if ((reg / mask) % 2 == 0) {    // 第 n 位当前是 0
        reg = reg + mask;           // 加上 2^n：这一位 0 -> 1，不会进位，其它位不受影响
    }
    return reg;                     // 如果原来就是 1，什么都不做
}
```

### 复杂度分析

- **时间复杂度 O(n)**：循环 n 次求 2ⁿ，外加除法、取模（在很多单片机上除法非常慢，甚至没有硬件除法器）。
- **空间复杂度 O(1)**。

> 💬 这种写法能 AC，但在面试里写出来会被扣分——面试官就是想看你会不会用位运算。

## 🚀 第四步：思路二 —— 按位或（标准答案）

### 思路

利用"**和 1 或 → 置 1；和 0 或 → 不变**"：

```
reg     = 0b0101   (5)
mask    = 0b0010   (1u << 1)
reg|mask= 0b0111   (7)
```

掩码里只有第 `n` 位是 1，所以只有第 `n` 位被强制变成 1，其他位都"和 0 或"，原样保留。而且不用判断这一位原来是不是 1——原来是 1 的话，或完还是 1。

### 代码

```c
uint32_t set_bit(uint32_t reg, int n) {
    uint32_t mask = 1u << n;   // 只有第 n 位是 1 的掩码（必须用 1u，n = 31 时才不会溢出）
    return reg | mask;         // 和 1 或 -> 置 1；和 0 或 -> 不变
}
```

### 复杂度分析

- **时间复杂度 O(1)**：一次移位 + 一次或运算，在 ARM Cortex-M 上通常只要 1~2 条指令。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **写成 `1 << n`**：`n = 31` 时是有符号溢出（未定义行为）。在本 OJ 上可能"碰巧"对，但换个编译器/优化等级就可能出错，面试时直接扣分。
   ```c
   return reg | (1 << n);    // ❌ n = 31 时 1 << 31 溢出
   ```
2. **用加法代替或**：`reg + (1u << n)` 在这一位**本来就是 1** 时会产生进位，把别的位改坏。示例 3 中 `8 + 8 = 16`，错！
3. **位号数错方向**：以为第 0 位是最左边那一位。记住：**第 0 位是最低位（最右边）**，代表数值 1。
4. **用 `&` 代替 `|`**：`reg & (1u << n)` 是"只保留第 n 位"，把其他位全部清零了——这是"读取某一位"的写法，不是"置位"。
5. **只写了 `reg | (1u << n);` 却忘了 `return`**：函数返回值是随机的。`-Wall` 会给出 "control reaches end of non-void function" 警告，别忽略它。
6. **用 `int` 存寄存器值**：`0x80000000` 以上的值放进 `int` 会变成负数，打印、比较、右移都会出问题。寄存器一律用 `uint32_t`。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 算术（除法、取模、加法） | O(n) | O(1) | ⭐ | 帮助理解"第 n 位 = 2ⁿ" |
| 按位或 `reg \| (1u << n)` | O(1) | O(1) | ⭐ | 面试和实际工作的标准写法 |

> 🎯 **学习建议**：把 "`|=` 置位、`&= ~` 清零、`^=` 翻转、`& ` 读取" 这四个写法背到条件反射，这是写单片机驱动的基本功。

## 🔗 举一反三

- **9002. 清零指定位**：`reg & ~(1u << n)`。
- **9003. 翻转指定位**：`reg ^ (1u << n)`。
- **一次置多位**：`reg | ((1u << 3) | (1u << 5))` 同时拉高 3 号和 5 号引脚。
- **宏写法**：很多老项目里会写 `#define SET_BIT(reg, n) ((reg) |= (1u << (n)))`，想一想为什么每个参数都要加括号？（提示：试试 `SET_BIT(x, 2 + 1)` 去掉括号会展开成什么）
- **思考题**：STM32 还有一个 `GPIOx_BSRR` 寄存器，写 1 置位、写 0 无效。为什么有了 `ODR |= mask` 还要设计它？（提示：读-改-写的三步之间如果来了一个中断，中断里也改了 ODR，会发生什么？）
