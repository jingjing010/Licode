# 7. 整数反转 —— 小白详细题解

> 这道题的"反转"部分很简单，真正的考点是：**整数溢出**。学会这道题，你就理解了 C 语言里 `int` 的边界。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把一个整数的数字**倒过来写**，符号保持不变。如果倒过来以后太大（超出 `int` 能表示的范围），就返回 0。

| 输入 x | 倒过来 | 输出 | 说明 |
|---|---|---|---|
| 123 | 321 | 321 | 普通情况 |
| -123 | -321 | -321 | 负号留在前面 |
| 120 | 021 | 21 | 前导 0 自然消失 |
| 1534236469 | 9646324351 | 0 | 超过 2147483647，溢出 |

**几个需要注意的细节：**

1. `int` 的范围是 `[-2147483648, 2147483647]`，即 `[INT_MIN, INT_MAX]`。
2. 题目说"不允许存储 64 位整数"，也就是**理想做法不用 `long long`**，而是在溢出发生**之前**就判断出来。
3. `x = -2147483648` 时，如果你先写 `x = -x` 取绝对值，就已经溢出了（正数最大只到 2147483647）。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用 `%` 和 `/` 拆数字

```c
int x = 123;
int d = x % 10;   // d = 3，取出最后一位
x = x / 10;       // x = 12，去掉最后一位（整数除法直接舍去小数）
```

### 2. 负数的 `%` 和 `/`

C 语言（C99 起）规定：**整数除法向 0 取整**，余数的符号**和被除数相同**。

| 表达式 | 结果 |
|---|---|
| `-123 / 10` | `-12`（不是 -13） |
| `-123 % 10` | `-3`（不是 7） |

所以对负数，取出来的每一位也是负的：`-123` 依次取出 `-3, -2, -1`，拼起来正好是 `-321`。**负数不需要单独处理！**

### 3. 整数溢出

`int` 只有 32 位。`2147483647 + 1` 的结果在 C 语言里是**未定义行为**（实际运行通常会变成一个负数），程序不会报错，只会悄悄算错。

```c
int a = INT_MAX;   // 2147483647，INT_MAX 定义在 <limits.h>
a = a * 10;        // ❌ 溢出！结果是乱的
```

### 4. `long long`

`long long` 至少 64 位，范围约 `±9.2 × 10^18`，能装下 10 位数反转后的结果。用它先算、再判断是否超出 `int`，是最容易想到的办法（虽然题目说"假设不允许"，但在本 OJ 能通过，适合先理解思路）。

---

## 💡 第三步：思路一 —— 用 long long 暂存（最容易想到）

### 思路

1. 用 `long long rev` 存反转结果，这样乘 10 不会溢出。
2. 每次取出 `x` 的最后一位，拼到 `rev` 后面：`rev = rev * 10 + digit`。
3. 结束后判断 `rev` 是否在 `[INT_MIN, INT_MAX]` 内，不在就返回 0。

### 手动模拟（示例 2：`x = -123`）

| 步骤 | x | digit = x % 10 | rev = rev * 10 + digit | x / 10 |
|---|---|---|---|---|
| 1 | -123 | -3 | -3 | -12 |
| 2 | -12 | -2 | -32 | -1 |
| 3 | -1 | -1 | -321 | 0 |

`x` 变成 0，循环结束，返回 `-321`。

### 代码

```c
int reverse(int x) {
    long long rev = 0;                  // 用 64 位整数存结果，乘 10 不会溢出

    while (x != 0) {                    // x 变成 0 说明每一位都取完了
        int digit = x % 10;             // 取出最后一位（负数时 digit 也是负的）
        rev = rev * 10 + digit;         // 拼到结果的末尾
        x /= 10;                        // 去掉最后一位
    }

    // 反转后的结果超出 int 范围，按题意返回 0
    if (rev > INT_MAX || rev < INT_MIN) {
        return 0;
    }
    return (int)rev;                    // 在范围内，安全地转回 int
}
```

### 复杂度分析

- **时间复杂度 O(log|x|)**：`x` 有几位就循环几次，最多 10 次。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 不用 64 位，提前判断溢出（标准解法）

### 思路

溢出只可能发生在 `rev * 10 + digit` 这一步。所以在这一步**之前**检查：

- 正方向：如果 `rev > INT_MAX / 10`，那 `rev * 10` 一定超过 `INT_MAX`；
  如果 `rev == INT_MAX / 10`（即 214748364），那么只有 `digit > 7` 才会溢出（因为 `INT_MAX` 的最后一位是 7）。
- 负方向：如果 `rev < INT_MIN / 10`，一定溢出；
  如果 `rev == INT_MIN / 10`（即 -214748364），那么 `digit < -8` 才会溢出（`INT_MIN` 的最后一位是 8）。

> 💬 **小知识**：其实 `rev == INT_MAX / 10` 时 `digit` 不可能大于 7——因为输入 `x` 本身不超过 2147483647，它的最高位最多是 2。但把判断写完整更安全，也更容易讲清楚。

### 手动模拟（`x = 1534236469`）

| 步骤 | digit | 检查前的 rev | rev > 214748364 吗？ | 新 rev |
|---|---|---|---|---|
| 1 | 9 | 0 | 否 | 9 |
| 2 | 6 | 9 | 否 | 96 |
| … | … | … | … | … |
| 9 | 3 | 96463243 | 否 | 964632435 |
| 10 | 1 | 964632435 | **是！** | 返回 0 |

### 代码

```c
int reverse(int x) {
    int rev = 0;                        // 全程只用 int

    while (x != 0) {
        int digit = x % 10;             // 取出最后一位

        // 正方向：rev * 10 + digit 会不会超过 INT_MAX？
        if (rev > INT_MAX / 10 || (rev == INT_MAX / 10 && digit > 7)) {
            return 0;
        }
        // 负方向：rev * 10 + digit 会不会小于 INT_MIN？
        if (rev < INT_MIN / 10 || (rev == INT_MIN / 10 && digit < -8)) {
            return 0;
        }

        rev = rev * 10 + digit;         // 确认安全后再计算
        x /= 10;
    }
    return rev;
}
```

### 复杂度分析

- **时间复杂度 O(log|x|)**，**空间复杂度 O(1)**。和思路一一样，但满足了"不使用 64 位整数"的要求。

---

## ⚠️ 第五步：小白常见错误

1. **先算再判断溢出**：`rev = rev * 10 + digit; if (rev > INT_MAX) return 0;` → `rev` 是 `int` 时它**永远不可能大于 `INT_MAX`**，溢出已经发生，判断形同虚设。
2. **先取绝对值** `if (x < 0) x = -x;` → `x = -2147483648` 时 `-x` 溢出，结果仍是负数，后面全错。
3. **用 `long long` 却写成 `rev = rev * 10 + digit` 而 `rev` 声明成 `int`** → 声明的类型才决定能不能装下，一定要 `long long rev`。
4. **把结果转成字符串再反转** → 能做，但要处理负号、前导零和溢出，比数学方法麻烦得多，也容易越界。
5. **以为 `-123 % 10 == 7`** → 那是 Python 的规则。C 语言里 `-123 % 10 == -3`。
6. **最后忘了 `return 0` 的情况**，或者把 `INT_MIN / 10` 写成 `-INT_MAX / 10`（它们相等，都是 -214748364，但最后一位边界是 8 而不是 7）。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否用 64 位 | 建议 |
|---|---|---|---|---|
| long long 暂存 | O(log\|x\|) | O(1) | 是 | 先理解思路 |
| 提前判断溢出 | O(log\|x\|) | O(1) | 否 | 面试标准答案 |
