# 9049. CRC-16/MODBUS 校验 —— 小白详细题解

> 只要做过工业设备（电表、PLC、变频器），就一定写过这段代码。它和 9048 的 CRC-8 原理完全相同，区别在于 16 位、初值 0xFFFF，以及最让新手困惑的"**反射**"。

---

## 📖 第一步：先读懂题目

### CRC 的 6 个参数

任何一种 CRC 都由下面几个参数唯一确定（这套描述方法叫 Rocksoft 模型）：

| 参数 | CRC-8（9048） | CRC-16/MODBUS（本题） |
|---|---|---|
| width | 8 | 16 |
| poly | 0x07 | 0x8005 |
| init | 0x00 | **0xFFFF** |
| refin | 否 | **是** |
| refout | 否 | **是** |
| xorout | 0x00 | 0x0000 |

### "反射"是什么？

串口（UART）发送一个字节时是**最低位先发**的。为了和硬件的发送顺序一致，MODBUS 的 CRC 规定每个字节**从最低位开始**参与计算（refin），最后的结果也**按位反转**（refout）。

"先反转输入、按左移算、再反转输出"等价于"**整个算法镜像**"：

| 左移算法（不反射） | 右移算法（反射） |
|---|---|
| 判断最高位 `crc & 0x8000` | 判断最低位 `crc & 0x0001` |
| `crc << 1` | `crc >> 1` |
| 异或 `0x8005` | 异或 `0xA001`（0x8005 的 16 位反转） |
| 字节异或到高 8 位 `crc ^= byte << 8` | 字节异或到低 8 位 `crc ^= byte` |

所以直接用右移算法，就不需要真的去反转任何东西。

`0x8005` → `1000 0000 0000 0101`，反转 → `1010 0000 0000 0001` = `0xA001`。

**容易忽略的细节：**

1. 初值是 `0xFFFF`，所以空数组的结果是 65535，不是 0。
2. Modbus 帧里 CRC **低字节在前**：示例 2 的 CRC 为 `0x0A84`，帧尾是 `84 0A`。这和一般的 Modbus 寄存器数据（高字节在前）相反，是经典坑点。

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `uint16_t` 与右移

`uint16_t` 是 16 位无符号整数。**无符号数右移时高位补 0**（逻辑右移），这正是 CRC 需要的。如果用有符号的 `int16_t`，负数右移时高位可能补 1（算术右移），结果就错了——**做位运算一律用无符号类型**。

### 2. `crc ^= buf[i]`

`buf[i]` 是 8 位，`crc` 是 16 位，异或时 `buf[i]` 自动扩展成 `0x00XX`，只影响 crc 的低 8 位——正好是右移算法要的"字节异或到低 8 位"。

### 3. 取出高、低字节

```c
uint8_t lo = crc & 0xFF;          // 低字节
uint8_t hi = (crc >> 8) & 0xFF;   // 高字节
```

## 💡 第三步：思路一 —— 逐位右移算法

### 代码

```c
uint16_t crc16Modbus(const uint8_t* buf, size_t len) {
    uint16_t crc = 0xFFFF;                           // init = 0xFFFF
    for (size_t i = 0; i < len; i++) {
        crc ^= buf[i];                               // 新字节异或到低 8 位
        for (int b = 0; b < 8; b++) {                // 逐位处理，从最低位开始
            if (crc & 0x0001) {                      // 最低位为 1
                crc = (uint16_t)((crc >> 1) ^ 0xA001);   // 右移后异或反转多项式
            } else {
                crc >>= 1;                           // 最低位为 0：只右移
            }
        }
    }
    return crc;                                      // xorout = 0
}
```

### 手动模拟（示例 2 第 1 个字节 0x01 的前几步）

| 步骤 | crc | 最低位 | 操作 |
|---|---|---|---|
| 初值 | 0xFFFF | | |
| `^= 0x01` | 0xFFFE | 0 | 右移 → 0x7FFF |
| 2 | 0x7FFF | 1 | 右移 0x3FFF，^ 0xA001 → 0x9FFE |
| 3 | 0x9FFE | 0 | 右移 → 0x4FFF |
| ... | | | 共 8 次，之后处理下一个字节 |

全部 6 个字节处理完得到 `0x0A84`。

### 复杂度分析

- 时间 **O(8 × len)**，空间 O(1)。

## 🚀 第四步：思路二 —— 256 项查表法

### 为什么能优化？

和 CRC-8 一样：一个字节的 8 次内层循环，结果只取决于"crc 低 8 位异或这个字节"后的值 `idx`，以及 crc 的高 8 位（它只是被右移 8 位）。于是：

```
crc = (crc >> 8) ^ table[(crc ^ byte) & 0xFF];
```

`table[idx]` = 把 `idx` 当作 crc、执行 8 次右移算法的结果。

### 代码

```c
static uint16_t crc16_table[256];
static bool crc16_ready = false;

static void crc16_build_table(void) {
    for (int idx = 0; idx < 256; idx++) {
        uint16_t crc = (uint16_t)idx;
        for (int b = 0; b < 8; b++) {
            crc = (crc & 1) ? (uint16_t)((crc >> 1) ^ 0xA001) : (uint16_t)(crc >> 1);
        }
        crc16_table[idx] = crc;
    }
    crc16_ready = true;
}

uint16_t crc16Modbus(const uint8_t* buf, size_t len) {
    if (!crc16_ready) crc16_build_table();
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < len; i++) {
        uint8_t idx = (uint8_t)(crc ^ buf[i]);           // 低 8 位与数据异或，作为下标
        crc = (uint16_t)((crc >> 8) ^ crc16_table[idx]);  // 高 8 位右移下来，再异或表项
    }
    return crc;
}
```

### 复杂度分析

- 时间 **O(len)**；额外空间 256 × 2 = 512 字节。

### 🔌 嵌入式实战：收发两侧怎么用

```c
/* 发送：算 CRC，低字节在前追加到帧尾 */
uint16_t c = crc16Modbus(frame, n);
frame[n]     = c & 0xFF;
frame[n + 1] = c >> 8;

/* 接收：整帧（含 CRC）再算一次，结果为 0 就说明校验正确 */
if (crc16Modbus(rx, rx_len) == 0) {
    /* 处理这一帧 */
}
```

"整帧再算一次等于 0"是 CRC 的数学性质，可以少写一次比较、也不用操心字节序。

## ⚠️ 第五步：小白常见错误

1. **初值写成 0** → 和 CRC-16/ARC 混淆了（ARC 的 init = 0，其他参数和 MODBUS 一样）。
2. **右移算法却异或 0x8005** → 右移版必须用反转后的 0xA001。
3. **用 `int16_t` 或 `int` 存 crc 又不截断** → 有符号右移高位补 1，或者左移版超过 16 位。
4. **发送 CRC 时高字节在前** → 设备会认为校验错误而不回应，这是现场调试 Modbus 最常见的问题。
5. **❌ `crc ^= buf[i] << 8` 配合右移** → 把左移版本和右移版本的写法混在一起了。

## 📊 第六步：方法对比

| 方法 | 每字节 | 额外空间 | 适用 |
|---|---|---|---|
| 逐位右移 | 8 次 | 0 | 波特率低、帧短（Modbus 通常 < 256 字节） |
| 256 项查表 | 1 次查表 | 512 字节 | 高速通信、批量计算 |
| 双 256 字节表（高低字节分开） | 1 次查表 | 512 字节 | 8 位 MCU 上避免 16 位运算，Modbus 官方文档的写法 |
