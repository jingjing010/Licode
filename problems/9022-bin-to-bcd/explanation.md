# 9022. 二进制转 BCD 码（RTC 时间设置）—— 小白详细题解

> 9021 是"读时间"（BCD → 二进制），这一题是"写时间"（二进制 → BCD）。两个函数总是成对出现在 RTC 驱动里。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把一个两位数拆成十位和个位，十位放进字节的高 4 位，个位放进低 4 位。

拿示例 1 `[59,23,12]` 来说：

| 数值 | 十位 | 个位 | 拼成的字节 | 十进制写法 |
|---|---|---|---|---|
| 59 | 5 | 9 | `0x59` | 89 |
| 23 | 2 | 3 | `0x23` | 35 |
| 12 | 1 | 2 | `0x12` | 18 |

**几个需要注意的细节：**

1. 输出是**十进制写法**，`0x59` 输出成 `89`。换成十六进制看，结果"长得和输入一样"，这正是 BCD 的特点。
2. 个位数也要编码：`9` → `0x09`，数值不变；`10` → `0x10 = 16`，数值变了。
3. 输入保证在 `0~99` 之间，一个字节放得下。

---

## 🧰 第二步：需要的 C 语言知识

### 1. 用 `/` 和 `%` 拆十进制数位

```c
59 / 10 = 5    // 整数除法，结果向零取整：十位
59 % 10 = 9    // 取余：个位
```

### 2. 用 `<<` 和 `|` 拼半字节

```
十位 5 = 0000 0101
5 << 4 = 0101 0000    // 挪到高 4 位
个位 9 = 0000 1001
按位或 = 0101 1001 = 0x59
```

因为个位只占低 4 位、十位只占高 4 位，两部分不重叠，`|` 和 `+` 的结果一样；用 `|` 更能表达"拼位"的意图。

### 3. 返回值强转 `uint8_t`

`(bin / 10) << 4` 的运算结果是 `int`，最大 `0x99 = 153`，强转回 `uint8_t` 不会丢数据，同时告诉读者"这里的结果是一个字节"。

---

## 💡 第三步：思路一 —— 除 10 取十位，模 10 取个位

### 思路

1. `tens = bin / 10`，`ones = bin % 10`
2. 返回 `(tens << 4) | ones`

### 手动模拟（示例 2：`[0,9,10,99]`）

| bin | tens | ones | `(tens << 4) \| ones` | 输出 |
|---|---|---|---|---|
| 0 | 0 | 0 | `0x00` | 0 |
| 9 | 0 | 9 | `0x09` | 9 |
| 10 | 1 | 0 | `0x10` | 16 |
| 99 | 9 | 9 | `0x99` | 153 |

结果 `[0,9,16,153]` ✅

### 代码

```c
uint8_t bin_to_bcd(uint8_t bin) {
    uint8_t tens = bin / 10;          // 十位数字
    uint8_t ones = bin % 10;          // 个位数字
    return (uint8_t)((tens << 4) | ones);   // 十位放高 4 位，个位放低 4 位
}
```

### 复杂度分析

- **时间复杂度 O(1)**，**空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 只做一次除法，加上 tens × 6

### 思路

和 9021 的思路二正好相反：BCD 的数值 = `tens × 16 + ones`，而 `bin = tens × 10 + ones`，所以

```
BCD = bin + tens × 6
```

只需要一次除法求出 `tens`，省掉 `%`（在没有硬件除法器的 MCU 上，比如 Cortex-M0，除法和取余都是调用软件库函数，比较慢）。

### 手动模拟（`bin = 59`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| 十位 | `59 / 10` | 5 |
| 加上 tens × 6 | `59 + 5 * 6` | 89 = `0x59` ✅ |

### 代码

```c
uint8_t bin_to_bcd(uint8_t bin) {
    uint8_t tens = bin / 10;
    // bin = tens*10 + ones，再加 tens*6 就得到 tens*16 + ones
    return (uint8_t)(bin + tens * 6);
}
```

> 💬 编译器对"除以常数 10"会优化成"乘法 + 移位"，所以在 Cortex-M3/M4 上两种写法都很快。思路二主要的价值是帮你理解 BCD 与二进制之间"差了 tens × 6"。

## 🔌 嵌入式实战

设置 DS3231 时间：

```c
void rtc_set_time(uint8_t hour, uint8_t min, uint8_t sec) {
    uint8_t r[3];
    r[0] = bin_to_bcd(sec);          // 秒，bit7 = 0 保证时钟运行 ...
    r[1] = bin_to_bcd(min);
    r[2] = bin_to_bcd(hour);         // 24 小时制：bit6 = 0
    i2c_write(DS3231_ADDR, 0x00, r, 3);
}
```

写之前最好先检查参数范围（`sec < 60`、`hour < 24`），否则 `bin_to_bcd(75)` 会得到 `0x75`，RTC 进入非法状态，读回来的时间会乱跳。

## ⚠️ 第五步：小白常见错误

1. **直接写入数值**：把 `59`（`0x3B`）写进秒寄存器，个位 `0xB` 不是合法 BCD，芯片行为未定义。
2. **十位没有左移**：`tens | ones` 得到 `5 | 9 = 13`，完全错误。
3. **移位方向或位数错**：`tens << 8` 会移出一个字节（截断后变 0），`tens >> 4` 方向反了。
4. **十位和个位放反**：`(ones << 4) | tens` 把 59 编码成 `0x95`。
5. **把 `/ 10` 写成 `/ 16`**：那是拆十六进制数位，不是十进制，`59 / 16 = 3`、`59 % 16 = 11`，结果 `0x3B` 又变回原数。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| `/ 10` 和 `% 10` 拆位 | O(1) | O(1) | 最直观，首选 |
| `bin + tens * 6` | O(1) | O(1) | 只需一次除法 |
| 100 项查表 | O(1) | O(100) Flash | 最快，但占空间 |
