# 字节游程长度解压：题解

## 📖 先读懂题目

输入合法[次数,值]编码，次数1..255，输入偶数长度且解码后≤1024字节。返回解压后的字节数组，空输入输出空数组。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[1,49,1,50,1,51,1,52,1,53,1,54,1,55,1,56,1,57]` | `[49,50,51,52,53,54,55,56,57]` |
| 2 | `[]` | `[]` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

第一遍累加次数以确定输出容量，第二遍把每个字节重复写入对应次数。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *runLengthDecode(const uint8_t *data, size_t len, int *returnSize) {
    int count = 0;
    for (size_t i = 0; i < len; i += 2)
        count += data[i];
    int *out = malloc((count + 1) * sizeof(int)), k = 0;
    for (size_t i = 0; i < len; i += 2)
        for (unsigned j = 0; j < data[i]; ++j)
            out[k++] = data[i + 1];
    *returnSize = k;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(输出长度)，输出空间 O(输出长度) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
