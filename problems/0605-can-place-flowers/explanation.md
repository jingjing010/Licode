# 605. 种花问题 —— 小白详细题解

> 一道非常适合入门「贪心」思想的题：能种就种，绝不犹豫。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一排地，`1` 表示已经有花，`0` 表示空地。规则是**两朵花不能挨着**。问：还能不能再种下 `n` 朵花？

拿示例 1 来说：`flowerbed = [1,0,0,0,1], n = 1`

| 下标 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 原来 | 1 | 0 | 0 | 0 | 1 |
| 能种吗？ | 已有花 | ❌ 左边是 1 | ✅ 左右都是 0 | ❌ 右边是 1 | 已有花 |

只有下标 2 能种，最多能再种 1 朵。`n = 1` → `true`；示例 2 中 `n = 2` → `false`。

**几个需要注意的细节：**

1. 数组**第一个**位置没有左邻居，**最后一个**位置没有右邻居，可以把"不存在的邻居"当成空地。
2. 种下一朵花之后，它会影响**后面**的位置（右边那个就不能种了），所以要记录下来。
3. `n` 可能是 `0`，此时什么都不用种，直接是 `true`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `bool` 返回值

```c
bool canPlaceFlowers(int* flowerbed, int flowerbedSize, int n)
```

`bool` 是 C99 引入的布尔类型（需要 `#include <stdbool.h>`，本 OJ 已经帮你包含），取值只有 `true` 和 `false`。`return cnt >= n;` 这种写法会直接把比较结果（真/假）返回。

### 2. 三目运算符 `?:` 处理边界

```c
int left = (i == 0) ? 0 : flowerbed[i - 1];
```

意思是：如果 `i == 0`（没有左邻居），`left` 就取 `0`；否则取 `flowerbed[i - 1]`。这样就**不会访问 `flowerbed[-1]`**（越界）。

### 3. 通过指针修改数组

`flowerbed` 是指针，`flowerbed[i] = 1;` 会真的改掉调用者的数组。本题判题程序不关心你改没改数组，所以可以放心地"在地图上做标记"。

---

## 💡 第三步：思路一 —— 贪心：从左往右，能种就种

### 思路

从左到右看每个位置 `i`，如果它满足：

- 自己是 `0`
- 左邻居是 `0`（或者不存在）
- 右邻居是 `0`（或者不存在）

就**立刻**种上（把 `flowerbed[i]` 改成 `1`），计数器加 1。最后看计数器是否 `>= n`。

> ❓ **为什么"能种就种"是对的？** 假设位置 `i` 能种但我们不种，留给右边的 `i+1` 种——这只会让更右边的 `i+2` 也不能种，情况只会更糟。所以越早种越好，这就是**贪心**。

### 手动模拟（`flowerbed = [0,0,1,0,0,0,0]`）

| i | 左 | 自己 | 右 | 能种？ | 种后数组 | cnt |
|---|---|---|---|---|---|---|
| 0 | (无)0 | 0 | 0 | ✅ | [1,0,1,0,0,0,0] | 1 |
| 1 | 1 | 0 | 1 | ❌ | 不变 | 1 |
| 2 | 0 | 1 | 0 | ❌ 已有花 | 不变 | 1 |
| 3 | 1 | 0 | 0 | ❌ | 不变 | 1 |
| 4 | 0 | 0 | 0 | ✅ | [1,0,1,0,1,0,0] | 2 |
| 5 | 1 | 0 | 0 | ❌ | 不变 | 2 |
| 6 | 0 | 0 | (无)0 | ✅ | [1,0,1,0,1,0,1] | 3 |

最多能再种 3 朵。

### 代码

```c
bool canPlaceFlowers(int* flowerbed, int flowerbedSize, int n) {
    int cnt = 0;                                   // 能新种下的花的数量
    for (int i = 0; i < flowerbedSize; i++) {
        // 越界的邻居当作空地 0
        int left  = (i == 0) ? 0 : flowerbed[i - 1];
        int right = (i == flowerbedSize - 1) ? 0 : flowerbed[i + 1];

        if (flowerbed[i] == 0 && left == 0 && right == 0) {
            flowerbed[i] = 1;                      // 种下！后面的位置会看到这朵花
            cnt++;
        }
    }
    return cnt >= n;                               // 能种的数量够 n 朵就行
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个位置看一次。
- **空间复杂度 O(1)**：只用了几个变量。

## 🚀 第四步：思路二 —— 跳着走 + 提前结束（不修改数组）

### 思路

观察一下：

- 如果 `flowerbed[i] == 1`，那么 `i+1` 肯定不能种，直接跳到 `i+2`。
- 如果 `flowerbed[i] == 0` 且右边也是 `0`（或越界），那 `i` 一定能种（左边一定是空的——因为我们是从"可种的位置"跳过来的），种完跳到 `i+2`。
- 如果 `flowerbed[i] == 0` 但右边是 `1`，那 `i` 不能种，`i+1` 是花，直接跳到 `i+3`。

另外，一旦已经种够 `n` 朵，就可以**提前返回** `true`，不用把数组走完。

### 代码

```c
bool canPlaceFlowers(int* flowerbed, int flowerbedSize, int n) {
    int i = 0;
    while (i < flowerbedSize && n > 0) {           // 种够了就停
        if (flowerbed[i] == 1) {
            i += 2;                                // 有花：下一个位置肯定不能种
        } else if (i == flowerbedSize - 1 || flowerbed[i + 1] == 0) {
            n--;                                   // 自己空、右边也空：种下
            i += 2;                                // 种完后右邻居不能种
        } else {
            i += 3;                                // 右边是花：跳过自己和那朵花
        }
    }
    return n <= 0;
}
```

> 💬 为什么到达 `i` 时左边一定是空的？因为每次跳跃都保证"跳过了一朵花及其右邻居"或"跳过了自己种的花及其右邻居"，所以 `i-1` 永远不是花。

### 复杂度分析

- **时间复杂度 O(n)**，常数更小，且可能提前结束。
- **空间复杂度 O(1)**，而且不修改输入数组。

---

## ⚠️ 第五步：小白常见错误

1. **访问 `flowerbed[i - 1]` 时没判断 `i == 0`** → 读到 `flowerbed[-1]`，越界，结果随机。
2. **访问 `flowerbed[i + 1]` 时没判断 `i == flowerbedSize - 1`** → 同理越界。比如 `[0]`、`n = 1` 应该返回 `true`。
3. **种下后忘了把 `flowerbed[i]` 改成 1** → `[0,0,0]` 会被算成能种 3 朵（下标 0、1、2 都判断为"左右为空"），正确答案是 2 朵。
4. **只数连续 0 的个数除以 2** → 没区分两端和中间。中间一段 `k` 个 0 能种 `(k-1)/2` 朵，靠边的一段能种 `k/2` 朵，混在一起很容易算错。
5. **写成 `return cnt == n;`** → 能种的比需要的多也应该是 `true`，要用 `>=`。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否修改输入 | 建议 |
|---|---|---|---|---|
| 贪心逐个检查 | O(n) | O(1) | 是 | 最直观，先写这个 |
| 跳格 + 提前结束 | O(n) | O(1) | 否 | 理解贪心后的进阶写法 |
