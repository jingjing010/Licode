# 128. 最长连续序列 —— 小白详细题解

> 排序能轻松做出来，但题目要求 O(n)。这道题教你一个很巧妙的哈希表用法：**只从"起点"开始数**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 从数组里挑出一些数，让它们能排成 `x, x+1, x+2, ...` 这样每次加 1 的一串，问这一串最长有多长。挑的时候**不用管它们在原数组里的位置**。

拿示例 1 `nums = [100,4,200,1,3,2]` 来说：

| 能组成的连续序列 | 长度 |
|---|---|
| 1, 2, 3, 4 | **4** |
| 100 | 1 |
| 200 | 1 |

答案是 4。

**几个需要注意的细节：**

1. **和原数组顺序无关**：`1, 2, 3, 4` 在原数组中是乱序、分散的，没关系。
2. **重复的数只算一次**：示例 3 `[1,0,1,2]` 的最长序列是 `0,1,2`，长度 3，不是 4。
3. **数组可能为空**：`[]` 的答案是 0。
4. 数值范围是 `-10^9 ~ 10^9`，不能开一个"值域大小"的数组来标记。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `qsort` 排序

```c
int cmp(const void* a, const void* b) {
    int x = *(const int*)a, y = *(const int*)b;
    return (x > y) - (x < y);      // x<y 返回 -1，x>y 返回 1，相等返回 0
}
qsort(nums, numsSize, sizeof(int), cmp);
```

> ⚠️ 不要写 `return x - y;`！`x = 10^9, y = -10^9` 时差值是 `2×10^9`，超过了 `int` 的上限（约 `2.1×10^9`），会溢出变成负数，排序结果就乱了。

### 2. 自己写一个简单的哈希集合

C 语言没有自带的 `set`。我们用"开放寻址 + 线性探测"写一个最简单的版本：

- 一个大数组 `keys[]` 存数值，`used[]` 标记格子有没有被占用。
- **存 x**：用哈希函数算出格子号 `h`，如果被别的数占了就看 `h+1`、`h+2`……直到空格子。
- **查 x**：从同一个格子号开始往后看，遇到 x 就是找到了，遇到空格子说明不存在。

格子数要比元素个数大很多（这里元素最多 10⁵，用 2¹⁸ = 262144 个格子），这样冲突少、速度快。

### 3. `static` 大数组

几十万个元素的数组如果写成函数里的局部变量，会放在**栈**上，可能栈溢出。加上 `static`（或写在函数外面）就放在静态区，安全。但要注意：`static` 数组**每次调用不会自动清零**，要手动 `memset`。

## 💡 第三步：思路一 —— 排序后数一数

### 思路

排序之后，能连成一串的数一定**挨在一起**。从左往右扫：

- 如果 `nums[i] == nums[i-1]`：重复，跳过（长度不变）。
- 如果 `nums[i] == nums[i-1] + 1`：接上了，当前长度 `cur++`。
- 否则：断了，`cur` 重新从 1 开始。

### 手动模拟（示例 3：`[1,0,1,2]` 排序后 `[0,1,1,2]`）

| i | nums[i] | 和前一个的关系 | cur | best |
|---|---|---|---|---|
| 0 | 0 | 第一个 | 1 | 1 |
| 1 | 1 | 0 + 1 = 1，接上 | 2 | 2 |
| 2 | 1 | 重复，跳过 | 2 | 2 |
| 3 | 2 | 1 + 1 = 2，接上 | 3 | **3** |

### 代码

```c
int cmpInt(const void* a, const void* b) {
    int x = *(const int*)a, y = *(const int*)b;
    return (x > y) - (x < y);          // 不用 x - y，防止溢出
}

int longestConsecutive(int* nums, int numsSize) {
    if (numsSize == 0) return 0;       // 空数组：答案 0
    qsort(nums, numsSize, sizeof(int), cmpInt);

    int best = 1, cur = 1;             // cur：以 nums[i] 结尾的连续序列长度
    for (int i = 1; i < numsSize; i++) {
        if (nums[i] == nums[i - 1]) {
            continue;                              // 重复的数，不影响长度
        } else if (nums[i] == nums[i - 1] + 1) {
            cur++;                                 // 刚好大 1，接上
        } else {
            cur = 1;                               // 断开了，重新开始
        }
        if (cur > best) best = cur;
    }
    return best;
}
```

> 💬 `nums[i - 1] + 1` 会不会溢出？数值最大 10⁹，加 1 远小于 `int` 上限，安全。

### 复杂度分析

- **时间复杂度 O(n log n)**：排序占大头。n = 10⁵ 时非常快，能 AC，但不满足题目 O(n) 的要求。
- **空间复杂度 O(log n)**：排序的递归栈。

## 🚀 第四步：思路二 —— 哈希集合 + 只从起点开始数（O(n)）

### 思路

把所有数放进哈希集合后，最直接的想法是：对每个数 `x`，看 `x+1`、`x+2`……在不在集合里，数出以 `x` 开头的长度。

但这样会**重复数很多次**：对于 `1,2,3,4`，从 1 数一遍（4 个），从 2 又数一遍（3 个），从 3 再数……如果整个数组是 `1 ~ 10^5`，总次数约 n²/2，超时。

**关键优化**：如果 `x - 1` 也在集合里，说明 `x` 不是一串的**开头**，从 `x` 数出来的长度一定比从 `x-1` 数的短，**直接跳过**！

这样每一串只会从它的起点被数一次，每个数最多被"数到"一次，总时间 O(n)。

### 手动模拟（示例 1：集合 = {100, 4, 200, 1, 3, 2}）

| x | x-1 在集合里吗？ | 操作 | 长度 |
|---|---|---|---|
| 100 | 99 不在 → 是起点 | 101 不在，停 | 1 |
| 4 | 3 在 → 不是起点 | 跳过 | — |
| 200 | 199 不在 → 是起点 | 201 不在，停 | 1 |
| 1 | 0 不在 → 是起点 | 2 在、3 在、4 在、5 不在 | **4** |
| 3 | 2 在 → 跳过 | — | — |
| 2 | 1 在 → 跳过 | — | — |

### 代码

```c
#define HASH_SIZE (1 << 18)      // 262144 个格子，远大于最多 10^5 个元素
#define HASH_BITS 18

static int keys[HASH_SIZE];      // 格子里存的数
static char used[HASH_SIZE];     // 格子是否被占用

// 哈希函数：乘一个大奇数，取高 18 位作为格子号（结果一定在 0 ~ HASH_SIZE-1）
static unsigned int hashOf(int x) {
    return ((unsigned int)x * 2654435761u) >> (32 - HASH_BITS);
}

static bool contains(int x) {
    unsigned int h = hashOf(x);
    while (used[h]) {                          // 遇到空格子就说明不存在
        if (keys[h] == x) return true;
        h = (h + 1) & (HASH_SIZE - 1);         // 线性探测：看下一个格子，到末尾绕回 0
    }
    return false;
}

static void insert(int x) {
    unsigned int h = hashOf(x);
    while (used[h]) {
        if (keys[h] == x) return;              // 已经存过了（重复的数），不再存
        h = (h + 1) & (HASH_SIZE - 1);
    }
    used[h] = 1;
    keys[h] = x;
}

int longestConsecutive(int* nums, int numsSize) {
    memset(used, 0, sizeof(used));             // static 数组要手动清空

    // 1. 所有数放进集合（自动去重）
    for (int i = 0; i < numsSize; i++) insert(nums[i]);

    int best = 0;
    // 2. 枚举集合里的每个数（遍历格子，而不是遍历 nums，这样重复的数只处理一次）
    for (int h = 0; h < HASH_SIZE; h++) {
        if (!used[h]) continue;
        int x = keys[h];
        if (contains(x - 1)) continue;         // x-1 存在 → x 不是起点，跳过
        // 3. x 是起点，往后数
        int len = 1;
        while (contains(x + 1)) {
            x++;
            len++;
        }
        if (len > best) best = len;
    }
    return best;
}
```

**代码中几个可能看不懂的地方：**

- `(unsigned int)x * 2654435761u`：先转成无符号数，负数也能正常参与运算，而且无符号乘法溢出是"自动取模"，不会出错。
- `>> (32 - HASH_BITS)`：取乘积的**高 18 位**。高位混合了 x 所有位的信息，分布比低位更均匀。
- `x - 1`、`x + 1` 会溢出吗？数值范围是 ±10⁹，离 `int` 上限还很远，安全。
- **为什么遍历格子而不是遍历 `nums`？** 如果 `nums` 是 5 万个 1 再加上 `2, 3, ..., 50001`，遍历 `nums` 会从起点 1 往后数 5 万遍，又变成 O(n²)。遍历格子保证每个不同的值只处理一次。

### 复杂度分析

- **时间复杂度 O(n)**：插入 n 次；每个数作为"起点检查"一次，作为"往后数"最多被数到一次。哈希操作平均 O(1)。（遍历 2¹⁸ 个格子是固定开销。）
- **空间复杂度 O(n)**：哈希表。

---

## ⚠️ 第五步：小白常见错误

1. **没有判断"是不是起点"，对每个数都往后数** → 数组是 `1 ~ 10^5` 打乱时，约 5×10⁹ 次查找，超时。
2. **排序法里没有跳过重复** → `[0,1,1,2]` 遇到第二个 1 时 `cur` 被重置成 1，最后答案 2（正确是 3）。
3. **比较函数写 `return x - y;`** → `10^9 - (-10^9)` 溢出，排序错乱，答案出错。
4. **空数组返回 1** → 排序法里 `best` 初始化成 1 之前必须先判断 `numsSize == 0`。
5. **哈希下标用 `x % HASH_SIZE`** → x 是负数时结果也是负数，数组越界崩溃。要先转成 `unsigned`，或用位运算保证非负。
6. **`static` 哈希表没有 `memset` 清零** → 判题会多次调用函数时（或你在本地多次测试时），上一次的数据残留，答案出错。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 排序后扫描 | O(n log n) | O(log n) | ⭐ | 简单可靠，先写对 |
| 哈希集合（每个数都往后数） | O(n²) | O(n) | ⭐⭐ | 会超时 |
| 哈希集合 + 只从起点数 | O(n) | O(n) | ⭐⭐⭐ | 满足题目要求的标准答案 |
