# 322. 零钱兑换 —— 小白详细题解

> 这是"完全背包"最经典的一道题。我们先用"递归 + 记忆化"从上往下想清楚，再改写成从下往上填表的动态规划。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 给你几种面额的硬币（每种**无限多**），要凑出总金额 `amount`，最少需要几枚？凑不出来就返回 `-1`。

拿示例 1 `coins = [1,2,5]`、`amount = 11` 来说：

| 凑法 | 硬币个数 |
|---|---|
| 1 × 11 | 11 |
| 5 + 2 + 2 + 2 | 4 |
| 5 + 5 + 1 | **3** ✅ |

**几个需要注意的细节：**

1. **贪心（先拿最大的）不一定对**：`coins = [1,3,4]`、`amount = 6`，贪心拿 4 + 1 + 1 = 3 枚，最优是 3 + 3 = 2 枚。
2. `amount = 0` 时，一枚都不用拿，答案是 **0**（示例 3）。
3. 凑不出来时返回 **-1**（示例 2：只有面额 2，凑不出奇数 3）。
4. 面额最大可达 `2^31 - 1`，比 `amount` 大得多，计算 `i - coins[k]` 前要先判断 `coins[k] <= i`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. "无穷大"怎么选？

求最小值时要用一个"不可能的大数"表示"凑不出来"。本题最多用 `amount` 枚面额为 1 的硬币，所以 **`amount + 1` 就是一个安全的无穷大**。

为什么不用 `INT_MAX`？因为后面要算 `dp[x] + 1`，`INT_MAX + 1` 会**溢出**变成一个很小的负数，反而被当成"最小值"选中。

### 2. 整数溢出的另一个坑

```c
if (i - coins[k] >= 0)       // 看起来没问题……
```

当 `i` 很小、`coins[k]` 接近 `2^31 - 1` 时，减法本身不会溢出（结果是一个很大的负数），但如果反过来写 `i + coins[k]` 就会溢出。最稳妥的写法是**直接比较** `coins[k] <= i`。

### 3. 递归函数与 `static` 辅助函数

思路一会写一个辅助递归函数。在 OJ 上写辅助函数时建议加 `static`，表示只在本文件内可见，避免和判题程序里的函数重名。

---

## 💡 第三步：思路一 —— 递归 + 记忆化（自顶向下）

### 思路

想凑出金额 `x`，**最后一枚**硬币可以是任意一种面额 `c`（只要 `c <= x`）。拿掉它之后，剩下的 `x - c` 也要用最少的硬币凑出来：

**`f(x) = min(f(x - c)) + 1`，对所有 `c <= x`**

- `f(0) = 0`
- 如果所有 `f(x - c)` 都凑不出来，`f(x)` 也凑不出来

直接递归会把同一个 `f(x)` 算很多遍（指数级）。所以用一个数组 `memo[x]` **记住**算过的结果，下次直接查表。

### 手动模拟（`coins = [1,2,5]`，求 f(6)）

| 要算的 | 最后一枚是 1 | 最后一枚是 2 | 最后一枚是 5 | 结果 |
|---|---|---|---|---|
| f(1) | f(0)+1 = 1 | — | — | 1 |
| f(2) | f(1)+1 = 2 | f(0)+1 = 1 | — | 1 |
| f(3) | f(2)+1 = 2 | f(1)+1 = 2 | — | 2 |
| f(4) | f(3)+1 = 3 | f(2)+1 = 2 | — | 2 |
| f(5) | f(4)+1 = 3 | f(3)+1 = 3 | f(0)+1 = 1 | 1 |
| f(6) | f(5)+1 = **2** | f(4)+1 = 3 | f(1)+1 = 2 | **2** |

f(6) = 2（5 + 1）。

### 代码

```c
// memo[x]：-2 表示还没算过，-1 表示凑不出来，其他值表示最少硬币数
static int* memo;

static int dfs(int* coins, int coinsSize, int x) {
    if (x == 0) return 0;                  // 金额为 0，不需要硬币
    if (memo[x] != -2) return memo[x];     // 算过了，直接返回

    int best = -1;                         // -1 表示目前还没找到凑法
    for (int k = 0; k < coinsSize; k++) {
        if (coins[k] > x) continue;        // 这枚硬币太大，用不上
        int sub = dfs(coins, coinsSize, x - coins[k]);   // 剩下的金额最少要几枚
        if (sub == -1) continue;           // 剩下的凑不出来
        if (best == -1 || sub + 1 < best) best = sub + 1;
    }

    memo[x] = best;                        // 记下来
    return best;
}

int coinChange(int* coins, int coinsSize, int amount) {
    memo = (int*)malloc(sizeof(int) * (amount + 1));
    for (int i = 0; i <= amount; i++) memo[i] = -2;   // 全部标记为"没算过"

    int ans = dfs(coins, coinsSize, amount);
    free(memo);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(amount × k)**（k 为面额种数）：每个金额只真正计算一次，每次枚举 k 种硬币。
- **空间复杂度 O(amount)**：memo 数组 + 递归栈。最坏递归深度约 `amount = 10⁴` 层，本题可以接受。

## 🚀 第四步：思路二 —— 自底向上的动态规划

### 思路

递归是"要算 f(11)，先去算 f(10)、f(9)、f(6)……"，从大往小问。反过来想：**从小往大依次算好 `dp[0], dp[1], …, dp[amount]`**，算 `dp[i]` 时用到的 `dp[i - c]` 都已经算好了。这样就不需要递归，也没有递归栈的开销。

- `dp[i]` = 凑出金额 `i` 最少需要几枚硬币
- `dp[0] = 0`，其余初始化为"无穷大" `amount + 1`
- `dp[i] = min(dp[i - c] + 1)`，对所有 `c <= i`
- 最后 `dp[amount]` 如果还是无穷大，说明凑不出来，返回 -1

### 手动模拟（`coins = [2]`，`amount = 3`，INF = 4）

| i | 用 2 | dp[i] |
|---|---|---|
| 0 | — | 0 |
| 1 | 2 > 1，用不了 | 4（INF） |
| 2 | dp[0] + 1 = 1 | 1 |
| 3 | dp[1] + 1 = 5，不比 4 小 | 4（INF） |

`dp[3]` 仍是 INF → 返回 **-1**。

> ❓ 注意 i = 3 那一行：`dp[1]` 是 INF（4），加 1 变成 5，仍然不会小于 INF，所以 INF 不会被"污染"成一个假的答案。这正是选 `amount + 1` 而不是 `INT_MAX` 的好处。

### 代码

```c
int coinChange(int* coins, int coinsSize, int amount) {
    int INF = amount + 1;                         // 硬币数不可能超过 amount，所以它就是"无穷大"
    int* dp = (int*)malloc(sizeof(int) * (amount + 1));
    dp[0] = 0;                                    // 凑 0 元不需要硬币

    for (int i = 1; i <= amount; i++) {
        dp[i] = INF;                              // 先假设凑不出来
        for (int k = 0; k < coinsSize; k++) {
            // 硬币不能比金额大；比较而不是相减，避免大面额带来的溢出问题
            if (coins[k] <= i && dp[i - coins[k]] + 1 < dp[i]) {
                dp[i] = dp[i - coins[k]] + 1;     // 最后一枚用 coins[k]
            }
        }
    }

    int ans = (dp[amount] >= INF) ? -1 : dp[amount];
    free(dp);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(amount × k)**：最多 10⁴ × 12 ≈ 1.2×10⁵ 次。
- **空间复杂度 O(amount)**。

## ⚠️ 第五步：小白常见错误

1. **贪心先拿大面额** → `[1,3,4]` 凑 6 得到 3 枚，正确是 2 枚。
2. **用 `INT_MAX` 当无穷大** → `dp[i - c] + 1` 溢出成负数，凑不出来的金额被当成"用了负数枚硬币"。
3. **忘记判断 `coins[k] <= i`** → 访问 `dp` 的负下标，越界崩溃。
4. **`amount == 0` 返回 -1** → 金额为 0 时答案是 0。
5. **最后没有把 INF 转换成 -1** → 凑不出来时输出了 `amount + 1`。
6. **不加记忆的递归** → 同一个金额被重复计算，指数级时间，必定超时。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 暴力递归 | 指数级 | O(amount) | ⭐ | 只用于理解 |
| 递归 + 记忆化 | O(amount × k) | O(amount) | ⭐⭐ | 思考过程最自然 |
| 自底向上 DP | O(amount × k) | O(amount) | ⭐⭐ | 推荐，代码短、无递归 |
