# 717. 1 比特与 2 比特字符 —— 小白详细题解

> 一道"模拟解码"的小题，能帮你练习**用下标跳着走**，以及从结论反推的思维。

---

## 📖 第一步：先读懂题目

有两种"字符"：

- `0` —— 一个 1 比特字符
- `10` 或 `11` —— 一个 2 比特字符（**以 1 开头的一定占两位**）

给你一串比特，最后一位一定是 `0`。问：从头解码到尾，**最后一个字符**是不是那个单独的 `0`？

拿两个示例来看：

| bits | 解码过程 | 最后一个字符 | 答案 |
|---|---|---|---|
| [1,0,0] | `10` + `0` | `0`（1 比特） | true |
| [1,1,1,0] | `11` + `10` | `10`（2 比特） | false |

**关键细节：**

1. 解码方式是**唯一**的：从左往右，看到 `0` 就是一个字符，看到 `1` 就必须和下一位一起组成字符。
2. 最后一位 `0` 可能被前面的 `1` "借走"，组成 `10`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 下标不一定每次 +1

```c
int i = 0;
while (i < bitsSize - 1) {
    if (bits[i] == 1) i += 2;   // 2 比特字符，跳过两位
    else i += 1;                // 1 比特字符，跳过一位
}
```

`for` 循环习惯写 `i++`，但这里每次跳的步数不一样，用 `while` 更清楚。

### 2. 巧用数值本身

因为 `bits[i]` 只能是 0 或 1，`i += bits[i] + 1;` 就能一行代替上面的 `if-else`：是 0 跳 1 步，是 1 跳 2 步。

---

## 💡 第三步：思路一 —— 从头模拟解码

### 思路

用 `i` 表示"下一个字符从哪里开始"。不断往后跳，**直到 `i` 到达或越过最后一位**：

- 如果 `i` 恰好停在最后一位（`i == bitsSize - 1`），说明最后的 `0` 是一个独立字符 → `true`
- 如果 `i` 跳过了最后一位（`i == bitsSize`），说明最后的 `0` 被前一个 `1` 带走了 → `false`

### 手动模拟

示例 1：`[1,0,0]`，`bitsSize - 1 = 2`

| i | bits[i] | 动作 | 新 i |
|---|---|---|---|
| 0 | 1 | 跳 2 | 2 |
| 2 | - | 停（i == 2，正好是最后一位） | → true |

示例 2：`[1,1,1,0]`，`bitsSize - 1 = 3`

| i | bits[i] | 动作 | 新 i |
|---|---|---|---|
| 0 | 1 | 跳 2 | 2 |
| 2 | 1 | 跳 2 | 4 |
| 4 | - | 停（i == 4，越过了最后一位） | → false |

### 代码

```c
bool isOneBitCharacter(int* bits, int bitsSize) {
    int i = 0;                         // 当前字符的起始位置
    while (i < bitsSize - 1) {         // 还没走到最后一位
        if (bits[i] == 1) {
            i += 2;                    // 1 开头：2 比特字符
        } else {
            i += 1;                    // 0：1 比特字符
        }
    }
    return i == bitsSize - 1;          // 恰好停在最后一位 → 最后一个是 1 比特字符
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最多走 n 步。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 只看结尾连续的 1

### 思路

前面的部分其实不影响结论，关键在于**最后那个 0 前面紧挨着有几个连续的 1**：

- 一串连续的 `1` 会两两配对成 `11`。
- 如果连续的 `1` 有**偶数**个，它们刚好配完，最后的 `0` 单独成字符 → `true`
- 如果有**奇数**个，剩下一个 `1` 必须和最后的 `0` 组成 `10` → `false`

> ❓ 为什么连续 1 前面的部分不影响？因为连续 1 的前面要么是数组开头，要么是一个 `0`。这个 `0` 无论是独立字符还是 `10` 的后半，都会让下一个字符**恰好从连续 1 的第一位开始**。

### 手动模拟

| bits | 末尾 0 前连续 1 的个数 | 奇偶 | 答案 |
|---|---|---|---|
| [1,0,0] | 0（倒数第二位是 0） | 偶 | true |
| [1,1,1,0] | 3 | 奇 | false |
| [0,1,1,0] | 2 | 偶 | true |

### 代码

```c
bool isOneBitCharacter(int* bits, int bitsSize) {
    int ones = 0;                                  // 末尾 0 之前连续 1 的个数
    for (int i = bitsSize - 2; i >= 0 && bits[i] == 1; i--) {
        ones++;                                    // 从倒数第二位往前数
    }
    return ones % 2 == 0;                          // 偶数个 → 最后的 0 独立
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最坏全是 1，但通常只看末尾一小段。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **只看倒数第二位是不是 1** → `[1,1,0]` 倒数第二位是 1，但 `11` + `0`，答案是 `true`。必须数**连续**的 1 有几个。
2. **循环条件写成 `i < bitsSize`** → 模拟时最后会走到"越过末尾"的位置，再判断 `i == bitsSize - 1` 就永远不成立了（停在最后一位时还会再跳一步）。应该是 `i < bitsSize - 1`。
3. **思路二从 `bitsSize - 1` 开始往前数** → 最后一位是 0，循环立刻停止，永远返回 `true`。应该从**倒数第二位** `bitsSize - 2` 开始。
4. **思路二没判断 `i >= 0`** → 全是 1 的前缀（如 `[1,1,1,0]`）会一直往前数到 `bits[-1]`，越界。
5. **以为 `10` 和 `11` 以外还有 `01`** → 2 比特字符一定以 1 开头，`0` 永远是独立字符的开头。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 从头模拟 | O(n) | O(1) | ⭐ | 最直观，按题意直接写 |
| 数末尾连续 1 | O(n) | O(1) | ⭐⭐ | 需要多一步推理，代码更短 |
