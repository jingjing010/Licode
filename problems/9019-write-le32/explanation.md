# 9019. 小端写入 uint32 到缓冲区 —— 小白详细题解

> 上一题是"把字节拼成整数"（解析/接收），这一题是"把整数拆成字节"（打包/发送）。两者合起来，就是所有通信协议代码的基本功。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把一个 32 位整数拆成 4 个字节，**最低的字节先写**，依次写到缓冲区 `offset` 开始的 4 个格子里，其它格子不许动。

拿示例 2 来说：`value = 1000 = 0x000003E8`，拆成 4 个字节：

| 字节 | B0（最低） | B1 | B2 | B3（最高） |
|---|---|---|---|---|
| 十六进制 | `E8` | `03` | `00` | `00` |
| 十进制 | 232 | 3 | 0 | 0 |

小端写入 `offset = 2`：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 写入前 | 2 | 1 | 0 | 0 | 0 | 0 | 255 |
| 写入后 | 2 | 1 | **232** | **3** | **0** | **0** | 255 |

**几个需要注意的细节：**

1. 函数返回 `void`，你是**直接修改 `buf`** 指向的内存，判题程序打印整个缓冲区来检查。
2. 下标 0、1、6 的字节必须**原封不动**——写多了、写错位置都会 WA。
3. "小端"说的是**数据在缓冲区里的排列**，与运行代码的 CPU 是什么字节序无关。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 小端在内存中的样子

```
value = 0x12345678，写入 buf[0..3]：

     buf[0]  buf[1]  buf[2]  buf[3]
     [0x78]  [0x56]  [0x34]  [0x12]
       ↑ 最低字节                ↑ 最高字节
```

"小端" = **低**位字节放在**低**地址（下标小的位置）。

### 2. 通过指针修改调用者的数据

```c
void write_le32(uint8_t* buf, int offset, uint32_t value)
```

`buf` 是指针，`buf[offset] = x;` 修改的就是调用者那块内存，所以函数不需要返回任何东西。注意这里的 `buf` **没有** `const`，因为我们要写它。

### 3. 截断：把大数放进 `uint8_t`

`uint8_t` 只能存 0~255。把一个 `uint32_t` 赋值给 `uint8_t` 时，C 语言会**自动只保留低 8 位**（无符号数的转换规则是"对 256 取模"）。所以：

```c
buf[i] = (uint8_t)(value >> 8);    // 与 (value >> 8) & 0xFF 效果完全相同
```

写 `& 0xFF` 和 `(uint8_t)` 强转都是为了**表明意图**，让读代码的人（和编译器的警告检查）知道"这里是故意截断的"。

### 4. 为什么不用 `*(uint32_t*)(buf + offset) = value;` 或 `memcpy`？

```c
*(uint32_t*)(buf + offset) = value;     // ❌ 非对齐访问 + 违反严格别名规则
memcpy(buf + offset, &value, 4);        // ❌ 字节顺序取决于 CPU：大端机器上会写成大端
```

`memcpy` 没有对齐和别名问题，但它按**本机内存布局**拷贝。STM32（小端）上碰巧正确，换到大端的 PowerPC 或某些 DSP 上就错了。**用移位拆字节的写法在任何 CPU 上结果都一样**，这才是可移植的协议代码。

---

## 💡 第三步：思路一 —— 逐个字节写入（标准写法）

### 思路

第 i 个字节（i = 0 最低）就是 `(value >> (8 * i)) & 0xFF`，写到 `buf[offset + i]`。

### 手动模拟（示例 1：`value = 0x12345678`，`offset = 0`）

| i | `value >> (8*i)` | `& 0xFF` | 写入位置 |
|---|---|---|---|
| 0 | `0x12345678` | `0x78` = 120 | `buf[0]` |
| 1 | `0x00123456` | `0x56` = 86 | `buf[1]` |
| 2 | `0x00001234` | `0x34` = 52 | `buf[2]` |
| 3 | `0x00000012` | `0x12` = 18 | `buf[3]` |

结果 `[120,86,52,18]` ✅

### 代码

```c
void write_le32(uint8_t* buf, int offset, uint32_t value) {
    // 小端：最低字节写在最前面
    buf[offset + 0] = (uint8_t)(value & 0xFF);          // bit7~0
    buf[offset + 1] = (uint8_t)((value >> 8) & 0xFF);   // bit15~8
    buf[offset + 2] = (uint8_t)((value >> 16) & 0xFF);  // bit23~16
    buf[offset + 3] = (uint8_t)((value >> 24) & 0xFF);  // bit31~24
}
```

### 复杂度分析

- **时间复杂度 O(1)**，**空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 循环 + 每次右移 8 位

### 思路

每写完最低字节，就把 `value` 右移 8 位，让下一个字节"掉"到最低位。循环 4 次即可。这种写法很容易改成"写 N 字节小端整数"的通用函数。

### 手动模拟（示例 2：`value = 0x000003E8`，`offset = 2`）

| i | 当前 value | 写入 `buf[2+i]` | 右移后 value |
|---|---|---|---|
| 0 | `0x000003E8` | `0xE8` = 232 | `0x00000003` |
| 1 | `0x00000003` | `0x03` = 3 | `0x00000000` |
| 2 | `0x00000000` | 0 | 0 |
| 3 | `0x00000000` | 0 | 0 |

### 代码

```c
void write_le32(uint8_t* buf, int offset, uint32_t value) {
    for (int i = 0; i < 4; i++) {
        buf[offset + i] = (uint8_t)(value & 0xFF);  // 写入当前最低字节
        value >>= 8;                                // 下一个字节移到最低位
    }
}
```

> 💬 `value` 是按值传递的**副本**，在函数里修改它不会影响调用者，放心右移。

---

## ⚠️ 第五步：小白常见错误

1. **写成了大端**：`buf[offset] = value >> 24` —— 那是大端写法，示例 1 会得到 `[18,52,86,120]`。牢记"小端低字节在前"。
2. **忘记加 `offset`**：总是写 `buf[0..3]`，示例 2 会把帧头 `2,1` 覆盖掉。
3. **循环写了 `i <= 4`**：多写了一个字节，`buf[offset + 4]` 被改成 0，破坏了后面的数据（在真实设备上可能破坏校验和甚至越界）。
4. **用 `int` 保存 `value` 再右移**：`int v = 0xFFFFFFFF` 实际是 `-1`，`v >> 8` 是算术右移，仍然是 `-1`；虽然本题每次只取低 8 位碰巧不出错，但这是坏习惯。处理位数据请一律用无符号类型。
5. **用指针强转一次性写入**：`*(uint32_t*)(buf + offset) = value;` 在 `offset` 不是 4 的倍数时，Cortex-M0 会 HardFault；而且大端 CPU 上字节顺序会反。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 可移植 | 建议 |
|---|---|---|---|---|
| 逐个字节写入 | O(1) | O(1) | ✅ | 最清晰，项目首选 |
| 循环右移 | O(1) | O(1) | ✅ | 易于推广到任意长度 |
| `memcpy(&value)` | O(1) | O(1) | ❌ 依赖 CPU 字节序 | 不推荐 |
| 指针强转 | O(1) | O(1) | ❌ 对齐/别名问题 | 禁止 |
