# 410. 分割数组的最大值 —— 小白详细题解

> 这是"**二分答案**"的经典困难题。核心技巧只有一句话：**把"求最优值"变成"判断某个值行不行"**。学会这一招，875、1011、1482 等一大串题都能秒。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把一排数字**切成 k 段**（每段连续、不能为空），每段算一个和，取其中**最大的那个和**。怎么切能让这个"最大和"尽量小？

拿示例 1 `nums = [7,2,5,10,8], k = 2` 来说，切一刀有 4 种切法：

| 切法 | 第 1 段和 | 第 2 段和 | 最大和 |
|---|---|---|---|
| [7] [2,5,10,8] | 7 | 25 | 25 |
| [7,2] [5,10,8] | 9 | 23 | 23 |
| [7,2,5] [10,8] | 14 | 18 | **18** ✅ |
| [7,2,5,10] [8] | 24 | 8 | 24 |

最小的"最大和"是 18。

**几个需要注意的细节：**

1. 段必须**连续**，不能重新排列数字。
2. 必须**恰好** k 段，每段非空。
3. 数字可以是 0。
4. 总和最大 `1000 × 10^6 = 10^9`，刚好还在 `int` 范围内，但中间计算时为了保险用 `long long`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `static` 辅助函数

```c
static int countPieces(int* nums, int numsSize, long long limit) { ... }
```

把"判断"逻辑单独写成一个函数，主函数会清爽很多。`static` 表示这个函数只在当前文件里可见，避免和别处同名函数冲突。

### 2. `long long` 防溢出

`int` 最大约 `2.1 × 10^9`。本题总和最多 `10^9`，但 `cur + nums[i]` 和二分的 `lo + hi` 都可能接近上限。用 `long long`（约 `9.2 × 10^18`）最省心。

### 3. 二维数组

动态规划解法要用二维数组 `long long dp[51][1001]`。它约占 400KB，放在函数里作为局部变量可能栈溢出，所以加 `static` 放到静态区。

---

## 💡 第三步：思路一 —— 动态规划（直接求最优）

### 思路

设 `dp[j][i]` = 把**前 i 个数**切成 **j 段**时，"最大段和"的最小值。

最后一段是 `nums[p..i-1]`（第 p 个到第 i-1 个），前面 `p` 个数切成 `j-1` 段：

```
dp[j][i] = min over p ( max(dp[j-1][p], sum(nums[p..i-1])) )
```

区间和用前缀和 `pre[i] - pre[p]` 在 O(1) 时间算出。答案是 `dp[k][n]`。

### 手动模拟（`nums = [1,4,4], k = 3`）

前缀和 `pre = [0,1,5,9]`。

| dp[j][i] | i=1 | i=2 | i=3 |
|---|---|---|---|
| j=1 | 1 | 5 | 9 |
| j=2 | - | max(1,4)=4 | min(max(1,8), max(5,4))=5 |
| j=3 | - | - | max(dp[2][2], 4)=4 |

答案 `dp[3][3] = 4` ✅。

### 代码

```c
int splitArray(int* nums, int numsSize, int k) {
    static long long dp[51][1001];   // static：避免 400KB 局部数组撑爆栈
    static long long pre[1001];
    int n = numsSize;

    pre[0] = 0;
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];   // 前缀和

    for (int j = 0; j <= k; j++)
        for (int i = 0; i <= n; i++)
            dp[j][i] = LLONG_MAX;    // 先全部设成"不可能"
    dp[0][0] = 0;                    // 0 个数切 0 段：最大和是 0

    for (int j = 1; j <= k; j++) {
        for (int i = j; i <= n; i++) {           // 至少 j 个数才能切 j 段
            for (int p = j - 1; p < i; p++) {    // 最后一段是 nums[p..i-1]
                if (dp[j - 1][p] == LLONG_MAX) continue;
                long long last = pre[i] - pre[p];
                long long worst = dp[j - 1][p] > last ? dp[j - 1][p] : last;
                if (worst < dp[j][i]) dp[j][i] = worst;
            }
        }
    }
    return (int)dp[k][n];
}
```

### 复杂度分析

- **时间复杂度 O(k · n²)**：`50 × 1000 × 1000 = 5 × 10^7`，本题能过。
- **空间复杂度 O(k · n)**。

## 🚀 第四步：思路二 —— 二分答案 + 贪心（最优解）

### 换个问法

直接求"最小的最大和"很难。但如果我问你：

> **"每段和不超过 `limit`，最少要切几段？"**

这就很简单了——**贪心**：从左往右装，当前段装得下就继续装，装不下就新开一段。

而且：`limit` 越大，每段能装越多，**需要的段数越少**。这是单调的！

| limit | 贪心切法（nums = [7,2,5,10,8]） | 段数 | <= 2 ? |
|---|---|---|---|
| 15 | [7,2,5] [10] [8] | 3 | 否 |
| 17 | [7,2,5] [10] [8] | 3 | 否 |
| 18 | [7,2,5] [10,8] | 2 | **是** |
| 20 | [7,2,5] [10,8] | 2 | 是 |

我们要找**最小的、使段数 <= k 的 limit**——"找第一个满足条件的值"，正是二分查找！

> 为什么"段数 <= k"就行，不用恰好等于 k？因为段数少于 k 时，可以把某些段再拆开（每个数单独一段），拆完每段只会更小，不会超过 limit。

### 区间定义与循环条件

- 答案范围：`lo = max(nums)`（每段至少要装下最大的那个数），`hi = sum(nums)`（整个数组一段）。
- 区间：闭区间 `[lo, hi]`，答案一定在里面。
- `while (lo < hi)`：`check(mid)` 成立时 `hi = mid`（mid 可能就是答案），否则 `lo = mid + 1`。
- `mid = lo + (hi - lo) / 2`，用 `long long` 更保险。

### 手动模拟（`nums = [7,2,5,10,8], k = 2`）

| 轮次 | lo | hi | mid | 段数 | 操作 |
|---|---|---|---|---|---|
| 1 | 10 | 32 | 21 | 2 | hi = 21 |
| 2 | 10 | 21 | 15 | 3 | lo = 16 |
| 3 | 16 | 21 | 18 | 2 | hi = 18 |
| 4 | 16 | 18 | 17 | 3 | lo = 18 |
| 结束 | 18 | 18 | | | 返回 18 ✅ |

### 代码

```c
// 每段和不超过 limit 时，贪心最少能切成几段
static int countPieces(int* nums, int numsSize, long long limit) {
    int pieces = 1;              // 至少有 1 段
    long long cur = 0;           // 当前这段的和
    for (int i = 0; i < numsSize; i++) {
        if (cur + nums[i] > limit) {   // 装不下了，新开一段
            pieces++;
            cur = 0;
        }
        cur += nums[i];
    }
    return pieces;
}

int splitArray(int* nums, int numsSize, int k) {
    long long lo = 0, hi = 0;
    for (int i = 0; i < numsSize; i++) {
        if (nums[i] > lo) lo = nums[i];   // 下界：最大元素
        hi += nums[i];                    // 上界：总和
    }

    while (lo < hi) {                     // 答案在 [lo, hi] 中
        long long mid = lo + (hi - lo) / 2;
        if (countPieces(nums, numsSize, mid) <= k) {
            hi = mid;            // mid 可行，答案 <= mid
        } else {
            lo = mid + 1;        // mid 太小，段数太多
        }
    }
    return (int)lo;
}
```

### 复杂度分析

- **时间复杂度 O(n · log(sum))**：二分约 30 轮，每轮扫一遍数组。约 `1000 × 30 = 3 × 10^4`，比 DP 快上千倍。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **`lo` 从 0 开始而不是 `max(nums)`** → 本模板里 `countPieces` 在 `limit < max` 时会把放不下的数硬塞进一段，可能误判为可行（例如 `[0,10], k = 2, limit = 0` 会被算成 2 段，错误地返回 0）。从 `max(nums)` 开始最安全。
2. **贪心时先加再判断** → 写成 `cur += nums[i]; if (cur > limit) { pieces++; cur = 0; }`，把超出的那个数丢掉了，下一段少算了它。
3. **判断条件写成 `== k`** → 段数小于 k 也是可行的（可以继续拆），写成 `== k` 会让二分失去单调性。
4. **DP 数组开成局部的大数组** → `long long dp[51][1001]` 约 400KB，可能栈溢出，加 `static` 或用 `malloc`。
5. **二分更新写成 `hi = mid - 1`** → mid 可行时它本身可能就是答案，不能排除。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 动态规划 | O(k · n²) | O(k · n) | ⭐⭐⭐ | 通用的"切分"问题思路 |
| 二分答案 + 贪心 | O(n · log(sum)) | O(1) | ⭐⭐⭐ | 最优解，必须掌握 |

> 🎯 **学习建议**：看到"**最大值最小**"或"**最小值最大**"，第一反应就是**二分答案**：猜一个答案，写一个 `check` 判断它行不行，再看 `check` 是否单调。
