# 9049. CRC-16/MODBUS 校验 —— 小白详细题解

> 做工业设备、串口通信几乎一定会碰到 Modbus。它的 CRC 和 9048 的 CRC-8 原理完全相同，但多了一个让初学者头疼的概念：**反射（reflect）**。弄懂"为什么右移、为什么是 0xA001"，你就能读懂任何一份 CRC 参数表。

---

## 📖 第一步：先读懂题目

和 CRC-8 相比有三处不同：

| | CRC-8（9048） | CRC-16/MODBUS（本题） |
|---|---|---|
| 宽度 | 8 位 | 16 位 |
| 初值 | 0x00 | **0xFFFF** |
| 处理顺序 | 每字节从最高位开始 → 左移，看最高位 | 每字节从**最低位**开始 → **右移，看最低位** |
| 代码中的多项式 | 0x07 | **0xA001**（0x8005 按位倒序） |

用示例 2 的第一个字节 `0x01` 演示前几步（crc 初值 0xFFFF）：

| 步骤 | crc（十六进制） | 最低位 | 操作 |
|---|---|---|---|
| crc ^= 0x01 | 0xFFFE | 0 | 右移 |
| 第 1 位 | 0x7FFF | 1 | 右移再异或 0xA001 |
| 第 2 位 | 0x3FFF ^ 0xA001 = 0x9FFE | 0 | 右移 |
| …… | …… | | |

处理完 6 个字节后得到 0x0A84 = 2692。

**容易忽略的细节：**

1. 初值是 `0xFFFF` 不是 0，所以空数据的结果是 65535。
2. 右移是**逻辑右移**，`crc` 必须是无符号类型（`uint16_t`），高位补 0。
3. 题目只要求返回 16 位数值。发送时**低字节在前**——这一点只影响组帧（见 9059），不影响计算。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 什么是"反射"？

反射就是把一个数的二进制**左右颠倒**：

```
0x8005 = 1000 0000 0000 0101
倒过来 = 1010 0000 0000 0001 = 0xA001
```

UART 发送一个字节时是**先发最低位**的。为了让 CRC 的计算顺序和线路上比特的顺序一致，Modbus 规定"输入反射"。如果老老实实地先把每个字节倒过来、再按 CRC-8 那样左移计算，最后再把结果倒回来，会非常麻烦。

聪明的做法：**把整个算法镜像过来**——左移变右移，看最高位变看最低位，多项式也倒过来（0x8005 → 0xA001）。数据和结果都不用再反射了，这就是本题代码的写法。

### 2. 无符号右移

```c
uint16_t crc = 0x8000;
crc >>= 1;      // 0x4000，高位补 0
```

如果是有符号数的负数，右移时高位可能补 1（算术右移），CRC 就全错了。所以 CRC 变量一律用无符号类型。

### 3. 取低字节、高字节

```c
uint8_t lo = crc & 0xFF;          // 低 8 位
uint8_t hi = (crc >> 8) & 0xFF;   // 高 8 位
```

## 💡 第三步：思路一 —— 逐位计算（反射版）

### 代码

```c
uint16_t crc16Modbus(const uint8_t* buf, size_t len) {
    uint16_t crc = 0xFFFF;                         // 初值
    for (size_t i = 0; i < len; i++) {
        crc ^= buf[i];                             // 反射算法：新字节异或进【低】8 位
        for (int k = 0; k < 8; k++) {
            if (crc & 0x0001) {                    // 看最低位
                crc = (uint16_t)((crc >> 1) ^ 0xA001);   // 右移后异或反射多项式
            } else {
                crc >>= 1;                         // 只右移
            }
        }
    }
    return crc;                                    // XorOut = 0，输出反射已经"自带"
}
```

### 复杂度分析

- **时间 O(8n)**，**空间 O(1)**。

## 🚀 第四步：思路二 —— 查表法

### 为什么能优化？

和 CRC-8 一样，每处理一个字节，内层 8 次循环只依赖 `(crc ^ byte)` 的**低 8 位**；高 8 位只是被右移了 8 次。于是：

```
crc = (crc >> 8) ^ table[(crc ^ byte) & 0xFF];
```

`table[v]` 就是"把 v 放进 crc 低 8 位、做 8 次逐位运算"后的结果。

### 代码

```c
static uint16_t crc_table[256];
static bool crc_table_ready = false;

static void build_table(void) {
    for (int v = 0; v < 256; v++) {
        uint16_t crc = (uint16_t)v;
        for (int k = 0; k < 8; k++) {
            crc = (crc & 1) ? (uint16_t)((crc >> 1) ^ 0xA001) : (uint16_t)(crc >> 1);
        }
        crc_table[v] = crc;
    }
    crc_table_ready = true;
}

uint16_t crc16Modbus(const uint8_t* buf, size_t len) {
    if (!crc_table_ready) build_table();
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < len; i++) {
        uint8_t idx = (uint8_t)(crc ^ buf[i]);            // 低 8 位与数据异或，作为下标
        crc = (uint16_t)((crc >> 8) ^ crc_table[idx]);    // 高 8 位右移下来，再异或表项
    }
    return crc;
}
```

### 🔌 嵌入式实战：接收端校验一帧

```c
// rx 是收到的完整 Modbus 帧（含最后 2 字节 CRC），n 为总长度
bool modbus_frame_ok(const uint8_t* rx, size_t n) {
    if (n < 4) return false;                                  // 最短帧：地址 + 功能码 + CRC
    uint16_t crc = crc16Modbus(rx, n - 2);                    // 只算 CRC 之前的部分
    return rx[n - 2] == (crc & 0xFF) && rx[n - 1] == (crc >> 8);  // 低字节在前
}
```

另一种写法：把整帧（包括 CRC 两个字节）一起算，结果为 0 就说明正确。

很多 Modbus 库（如 libmodbus、FreeModbus）用的是**两张 256 字节的表**（高字节表、低字节表），原理相同，只是把 16 位表拆成了两个 8 位表，适合只有 8 位总线的老单片机。

### 复杂度分析

- **时间 O(n)**，**空间 512 字节**（256 个 uint16_t）。

## ⚠️ 第五步：小白常见错误

1. **照抄 CRC-8 的左移写法，只把多项式改成 0x8005** → 没处理反射，结果完全不同。左移就用 0x8005，右移就用 0xA001，不能混。
2. **初值写成 0** → 示例 1 会得到 0xBB3D（那是 CRC-16/ARC 的值）。
3. **`crc` 用 `int16_t`** → 最高位为 1 时右移可能补 1。
4. **组帧时 CRC 高字节在前** → Modbus 规定低字节在前，从机会认为 CRC 错误而不响应。
5. **查表法下标写成 `crc_table[crc ^ buf[i]]`** → crc 是 16 位，下标可能超过 255，越界！必须先取低 8 位。

---

## 📊 第六步：方法对比

| 方法 | 时间 | 额外空间 | 说明 |
|---|---|---|---|
| 逐位法（右移 + 0xA001） | O(8n) | 无 | 代码短，Modbus 帧一般很短，够用 |
| 单表查表法 | O(n) | 512 字节 | 速度快 |
| 双 8 位表 | O(n) | 512 字节 | 8 位机友好，FreeModbus 等库的写法 |
