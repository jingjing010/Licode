# 35. 搜索插入位置 —— 小白详细题解

> 这是学习**二分查找**的标准入门题。把这道题吃透，后面一大串"二分"题都会轻松很多。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 给你一排**从小到大排好、没有重复**的数字，再给一个 `target`。如果 `target` 在里面，告诉我它在第几个；如果不在，告诉我**把它插进去后它会排在第几个**。

拿 `nums = [1,3,5,6]` 来说：

| target | 在数组里吗？ | 答案 | 理由 |
|---|---|---|---|
| 5 | 在，下标 2 | 2 | 直接返回下标 |
| 2 | 不在 | 1 | 2 应该插在 1 和 3 之间，也就是下标 1 |
| 7 | 不在 | 4 | 比所有数都大，插在最后，下标 4（等于数组长度） |
| 0 | 不在 | 0 | 比所有数都小，插在最前面 |

**几个需要注意的细节：**

1. 两种情况其实可以合并成一句话：**答案 = 第一个 `>= target` 的元素的下标**。如果所有元素都 `< target`，答案就是 `numsSize`。
2. 答案可能等于 `numsSize`（插到最后），这不是越界，是合法答案。
3. 题目要求 `O(log n)`，也就是要用二分查找。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 整数除法会向下取整

```c
int mid = (0 + 3) / 2;   // 结果是 1，不是 1.5
```

C 语言里两个 `int` 相除，结果直接丢掉小数部分。二分查找里算中点就靠它。

### 2. 为什么写 `lo + (hi - lo) / 2` 而不是 `(lo + hi) / 2`？

`lo + hi` 在下标很大（接近 `INT_MAX`）时可能**溢出**变成负数。`lo + (hi - lo) / 2` 数学上相等，但不会溢出。本题数据小，两种都行，但养成好习惯很重要。

---

## 💡 第三步：思路一 —— 从左到右扫描（最容易想到）

### 思路

从头开始看，遇到第一个 `>= target` 的数，就返回它的下标；如果走到最后都没遇到，返回 `numsSize`。

### 手动模拟（`nums = [1,3,5,6], target = 2`）

| i | nums[i] | nums[i] >= 2 ? |
|---|---|---|
| 0 | 1 | 否 |
| 1 | 3 | **是** → 返回 1 |

### 代码

```c
int searchInsert(int* nums, int numsSize, int target) {
    // 从左往右找第一个 >= target 的位置
    for (int i = 0; i < numsSize; i++) {
        if (nums[i] >= target) {
            return i;        // 找到了：target 就在这里，或者应该插在这里
        }
    }
    // 所有数都比 target 小，插到最后
    return numsSize;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最坏要看完整个数组。本题 n ≤ 10⁴，其实能过，但不符合题目 `O(log n)` 的要求。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（题目要求的写法）

### 思路

数组是有序的！看一眼中间的数 `nums[mid]`：

- 如果 `nums[mid] < target`：答案一定在 `mid` **右边**（`mid` 和它左边的都太小了），`lo = mid + 1`
- 否则 `nums[mid] >= target`：`mid` **可能**就是答案，答案在 `mid` 或它左边，`hi = mid`

我们用**左闭右开**区间 `[lo, hi)` 表示"答案可能在的范围"。一开始 `lo = 0, hi = numsSize`（注意 `hi` 可以取到 `numsSize`，因为答案可能是插到最后）。当 `lo == hi` 时，范围只剩一个位置，就是答案。

### 手动模拟（`nums = [1,3,5,6], target = 2`）

| 轮次 | lo | hi | mid | nums[mid] | 比较 | 操作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 5 | 5 >= 2 | hi = 2 |
| 2 | 0 | 2 | 1 | 3 | 3 >= 2 | hi = 1 |
| 3 | 0 | 1 | 0 | 1 | 1 < 2 | lo = 1 |
| 结束 | 1 | 1 | | | lo == hi | 返回 1 ✅ |

每一轮范围都缩小一半，10⁴ 个数最多只要约 14 轮！

### 代码

```c
int searchInsert(int* nums, int numsSize, int target) {
    int lo = 0;              // 答案可能的最小下标
    int hi = numsSize;       // 答案可能的最大下标（可以等于 numsSize，表示插在最后）

    // 区间 [lo, hi) 里还有多个候选时继续缩小
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;   // 中点，防溢出写法
        if (nums[mid] < target) {
            lo = mid + 1;    // mid 太小，答案在右边（不含 mid）
        } else {
            hi = mid;        // nums[mid] >= target，mid 可能是答案，保留它
        }
    }
    return lo;               // 此时 lo == hi，就是第一个 >= target 的位置
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：每轮砍掉一半。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **`hi` 初始化成 `numsSize - 1`** → 用 `[lo, hi)` 写法时，target 比所有数都大（如示例 3 的 7）就永远返回不了 `4`。
2. **写成 `hi = mid - 1`** → 在 `nums[mid] >= target` 时，`mid` 本身可能就是答案，把它排除掉就错了。
3. **循环条件写成 `lo <= hi` 但更新用 `hi = mid`** → 当 `lo == hi` 时 `mid == lo`，`hi = mid` 不会变化，**死循环**（超时）。闭区间和开区间的写法不要混用。
4. **找到相等就返回，找不到时返回 `-1`** → 这是普通二分查找的写法，本题不存在时要返回插入位置，不是 `-1`。
5. **`mid = (lo + hi) / 2` 在大数据下溢出** → 本题不会，但换到下标接近 `INT_MAX` 的题就会出错。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 顺序扫描 | O(n) | O(1) | ⭐ | 帮助理解"第一个 >= target" |
| 二分查找 | O(log n) | O(1) | ⭐⭐ | 题目要求，必须掌握 |

> 🎯 **学习建议**：记住一个模板——"找第一个满足条件的位置"用 `[lo, hi)`，`lo = mid + 1` / `hi = mid`，最后返回 `lo`。
