# 9016. 16 位字节序交换 —— 小白详细题解

> 字节序是嵌入式面试的"开胃菜"，几乎必问。这道题是字节序系列的第一题，先把"高字节、低字节、大端、小端"这些概念彻底搞清楚。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一个 16 位的数由 **2 个字节** 组成。请把这两个字节**对调位置**。

拿示例 1 来说，`4660` 写成十六进制是 `0x1234`：

| | 高字节（bit15~bit8） | 低字节（bit7~bit0） |
|---|---|---|
| 交换前 `0x1234` | `0x12` | `0x34` |
| 交换后 `0x3412` | `0x34` | `0x12` |

`0x3412` 换算成十进制就是 `3 × 4096 + 4 × 256 + 1 × 16 + 2 = 13330`。

**几个需要注意的细节：**

1. 输入输出都是**十进制**，但思考时一定要换成**十六进制**——1 位十六进制正好是 4 个 bit，2 位十六进制正好是 1 个字节，一目了然。
2. `255 = 0x00FF`，高字节是 `0x00`，交换后变成 `0xFF00 = 65280`。别忘了前导 0 也是一个字节！
3. 交换两次等于没交换：`swap16(swap16(x)) == x`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 什么是大端、小端？

内存是按**字节**编址的。一个 16 位数要占 2 个地址，问题是：高字节放在低地址，还是低字节放在低地址？

假设变量 `uint16_t v = 0x1234;` 存放在地址 `0x20000000`：

```
              地址:  0x20000000   0x20000001
小端 (STM32/x86):      [ 0x34 ]     [ 0x12 ]    ← 低字节在低地址（"小头在前"）
大端 (网络字节序):      [ 0x12 ]     [ 0x34 ]    ← 高字节在低地址（"大头在前"，和书写顺序一致）
```

当一个小端 MCU 收到大端传感器发来的 `0x12 0x34` 两个字节，如果直接当成本机的 `uint16_t` 来用，读出来就是 `0x3412`——错了！所以要 `swap16` 一下。

> 💬 记忆口诀：**"小端：小（低字节）在小（低地址）"**。

### 2. 位运算三件套

| 写法 | 含义 | 例子（x = 0x1234） |
|---|---|---|
| `x & 0xFF` | 只保留低 8 位（"掩码"） | `0x0034` |
| `x >> 8` | 右移 8 位，高字节掉到低位 | `0x0012` |
| `x << 8` | 左移 8 位，低字节升到高位 | `0x123400`（注意！见下） |
| `a \| b` | 按位或，把两部分"拼"起来 | `0x3400 \| 0x0012 = 0x3412` |

### 3. ⭐ 整型提升（integer promotion）—— 本题最大的坑

C 语言规定：比 `int` 窄的类型（`uint8_t`、`uint16_t`、`char`、`short`）参与运算前，会**先自动转换成 `int`**。

所以 `x << 8` 的计算过程是：

```
x 是 uint16_t 的 0x1234
→ 先提升成 int 的 0x00001234
→ 左移 8 位得到 int 的 0x00123400   ← 并没有在 16 位处"截断"！
```

结果超出了 16 位。如果你直接 `return (x << 8) | (x >> 8);`，返回类型 `uint16_t` 会在**最后一步**截断，结果恰好是对的；但在中间如果你拿这个值去做比较、或者赋给 `uint32_t`，就会出错。好习惯是：**用 `& 0xFF` 先挑出需要的字节，最后再显式 `(uint16_t)` 强转**，意图清清楚楚。

## 💡 第三步：思路一 —— 拆成两个字节再拼回去（最直观）

### 思路

1. 取出低字节：`lo = x & 0xFF`
2. 取出高字节：`hi = (x >> 8) & 0xFF`
3. 拼起来：新的高字节是 `lo`，新的低字节是 `hi` → `(lo << 8) | hi`

### 手动模拟（示例 1：`x = 0x1234`）

| 步骤 | 表达式 | 结果 |
|---|---|---|
| 1 | `lo = 0x1234 & 0xFF` | `0x34` |
| 2 | `hi = (0x1234 >> 8) & 0xFF` | `0x12` |
| 3 | `lo << 8` | `0x3400` |
| 4 | `0x3400 \| 0x12` | `0x3412` = 13330 ✅ |

### 代码

```c
uint16_t swap16(uint16_t x) {
    uint8_t lo = (uint8_t)(x & 0xFF);         // 低字节：0x1234 -> 0x34
    uint8_t hi = (uint8_t)((x >> 8) & 0xFF);  // 高字节：0x1234 -> 0x12

    // 低字节放到高 8 位，高字节放到低 8 位，再强转回 16 位
    return (uint16_t)(((uint16_t)lo << 8) | hi);
}
```

### 复杂度分析

- **时间复杂度 O(1)**：只做了几次位运算。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 一行写法（面试标准答案）

### 思路

把思路一的中间变量省掉：`((x & 0x00FF) << 8)` 是"低字节升到高位"，`((x >> 8) & 0x00FF)` 是"高字节降到低位"，两者按位或。

这也是很多芯片厂商 SDK 和 Linux 内核里 `__swab16` 的写法。用宏写时要**给每个参数加括号**。

### 代码

```c
uint16_t swap16(uint16_t x) {
    // 0x00FFu 中的 u 表示无符号常量，避免有符号移位带来的麻烦
    return (uint16_t)(((x & 0x00FFu) << 8) |   // 低字节 -> 高位
                      ((x >> 8) & 0x00FFu));   // 高字节 -> 低位
}
```

> 💬 **扩展**：ARM Cortex-M3/M4 有一条专门的汇编指令 `REV16` 能一步完成字节交换，CMSIS 里叫 `__REV16()`；GCC 也有 `__builtin_bswap16()`。好的编译器看到上面的写法，往往会自动优化成这条指令。面试时先写位运算版，再提一句这个，加分！

## ⚠️ 第五步：小白常见错误

1. **移位位数写错**：交换**字节**要移 **8** 位，不是 4 位。`x << 4` 交换的是"半字节"（nibble），`0x1234` 会变成别的东西。
2. **忘记掩码**：写成 `(x << 8) | (x >> 8)` 再赋给 `uint32_t` 变量，会得到 `0x123412` 这样的"脏"结果——这就是整型提升的坑。
3. **用 `int16_t`（有符号）做移位**：`int16_t x = -1; x >> 8` 是**算术右移**，高位补 1 而不是补 0，结果会出错。处理字节时一律用**无符号类型**。
4. **用逻辑与 `&&` / 逻辑或 `||` 代替按位运算 `&` / `|`**：`x && 0xFF` 的结果只能是 0 或 1，完全不是你想要的。
5. **把十进制和十六进制混在一起想**：`4660` 交换后不是"`6604`"！一定要先换成 `0x1234` 再思考。
