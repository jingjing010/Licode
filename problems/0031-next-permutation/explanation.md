# 31. 下一个排列 —— 小白详细题解

> 这道题没有复杂的数据结构，难点在于**想清楚"下一个"到底是怎么来的**。我们像查字典一样，一步步推出规律。

---

## 📖 第一步：先读懂题目

"字典序"就是查字典的顺序：先比第一个数，第一个数一样再比第二个……

把 `[1,2,3]` 的所有排列按字典序排好：

| 序号 | 排列 |
|---|---|
| 1 | [1,2,3] |
| 2 | [1,3,2] |
| 3 | [2,1,3] |
| 4 | [2,3,1] |
| 5 | [3,1,2] |
| 6 | [3,2,1] |

用大白话说，这道题就是：

> 给你其中一个排列，把它**原地**改成表里的**下一行**。如果已经是最后一行（最大的），就绕回第一行（最小的，也就是升序）。

**几个需要注意的细节：**

1. 数组里**可能有重复数字**，例如 `[1,1,5]` → `[1,5,1]`。
2. 函数返回 `void`，要直接修改 `nums`。
3. 题目要求只用常数额外空间，不能把所有排列都生成出来。
4. 只有一个元素时，下一个排列就是它自己。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 交换两个元素

```c
int t = nums[i];
nums[i] = nums[j];
nums[j] = t;
```

### 2. 双指针反转一段数组

把下标 `l` 到 `r` 的部分反转：两头交换，然后往中间靠拢。

```c
while (l < r) {
    int t = nums[l]; nums[l] = nums[r]; nums[r] = t;
    l++;
    r--;
}
```

### 3. 循环里的下标越界

从右往左找时经常写 `nums[i] >= nums[i + 1]`，所以 `i` 要从 `numsSize - 2` 开始，否则 `nums[i + 1]` 就越界了。同时条件里要先写 `i >= 0`，利用 `&&` 的**短路**特性，`i` 变成 -1 时不会再去访问 `nums[-1]`。

---

## 💡 第三步：思路一 —— 找下降点 + 交换 + 排序后缀

### 思路

想让排列"只大一点点"，就要**尽量改动靠右的位置**（就像数字 1299 的下一个是 1300，改动的是靠右的部分）。

**第 1 步：找"下降点" `i`。** 从右往左看，找第一个满足 `nums[i] < nums[i+1]` 的位置。

- 在 `i` 右边，数字是**从左到右不增**的（例如 `5,4,3`），这已经是这几个数能组成的**最大**排列了，只动右边不可能变大。
- 所以必须把 `nums[i]` 换成一个更大的数。

**第 2 步：在右边找一个"比 `nums[i]` 大的最小的数" `nums[j]`，和 `nums[i]` 交换。** 换一个最小的更大的数，才能保证"只大一点点"。

**第 3 步：把 `i` 右边的部分变成最小（升序）。** 因为 `i` 位置已经变大了，后面要尽可能小。最直接的办法就是对后缀**排序**。

**特殊情况**：找不到 `i`（整个数组不增，比如 `[3,2,1]`），说明已经是最大排列，直接把整个数组排成升序。

### 手动模拟（`nums = [1,2,3,6,5,4]`）

| 步骤 | 操作 | 数组 |
|---|---|---|
| 1 | 从右往左：4 ≤ 5 ≤ 6，而 3 < 6，下降点 `i = 2`（数字 3） | [1,2,**3**,6,5,4] |
| 2 | 右边比 3 大的有 6、5、4，其中最小的是 4，交换 | [1,2,**4**,6,5,**3**] |
| 3 | 把下标 3 之后的 `6,5,3` 升序排列 | [1,2,4,**3,5,6**] |

答案 `[1,2,4,3,5,6]`。

### 代码

```c
void nextPermutation(int* nums, int numsSize) {
    // 第 1 步：从右往左找第一个 nums[i] < nums[i+1] 的位置
    int i = numsSize - 2;
    while (i >= 0 && nums[i] >= nums[i + 1]) {
        i--;
    }

    if (i >= 0) {
        // 第 2 步：在 i 右边找"比 nums[i] 大的数"里最小的那个
        int j = -1;
        for (int k = i + 1; k < numsSize; k++) {
            if (nums[k] > nums[i] && (j == -1 || nums[k] <= nums[j])) {
                j = k;                   // 用 <= 是为了在相同值里取最靠右的，不影响结果
            }
        }
        int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
    }

    // 第 3 步：把 i 右边的部分排成升序（简单的插入排序）
    // i == -1 时就是把整个数组排成升序
    for (int a = i + 2; a < numsSize; a++) {
        int key = nums[a];
        int b = a - 1;
        while (b > i && nums[b] > key) {     // 只在 i 右边的范围内挪动
            nums[b + 1] = nums[b];
            b--;
        }
        nums[b + 1] = key;
    }
}
```

### 复杂度分析

- **时间复杂度 O(n²)**：插入排序后缀最坏 O(n²)。本题 n ≤ 100，完全够用。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 反转代替排序（O(n)）

### 思路

思路一的第 3 步其实不需要排序！仔细看：

- 交换之前，`i` 右边是**不增**的（从左到右越来越小或相等）。
- 我们交换进去的 `nums[i]`，比 `nums[j]` 小、但不小于 `nums[j]` 右边的数（因为 `nums[j]` 是"最小的比 `nums[i]` 大的数"）。所以交换之后，右边**仍然是不增的**。

一个不增的序列，要变成升序，**直接反转**就行了！反转只要 O(n)。

同理，`nums[j]` 也不用一个个比较：因为右边是不增的，**从右往左第一个大于 `nums[i]` 的数**就是"最小的更大的数"。

### 手动模拟（示例 3：`nums = [1,1,5]`）

| 步骤 | 操作 | 数组 |
|---|---|---|
| 1 | 从右往左：1 < 5，下降点 `i = 1` | [1,**1**,5] |
| 2 | 从右往左找第一个 > 1 的：`j = 2`（数字 5），交换 | [1,**5**,**1**] |
| 3 | 反转下标 2 之后的部分（只有一个数，不变） | [1,5,1] |

再看示例 2：`[3,2,1]` 找不到下降点，`i = -1`，直接反转整个数组得到 `[1,2,3]`。

### 代码

```c
void nextPermutation(int* nums, int numsSize) {
    // 第 1 步：找下降点 i
    int i = numsSize - 2;
    while (i >= 0 && nums[i] >= nums[i + 1]) {
        i--;
    }

    // 第 2 步：如果存在下降点，从右往左找第一个比 nums[i] 大的数并交换
    if (i >= 0) {
        int j = numsSize - 1;
        while (nums[j] <= nums[i]) {     // 一定能找到，因为 nums[i+1] > nums[i]
            j--;
        }
        int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
    }

    // 第 3 步：反转 i+1 到末尾（这部分是不增的，反转后就是升序）
    int l = i + 1, r = numsSize - 1;
    while (l < r) {
        int t = nums[l]; nums[l] = nums[r]; nums[r] = t;
        l++;
        r--;
    }
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最多扫三遍。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **找下降点写成 `while (i >= 0 && nums[i] > nums[i + 1]) i--`（少了等号）** → 遇到相等的数会提前停下。比如 `[5,1,1]`：`i = 1` 时 `1 > 1` 不成立就停了，误把它当成下降点，最终得到 `[1,5,1]`，正确答案是 `[1,1,5]`。
2. **找 `j` 时写成 `while (nums[j] < nums[i]) j--`（少了等号）** → 会停在和 `nums[i]` 相等的数上，交换两个相同的数等于没换。比如 `[2,3,2]` 会得到 `[2,2,3]`，正确答案是 `[3,2,2]`。
3. **`i` 从 `numsSize - 1` 开始** → 访问 `nums[i + 1]` 越界。
4. **找不到下降点时忘记反转整个数组** → `[3,2,1]` 原样输出，应该是 `[1,2,3]`。
5. **反转了整个数组而不是 `i + 1` 之后的部分** → 把前面不该动的数也打乱了。
6. **把后缀从大到小排** → 后缀应该是最小的，必须是升序。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 枚举所有排列再找下一个 | O(n! × n) | O(n! × n) | ⭐ | 只适合理解题意，n 稍大就不行 |
| 交换 + 排序后缀 | O(n²) 或 O(n log n) | O(1) | ⭐⭐ | 先理解三步的含义 |
| 交换 + 反转后缀 | O(n) | O(1) | ⭐⭐ | 推荐，标准答案 |
