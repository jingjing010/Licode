# 153. 寻找旋转排序数组中的最小值 —— 小白详细题解

> 二分查找不一定要"找某个值"，也可以用来"找分界点"。这道题就是在找旋转数组里那个"断崖"的位置。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一个升序数组被"转"了若干次（每转一次，把最后一个数挪到最前面），请找出里面**最小的数**。

示例 2 `nums = [4,5,6,7,0,1,2]`：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 数值 | 4 | 5 | 6 | 7 | **0** | 1 | 2 |
| 所在段 | 左段 | 左段 | 左段 | 左段 | 右段 | 右段 | 右段 |

最小值 0 正好是**右段的第一个数**，也就是"断崖"之后的那个数。

**几个需要注意的细节：**

1. 转了 `n` 次等于没转（示例 3），这时整个数组升序，最小值是第一个数。
2. 返回的是**最小值本身**，不是下标。
3. 元素互不相同。

---

## 🧰 第二步：这道题需要的 C 语言知识

### "找边界"型二分的模板

```c
int lo = 0, hi = numsSize - 1;
while (lo < hi) {                 // 注意是 <，lo == hi 时就是答案
    int mid = lo + (hi - lo) / 2; // 向下取整，保证 mid < hi
    if (条件成立) hi = mid;       // 答案在 [lo, mid]
    else lo = mid + 1;            // 答案在 [mid+1, hi]
}
// 循环结束 lo == hi，就是答案的位置
```

因为 `mid` 向下取整，`mid` 一定严格小于 `hi`，所以 `hi = mid` 每次都能让区间变小，不会死循环。

---

## 💡 第三步：思路一 —— 遍历找最小（最容易想到）

### 代码

```c
int findMin(int* nums, int numsSize) {
    int ans = nums[0];                 // 先假设第一个最小
    for (int i = 1; i < numsSize; i++) {
        if (nums[i] < ans) {
            ans = nums[i];             // 发现更小的就更新
        }
    }
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：能过，但不满足 `O(log n)` 的要求。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（和右端点比较）

### 思路

关键观察：**右段的所有数 < 左段的所有数**，并且**右段的数都 <= 数组最后一个数**。

所以拿 `nums[mid]` 和当前区间最右边的 `nums[hi]` 比较：

- `nums[mid] < nums[hi]`：`mid` 到 `hi` 这一段是升序的，`mid` 在右段（或者整个区间本来就有序）。最小值在 `mid` 或它**左边** → `hi = mid`
- `nums[mid] > nums[hi]`：`mid` 在左段，断崖在 `mid` 右边，最小值在 `mid` **右边** → `lo = mid + 1`

（元素互不相同，且 `mid < hi`，所以不会相等。）

### 手动模拟（示例 1，`nums = [3,4,5,1,2]`）

| 轮次 | lo | hi | mid | nums[mid] | nums[hi] | 比较 | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 2 | 5 | 2 | 5 > 2 | lo = 3 |
| 2 | 3 | 4 | 3 | 1 | 2 | 1 < 2 | hi = 3 |
| 结束 | 3 | 3 | | | | | 返回 nums[3] = **1** ✅ |

### 代码

```c
int findMin(int* nums, int numsSize) {
    int lo = 0, hi = numsSize - 1;
    while (lo < hi) {                      // 区间里不止一个数
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] < nums[hi]) {
            hi = mid;                      // [mid, hi] 升序，最小值在 mid 或左边
        } else {
            lo = mid + 1;                  // mid 在左段，最小值在右边
        }
    }
    return nums[lo];                       // lo == hi，就是最小值的位置
}
```

### 复杂度分析

- **时间复杂度 O(log n)**。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **和 `nums[lo]` 比较** → 没旋转的数组（如 `[11,13,15,17]`）里 `nums[mid] > nums[lo]`，你会以为最小值在右边，结果错误。和 `nums[lo]` 比较需要额外特判，和 `nums[hi]` 比较则不需要。
2. **写成 `hi = mid - 1`** → `nums[mid]` 可能就是最小值，被跳过了。
3. **循环条件写成 `lo <= hi` 同时用 `hi = mid`** → `lo == hi` 时 `hi = mid` 不变，死循环。
4. **返回 `lo`（下标）而不是 `nums[lo]`** → 题目要的是最小**值**。
5. **和 `nums[numsSize - 1]` 而不是 `nums[hi]` 比较** → 其实这道题也能对，但换到"81/154 有重复元素"版本时思路就不通用了，建议养成和当前区间右端点比较的习惯。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 遍历 | O(n) | O(1) | ⭐ | 理解题意 |
| 二分（比较右端点） | O(log n) | O(1) | ⭐⭐ | 题目要求 |
