# 9007. 32 位位序反转 —— 小白详细题解

> 调 SPI 时最常见的"数据对不上"问题之一就是 **MSB first / LSB first 没对齐**。这时要么改外设配置，要么在软件里把位序反过来。本题就是后者，同时也是力扣 190 的嵌入式版本。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把 32 个开关组成的一排**左右镜像**一下：最右边的跑到最左边，最左边的跑到最右边。

用 8 位举例（真实题目是 32 位，道理一样）：

| 位号 | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| 原数据 | 1 | 1 | 0 | 1 | 0 | 0 | 1 | 0 |
| 反转后 | 0 | 1 | 0 | 0 | 1 | 0 | 1 | 1 |

规律：原来第 `i` 位 → 结果第 `7 - i` 位。32 位时就是第 `31 - i` 位。

**几个需要注意的细节：**

1. 是**位**反转，不是**字节**反转。`0x12345678` 字节反转（大小端转换）是 `0x78563412`，位反转是 `0x1E6A2C48`，完全不同。
2. **前导 0 也要参与反转**。示例 1 中 `1` 只有一个有效位，但它前面还有 31 个 0，反转后 1 跑到了第 31 位，所以是 `2147483648` 而不是 `1`。
3. 反转两次等于原数——可以用这一点自查。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 取最低位、拼到最低位

- `x & 1u`：取出 `x` 的最低位（0 或 1）。
- `(r << 1) | bit`：把 `r` 整体左移一位，空出来的最低位填上 `bit`。

这两个动作配合起来，就像"从一摞盘子的顶上拿一个，放到另一摞的顶上"——拿的顺序和放的顺序正好相反，天然就是反转。

### 2. 交换相邻的两组位

`((x >> k) & M) | ((x & M) << k)` 可以把"每 `2k` 位一组"中的左右两半对调，其中 `M` 是"每组低 `k` 位为 1"的掩码：

| k | M | 作用 |
|---|---|---|
| 1 | `0x55555555`（`0101…`） | 相邻 1 位互换 |
| 2 | `0x33333333`（`0011…`） | 相邻 2 位互换 |
| 4 | `0x0F0F0F0F` | 相邻 4 位互换 |
| 8 | `0x00FF00FF` | 相邻字节互换 |
| 16 | （不需要掩码） | 高低 16 位互换 |

### 3. 无符号移位溢出的位会被丢掉

`x << 1` 时第 31 位被移出去，`x >> 1` 时第 0 位被移出去，对 `uint32_t` 来说这是**有定义**的行为，正好被我们利用。

## 💡 第三步：思路一 —— 逐位搬运（最朴素）

### 思路

循环 32 次：每次从 `x` 的最低位取出一位，拼到 `result` 的最低位，然后 `result` 左移、`x` 右移。先取出来的位被左移的次数最多，最后就落在了最高位。

### 手动模拟（用 4 位演示：`x = 0b0010`）

| 第几次 | x & 1 | result（拼之后） | x（右移之后） |
|---|---|---|---|
| 1 | 0 | 0000 | 0001 |
| 2 | 1 | 0001 | 0000 |
| 3 | 0 | 0010 | 0000 |
| 4 | 0 | 0100 | 0000 |

`0b0010` 反转得到 `0b0100` ✔（32 位时同理，要循环满 32 次）。

### 代码

```c
uint32_t reverse_bits32(uint32_t x) {
    uint32_t result = 0;
    for (int i = 0; i < 32; i++) {        // 必须循环满 32 次，前导 0 也要搬
        result = (result << 1) | (x & 1u); // 腾出最低位，放入 x 的最低位
        x >>= 1;                           // 处理 x 的下一位
    }
    return result;
}
```

### 复杂度分析

- **时间复杂度 O(32)**：固定循环 32 次。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 分治交换（无循环）

### 思路

把 8 位数据记为 `abcdefgh`（每个字母代表一位），三步就能反转：

| 步骤 | 操作 | 结果 |
|---|---|---|
| 初始 | | `ab cd ef gh` |
| 1 | 相邻 1 位互换 | `ba dc fe hg` |
| 2 | 相邻 2 位互换 | `dcba hgfe` |
| 3 | 相邻 4 位互换 | `hgfedcba` ✔ |

32 位多两步：相邻 8 位互换、高低 16 位互换，一共 5 步。

为什么对？每一步都只在**组内**做镜像，而"小组内镜像 + 大组内交换左右两半"= "大组内镜像"。从 2 位组一路翻到 32 位组，整个数就镜像了。

### 代码

```c
uint32_t reverse_bits32(uint32_t x) {
    x = ((x >> 1) & 0x55555555u) | ((x & 0x55555555u) << 1);  // 相邻 1 位互换
    x = ((x >> 2) & 0x33333333u) | ((x & 0x33333333u) << 2);  // 相邻 2 位互换
    x = ((x >> 4) & 0x0F0F0F0Fu) | ((x & 0x0F0F0F0Fu) << 4);  // 相邻 4 位互换
    x = ((x >> 8) & 0x00FF00FFu) | ((x & 0x00FF00FFu) << 8);  // 相邻字节互换
    x = (x >> 16) | (x << 16);                                 // 高低半字互换
    return x;
}
```

### 复杂度分析

- **时间复杂度 O(log 32) = 5 步**，没有循环和分支，耗时固定。
- **空间复杂度 O(1)**。

## ⚠️ 第五步：小白常见错误

1. **x 变成 0 就提前退出**：
   ```c
   while (x) { result = (result << 1) | (x & 1u); x >>= 1; }   // ❌ 少移了前导 0 对应的次数
   ```
   示例 1 会输出 `1` 而不是 `2147483648`。必须**固定循环 32 次**。
2. **把位反转和字节反转搞混**：`(x >> 24) | ((x >> 8) & 0xFF00) | ...` 是大小端转换（见 9017），不是本题。
3. **先移位再拼接的顺序反了**：`result = (result | (x & 1u)) << 1;` 在最后一次循环后会多移一位，最低位总是 0，最高位被挤掉。
4. **掩码写错位置**：`((x & 0x55555555u) >> 1)` 会把每组的低位右移进**隔壁组**。要记住：右移之后再与掩码，与掩码之后再左移。
5. **用 `int` 做结果**：`result << 1` 在最高位为 1 时对 `int` 是有符号溢出（UB），全程用 `uint32_t`。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐位搬运 | O(32) | O(1) | ⭐ | 最直观，面试先写这个 |
| 分治交换 | O(5) | O(1) | ⭐⭐⭐ | 无分支，追问"能不能更快"时给出 |
| 查表（256 项 × 4 次） | O(4) | O(256) | ⭐⭐ | 8 位单片机常用 |

## 🔌 嵌入式实战

- **ARM 有专门的指令**：Cortex-M3/M4/M7 上的 `RBIT` 指令一个周期完成 32 位位反转，CMSIS 提供 `__RBIT(x)`。Cortex-M0 没有这条指令，只能用本题的软件写法。
- **先看能不能改硬件配置**：STM32 的 SPI 有 `LSBFIRST` 位，直接配置成和对方一致，比软件反转省事得多。软件反转主要用于"硬件不支持"或"PCB 已经画反了"的情况。
- **CRC 计算**：很多 CRC 标准（如 CRC-32/以太网）要求输入/输出"反射"（reflect），本质上就是位反转。
