# 按奇偶排序数组：题解

## 📖 先读懂题目

第一遍收集偶数，第二遍收集奇数。这样既能满足偶数在前，也能稳定保留每组的相对顺序。题目允许任何组内顺序，所以驱动只检查排列合法性再标准化输出。

### 示例1

输入：
```text
[3,1,2,4]
```
输出：
```text
[2,4,3,1]
```

### 示例2

输入：
```text
[0]
```
输出：
```text
[0]
```


## 🧰 C 语言知识

数组参数传入的是指针，长度单独传递。字符串结尾的`'\0'`不是普通数据，动态结果必须多留一个字节。链表通过`next`连接，断开或拼接前要确定后继仍可找到。返回数组时同时设置`*returnSize`。

## 💡 解题步骤

1. 最简单的做法：新建一个数组，先把所有偶数放进去，再把所有奇数放进去。
2. 想不用额外数组？用一个下标 k 表示「下一个偶数该放的位置」，遇到偶数就和 nums[k] 交换。
3. 或者左右双指针：左边找奇数、右边找偶数，找到就交换，直到两指针相遇。

## 可直接提交的 C 代码

```c
int* sortArrayByParity(int* nums, int numsSize, int* returnSize) {
    int *out = malloc(numsSize * sizeof(int));
    int k = 0;
    for (int parity = 0; parity <= 1; ++parity) {
        for (int i = 0; i < numsSize; ++i) {
            if (nums[i] % 2 == parity) out[k++] = nums[i];
        }
    }
    *returnSize = numsSize;
    return out;
}
```

## 📊 复杂度

时间 O(n)，输出空间 O(n)。先用题面样例逐步跟踪变量，再检查最短输入与重复值，不应仅凭一个正常样例判断算法正确。

## ⚠️ 常见错误

- 把数组边界`i < n`误写成`i <= n`。
- 忘记返回数组的有效长度，或字符串结尾缺少`'\0'`。
- 把题目中的严格比较写成允许相等，或把有重数的元素当作集合。
- 返回局部数组地址，函数退出后该内存不再有效。

## 🔗 举一反三

改变输入长度为1、重复值、边界整数，手工验证每一步保存的状态。思考能否在输入逐个到达时保留相同的状态完成计算。
