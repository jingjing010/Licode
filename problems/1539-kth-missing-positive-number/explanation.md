# 第 k 个缺失的正整数：题解

## 📖 先读懂题目

给定严格递增正整数数组，返回未出现在其中的第k个正整数。1 ≤ 数组长度,k ≤ 1000，元素 ≤ 1000。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[2,3,4,7,11] / 5` | `9` |
| 2 | `[1,2,3,4] / 2` | `6` |

## 🧰 需要的 C 语言知识

数组形参是指针，不能用`sizeof(指针)`推算元素个数，要使用单独传入的长度。下标从0开始，最后一个有效下标是长度减1。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

缺失数量随着下标递增而不减，二分查找第一个缺失数量至少k的位置，答案等于该位置下标加k。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int findKthPositive(int *arr, int arrSize, int k) {
    int lo = 0, hi = arrSize;
    /* arr[mid]之前缺失的数量为arr[mid]-(mid+1)。 */
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] - mid - 1 >= k)
            hi = mid;
        else
            lo = mid + 1;
    }
    return lo + k;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(log n)，空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 循环写成`i <= 长度`，访问数组末尾之后的内存。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
