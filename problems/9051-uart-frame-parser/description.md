MCU 通过串口和上位机、传感器模块通信时，串口只能一个字节一个字节地收数据，没有"一包"的概念。所以双方要约定一个**帧格式**，接收方从连续的字节流中把一帧帧数据"切"出来，同时还要能应付线路干扰产生的垃圾字节、校验错误和半截帧。

本题的帧格式如下：

| 帧头 | 帧头 | 长度 | 数据 | 校验 |
|---|---|---|---|---|
| `0xAA`（170） | `0x55`（85） | `LEN`（0 ~ 255） | `LEN` 个字节 | `CHK` |

其中 `CHK = (LEN + 所有数据字节之和) & 0xFF`。

给你接收到的字节流 `buf`，请按以下规则**从前往后**解析，返回所有**有效帧的数据部分**：

1. **找帧头**：寻找连续的 `0xAA 0x55`。帧头之前不属于任何帧的字节都是垃圾，直接跳过。注意 `0xAA 0xAA 0x55` 中，第二个 `0xAA` 和 `0x55` 构成帧头。
2. **读帧体**：帧头之后紧跟的 1 个字节是 `LEN`，再往后 `LEN` 个字节是数据，再下一个字节是 `CHK`。
3. **校验**：`CHK` 正确则这一帧有效；不正确则丢弃这一帧。**无论是否有效**，都从 `CHK` 的下一个字节开始继续找帧头（已经被这一帧读走的字节不会再被重新扫描）。
4. 字节流结束时还没读完的半截帧直接丢弃。

### 示例 1

```
输入：buf = [170,85,2,16,32,50,0,170,85,1,7,8]
输出：[[16,32],[7]]
解释：
第 1 帧：AA 55 | LEN=2 | 16 32 | CHK=50，2+16+32=50，有效。
字节 0 是垃圾，跳过。
第 2 帧：AA 55 | LEN=1 | 7 | CHK=8，1+7=8，有效。
```

### 示例 2

```
输入：buf = [170,85,1,5,0,170,85,1,5,6]
输出：[[5]]
解释：第 1 帧校验应为 1+5=6，实际收到 0，丢弃；从下一个字节继续，第 2 帧有效。
```

### 示例 3

```
输入：buf = [170,170,85,1,3,4,170,85,3,1,2]
输出：[[3]]
解释：第 1 个 0xAA 后面不是 0x55，但第 2 个 0xAA 后面是 0x55，组成帧头，得到有效帧 [3]。
     之后 AA 55 LEN=3，数据只收到 1、2 两个字节字节流就结束了，半截帧丢弃。
```

### 提示

- `0 <= len <= 10^5`
- `0 <= buf[i] <= 255`
- 可能存在 `LEN = 0` 的有效帧，此时输出空数组 `[]`

### 函数说明

```c
int** parseFrames(const uint8_t* buf, size_t len, int* returnSize, int** returnColumnSizes);
```

- 返回值：`malloc` 申请的二维数组，第 `i` 行是第 `i` 个有效帧的数据部分（按在字节流中出现的顺序）
- `*returnSize`：有效帧的个数
- `*returnColumnSizes`：`malloc` 申请的数组，`(*returnColumnSizes)[i]` 是第 `i` 个有效帧的数据长度

### 自定义输入格式

```
[170,85,2,16,32,50]
```

一行字节数组（每个元素 `0 ~ 255`）。
