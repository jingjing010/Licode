# 到达终点数字：题解

## 📖 先读懂题目

从数轴0出发，第k次移动必须走k个单位，可向左或右。返回到达非零 target 所需的最少次数，|target| ≤ 10^9。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `2` | `3` |
| 2 | `3` | `2` |

## 🧰 需要的 C 语言知识

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

先全部向目标方向走，直到总步长覆盖目标且差值为偶数；反转部分步长即可抵消差值。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int reachNumber(int target) {
    long long t = target;
    if (t < 0)
        t = -t;
    long long sum = 0;
    int k = 0;
    /* 反转一步方向会使总位移减少该步长的两倍。 */
    while (sum < t || (sum - t) % 2 != 0)
        sum += ++k;
    return k;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(√|target|)，空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
- 修改函数签名或参数顺序，导致判题驱动无法正确调用。

## 🔗 举一反三

尝试把同一处理过程改成逐个输入的流式接口，思考需要保留哪些状态。用空边界、最小值、最大值和重复值检查自己的实现。
