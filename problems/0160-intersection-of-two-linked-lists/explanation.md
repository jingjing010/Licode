# 160. 相交链表 —— 小白详细题解

> 这道题的精髓是一句很浪漫的话：**"我走过你走过的路，你走过我走过的路，我们终会相遇。"** 先别急，我们从最笨的方法讲起。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 两条链表 A 和 B，可能在某个结点"汇合"，汇合之后就**共用同一段尾巴**（像字母 Y）。找出汇合的第一个结点；如果根本没汇合，返回 `NULL`。

示例 1：

```
A:       4 -> 1
                \
                 8 -> 4 -> 5
                /
B:  5 -> 6 -> 1
```

| | 独有部分 | 共用部分 |
|---|---|---|
| 链表 A | 4, 1（2 个，即 skipA = 2） | 8, 4, 5 |
| 链表 B | 5, 6, 1（3 个，即 skipB = 3） | 8, 4, 5 |

答案是值为 8 的那个结点。

**几个需要注意的细节：**

1. "相交"指的是**同一个结点**（内存地址相同），不是值相同。示例 1 中 A 和 B 里都有一个值为 1 的结点，但它们是两个不同的结点，所以交点不是 1。
2. `intersectVal`、`skipA`、`skipB` **不会传给你的函数**，它们只是告诉判题程序怎么搭链表。你只能拿到 `headA` 和 `headB`。
3. 一旦相交，后面就完全一样了。单链表每个结点只有一个 `next`，不可能"汇合后又分开"，所以形状只能是 Y 形，不可能是 X 形。
4. 不能修改链表。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 比较指针 vs 比较值

```c
if (pa == pb)            // 两个指针指向【同一个结点】（地址相同）
if (pa->val == pb->val)  // 只是两个结点的值相等，可能是不同的结点
```

本题要比较的是**指针本身**。

### 2. 三目运算符 `? :`

```c
pa = (pa != NULL) ? pa->next : headB;
```

等价于：

```c
if (pa != NULL) pa = pa->next;   // 还没走完，就往后走一步
else            pa = headB;      // 走完了，跳到另一条链表的头
```

### 3. 访问 `->next` 之前要保证指针不是 `NULL`

`NULL->next` 会让程序崩溃（Runtime Error）。所以每次写 `p->next` 前都要想一想：`p` 可能是 `NULL` 吗？

---

## 💡 第三步：思路一 —— 暴力枚举（最容易想到）

### 思路

对 A 中的每一个结点 `pa`，都去 B 里从头到尾找一遍，看有没有哪个结点 `pb` **就是** `pa`（指针相等）。A 中第一个能在 B 里找到的结点就是交点。

### 手动模拟（示例 2：A = `1 9 1 [2 4]`，B = `3 [2 4]`，方括号是共用部分）

| pa（A 中的结点） | 在 B 中找 | 找到了吗？ |
|---|---|---|
| 1 | 3、2、4 都不是它 | ❌ |
| 9 | 3、2、4 都不是它 | ❌ |
| 1 | 3、2、4 都不是它（B 里没有这个结点） | ❌ |
| 2 | 3 不是，2 **就是它** | ✅ 返回这个结点 |

### 代码

```c
// ❌ 能得到正确答案，但最大数据会超时，仅用于理解题意
struct ListNode *getIntersectionNode(struct ListNode *headA, struct ListNode *headB) {
    // 外层：依次拿出 A 的每个结点
    for (struct ListNode* pa = headA; pa != NULL; pa = pa->next) {
        // 内层：在 B 里从头找，有没有和 pa 是【同一个结点】的
        for (struct ListNode* pb = headB; pb != NULL; pb = pb->next) {
            if (pa == pb) {         // 比较的是指针（地址），不是值
                return pa;          // A 中第一个出现在 B 里的结点，就是交点
            }
        }
    }
    return NULL;                    // 一个都没找到：不相交
}
```

### 复杂度分析

- **时间复杂度 O(m × n)**：最坏要比较 3×10⁴ × 3×10⁴ ≈ 9×10⁸ 次，本题会**超时**。
- **空间复杂度 O(1)**。

> 💬 这个方法只是帮你理解"相交 = 指针相同"。下面看怎么优化。

---

## 🚀 第四步：思路二 —— 先对齐长度，再同步走

### 思路

假设两条链表一样长，事情就很简单：两个指针同时从头出发，每次各走一步，**第一次 `pa == pb` 的地方就是交点**（不相交时会同时走到 `NULL`，`NULL == NULL` 也会停下）。

长度不一样怎么办？交点之后的部分两人是一样长的，**多出来的长度一定在前面的"独有部分"**。所以：

1. 先分别数出两条链表的长度 `lenA`、`lenB`
2. 让长的那条先走 `|lenA - lenB|` 步，这样两个指针离终点的距离就一样了
3. 两个指针同步往后走，直到相等

### 手动模拟（示例 1：lenA = 5，lenB = 6）

B 比 A 长 1，先让 `pb` 走 1 步（从 5 走到 6）：

| 轮次 | pa | pb | 同一个结点？ |
|---|---|---|---|
| 开始 | A 的 4 | B 的 6 | ❌ |
| 1 | A 的 1 | B 的 1 | ❌（值一样但不是同一个结点） |
| 2 | 共用的 8 | 共用的 8 | ✅ 返回 |

### 代码

```c
// 求链表长度
static int getLength(struct ListNode* head) {
    int len = 0;
    while (head != NULL) {
        len++;
        head = head->next;
    }
    return len;
}

struct ListNode *getIntersectionNode(struct ListNode *headA, struct ListNode *headB) {
    int lenA = getLength(headA);
    int lenB = getLength(headB);
    struct ListNode* pa = headA;
    struct ListNode* pb = headB;

    // 1. 让长的那条先走几步，使两个指针到终点的距离相同
    while (lenA > lenB) { pa = pa->next; lenA--; }
    while (lenB > lenA) { pb = pb->next; lenB--; }

    // 2. 同步往后走，第一次相等就是交点；不相交时两者会同时变成 NULL
    while (pa != pb) {
        pa = pa->next;
        pb = pb->next;
    }
    return pa;
}
```

### 复杂度分析

- **时间复杂度 O(m + n)**：数长度各走一遍，再同步走一遍。
- **空间复杂度 O(1)**：只用了几个变量。

---

## 🌟 第五步：思路三 —— 双指针"交换跑道"（最优雅）

### 思路

思路二需要先数长度。能不能**不数长度**也让两个指针"对齐"？

设 A 的独有部分长 `a`，B 的独有部分长 `b`，共用部分长 `c`：

- 指针 `pa` 先走完 A（`a + c` 步），然后**跳到 B 的头**继续走
- 指针 `pb` 先走完 B（`b + c` 步），然后**跳到 A 的头**继续走

当 `pa` 在 B 上走了 `b` 步、`pb` 在 A 上走了 `a` 步时，两人都走了 **`a + c + b`** 步，正好同时到达交点！

如果不相交（`c = 0`），两人走完 `a + b` 步后会**同时**变成 `NULL`，`pa == pb == NULL`，循环结束，返回 `NULL`。

> 💡 这就是开头那句话：我走完我的路再走你的路，你走完你的路再走我的路，总路程一样长，所以一定会在交点相遇。

### 手动模拟（示例 2：A = `1 9 1 [2 4]`，B = `3 [2 4]`，a = 3，b = 1，c = 2）

| 步数 | pa | pb | 相等？ |
|---|---|---|---|
| 0 | A 的 1 | B 的 3 | ❌ |
| 1 | A 的 9 | 共用的 2 | ❌ |
| 2 | A 的 1 | 共用的 4 | ❌ |
| 3 | 共用的 2 | NULL（B 走完了） | ❌ |
| 4 | 共用的 4 | **跳到 A 的头** 1 | ❌ |
| 5 | NULL（A 走完了） | A 的 9 | ❌ |
| 6 | **跳到 B 的头** 3 | A 的 1 | ❌ |
| 7 | 共用的 2 | 共用的 2 | ✅ 返回 |

两人都走了 a + c + b = 3 + 2 + 1 = 6 步后（再加上一步"跳"的动作）在交点相遇。

### 代码

```c
struct ListNode *getIntersectionNode(struct ListNode *headA, struct ListNode *headB) {
    struct ListNode* pa = headA;
    struct ListNode* pb = headB;

    // 两个指针不相等就一直走；相等时要么是交点，要么同时为 NULL（不相交）
    while (pa != pb) {
        // pa 没走完就往后走一步；走到 NULL 就换到 B 的头
        pa = (pa != NULL) ? pa->next : headB;
        // pb 没走完就往后走一步；走到 NULL 就换到 A 的头
        pb = (pb != NULL) ? pb->next : headA;
    }
    return pa;
}
```

**为什么不会死循环？** 每个指针最多走 `a + c + b + 1` 次就一定会和另一个相遇（交点或 `NULL`），所以循环最多执行 m + n + 1 次。

### 复杂度分析

- **时间复杂度 O(m + n)**。
- **空间复杂度 O(1)**。

## ⚠️ 第六步：小白常见错误

1. **比较值而不是指针**：`if (pa->val == pb->val)`，示例 1 中会错误地在值为 1 的结点处返回。必须写 `pa == pb`。
2. **思路三中走到 `NULL` 时跳过了 `NULL` 这一步**：
   ```c
   pa = pa->next;               // ❌
   if (pa == NULL) pa = headB;  //    这样 pa 永远不会等于 NULL
   ```
   不相交时两个指针永远不会同时为 `NULL`，会**死循环**。正确写法是"当前是 `NULL` 才跳"，让 `NULL` 也作为一个"位置"参与比较。
3. **跳错了链表**：`pa` 走完后跳到 `headA`（自己的头）而不是 `headB`，两人的路程就不相等了，可能永远对不齐。
4. **修改链表来做标记**：比如把 A 的尾巴接到 B 的头上变成环再用第 142 题的方法，思路可以，但**返回前必须恢复**，否则本题判为错误。
5. **思路二忘了处理不相交**：其实同步走的循环 `while (pa != pb)` 在不相交时会同时走到 `NULL` 自然结束，不需要额外判断；但如果写成 `while (pa->next != NULL)` 之类的条件就容易出错。

## 📊 第七步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 暴力枚举 | O(m × n) | O(1) | ⭐ | ❌ 本题会超时，只用来理解题意 |
| 哈希表记录 A 的所有结点 | O(m + n) | O(m) | ⭐⭐ | C 语言要自己写哈希表，麻烦 |
| 先对齐长度再同步走 | O(m + n) | O(1) | ⭐⭐ | 思路直观，推荐先写 |
| 双指针交换跑道 | O(m + n) | O(1) | ⭐⭐ | **最优雅**，代码最短 |
