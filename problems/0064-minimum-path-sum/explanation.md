# 64. 最小路径和 —— 小白详细题解

> 这道题是 62 题「不同路径」的姊妹题：把"数有几条路"换成"找最省钱的那条路"。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一个棋盘，每个格子上写着一个"过路费"。你从左上角出发，只能**向右**或**向下**走，走到右下角。经过的格子（包括起点和终点）的数字都要加起来，问**最少**要交多少钱。

拿示例 1 来说：

| | 列 0 | 列 1 | 列 2 |
|---|---|---|---|
| 行 0 | **1** | **3** | **1** |
| 行 1 | 1 | 5 | **1** |
| 行 2 | 4 | 2 | **1** |

加粗的路线 `1→3→1→1→1` 总和是 7，这是所有路线里最小的。

**几个需要注意的细节：**

1. **起点和终点的数字也要算进去**。
2. 所有数字都 `>= 0`，不会出现负数。
3. 最大和不超过 `(200 + 200 - 1) × 200 ≈ 8 万`，`int` 完全够用。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 力扣的二维数组参数

```c
int minPathSum(int** grid, int gridSize, int* gridColSize)
```

| 参数 | 含义 |
|---|---|
| `int** grid` | "指针的指针"：`grid[i]` 是第 `i` 行（一个 `int*`），`grid[i][j]` 是具体的数 |
| `int gridSize` | 有几行，也就是 `m` |
| `int* gridColSize` | 一个数组，`gridColSize[i]` 是第 `i` 行有几列。本题每行一样长，用 `gridColSize[0]` 就是 `n` |

### 2. 动态申请二维数组

```c
int** dp = (int**)malloc(sizeof(int*) * m);   // 先申请 m 个"行指针"
for (int i = 0; i < m; i++)
    dp[i] = (int*)malloc(sizeof(int) * n);    // 再给每一行申请 n 个 int
```

用完后要先 `free(dp[i])` 每一行，再 `free(dp)`。

### 3. 求两个数的较小值

C 语言没有内置的 `min`，可以写一个小函数，或者用三目运算符：`a < b ? a : b`。

---

## 💡 第三步：思路一 —— 二维 DP 表格

### 思路

先想"暴力"：把所有路线都走一遍，取最小。但路线数量是组合数级别的（200×200 的网格路线数是天文数字），一定超时。

换个角度：走到格子 `(i, j)` 的**最后一步**，要么从**上面** `(i-1, j)` 下来，要么从**左边** `(i, j-1)` 过来。
那么，到 `(i, j)` 的最小花费 = **两者中更便宜的那个** + 当前格子的过路费：

```
dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]
```

边界：
- `dp[0][0] = grid[0][0]`
- 第 0 行只能从左边来：`dp[0][j] = dp[0][j-1] + grid[0][j]`
- 第 0 列只能从上面来：`dp[i][0] = dp[i-1][0] + grid[i][0]`

### 手动模拟（示例 1）

| dp | 列 0 | 列 1 | 列 2 |
|---|---|---|---|
| 行 0 | 1 | 1+3=4 | 4+1=5 |
| 行 1 | 1+1=2 | min(4,2)+5=7 | min(5,7)+1=6 |
| 行 2 | 2+4=6 | min(7,6)+2=8 | min(6,8)+1=**7** |

右下角是 7。

### 代码

```c
// 求较小值的小工具
static int minInt(int a, int b) {
    return a < b ? a : b;
}

int minPathSum(int** grid, int gridSize, int* gridColSize) {
    int m = gridSize;              // 行数
    int n = gridColSize[0];        // 列数（每行一样长）

    // 1. 申请 m 行 n 列的 dp 表
    int** dp = (int**)malloc(sizeof(int*) * m);
    for (int i = 0; i < m; i++) {
        dp[i] = (int*)malloc(sizeof(int) * n);
    }

    // 2. 起点
    dp[0][0] = grid[0][0];
    // 3. 第 0 行：只能从左边来
    for (int j = 1; j < n; j++) dp[0][j] = dp[0][j - 1] + grid[0][j];
    // 4. 第 0 列：只能从上面来
    for (int i = 1; i < m; i++) dp[i][0] = dp[i - 1][0] + grid[i][0];

    // 5. 其余格子：上面和左边取较小的，再加上自己
    for (int i = 1; i < m; i++) {
        for (int j = 1; j < n; j++) {
            dp[i][j] = minInt(dp[i - 1][j], dp[i][j - 1]) + grid[i][j];
        }
    }

    int ans = dp[m - 1][n - 1];

    // 6. 释放内存：先释放每一行，再释放行指针数组
    for (int i = 0; i < m; i++) free(dp[i]);
    free(dp);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(mn)**：每个格子算一次。
- **空间复杂度 O(mn)**：一张 dp 表。

## 🚀 第四步：思路二 —— 直接在 grid 上原地计算（O(1) 额外空间）

### 思路

仔细看：`grid[i][j]` 这个数，只在计算 `dp[i][j]` 时用一次，之后就再也不用了。
那就**直接把 `dp[i][j]` 写回 `grid[i][j]`**，省掉整张 dp 表。

> 💬 力扣上这样修改输入是允许的。如果面试官不允许改输入，可以用 62 题的"一维滚动数组"：只开一个长度为 `n` 的数组。

### 代码

```c
int minPathSum(int** grid, int gridSize, int* gridColSize) {
    int m = gridSize, n = gridColSize[0];

    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            if (i == 0 && j == 0) continue;          // 起点不变
            if (i == 0) {
                grid[i][j] += grid[i][j - 1];        // 第 0 行：只能从左边来
            } else if (j == 0) {
                grid[i][j] += grid[i - 1][j];        // 第 0 列：只能从上面来
            } else {
                int up = grid[i - 1][j];             // 从上面来的最小花费
                int left = grid[i][j - 1];           // 从左边来的最小花费
                grid[i][j] += (up < left ? up : left);
            }
        }
    }
    return grid[m - 1][n - 1];                       // 右下角存的就是答案
}
```

### 复杂度分析

- **时间复杂度 O(mn)**
- **空间复杂度 O(1)**：没有额外申请数组。

---

## ⚠️ 第五步：小白常见错误

1. **把列数写成 `gridSize`** → `gridSize` 是**行数**，列数是 `gridColSize[0]`。网格不是正方形时（如示例 2 是 2×3）就会越界或算错。
2. **忘了处理第 0 行 / 第 0 列** → 访问 `grid[-1][j]` 越界，程序崩溃。
3. **把 `dp` 初始化为 0 再统一套公式** → 第 0 行会错误地和"上面的 0"比较，得到偏小的答案。
4. **用贪心：每一步都往更小的格子走** → 局部最优不等于全局最优。例如 `[[1,2,5],[3,2,1]]` 中先走 2 再走 2 再走 1 才是最优，贪心可能走错。
5. **只加了经过的格子，漏了起点** → `dp[0][0]` 必须等于 `grid[0][0]`，不是 0。
6. **用递归暴力枚举所有路线** → 200×200 的网格路线数量是天文数字，一定超时。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 递归枚举所有路线 | 指数级 | O(m+n) | ⭐ | 会超时，只用来理解题意 |
| 二维 DP | O(mn) | O(mn) | ⭐⭐ | 先写这个 |
| 原地 DP | O(mn) | O(1) | ⭐⭐ | 理解后的简洁写法 |
