# SLIP 帧转义解码：题解

## 📖 先读懂题目

输入为9073生成的一个完整合法帧，首尾为C0，内部转义有效，不含其他帧。返回原始数据。长度2到2050。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[192,49,50,51,52,53,54,55,56,57,192]` | `[49,50,51,52,53,54,55,56,57]` |
| 2 | `[192,192]` | `[]` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

跳过首尾END，看到ESC就额外读取一个字节，将两种转义恢复成原字符。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *slipDecode(const uint8_t *data, size_t len, int *returnSize) {
    int *out = malloc(len * sizeof(int)), k = 0;
    for (size_t i = 1; i + 1 < len; ++i) {
        int x = data[i];
        if (x == 0xdb) {
            ++i;
            x = data[i] == 0xdc ? 0xc0 : 0xdb;
        }
        out[k++] = x;
    }
    *returnSize = k;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，输出空间 O(n) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
