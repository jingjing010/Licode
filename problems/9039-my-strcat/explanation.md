# 9039. 实现 strcat —— 小白详细题解

> strcat = "找到结尾" + "strcpy"。如果你已经做过 9035（strlen）和 9036（strcpy），这道题就是把两段代码拼起来。面试官真正想听的是后半段：**为什么循环里反复调用 strcat 会很慢？** 这就是著名的"画家施莱米尔"问题。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 找到 `dst` 末尾的 `'\0'`，从这个位置开始把 `src` 一个字符一个字符抄过来（`src` 的 `'\0'` 也要抄），`dst` 原来的 `'\0'` 被覆盖掉。

拿示例 1 来说（`dst = "Temp="`，`src = "25C"`，缓冲区正好 9 字节）：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| 拼接前 | T | e | m | p | = | **\0** | # | # | # |
| 拼接后 | T | e | m | p | = | **2** | **5** | **C** | **\0** |

下标 5 的 `'\0'` 被 `'2'` 覆盖，新的 `'\0'` 在下标 8。

**几个需要注意的细节：**

1. 从 `dst` 的 **`'\0'` 处**开始写，不是从 `'\0'` 的下一个位置。
2. `src` 的 `'\0'` 必须复制，否则结果不是合法字符串（下标 8 还是 `'#'`）。
3. `dst` 为空串时，`'\0'` 就在下标 0（示例 2）。
4. 返回**原始的 `dst`**。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 字符串的"长度"和"容量"是两回事

```c
char buf[32] = "Temp=";
// 长度 strlen(buf) = 5，容量 sizeof(buf) = 32
```

strcat 只知道长度（靠找 `'\0'`），**不知道容量**。调用者必须保证 `strlen(dst) + strlen(src) + 1 <= 容量`，否则就会写出界。

### 2. 用指针找结尾

```c
char* d = dst;
while (*d != '\0') d++;   // 结束后 d 指向 dst 的 '\0'
```

这就是 9035 strlen 的核心循环，只不过我们要的不是长度，而是**结尾的位置**。

### 3. 复制直到 `'\0'`

```c
while ((*d++ = *src++) != '\0');   // 9036 的经典写法：先复制，再判断刚复制的是不是 '\0'
```

## 💡 第三步：思路一 —— 下标版：先求长度，再复制

### 思路

1. 用下标 `i` 数出 `dst` 的长度，此时 `dst[i]` 就是 `'\0'`
2. 用下标 `j` 遍历 `src`，`dst[i + j] = src[j]`
3. 最后补 `dst[i + j] = '\0'`

### 手动模拟（示例 1）

| 步骤 | i | j | 动作 | dst |
|---|---|---|---|---|
| 求长度 | 5 | — | dst[5] 是 '\0' | `Temp=\0###` |
| 复制 | 5 | 0 | dst[5] = '2' | `Temp=2###` |
| 复制 | 5 | 1 | dst[6] = '5' | `Temp=25##` |
| 复制 | 5 | 2 | dst[7] = 'C' | `Temp=25C#` |
| 补结尾 | 5 | 3 | dst[8] = '\0' | `Temp=25C\0` |

### 代码

```c
char* my_strcat(char* dst, const char* src) {
    size_t i = 0;
    // 1. 找到 dst 的 '\0'
    while (dst[i] != '\0') {
        i++;
    }
    // 2. 从 dst[i] 开始复制 src 的字符
    size_t j = 0;
    while (src[j] != '\0') {
        dst[i + j] = src[j];
        j++;
    }
    // 3. 补上结束符
    dst[i + j] = '\0';
    return dst;
}
```

### 复杂度分析

- **时间复杂度 O(n + m)**：n、m 分别是 `dst`、`src` 的长度。找结尾要走 n 步，复制要走 m 步。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 指针版（经典写法）

### 思路

逻辑一样，用指针 `d` 代替下标：先让 `d` 走到 `'\0'`，再用 strcpy 的一行流复制。

### 代码

```c
char* my_strcat(char* dst, const char* src) {
    char* d = dst;                         // dst 要作为返回值，用 d 来移动
    while (*d) {                           // 1. 走到 dst 的 '\0'
        d++;
    }
    while ((*d++ = *src++) != '\0') {      // 2. 从 '\0' 处开始复制，连 src 的 '\0' 一起
    }
    return dst;
}
```

### 复杂度分析

- **时间复杂度 O(n + m)**。
- **空间复杂度 O(1)**。

## 🔌 嵌入式实战：拼接多段字符串时别用连续的 strcat

假设要拼一条 AT 指令：

```c
char cmd[64] = "AT+CWJAP=\"";
strcat(cmd, ssid);
strcat(cmd, "\",\"");
strcat(cmd, password);
strcat(cmd, "\"\r\n");
```

每次 strcat 都要**从头**找一遍 `'\0'`。拼 k 段、总长 L 时，总代价接近 O(k × L)。这就是"画家施莱米尔"：他每天刷油漆都要走回起点蘸油漆，所以越刷越慢。

更好的写法：**记住当前结尾**，或者直接用 snprintf 一步到位：

```c
// 写法一：自己维护结尾指针（类似 stpcpy）
char* append(char* end, const char* s) {
    while ((*end = *s++) != '\0') end++;
    return end;            // 返回新的 '\0' 位置，下次直接从这里接着写
}

// 写法二：snprintf 一次完成，而且不会超过缓冲区大小
snprintf(cmd, sizeof(cmd), "AT+CWJAP=\"%s\",\"%s\"\r\n", ssid, password);
```

## ⚠️ 第五步：小白常见错误

1. **从 `'\0'` 的下一个位置开始写**：

   ```c
   while (*d++) ;           // ❌ 循环结束时 d 已经越过了 '\0'
   while ((*d++ = *src++)) ;
   ```

   结果 `dst` 中间夹着一个 `'\0'`，打印出来只有 `"Temp="`；还会多写一个字节，越界。
2. **忘了复制 src 的 `'\0'`**：判题会提示"结果没有以 '\0' 结尾"。
3. **返回了移动后的指针**：返回 `d` 或者移动过的 `dst`。
4. **目标缓冲区不够大**：

   ```c
   char buf[8] = "Temp=";
   strcat(buf, "25.5C");   // ❌ 需要 5 + 5 + 1 = 11 字节，只有 8 字节
   ```

5. **dst 没有初始化**：`char buf[32]; strcat(buf, "x");` 里 `buf` 的内容是随机的，不一定有 `'\0'`，strcat 会在内存里一路找下去。先写 `buf[0] = '\0';`。
6. **用字符串常量当 dst**：`char* p = "abc"; strcat(p, "d");` 字符串常量在只读区（单片机上通常在 Flash），写它会出错。

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 下标：求长度 + 复制 | O(n + m) | O(1) | ⭐ | 思路清晰 |
| 指针：走到结尾 + 一行复制 | O(n + m) | O(1) | ⭐⭐ | 面试经典写法 |

> 🎯 **学习建议**：把常见错误第 1 条的代码在纸上模拟一遍，看清"`*d++` 在判断时已经让 `d` 越过 `'\0'`"——这是指针写法里最隐蔽的坑。
