# 287. 寻找重复数 —— 小白详细题解

> 这道题如果允许用额外空间，就是一道简单题；难就难在题目要求**不修改数组、只用 O(1) 空间**。最优解是把数组"看成"一个链表，用"环形链表"的快慢指针来做——非常巧妙。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 数组有 `n + 1` 个格子，每个格子里的数都在 `1 ~ n` 之间。只有一个数重复了（可能重复很多次），把它找出来。

拿示例 1 `nums = [1,3,4,2,2]` 来说：`n = 4`，数都在 1~4 之间。

| 数值 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 出现次数 | 1 | **2** | 1 | 1 |

答案是 2。

**几个需要注意的细节：**

1. 重复的数可能出现**不止两次**（示例 3 `[3,3,3,3,3]`），这时其他某些数就没出现。
2. 为什么一定有重复？`n + 1` 个格子只能放 `1 ~ n` 这 `n` 种数，根据**抽屉原理**，至少有两个格子放了同一个数。
3. 题目要求**不能修改数组**（所以不能排序），且只能用常数额外空间。判题程序不会检查这两点，但我们要朝着这个目标努力。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. `calloc` 申请并清零

```c
bool* seen = (bool*)calloc(numsSize, sizeof(bool));   // numsSize 个 bool，全部为 false
```

`calloc(个数, 每个的大小)` 和 `malloc` 类似，但会把内存全部清零，省去了手动初始化。用完记得 `free(seen)`。

### 2. `do { ... } while (条件);` 循环

普通的 `while` 先判断条件再执行；`do-while` **先执行一次**再判断。思路二里快慢指针一开始都在起点（相等），如果用普通 `while (slow != fast)`，循环一次都不会执行。所以要用 `do-while`，先各走一步再比较。

### 3. "用值当下标"

本题所有值都在 `1 ~ n`，而数组下标范围是 `0 ~ n`，所以 `nums[nums[i]]` 永远不会越界。这正是思路二能成立的前提。

---

## 💡 第三步：思路一 —— 标记数组（用 O(n) 空间）

### 思路

开一个 `seen` 数组记录每个数"见没见过"。从左往右扫描，第一个"已经见过"的数就是答案。

### 手动模拟（示例 2：`nums = [3,1,3,4,2]`）

| i | nums[i] | seen[nums[i]] 之前 | 操作 |
|---|---|---|---|
| 0 | 3 | false | 标记 seen[3] = true |
| 1 | 1 | false | 标记 seen[1] = true |
| 2 | 3 | **true** | 找到重复，返回 **3** |

### 代码

```c
int findDuplicate(int* nums, int numsSize) {
    // 值的范围是 1 ~ n = numsSize - 1，开 numsSize 个格子正好够用
    bool* seen = (bool*)calloc(numsSize, sizeof(bool));
    int ans = -1;

    for (int i = 0; i < numsSize; i++) {
        if (seen[nums[i]]) {        // 之前见过，就是重复的数
            ans = nums[i];
            break;
        }
        seen[nums[i]] = true;       // 第一次见到，做个标记
    }

    free(seen);
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(n)**。
- **空间复杂度 O(n)**：不满足题目 O(1) 空间的要求（但能通过）。

---

## 🚀 第四步：思路二 —— 快慢指针（Floyd 判圈）

### 思路

**第 1 步：把数组看成链表。** 把每个下标 `i` 看成一个结点，它的"下一个"是 `nums[i]`。从下标 0 出发一直往下走：`0 → nums[0] → nums[nums[0]] → ...`

以示例 1 `[1,3,4,2,2]` 为例：

| 下标 i | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| nums[i]（下一个） | 1 | 3 | 4 | 2 | 2 |

从 0 出发：`0 → 1 → 3 → 2 → 4 → 2 → 4 → 2 → ...`

```
0 → 1 → 3 → 2 ⇄ 4
            ↑ 环的入口
```

**第 2 步：为什么一定有环，环的入口就是重复数？**

- 每个结点都有"下一个"，而结点个数有限，一直走下去必然会回到走过的结点，所以一定有环。
- 下标 0 没有任何格子指向它（值都 ≥ 1），所以 0 不在环上。
- 环的入口是一个"有两个结点指向它"的结点：一个来自环外，一个来自环内。"有两个格子的值都等于它" —— 这正是**重复的数**！上例中 `nums[3] = 2`、`nums[4] = 2`，入口是 2。

**第 3 步：用 Floyd 判圈算法找环的入口（和"142. 环形链表 II"完全一样）。**

1. 慢指针每次走 1 步 `slow = nums[slow]`，快指针每次走 2 步 `fast = nums[nums[fast]]`，直到相遇。
2. 让慢指针回到起点 0，然后两个指针**都每次走 1 步**，再次相遇的位置就是环的入口。

> 💬 为什么第 2 阶段能找到入口？设起点到入口距离为 a，入口到相遇点距离为 b，环长为 L。相遇时快指针走的路程是慢指针的 2 倍，可以推出 a = (L - b) + kL，也就是"从起点走 a 步"和"从相遇点走 a 步"会同时到达入口。初学时记住结论即可。

### 手动模拟（示例 1：`[1,3,4,2,2]`）

**阶段 1：找相遇点**

| 第几步 | slow（走 1 步） | fast（走 2 步） | 相遇？ |
|---|---|---|---|
| 初始 | 0 | 0 | |
| 1 | 1 | nums[nums[0]] = nums[1] = 3 | 否 |
| 2 | 3 | nums[nums[3]] = nums[2] = 4 | 否 |
| 3 | 2 | nums[nums[4]] = nums[2] = 4 | 否 |
| 4 | 4 | nums[nums[4]] = nums[2] = 4 | **是，在 4** |

**阶段 2：找入口**

| 第几步 | slow（从 0 出发） | fast（从 4 出发） | 相遇？ |
|---|---|---|---|
| 初始 | 0 | 4 | 否 |
| 1 | 1 | 2 | 否 |
| 2 | 3 | 4 | 否 |
| 3 | 2 | 2 | **是，答案 2** |

### 代码

```c
int findDuplicate(int* nums, int numsSize) {
    int slow = 0, fast = 0;

    // 阶段 1：快指针每次 2 步，慢指针每次 1 步，直到在环里相遇
    do {
        slow = nums[slow];              // 走 1 步
        fast = nums[nums[fast]];        // 走 2 步
    } while (slow != fast);

    // 阶段 2：慢指针回到起点，两个指针都每次走 1 步，相遇处就是环的入口
    slow = 0;
    while (slow != fast) {
        slow = nums[slow];
        fast = nums[fast];
    }
    return slow;                        // 环的入口 = 重复的数
}
```

### 复杂度分析

- **时间复杂度 O(n)**：两个阶段都在 O(n) 步内结束。
- **空间复杂度 O(1)**：只用了两个变量，而且**没有修改数组**。

---

## ⚠️ 第五步：小白常见错误

1. **阶段 1 用 `while (slow != fast)` 而不是 `do-while`** → 一开始两者都是 0，循环直接跳过，阶段 2 也立即结束，返回 0。
2. **快指针写成 `fast = nums[fast]; fast = nums[slow];` 之类** → 快指针必须连续走两步：`fast = nums[nums[fast]]`。
3. **阶段 2 快指针还是走 2 步** → 两个指针必须**同速**，否则不保证在入口相遇。
4. **返回下标而不是值** → 阶段 2 相遇时 `slow` 本身就是"结点编号"，也就是重复的那个**值**，直接返回 `slow`。不要返回 `nums[slow]`。
5. **排序后找相邻相等** → 能得到正确答案，但修改了数组，违反了题目要求。
6. **用"求和减去 1+2+…+n"** → 只在重复数恰好出现两次、且其他数都出现时成立；示例 3 `[3,3,3,3,3]` 就会出错。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 不改数组？ | 难度 |
|---|---|---|---|---|
| 排序后找相邻 | O(n log n) | O(1) | ❌ | ⭐ |
| 标记数组 | O(n) | O(n) | ✅ | ⭐ |
| 二分查找（数一数 ≤ mid 的个数） | O(n log n) | O(1) | ✅ | ⭐⭐⭐ |
| 快慢指针 | O(n) | O(1) | ✅ | ⭐⭐⭐⭐ |

> 💬 二分思路：对于值 `mid`，如果数组里 `≤ mid` 的数**多于** `mid` 个，说明重复数在 `[1, mid]` 里，否则在 `[mid+1, n]` 里。
