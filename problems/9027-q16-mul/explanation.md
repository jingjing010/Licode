# 9027. Q16.16 定点数乘法 —— 小白详细题解

> 没有浮点单元的 MCU 上，"用整数假装小数"是提速的核心手段。这道题只有三行代码，但每一行都踩着一个经典的坑：**乘法溢出**、**负数的取整方向**、**结果饱和**。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 每个整数其实代表"它除以 65536"那个小数。两个这样的数相乘，结果也要用同样的方式表示。

为什么要"再除以 65536"？设 `a = x × 65536`，`b = y × 65536`：

```
a × b = x × y × 65536 × 65536
```

我们想要的是 `x × y × 65536`，所以 `a × b` 还要**再除以一次 65536**，也就是右移 16 位。

拿示例 1 来说：

| | 实数 | 原始值 |
|---|---|---|
| a | 1.5 | 98304 |
| b | 2.0 | 131072 |
| a × b | — | 12884901888（已经超过 32 位！） |
| ÷ 65536 | 3.0 | **196608** |

**几个需要注意的细节：**

1. `a × b` 可能高达 `2^62`，**必须用 64 位**计算。
2. 除不尽时要**向负无穷取整**：`-1 × 1 / 65536 = -0.0000153`，结果是 `-1` 而不是 `0`。
3. Q16.16 能表示的范围约是 `-32768 ~ 32767.99998`，超出就**饱和**到边界值。

---

## 🧰 第二步：需要的 C 语言知识

### 1. 先转换类型，再相乘

```c
int64_t p = a * b;             // ❌ 先按 32 位相乘（溢出！），再把错误结果扩展成 64 位
int64_t p = (int64_t)a * b;    // ✅ a 先变成 64 位，b 也随之提升，乘法在 64 位中进行
```

C 语言里运算的类型由**操作数**决定，而不是由"结果要存到哪里"决定。这是嵌入式里最常见的溢出 bug。

### 2. 右移和除法对负数的区别

| 表达式 | 结果 | 取整方向 |
|---|---|---|
| `-1 / 65536` | 0 | 向零取整（C99 规定） |
| `-1 >> 16` | -1 | 向负无穷（GCC 等对负数做算术右移） |

对负数右移在 C 标准中是**实现定义**的行为，但 GCC、Clang、Keil、IAR 都是算术右移（高位补符号位）。本题规定"向负无穷取整"，正好等于算术右移的结果，这也是 DSP 库（如 CMSIS-DSP）的标准做法。

### 3. 饱和（saturation）

溢出时"卡在边界"而不是"绕回去"。对控制系统来说，`32767` 变成 `-32768` 意味着电机突然反转，而饱和只是"输出到最大"，安全得多。

---

## 💡 第三步：思路一 —— 64 位乘法 + 算术右移 + 饱和

### 思路

1. `p = (int64_t)a * b`
2. `q = p >> 16`（GCC 上对负数是算术右移，恰好向负无穷取整）
3. 把 `q` 夹到 `[INT32_MIN, INT32_MAX]`

### 手动模拟

| a | b | p = a × b | p >> 16 | 饱和后 |
|---|---|---|---|---|
| 98304 | 131072 | 12884901888 | 196608 | 196608 |
| −98304 | 32768 | −3221225472 | −49152 | −49152 |
| 2147483647 | 131072 | 281474976579584 | 4294967294 | **2147483647** |
| −1 | 1 | −1 | −1 | −1 |

### 代码

```c
int32_t q16_mul(int32_t a, int32_t b) {
    int64_t p = (int64_t)a * b;          // 先扩展到 64 位再乘，不会溢出
    int64_t q = p >> 16;                 // 去掉多出来的 2^16（算术右移，向负无穷取整）

    if (q > INT32_MAX) return INT32_MAX; // 正向饱和
    if (q < INT32_MIN) return INT32_MIN; // 负向饱和
    return (int32_t)q;
}
```

### 复杂度分析

- **时间复杂度 O(1)**，**空间复杂度 O(1)**。在 Cortex-M3/M4 上，64 位乘法是一条 `SMULL` 指令。

---

## 🚀 第四步：思路二 —— 不依赖"负数右移"的可移植写法

### 思路

如果项目的编码规范（例如 MISRA C）禁止对负数右移，可以分正负两种情况处理：

- `p >= 0`：`p >> 16` 就是向下取整，没有争议
- `p < 0`：`floor(p / 65536) = -ceil(-p / 65536) = -((-p + 65535) >> 16)`

`-p` 是正数，右移完全由标准定义；`+ 65535` 的作用是把"向下取整"变成"向上取整"。

### 手动模拟（`p = -1`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| 取绝对值 | `-p` | 1 |
| 向上取整 | `(1 + 65535) >> 16` | 1 |
| 恢复符号 | `-1` | −1 ✅ |

### 代码

```c
int32_t q16_mul(int32_t a, int32_t b) {
    int64_t p = (int64_t)a * b;
    int64_t q;
    if (p >= 0) {
        q = p >> 16;                     // 非负数：直接右移
    } else {
        q = -((-p + 65535) >> 16);       // 负数：对绝对值向上取整，再取负
    }

    if (q > INT32_MAX) return INT32_MAX;
    if (q < INT32_MIN) return INT32_MIN;
    return (int32_t)q;
}
```

> 💬 这里 `-p` 不会溢出：`|p|` 最大是 `2^31 × 2^31 = 2^62`，远小于 `int64_t` 的上限。

## 🔌 嵌入式实战

PID 控制器里的定点运算：

```c
typedef int32_t q16_t;
#define Q16(x)  ((q16_t)((x) * 65536.0))        // 编译期常量换算 ...

q16_t kp = Q16(1.25), ki = Q16(0.02);
q16_t out = q16_mul(kp, err) + q16_mul(ki, integral);
```

- 加减法直接用 `+`、`-`（两边格式相同，不需要换算）。
- 乘法必须用 `q16_mul`，除法则是 `((int64_t)a << 16) / b`。
- 很多项目还会把"四舍五入"做成可选：`(p + 0x8000) >> 16`，误差更小。

---

## ⚠️ 第五步：小白常见错误

1. **`(int64_t)(a * b)`**：括号位置错了，乘法仍在 32 位中进行，先溢出再转换。
2. **先右移再相乘**：`(a >> 8) * (b >> 8)` 能避免溢出，但丢掉了低 8 位，`0.001 × 0.001` 直接变 0，精度损失严重。
3. **用 `/ 65536` 代替 `>> 16`**：对负数是向零取整，`-1 × 1` 得到 0，与题目要求不符。
4. **不做饱和**：`(int32_t)q` 直接截断，`2147483647 × 2.0` 变成 `-2`，控制系统会"反向暴走"。
5. **用 `float` 偷懒**：`(int32_t)((float)a * b / 65536)`——`float` 只有 24 位精度，大数会算错，而且在无 FPU 的 MCU 上很慢。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| 64 位乘法 + 算术右移 | O(1) | O(1) | 最简洁，GCC/Keil/IAR 通用 |
| 分正负处理 | O(1) | O(1) | 完全符合 C 标准 / MISRA |
| 先移位再乘 | O(1) | O(1) | ❌ 精度损失 |
| 浮点运算 | 慢 | O(1) | ❌ 精度不足、无 FPU 时很慢 |
