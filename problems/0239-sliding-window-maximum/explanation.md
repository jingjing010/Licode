# 239. 滑动窗口最大值 —— 小白详细题解

> 这是**单调队列**的模板题。暴力法人人都会，但会超时；真正要学的是："哪些数已经**没有希望**成为最大值了，可以提前扔掉？"

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 拿一个能框住 `k` 个数的"框"，从数组最左边开始，每次往右挪一格，直到框的右边碰到数组末尾。每挪到一个位置，记下框里最大的数。

示例 1 `nums = [1,3,-1,-3,5,3,6,7], k = 3`：

| 窗口（下标） | 窗口里的数 | 最大值 |
|---|---|---|
| 0~2 | 1, 3, -1 | 3 |
| 1~3 | 3, -1, -3 | 3 |
| 2~4 | -1, -3, 5 | 5 |
| 3~5 | -3, 5, 3 | 5 |
| 4~6 | 5, 3, 6 | 6 |
| 5~7 | 3, 6, 7 | 7 |

答案 `[3,3,5,5,6,7]`。

**几个需要注意的细节：**

1. 一共有 `n - k + 1` 个窗口，答案数组就这么长。
2. `k` 可能等于 1（每个数自己就是最大值），也可能等于 `n`（只有一个窗口）。
3. 数组里有**负数**，求最大值时初始值不能设成 0。
4. n 最大 10⁵，k 也能到 10⁵ 级别，**O(n·k) 的暴力会超时**。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 返回数组：`malloc` + `*returnSize`

```c
int* ans = (int*)malloc(sizeof(int) * (numsSize - k + 1));
*returnSize = numsSize - k + 1;
```

### 2. 用数组 + 两个下标模拟"双端队列"

C 语言没有现成的队列。我们用一个普通数组 `dq` 加上两个下标：

```c
int dq[...];          // 存放元素
int head = 0;         // 队头位置：dq[head] 是队头元素
int tail = 0;         // 队尾的下一个位置：dq[tail - 1] 是队尾元素
                      // 队列里的元素是 dq[head], dq[head+1], ..., dq[tail-1]
                      // 队列为空 ⟺ head == tail
```

| 操作 | 写法 |
|---|---|
| 从队尾加入 x | `dq[tail++] = x;` |
| 从队尾弹出 | `tail--;` |
| 从队头弹出 | `head++;` |
| 看队头 / 队尾 | `dq[head]` / `dq[tail - 1]` |

每个元素最多进队一次，所以数组开 `numsSize` 那么大就够了，`head` 和 `tail` 只会往右走，不会越界。

---

## 💡 第三步：思路一 —— 暴力：每个窗口都扫一遍

### 思路

对每个窗口的起点 `i`（`0 ~ n-k`），把 `nums[i..i+k-1]` 扫一遍找最大值。

### 代码

```c
// ❌ 会超时：n = 10^5、k = 5×10^4 时要比较约 2.5×10^9 次，仅用于理解题意
int* maxSlidingWindow(int* nums, int numsSize, int k, int* returnSize) {
    int cnt = numsSize - k + 1;                  // 窗口个数
    int* ans = (int*)malloc(sizeof(int) * cnt);
    *returnSize = cnt;
    for (int i = 0; i < cnt; i++) {              // 枚举窗口起点
        int mx = nums[i];                        // 用窗口第一个数做初始值（不能用 0，可能全是负数）
        for (int j = i + 1; j < i + k; j++) {
            if (nums[j] > mx) mx = nums[j];
        }
        ans[i] = mx;
    }
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O((n-k+1) × k)**：k 取 n/2 左右时最坏，约 n²/4 = 2.5×10⁹，必然超时。
- **空间复杂度 O(1)**（答案数组不算）。

问题在哪？窗口每次只挪一格，只有**一个数进来、一个数出去**，其余 k-1 个数都是一样的，我们却从头扫了一遍。

## 🚀 第四步：思路二 —— 单调队列（O(n)）

### 关键观察：有些数"永远没希望"

假设窗口里有一个旧数 `a`（下标 `i`），又进来一个新数 `b`（下标 `j > i`），并且 `b >= a`。

- `a` 比 `b` **更早离开**窗口（因为 `i < j`）；
- 在 `a` 还在窗口里的每一刻，`b` 也都在，而且 `b >= a`。

所以 `a` **永远不可能成为最大值**了，可以直接扔掉！

### 思路

用一个双端队列存**下标**，并时刻保证：**队列里下标对应的值，从队头到队尾是递减的**。

对每个新来的 `nums[i]`：

1. **从队尾踢人**：队尾对应的值 `<= nums[i]` 的，全都没希望了，弹出。
2. **入队**：把 `i` 放到队尾。
3. **从队头踢人**：如果队头的下标已经滑出窗口（`<= i - k`），弹出。
4. **记录答案**：当 `i >= k - 1`（第一个完整窗口形成后），队头就是当前窗口的最大值。

> ❓ **为什么队列里存下标而不是值？** 第 3 步要判断"队头是不是已经滑出窗口了"，只有知道它的下标才能判断。值随时可以用 `nums[下标]` 取到。

### 手动模拟（示例 1：`nums = [1,3,-1,-3,5,3,6,7], k = 3`）

队列一栏写成"下标(值)"，从队头到队尾：

| i | nums[i] | 从队尾弹出 | 入队后 | 队头过期？ | 队列 | 答案 |
|---|---|---|---|---|---|---|
| 0 | 1 | — | 0(1) | — | 0(1) | 窗口未满 |
| 1 | 3 | 弹出 0(1) | 1(3) | — | 1(3) | 窗口未满 |
| 2 | -1 | — | 1(3) 2(-1) | — | 1(3) 2(-1) | **3** |
| 3 | -3 | — | 1(3) 2(-1) 3(-3) | 1 > 0，没过期 | 1(3) 2(-1) 3(-3) | **3** |
| 4 | 5 | 弹出 3、2、1 | 4(5) | — | 4(5) | **5** |
| 5 | 3 | — | 4(5) 5(3) | — | 4(5) 5(3) | **5** |
| 6 | 6 | 弹出 5、4 | 6(6) | — | 6(6) | **6** |
| 7 | 7 | 弹出 6 | 7(7) | — | 7(7) | **7** |

### 代码

```c
int* maxSlidingWindow(int* nums, int numsSize, int k, int* returnSize) {
    // dq：双端队列，存下标；对应的值从队头到队尾单调递减
    int* dq = (int*)malloc(sizeof(int) * numsSize);
    int head = 0, tail = 0;                       // 队列元素是 dq[head..tail-1]

    int* ans = (int*)malloc(sizeof(int) * (numsSize - k + 1));
    int cnt = 0;

    for (int i = 0; i < numsSize; i++) {
        // 1. 队尾的值 <= nums[i]：它们比 nums[i] 早离开又不比它大，永远没希望了
        while (tail > head && nums[dq[tail - 1]] <= nums[i]) {
            tail--;
        }
        // 2. 新下标入队
        dq[tail++] = i;
        // 3. 队头下标已经不在窗口 [i-k+1, i] 里了，弹出
        if (dq[head] <= i - k) {
            head++;
        }
        // 4. 从第一个完整窗口开始记录答案，队头就是最大值
        if (i >= k - 1) {
            ans[cnt++] = nums[dq[head]];
        }
    }

    free(dq);
    *returnSize = cnt;
    return ans;
}
```

**为什么第 3 步用 `if` 而不是 `while` 就够了？** 窗口每次只右移一格，最多只有一个下标（`i - k`）刚好过期；而队列里的下标是递增的，过期的那个只可能在队头。

### 复杂度分析

- **时间复杂度 O(n)**：虽然有 while，但每个下标**最多入队一次、出队一次**，总操作次数不超过 2n。
- **空间复杂度 O(k)**：队列里最多同时有 k 个下标（我们直接开了 n 个，也是 O(n)）。

## ⚠️ 第五步：小白常见错误

1. **暴力求最大值时 `int mx = 0;`** → 窗口里全是负数时答案错成 0。要用窗口第一个数做初始值，或者用 `INT_MIN`。
2. **队列里存值而不是下标** → 没法判断队头是不是已经滑出窗口了，过期的大数会一直"霸占"队头。
3. **过期判断写错**：窗口是 `[i-k+1, i]`，过期条件是 `dq[head] <= i - k`。写成 `< i - k` 会让窗口变成 k+1 大小。
4. **先判断过期、再入队，并且队列可能为空时访问 `dq[head]`** → 队列为空时 `dq[head]` 是垃圾值。按"先踢队尾 → 入队 → 踢队头"的顺序，踢队头时队列至少有刚入队的 i，不会为空。
5. **从队尾弹出的条件写成 `<` 还是 `<=`？** 两种都能得到正确答案；用 `<=` 会把相等的旧值也弹掉，队列更短。但千万别写成 `>`，那样队列就变成递增的了。
6. **答案数组长度开成 `numsSize`，`*returnSize` 也写成 `numsSize`** → 多输出了 k-1 个垃圾值。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 暴力扫描每个窗口 | O(n·k) | O(1) | ⭐ | 会超时，只用来理解题意 |
| 大根堆（优先队列，懒删除过期元素） | O(n log n) | O(n) | ⭐⭐⭐ | C 语言要手写堆，比较麻烦 |
| 单调队列 | O(n) | O(k) | ⭐⭐ | 标准答案，必须掌握 |
