# 1011. 在 D 天内送达包裹的能力 —— 小白详细题解

> 又是一道"**二分答案**"题。和 875 题（珂珂吃香蕉）一样的套路：猜一个载重，检查能否按时送完，然后二分找最小的可行载重。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 一排包裹**按顺序**排在传送带上，每天用船运一批，一批的总重量不能超过船的载重。要在 `days` 天内全部运完，**船的载重最小是多少**？

拿示例 2 `weights = [3,2,2,4,1,4], days = 3` 来说：

| 载重 | 怎么装（按顺序，装不下就明天） | 天数 | <= 3 ? |
|---|---|---|---|
| 5 | [3,2] [2] [4,1] [4] | 4 | ❌ |
| **6** | [3,2] [2,4] [1,4] | **3** | ✅ |
| 7 | [3,2,2] [4,1] [4] | 3 | ✅ |

最小可行载重是 6。

**几个需要注意的细节：**

1. 包裹必须**按顺序**装，不能挑着装（示例 1 的解释特别强调了这一点）。
2. 一个包裹不能拆开，所以载重至少是 `max(weights)`，否则最重的包裹永远运不走。
3. 载重等于 `sum(weights)` 时一天就能运完，所以答案不会超过总和。
4. 总重量最多 `5×10^4 × 500 = 2.5×10^7`，int 够用。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 辅助函数

把"给定载重，算需要几天"写成一个单独的函数，主函数只负责二分，结构清晰：

```c
static int daysNeeded(int* weights, int weightsSize, int cap);
```

`static` 让这个函数只在当前文件可见，不会和别处重名。

### 2. 同时求最大值和总和

```c
int mx = 0, sum = 0;
for (int i = 0; i < n; i++) {
    if (weights[i] > mx) mx = weights[i];   // 最大值
    sum += weights[i];                      // 总和
}
```

一次循环同时求出二分的下界和上界。

---

## 💡 第三步：思路一 —— 载重从小到大逐个试（会超时）

### 思路

载重从 `max(weights)` 开始，每次加 1，第一个能在 days 天内运完的就是答案。

### 代码

```c
// ❌ 思路正确但会超时：载重最多要试约 2.5×10^7 次，每次 O(n)
int shipWithinDays(int* weights, int weightsSize, int days) {
    int cap = 0;
    for (int i = 0; i < weightsSize; i++)
        if (weights[i] > cap) cap = weights[i];   // 从最大包裹重量开始试
    while (1) {
        int d = 1, cur = 0;                        // 模拟装船
        for (int i = 0; i < weightsSize; i++) {
            if (cur + weights[i] > cap) { d++; cur = 0; }
            cur += weights[i];
        }
        if (d <= days) return cap;
        cap++;
    }
}
```

### 复杂度分析

- **时间复杂度 O(n · sum)**：最坏 `5×10^4 × 2.5×10^7`，绝对超时。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 二分答案 + 贪心检查（标准解法）

### 贪心检查：给定载重，最少几天？

从第一个包裹开始，**今天能装就装**，装不下就开始新的一天。为什么贪心是对的？因为今天多装一个，只会让后面剩下的更少，不会让天数变多。

### 为什么能二分？

载重越大，每天能装越多，需要的天数**单调不增**：

```
载重:        4    5    6    7    8   ...  16
需要天数:    5    4    3    3    3   ...   1
<= 3 ?:      否   否   是   是   是  ...  是
                       ↑ 第一个"是"
```

找第一个"是"——二分！

### 区间定义与循环条件

- 区间：**闭区间 `[lo, hi]`**，`lo = max(weights)`，`hi = sum(weights)`。
- `while (lo < hi)`。
- `daysNeeded(mid) <= days`：mid 可行，答案是 mid 或更小：`hi = mid`
- 否则：载重不够：`lo = mid + 1`
- `mid = lo + (hi - lo) / 2`（本题 hi 最大 2.5×10⁷，`lo + hi` 不会溢出，但保持好习惯）。

### 手动模拟（`weights = [3,2,2,4,1,4], days = 3`）

`lo = 4, hi = 16`。

| 轮次 | lo | hi | mid | 贪心装法 | 天数 | <= 3 ? | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 4 | 16 | 10 | [3,2,2] [4,1,4] | 2 | 是 | hi = 10 |
| 2 | 4 | 10 | 7 | [3,2,2] [4,1] [4] | 3 | 是 | hi = 7 |
| 3 | 4 | 7 | 5 | [3,2] [2] [4,1] [4] | 4 | 否 | lo = 6 |
| 4 | 6 | 7 | 6 | [3,2] [2,4] [1,4] | 3 | 是 | hi = 6 |
| 结束 | 6 | 6 | | | | | 返回 6 ✅ |

### 代码

```c
// 船的载重为 cap 时，贪心装载需要几天
static int daysNeeded(int* weights, int weightsSize, int cap) {
    int d = 1;                   // 至少需要 1 天
    int cur = 0;                 // 今天已经装了多重
    for (int i = 0; i < weightsSize; i++) {
        if (cur + weights[i] > cap) {   // 今天装不下这个包裹了
            d++;                 // 换到明天
            cur = 0;
        }
        cur += weights[i];
    }
    return d;
}

int shipWithinDays(int* weights, int weightsSize, int days) {
    int lo = 0, hi = 0;
    for (int i = 0; i < weightsSize; i++) {
        if (weights[i] > lo) lo = weights[i];   // 下界：最重的包裹
        hi += weights[i];                       // 上界：所有包裹总重
    }

    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (daysNeeded(weights, weightsSize, mid) <= days) {
            hi = mid;            // 载重 mid 来得及，试试更小的
        } else {
            lo = mid + 1;        // 来不及，载重要更大
        }
    }
    return lo;
}
```

### 复杂度分析

- **时间复杂度 O(n · log(sum))**：二分约 25 轮，每轮 O(n)。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **下界从 1（或 0）开始** → 载重小于最重包裹时，`daysNeeded` 会把放不下的包裹硬塞进去，天数算错，可能返回一个根本运不走最重包裹的载重。下界必须是 `max(weights)`。
2. **贪心时先加再判断** → `cur += w; if (cur > cap) { d++; cur = 0; }`，把超出的包裹"丢掉"了，下一天少算了它的重量。
3. **天数初始化为 0** → 最后一天的货装完后没有计数，少算一天。
4. **check 条件写成 `== days`** → 用更少的天数运完也是可以的，应该是 `<= days`。
5. **以为可以调整包裹顺序（排序）** → 题目要求按顺序装，排序后答案就错了。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 逐个尝试载重 | O(n · sum) | O(1) | ⭐ | 会超时 |
| 二分答案 + 贪心 | O(n · log sum) | O(1) | ⭐⭐ | 标准解法 |
