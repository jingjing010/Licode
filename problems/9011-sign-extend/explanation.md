# 9011. 符号扩展 —— 小白详细题解

> 读传感器时最经典的 bug："温度一到零下就变成 4000 多度"。原因就是忘了做**符号扩展**。本题从补码讲起，给出三种写法，其中 `(raw ^ m) - m` 是一个值得背下来的小技巧。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 传感器给你一个 `bits` 位的补码，装在 `uint32_t` 的低位里。请算出它真正代表的有符号数。

以 4 位补码为例（`bits = 4`），它能表示 -8 ~ 7：

| 二进制 | 当成无符号 | 当成 4 位补码 |
|---|---|---|
| `0000` | 0 | 0 |
| `0111` | 7 | 7（最大值） |
| `1000` | 8 | **-8**（最小值） |
| `1110` | 14 | **-2** |
| `1111` | 15 | **-1** |

规律：**最高位（符号位）是 0，值不变；是 1，真实值 = 无符号值 − 2^bits**。例如 `1110`：14 − 16 = −2。

**几个需要注意的细节：**

1. 符号位是第 `bits - 1` 位，不是第 31 位。12 位补码的符号位是第 11 位。
2. `bits = 32` 时，`raw` 本身就是一个完整的 32 位补码，直接转成 `int32_t` 即可，但很多写法在这里会触发 `1u << 32` 之类的未定义行为。
3. `bits = 1` 时只有符号位，能表示的数只有 0 和 −1。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 补码（two's complement）

计算机里的负数用补码表示：`-x` 的补码 = `x` 按位取反再加 1。补码的好处是加减法不用区分正负，硬件简单。对一个 `bits` 位的补码，最高位的"权重"是 **−2^(bits−1)**，其余位权重为正：

```
1110（4 位）= -8 + 4 + 2 + 0 = -2
```

### 2. 什么叫"符号扩展"？

把一个窄的补码变宽时，**用符号位填满新增的高位**，数值保持不变：

```
4 位 1110 (-2)  →  8 位 1111 1110 (-2)     ✔ 用 1 填
4 位 0110 ( 6)  →  8 位 0000 0110 ( 6)     ✔ 用 0 填
4 位 1110       →  8 位 0000 1110 (14)     ✘ 用 0 填，就变成正数了
```

### 3. `int32_t` 和 `int64_t`

- `int32_t`：恰好 32 位的有符号整数，范围 −2³¹ ~ 2³¹−1。
- `int64_t`：64 位有符号整数。用它来做中间计算，`raw − 2^32` 这种运算就不会溢出。

### 4. 无符号转有符号

`(int32_t)u`：如果 `u <= 0x7FFFFFFF`，值不变；如果更大，C 标准规定结果是"**实现定义**"的。GCC、Clang、ARM 编译器都定义为"按位原样解释"（即 `u − 2³²`），嵌入式代码普遍依赖这一点。

---

## 💡 第三步：思路一 —— 判断符号位，按公式计算（最朴素）

### 思路

1. 读出符号位：`(raw >> (bits - 1)) & 1u`。
2. 是 0 → 返回 `raw`；是 1 → 返回 `raw − 2^bits`。
3. `2^bits` 在 `bits = 32` 时是 2³²，`uint32_t` 放不下，所以用 `int64_t` 来算。

### 手动模拟（示例 1：`raw = 4095, bits = 12`）

| 步骤 | 计算 | 结果 |
|---|---|---|
| 符号位 | (4095 >> 11) & 1 | 1 |
| 是负数 | 4095 − 2¹² = 4095 − 4096 | **-1** |

### 代码

```c
int32_t sign_extend(uint32_t raw, int bits) {
    uint32_t sign = (raw >> (bits - 1)) & 1u;          // 第 bits-1 位是符号位
    if (sign == 0) {
        return (int32_t)raw;                           // 正数：值不变（raw < 2^31，转换安全）
    }
    // 负数：真实值 = raw - 2^bits，用 64 位计算避免 bits = 32 时溢出
    return (int32_t)((int64_t)raw - ((int64_t)1 << bits));
}
```

### 复杂度分析

- **时间复杂度 O(1)**。但在 32 位单片机上 64 位减法要多条指令，还有一个分支。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 异或再相减（无分支，推荐）

### 思路

令 `m = 1u << (bits - 1)`（只有符号位为 1），答案是 `(raw ^ m) - m`。

为什么？分两种情况：

- **符号位为 0**：`raw ^ m` 把符号位变成 1，相当于 `raw + m`；再减 `m`，得到 `raw`。✔
- **符号位为 1**：`raw ^ m` 把符号位变成 0，相当于 `raw − m`；再减 `m`，得到 `raw − 2m = raw − 2^bits`。✔

两种情况恰好都对，而且不需要 `if`。

### 手动模拟

| | raw | m | raw ^ m | (raw ^ m) − m |
|---|---|---|---|---|
| 4 位 `1110` | 14 | 8 | 6 | **−2** ✔ |
| 4 位 `0110` | 6 | 8 | 14 | **6** ✔ |
| 示例 3 | 0x800000 | 0x800000 | 0 | **−8388608** ✔ |

在 `uint32_t` 里，`0 − 0x800000` 会回绕成 `0xFF800000`，再转换成 `int32_t` 就是 −8388608——高位正好被填满了 1，这就是"符号扩展"。

### 代码

```c
int32_t sign_extend(uint32_t raw, int bits) {
    uint32_t m = 1u << (bits - 1);     // 只有符号位为 1 的掩码；bits <= 32，移位数最大 31，安全
    return (int32_t)((raw ^ m) - m);   // 无符号运算自动回绕，结果按补码解释即为答案
}
```

### 复杂度分析

- **时间复杂度 O(1)**：一次移位、一次异或、一次减法，无分支。
- **空间复杂度 O(1)**。

### 另一种常见写法：先左移、再算术右移

把符号位左移到第 31 位，转成 `int32_t`，再右移回来——对有符号负数，GCC/ARM 的右移是**算术右移**（左边补符号位），高位自然就被填满了：

```c
int32_t sign_extend(uint32_t raw, int bits) {
    int shift = 32 - bits;                       // bits = 32 时为 0，不用移
    return (int32_t)(raw << shift) >> shift;     // 依赖"有符号右移是算术右移"（实现定义）
}
```

这种写法在 Linux 内核（`sign_extend32()`）里就有，但它依赖两个"实现定义"的行为，可移植性略差于思路二。

---

## ⚠️ 第五步：小白常见错误

1. **直接强转**：
   ```c
   return (int32_t)raw;    // ❌ 4095 还是 4095，没有做符号扩展
   ```
2. **用 `1u << bits` 构造 2^bits**：`bits = 32` 时是未定义行为。
   ```c
   return (raw & (1u << (bits - 1))) ? (int32_t)(raw - (1u << bits)) : (int32_t)raw;   // ❌ bits = 32 出错
   ```
3. **符号位位置数错**：把第 `bits` 位当成符号位。12 位数的位号是 0~11，符号位是第 **11** 位。
4. **把"取反加一"用在这里**：`-(int32_t)(~raw + 1)` 之类的写法没有考虑 `raw` 的高位是 0，`~raw` 会把高位的 0 也翻成 1，结果错乱。
5. **用位域结构体 `struct { int v : 12; }`**：`int` 位域到底是有符号还是无符号是"实现定义"的，不同编译器结果可能不同。要写就明确写 `signed int v : 12;`。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 判断符号位 + 64 位减法 | O(1) | O(1) | ⭐ | 最好理解 |
| `(raw ^ m) - m` | O(1) | O(1) | ⭐⭐ | 无分支，推荐背下来 |
| 左移再算术右移 | O(1) | O(1) | ⭐⭐ | 内核常见，依赖实现定义行为 |

## 🔌 嵌入式实战

24 位 ADC 读数（大端，3 字节）转电压的典型流程（示意）：

```c
uint8_t rx[3];
spi_read(rx, 3);                                            /* 读 3 字节原始数据 */
uint32_t raw = ((uint32_t)rx[0] << 16) | ((uint32_t)rx[1] << 8) | rx[2];
int32_t code = sign_extend(raw, 24);                        /* -8388608 ~ 8388607 */
float volt = code * (2.048f / 8388608.0f);                  /* 按满量程换算电压 */
```

- ARM Cortex-M3/M4 有 `SBFX`（有符号位域提取）指令，一条指令完成"取位域 + 符号扩展"。编译器看到"左移再算术右移"那样的写法时常常会生成它。
- 16 位传感器（如 MPU6050 的加速度）其实也要符号扩展，只是大家通常写成 `(int16_t)((hi << 8) | lo)`，借助 `int16_t` 的转换隐式完成了。
