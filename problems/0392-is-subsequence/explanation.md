# 392. 判断子序列 —— 小白详细题解

> 一道非常经典的**同向双指针 + 贪心**题。进阶部分还会引出“预处理 + 动态规划”的思想。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 能不能从 `t` 里**删掉一些字符**（不能调换顺序），剩下的恰好是 `s`？

拿示例 1 `s = "abc"`, `t = "ahbgdc"` 来说：

| t | **a** | h | **b** | g | d | **c** |
|---|---|---|---|---|---|---|
| 保留？ | ✅ | 删 | ✅ | 删 | 删 | ✅ |

剩下 `"abc"`，所以是子序列。

示例 2 `s = "axc"`：`t` 里根本没有 `x`，不可能。

**几个需要注意的细节：**

1. **子序列 ≠ 子串**：子序列可以不连续，但**顺序不能乱**。`"acb"` 不是 `"ahbgdc"` 的子序列（`t` 中 `b` 在 `c` 前面）。
2. `s` 可能是**空串** `""`，空串是任何字符串的子序列，返回 `true`。
3. `t` 也可能是空串，这时只有 `s` 也为空才返回 `true`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用 `'\0'` 判断字符串结束

不需要 `strlen`，`s[i] == '\0'` 就表示 `s` 已经走完了。空串 `""` 的第 0 个字符就是 `'\0'`。

### 2. 为什么“贪心地匹配最早出现的”是对的？

假设 `s[0] = 'a'`，`t` 里有好几个 `a`。选**最靠前**的那个 `a` 去匹配，留给后面字符的“剩余部分”最长，选择最多——所以选最早的一定不会更差。这就是**贪心**。

### 3. 二维数组的动态申请（进阶用）

```c
int (*nxt)[26] = malloc(sizeof(int[26]) * (m + 1));   // m+1 行、每行 26 列
nxt[i][c] = ...;                                     // 和普通二维数组一样使用
```

`int (*nxt)[26]` 读作“`nxt` 是一个指针，指向含 26 个 int 的数组”，所以 `nxt[i]` 就是第 i 行。

---

## 💡 第三步：思路一 —— 双指针（贪心）

### 思路

- `i` 指向 `s` 中**下一个要匹配**的字符，`j` 扫描 `t`；
- 如果 `t[j] == s[i]`，匹配成功，`i++`；
- 无论是否匹配，`j++`；
- 最后如果 `i` 走到了 `s` 的末尾，说明全部匹配上了。

### 手动模拟（示例 2：`s = "axc"`, `t = "ahbgdc"`）

| j | t[j] | s[i] | 相等？ | i |
|---|---|---|---|---|
| 0 | a | a | ✅ | 1 |
| 1 | h | x | ❌ | 1 |
| 2 | b | x | ❌ | 1 |
| 3 | g | x | ❌ | 1 |
| 4 | d | x | ❌ | 1 |
| 5 | c | x | ❌ | 1 |

`t` 扫完了，`i = 1`，`s[1] = 'x'` 不是 `'\0'`，返回 `false`。

### 代码

```c
bool isSubsequence(char* s, char* t) {
    int i = 0;                              // s 中下一个要匹配的位置
    for (int j = 0; t[j] != '\0'; j++) {    // 扫描 t
        if (s[i] == '\0') break;            // s 已经全部匹配完，可以提前结束
        if (s[i] == t[j]) {                 // 匹配上一个字符
            i++;
        }
    }
    return s[i] == '\0';                    // s 走到末尾 = 全部匹配上
}
```

> 💬 `if (s[i] == '\0') break;` 这一行很重要：如果没有它，`s` 匹配完后 `s[i]` 是 `'\0'`，不会和 `t` 的字母相等，结果依然正确——但**不会越界吗**？不会，因为 `i` 停在 `'\0'` 上不再增加。这里加上它只是为了提前结束。

### 复杂度分析

- **时间复杂度 O(m)**：m 是 `t` 的长度，`t` 只扫描一遍。
- **空间复杂度 O(1)**。

## 🚀 第四步：思路二 —— 预处理 `t`（进阶：大量查询）

### 为什么需要它？

进阶问题说：有 10 亿个不同的 `s` 要和**同一个** `t` 比较。思路一每次都要把 `t` 从头扫一遍（O(m)），太慢了。

如果能预先算好一张表：**“从 `t` 的位置 `i` 开始往后，字母 `c` 第一次出现在哪里”**，那么匹配 `s` 时每个字符都能**直接跳**到下一个位置，每次查询只要 O(|s|)。

### 状态定义

`nxt[i][c]`：在 `t[i], t[i+1], ..., t[m-1]` 中，字母 `c` 第一次出现的下标；不存在则为 `m`。

从后往前填表（这就是动态规划）：

- `nxt[m][c] = m`（已经没有字符了）；
- 如果 `t[i] == c`，则 `nxt[i][c] = i`；否则 `nxt[i][c] = nxt[i + 1][c]`。

### 手动模拟（`t = "ahbgdc"`, m = 6，只列 a、b、c 三列）

| i | t[i] | nxt[i][a] | nxt[i][b] | nxt[i][c] |
|---|---|---|---|---|
| 6 | — | 6 | 6 | 6 |
| 5 | c | 6 | 6 | 5 |
| 4 | d | 6 | 6 | 5 |
| 3 | g | 6 | 6 | 5 |
| 2 | b | 6 | 2 | 5 |
| 1 | h | 6 | 2 | 5 |
| 0 | a | 0 | 2 | 5 |

查询 `s = "abc"`：从 `pos = 0` 开始，`nxt[0][a] = 0` → pos = 1；`nxt[1][b] = 2` → pos = 3；`nxt[3][c] = 5` → pos = 6。三个字符都找到了，返回 `true`。

### 代码

```c
bool isSubsequence(char* s, char* t) {
    int m = strlen(t);

    // nxt[i][c]：从 t[i] 开始往后，字母 'a'+c 第一次出现的下标；不存在为 m
    int (*nxt)[26] = malloc(sizeof(int[26]) * (m + 1));
    for (int c = 0; c < 26; c++) nxt[m][c] = m;      // 边界：后面没有字符了
    for (int i = m - 1; i >= 0; i--) {               // 从后往前填表
        for (int c = 0; c < 26; c++) {
            nxt[i][c] = (t[i] - 'a' == c) ? i : nxt[i + 1][c];
        }
    }

    // 查询：每个字符直接跳到下一个出现位置
    int pos = 0;                                     // 当前可以使用的 t 的起始位置
    bool ok = true;
    for (int i = 0; s[i] != '\0'; i++) {
        int p = nxt[pos][s[i] - 'a'];
        if (p == m) {                                // 后面再也没有这个字母了
            ok = false;
            break;
        }
        pos = p + 1;                                 // 下一个字符要从 p 之后找
    }

    free(nxt);
    return ok;
}
```

### 复杂度分析

- **预处理 O(26 × m)**，**每次查询 O(|s|)**。只有一次查询时比思路一慢，但查询次数很多时优势巨大。
- **空间复杂度 O(26 × m)**。

---

## ⚠️ 第五步：小白常见错误

1. **当成子串来判断** → 用 `strstr(t, s)` 只能判断连续出现，`"abc"` 和 `"ahbgdc"` 会被判成 `false`。
2. **匹配失败时只移动 `i` 或者两个都不动** → 应该是“匹配成功 `i++`，`j` 每次都 `++`”。
3. **没处理空串** → 用 `strlen(s) - 1` 之类的写法，在 `s` 为空时会出问题。按 `'\0'` 判断最稳。
4. **返回 `i == strlen(t)`** → 比较对象搞错了，应该看 `s` 是否走完。
5. **进阶写法中 `pos = p` 而不是 `p + 1`** → 同一个 `t[p]` 会被重复使用，`s = "aa"`、`t = "a"` 会被错误地判成 `true`。

---

## 📊 第六步：两种方法对比

| 方法 | 预处理 | 单次查询 | 空间 | 适用场景 |
|---|---|---|---|---|
| 双指针 | 无 | O(m) | O(1) | 只查一次（本题） |
| 预处理 nxt 表 | O(26m) | O(\|s\|) | O(26m) | 同一个 t 被查询很多次 |

> 🎯 **学习建议**：先熟练掌握双指针写法；进阶写法体现的“**预处理换查询速度**”思想，在很多题里都会出现。
