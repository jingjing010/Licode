# 162. 寻找峰值 —— 小白详细题解

> 这道题最神奇的地方是：数组**根本没排序**，却依然能用二分查找。理解了"为什么能二分"，你对二分的认识就上了一个台阶。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 把数组想象成一排高低不同的山。"峰值"就是比左右两边邻居都高的那个位置。找到**任意一个**峰值，返回它的下标。数组两端外面都当成"无限深的山谷"（`-∞`）。

拿示例 2 `nums = [1,2,1,3,5,6,4]` 来说：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 数值 | 1 | **2** | 1 | 3 | 5 | **6** | 4 |
| 是峰值吗？ | 否 | ✅ 2>1 且 2>1 | 否 | 否 | 否 | ✅ 6>5 且 6>4 | 否 |

下标 1 和 5 都是峰值，返回哪个都对。

**几个需要注意的细节：**

1. 因为两端外面是 `-∞`，**第一个元素只要比第二个大就是峰值**，最后一个元素只要比倒数第二个大也是峰值。只有 1 个元素时，它本身就是峰值。
2. 题目保证相邻元素**不相等**，所以不会出现"平地"。
3. 峰值**一定存在**（后面会解释为什么）。
4. 本 OJ 判题：检查你返回的下标是不是峰值，是就输出 `true`。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 数组越界访问

C 语言**不会**帮你检查下标是否越界。写 `nums[mid + 1]` 之前，必须保证 `mid + 1 < numsSize`，否则读到的是一块不属于你的内存，结果完全随机。

### 2. 中点的防溢出写法

```c
int mid = lo + (hi - lo) / 2;   // 推荐
int mid2 = (lo + hi) / 2;       // lo + hi 很大时可能溢出
```

本题 `n <= 1000` 不会溢出，但养成习惯很重要。

### 3. 比较时不要做减法

`nums[i]` 可以是 `-2^31` 或 `2^31-1`，如果写 `nums[mid] - nums[mid + 1] < 0` 来比较，减法本身就会溢出。**直接用 `<` 比较**最安全。

---

## 💡 第三步：思路一 —— 从左往右扫（最容易想到）

### 思路

从左往右走，一开始在"上坡"。第一次遇到 `nums[i] > nums[i + 1]`（开始下坡），`i` 就是山顶。如果一直在上坡，那最后一个元素就是峰值（右边是 `-∞`）。

为什么不用检查左边？因为能走到 `i`，说明之前一直是上坡，`nums[i - 1] < nums[i]` 已经成立了。

### 手动模拟（`nums = [1,2,3,1]`）

| i | nums[i] | nums[i+1] | nums[i] > nums[i+1] ? |
|---|---|---|---|
| 0 | 1 | 2 | 否，继续上坡 |
| 1 | 2 | 3 | 否，继续上坡 |
| 2 | 3 | 1 | **是** → 返回 2 |

### 代码

```c
int findPeakElement(int* nums, int numsSize) {
    // 只比较到倒数第二个，保证 nums[i + 1] 不越界
    for (int i = 0; i + 1 < numsSize; i++) {
        if (nums[i] > nums[i + 1]) {
            return i;            // 第一次开始下坡，i 就是山顶
        }
    }
    return numsSize - 1;         // 一路上坡，最后一个就是峰值
}
```

### 复杂度分析

- **时间复杂度 O(n)**：本题 n ≤ 1000 能过，但不满足题目 `O(log n)` 的要求。
- **空间复杂度 O(1)**。

---

## 🚀 第四步：思路二 —— 二分查找（题目要求）

### 为什么没排序也能二分？

关键是一句话：**沿着上坡走，一定能走到山顶。**

看中间位置 `mid` 和它右边的 `mid + 1`：

- 如果 `nums[mid] < nums[mid + 1]`：mid 处在**上坡**。从 `mid + 1` 往右走，要么一直上坡走到最后一个元素（它右边是 `-∞`，所以它就是峰值），要么中途某处开始下坡（那里就是峰值）。总之**右半边 `[mid+1, hi]` 一定有峰值**。
- 否则 `nums[mid] > nums[mid + 1]`：mid 处在**下坡**。同理往左看，**左半边 `[lo, mid]` 一定有峰值**（mid 自己也可能就是）。

每次都能扔掉一半，这就是二分。二分不一定要求"有序"，只要求**每次能判断答案在哪一半**。

### 区间定义与循环条件

- 区间：**闭区间 `[lo, hi]`**，含义是"这里面一定有峰值"。初始 `lo = 0, hi = numsSize - 1`。
- 循环条件：`while (lo < hi)`。当 `lo == hi` 时只剩一个候选，它就是答案。
- 为什么 `nums[mid + 1]` 不会越界？因为 `lo < hi` 时，`mid = lo + (hi - lo) / 2` 向下取整，一定有 `mid < hi`，所以 `mid + 1 <= hi <= numsSize - 1`。
- 更新：上坡 `lo = mid + 1`（mid 不是峰值，可以扔掉）；下坡 `hi = mid`（mid 可能是峰值，要保留）。

### 手动模拟（`nums = [1,2,1,3,5,6,4]`）

| 轮次 | lo | hi | mid | nums[mid] | nums[mid+1] | 判断 | 操作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 6 | 3 | 3 | 5 | 上坡 | lo = 4 |
| 2 | 4 | 6 | 5 | 6 | 4 | 下坡 | hi = 5 |
| 3 | 4 | 5 | 4 | 5 | 6 | 上坡 | lo = 5 |
| 结束 | 5 | 5 | | | | lo == hi | 返回 5 ✅ |

### 代码

```c
int findPeakElement(int* nums, int numsSize) {
    int lo = 0;                  // 闭区间 [lo, hi] 内一定有峰值
    int hi = numsSize - 1;

    while (lo < hi) {            // 还剩至少 2 个候选
        int mid = lo + (hi - lo) / 2;   // 防溢出；且 mid < hi，mid+1 不越界
        if (nums[mid] < nums[mid + 1]) {
            lo = mid + 1;        // 上坡：峰值在右边，mid 不可能是峰值
        } else {
            hi = mid;            // 下坡：峰值在左边（含 mid）
        }
    }
    return lo;                   // lo == hi，就是峰值
}
```

### 复杂度分析

- **时间复杂度 O(log n)**：每轮区间缩小一半。
- **空间复杂度 O(1)**。

---

## ⚠️ 第五步：小白常见错误

1. **用 `while (lo <= hi)` 搭配 `hi = mid`** → 当 `lo == hi` 时 `hi = mid` 不变，死循环。
2. **和左边 `nums[mid - 1]` 比较却不检查 `mid > 0`** → `mid == 0` 时越界读取 `nums[-1]`。
3. **下坡时写 `hi = mid - 1`** → 把真正的峰值 mid 扔掉了。比如 `[1,3,2]`，mid=1 正好是峰值，扔掉后就找不到了。
4. **用减法比较 `nums[mid] - nums[mid+1] < 0`** → 遇到 `[-2147483648, 2147483647]` 这种数据会溢出，判断反了。
5. **以为必须先排序** → 排序后下标全乱了，返回的下标没有意义。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 顺序扫描 | O(n) | O(1) | ⭐ | 帮助理解"上坡→下坡" |
| 二分查找 | O(log n) | O(1) | ⭐⭐ | 题目要求，理解"为什么能二分" |

> 🎯 **学习建议**：二分的本质不是"有序"，而是"**能根据 mid 判断答案在哪一半**"。这道题是最好的例子。
