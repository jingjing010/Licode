# 窗口看门狗喂狗判定：题解

## 📖 先读懂题目

给定自上次喂狗以来的elapsed及允许闭区间[minimum,maximum]，返回当前是否允许喂狗。参数为uint32_t，minimum≤maximum。实际芯片窗口边界以手册为准。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `0 / 10 / 20` | `false` |
| 2 | `1 / 10 / 20` | `false` |

## 🧰 需要的 C 语言知识

`uint32_t`运算按2^32取模。先转换为无符号类型再移位，避免负数左移；移位数必须小于类型位宽。超过INT_MAX的结果仍要按无符号值理解。

整数除法会向零截断。乘法中间结果可能大于最终答案，要在乘法发生之前转换为更宽的整数类型。布尔函数使用`true`与`false`表达判断结果。

## 💡 推导与实现

窗口看门狗既不能喂得太早，也不能太晚。本练习把两端边界都定义为允许。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
bool watchdogCanFeed(uint32_t elapsed, uint32_t minimum, uint32_t maximum) {
    return elapsed >= minimum && elapsed <= maximum;
}
```

| 方法 | 代价 | 用途 |

| 上述实现 | 时间 O(1)，空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 用有符号int承接无符号32位位模式，导致最高位被当成符号。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
- 直接复制main函数或打印调试信息，导致与平台自动生成的输入输出冲突。
