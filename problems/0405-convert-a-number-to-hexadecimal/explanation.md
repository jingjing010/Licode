# 数字转换为十六进制数：题解

## 📖 先读懂题目

把32位有符号整数 num 转为小写十六进制字符串，不加0x、不保留多余前导0。负数采用32位补码。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `26` | `"1a"` |
| 2 | `-1` | `"ffffffff"` |

## 🧰 需要的 C 语言知识

`uint32_t`运算按2^32取模。先转换为无符号类型再移位，避免负数左移；移位数必须小于类型位宽。超过INT_MAX的结果仍要按无符号值理解。

申请输出字符串时，要在有效字符之外多留1字节写入结束符。参考实现返回动态内存，由调用方负责释放。

## 💡 推导与实现

转换为 uint32_t 保留补码位模式，再按4位一组映射为小写十六进制数字。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
char *toHex(int num) {
    uint32_t x = (uint32_t)num;
    char tmp[8];
    int n = 0;
    /* 负数按32位补码解释，每次取最低4位。 */
    do {
        tmp[n++] = "0123456789abcdef"[x & 15];
        x >>= 4;
    } while (x);
    char *out = malloc(n + 1);
    for (int i = 0; i < n; ++i)
        out[i] = tmp[n - 1 - i];
    out[n] = 0;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(1)，输出空间 O(1) | 正式提交 |

## ⚠️ 常见错误

- 用有符号int承接无符号32位位模式，导致最高位被当成符号。
- 只申请有效字符数大小的缓冲区，没有给结束符留空间。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
