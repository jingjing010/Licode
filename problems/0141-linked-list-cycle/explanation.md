# 141. 环形链表 —— 小白详细题解

> 这道题是**快慢指针**（又叫"龟兔赛跑"、Floyd 判圈法）的招牌题。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 沿着链表的 `next` 一直往后走，如果某一刻走回了**之前走过的结点**，说明链表里有一个"圈"（环），返回 `true`；如果最后走到了 `NULL`，说明没有环，返回 `false`。

示例 1：`head = [3,2,0,-4], pos = 1`，尾结点 -4 的 `next` 指回下标 1 的结点 2：

| 步数 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | … |
|---|---|---|---|---|---|---|---|---|---|
| 走到的结点 | 3 | 2 | 0 | -4 | **2** | 0 | -4 | 2 | 永远走不完 |

**几个需要注意的细节：**

1. `pos` **不会传给你的函数**！它只是用来告诉判题程序怎么搭建链表。你只能拿到 `head`。
2. 链表可能是空的（`head == NULL`），这时没有环。
3. "有环"判断的是**结点是否重复**（指针相同），不是值是否重复。`[5,5,5]` 没有环也可能值都一样。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 比较两个指针

```c
if (slow == fast)   // 判断两个指针是否指向【同一个结点】（地址相同）
```

这和 `slow->val == fast->val`（值相同）完全不是一回事。本题要比较的是指针本身。

### 2. 走两步之前要检查

```c
fast = fast->next->next;   // 需要保证 fast 和 fast->next 都不是 NULL
```

所以循环条件要写成 `while (fast != NULL && fast->next != NULL)`，利用 `&&` 的短路特性，左边为假时右边不会执行。

---

## 💡 第三步：思路一 —— 数步数（利用数据范围）

### 思路

题目说结点最多 `10^4` 个。没有环的链表，最多走 `10^4` 步就一定会走到 `NULL`。

所以：**沿着 `next` 走，如果走了超过 `10^4` 步还没遇到 `NULL`，一定是在环里打转了**。

### 手动模拟（示例 3：`[1], pos = -1`）

| 步数 | p | p == NULL？ |
|---|---|---|
| 0 | 结点 1 | 否，继续 |
| 1 | NULL | 是 → 返回 false |

示例 1 有环，会一直走到第 10001 步还没遇到 `NULL`，返回 `true`。

### 代码

```c
bool hasCycle(struct ListNode *head) {
    struct ListNode* p = head;
    int steps = 0;
    while (p != NULL) {             // 走到 NULL 说明链表有尽头，没有环
        p = p->next;
        steps++;
        if (steps > 10000) {        // 结点最多 10^4 个，走了这么多步还没结束 → 一定有环
            return true;
        }
    }
    return false;
}
```

### 复杂度分析

- **时间复杂度 O(n)**：最多走约 10^4 步。
- **空间复杂度 O(1)**。

> ⚠️ 这个方法依赖"结点数上限"这个条件，换一道没有上限的题就不能用了。另一种通用做法是用**哈希表**记录走过的结点，再次遇到就说明有环，但 C 语言没有现成的哈希表，写起来比较麻烦，而且要 O(n) 空间。下面介绍真正通用、O(1) 空间的方法。

---

## 🚀 第四步：思路二 —— 快慢指针（龟兔赛跑）

### 思路

想象操场跑步：如果跑道是一条直线（无环），跑得快的人先到终点；如果跑道是一个圈（有环），跑得快的人迟早会**从后面追上**跑得慢的人。

- 慢指针 `slow`（乌龟）：每次走 **1** 步
- 快指针 `fast`（兔子）：每次走 **2** 步
- 如果 `fast` 走到了 `NULL` → 无环
- 如果某一时刻 `slow == fast` → 有环

> ❓ **为什么一定能追上，不会"跳过去"？** 进入环以后，每走一轮，快指针和慢指针之间的距离就**缩小 1**。距离每次减 1，一定会减到 0，不会跳过。

### 手动模拟（示例 1：`[3,2,0,-4], pos = 1`）

| 轮次 | slow | fast | 相遇？ |
|---|---|---|---|
| 开始 | 3 | 3 | （起点，不算） |
| 1 | 2 | 0 | 否 |
| 2 | 0 | 2 | 否 |
| 3 | -4 | -4 | ✅ 返回 true |

### 代码

```c
bool hasCycle(struct ListNode *head) {
    struct ListNode* slow = head;    // 乌龟，一次走 1 步
    struct ListNode* fast = head;    // 兔子，一次走 2 步

    // fast 能走两步的前提：fast 和 fast->next 都不是 NULL
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {          // 指针相同 → 指向同一个结点 → 被追上了 → 有环
            return true;
        }
    }
    return false;                    // 兔子跑到了终点 NULL → 无环
}
```

注意：**先走再判断**。如果先判断 `slow == fast`，一开始两者都是 `head`，会直接误判为有环。

### 复杂度分析

- **时间复杂度 O(n)**：无环时快指针走 n/2 轮到终点；有环时慢指针进环后，最多一圈内被追上。
- **空间复杂度 O(1)**：只用了两个指针。

---

## ⚠️ 第五步：小白常见错误

1. **循环条件只写 `fast->next != NULL`**：当 `fast` 本身是 `NULL`（比如空链表或偶数长度无环链表走到末尾）时，访问 `fast->next` 会崩溃。必须写 `fast != NULL && fast->next != NULL`。
2. **在移动前判断相遇**：`slow` 和 `fast` 一开始都指向 `head`，在循环开头判断 `slow == fast` 会立刻返回 true。
3. **比较值而不是指针**：`slow->val == fast->val`，遇到 `[5,5,5]` 这种值相同但无环的链表会误判为 true。
4. **用"遇到重复的值"来判断环**：同上，环的定义是结点（地址）重复，不是值重复。
5. **试图修改链表来做标记**（比如把走过的结点 `val` 改成一个特殊值）：可能和真实的值冲突，而且破坏了原数据，不是好习惯。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 通用性 | 建议 |
|---|---|---|---|---|
| 数步数 | O(n) | O(1) | 依赖结点数上限 | 理解"有环走不完" |
| 哈希表记录走过的结点 | O(n) | O(n) | 通用 | C 语言写起来麻烦 |
| 快慢指针 | O(n) | O(1) | 通用 | **标准答案**，必须掌握 |

> 🎯 **学习建议**：用两个手指在纸上画的环形链表上模拟快慢指针，一个一次跳一格，一个一次跳两格，看看它们在哪里相遇。
