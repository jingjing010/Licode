# 21. 合并两个有序链表 —— 小白详细题解

> 这是很多人遇到的第一道**链表题**。链表题的难点不在算法，而在"指针到底指向哪里"。我们会画很多图，一步一步来。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有两串已经**从小到大排好队**的珠子（链表），请你把它们**合成一串**，合完之后依然从小到大排好。

拿示例 1 来说：

```
list1:  1 -> 2 -> 4
list2:  1 -> 3 -> 4
结果:   1 -> 1 -> 2 -> 3 -> 4 -> 4
```

**几个需要注意的细节：**

1. 链表可能是**空的**（示例 2、3）。空链表在 C 里就是 `NULL`，返回空链表就是 `return NULL;`。
2. 题目说"通过拼接给定的两个链表的所有节点"——意思是**直接把原来的结点重新串起来**就行，不需要 `malloc` 新结点。
3. 两个链表里可能有**相同的值**（比如两个 1），都要保留，不能去重。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 结构体 `struct ListNode`

```c
struct ListNode {
    int val;                 // 这个结点存的数字
    struct ListNode *next;   // 指向下一个结点的指针；最后一个结点的 next 是 NULL
};
```

一个链表 `1 -> 2 -> 4` 在内存里是这样的：

```
 head
  |
  v
+-----+------+    +-----+------+    +-----+------+
|  1  | next-+--->|  2  | next-+--->|  4  | NULL |
+-----+------+    +-----+------+    +-----+------+
```

我们手里只有 `head`（第一个结点的地址），想找后面的结点只能顺着 `next` 一个一个走。

### 2. `->` 和 `.` 的区别

| 写法 | 什么时候用 | 例子 |
|---|---|---|
| `p->val` | `p` 是**指针** | `struct ListNode* p; p->val` |
| `d.val` | `d` 是**结构体变量本身** | `struct ListNode d; d.val` |

`p->val` 其实就是 `(*p).val` 的简写：先通过指针找到结构体，再取成员。

### 3. 访问前先判断是不是 `NULL`

```c
p->val      // 如果 p == NULL，程序会直接崩溃（Runtime Error：访问违规）
```

**链表题 90% 的运行错误都来自对 `NULL` 用了 `->`。** 写 `p->xxx` 之前，先问自己：`p` 有没有可能是 `NULL`？

---

## 💡 第三步：思路一 —— 迭代 + 哑结点（最推荐）

### 思路

想象你在**排队合并两支队伍**：每次看两支队伍**排头**的人，谁小就让谁出列，站到新队伍的末尾。

- 用 `list1`、`list2` 分别指向两个链表"当前排头"的结点
- 用 `tail` 指向新链表的"最后一个结点"，新来的结点就接在 `tail` 后面
- 某一支队伍走完了，另一支剩下的人**本来就是排好序的**，整体接上即可

### ❓ 什么是"哑结点"（dummy）？为什么要它？

新链表一开始是空的，第一个结点要单独处理（"头是谁？"），很麻烦。
技巧：先造一个**假的头结点** `dummy`，新链表就挂在它后面。最后返回 `dummy.next` 就是真正的头。

```
dummy -> (真正的结果从这里开始)
  ^
 tail（一开始指向 dummy）
```

`dummy` 只是个"挂钩"，它本身的 `val` 没有意义。它是一个普通局部变量（不是指针），所以用 `dummy.next`，而 `tail` 是指针，用 `tail->next`。

### 手动模拟（示例 1）

| 步骤 | list1 当前 | list2 当前 | 比较 | 接到 tail 后面的 | 新链表 |
|---|---|---|---|---|---|
| 1 | 1 | 1 | 1 <= 1 | list1 的 1 | 1 |
| 2 | 2 | 1 | 2 > 1 | list2 的 1 | 1 -> 1 |
| 3 | 2 | 3 | 2 <= 3 | list1 的 2 | 1 -> 1 -> 2 |
| 4 | 4 | 3 | 4 > 3 | list2 的 3 | 1 -> 1 -> 2 -> 3 |
| 5 | 4 | 4 | 4 <= 4 | list1 的 4 | 1 -> 1 -> 2 -> 3 -> 4 |
| 6 | NULL | 4 | list1 走完了 | 把 list2 剩下的整体接上 | 1 -> 1 -> 2 -> 3 -> 4 -> 4 |

### 代码

```c
struct ListNode* mergeTwoLists(struct ListNode* list1, struct ListNode* list2) {
    // 1. 哑结点：一个"假头"，结果链表挂在它后面
    struct ListNode dummy;
    dummy.next = NULL;
    struct ListNode* tail = &dummy;     // tail 指向结果链表的最后一个结点

    // 2. 两个链表都还有结点时，比较排头，小的那个接到 tail 后面
    while (list1 != NULL && list2 != NULL) {
        if (list1->val <= list2->val) {
            tail->next = list1;         // 把 list1 的排头接上
            list1 = list1->next;        // list1 往后走一步
        } else {
            tail->next = list2;
            list2 = list2->next;
        }
        tail = tail->next;              // tail 移到新的末尾
    }

    // 3. 至多还剩一个链表没走完，它本身有序，整体接上
    if (list1 != NULL) {
        tail->next = list1;
    } else {
        tail->next = list2;
    }

    // 4. 真正的头是 dummy 后面的那个结点
    return dummy.next;
}
```

### 复杂度分析

- **时间复杂度 O(n + m)**：n、m 是两个链表的长度，每个结点只被访问一次。
- **空间复杂度 O(1)**：只用了 `dummy`、`tail` 几个变量，没有申请新结点。

> 💬 **小白提示**：为什么 `dummy` 可以是局部变量？因为我们最后返回的是 `dummy.next`（一个原有结点的地址），不是 `&dummy`。函数结束后 `dummy` 被回收也没关系。

## 🚀 第四步：思路二 —— 递归（代码更短，理解一下）

### 思路

把问题"缩小一点"：

> 合并 `list1` 和 `list2` 的结果 = **两个头里较小的那个** + 合并（剩下的部分）

比如 `list1 = 1->2->4`，`list2 = 1->3->4`：
较小的头是 `list1` 的 1，那么结果就是 `1 -> 合并(2->4, 1->3->4)`。
"合并(2->4, 1->3->4)" 又是一个**同样的问题，只是更小**——交给函数自己去做。

**递归出口**（什么时候不用再往下拆）：其中一个链表是空的，直接返回另一个。

### 代码

```c
struct ListNode* mergeTwoLists(struct ListNode* list1, struct ListNode* list2) {
    // 递归出口：有一个是空链表，结果就是另一个
    if (list1 == NULL) return list2;
    if (list2 == NULL) return list1;

    if (list1->val <= list2->val) {
        // list1 的头更小：它就是结果的头，它后面接上"剩下的合并结果"
        list1->next = mergeTwoLists(list1->next, list2);
        return list1;
    } else {
        list2->next = mergeTwoLists(list1, list2->next);
        return list2;
    }
}
```

### 复杂度分析

- **时间复杂度 O(n + m)**：每次递归消耗掉一个结点。
- **空间复杂度 O(n + m)**：递归调用本身要占用栈空间，深度最多 n + m 层。本题最多 100 层，完全没问题；但如果链表有几十万个结点，递归可能**栈溢出**，这时迭代写法更安全。

---

## ⚠️ 第五步：小白常见错误

1. **对 `NULL` 使用 `->`** → 例如在循环里写 `while (list1->next != NULL)`，当 `list1` 本身是 `NULL`（空链表）时直接崩溃。循环条件应该判断 `list1 != NULL`。
2. **忘记移动 `tail`** → 少了 `tail = tail->next;`，每次都覆盖 `dummy.next`，结果只剩最后接上的那一个结点。
3. **循环结束后忘记接上剩余部分** → 少了 `tail->next = list1 ? list1 : list2;`，结果会丢掉一截（比如示例 1 只输出 `[1,1,2,3,4]`）。
4. **把 `dummy` 写成指针却没分配内存** → `struct ListNode* dummy; dummy->next = NULL;` 中 `dummy` 是野指针，会崩溃。要么写成结构体变量 `struct ListNode dummy;`，要么 `malloc`。
5. **返回了 `&dummy` 或 `dummy` 本身** → 应该返回 `dummy.next`，否则结果开头会多一个乱七八糟的值。
6. **重复定义 `struct ListNode`** → 系统已经定义好了，你再写一遍会报 `redefinition of 'struct ListNode'` 编译错误。

---

## 📊 第六步：两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 迭代 + 哑结点 | O(n + m) | O(1) | ⭐⭐ | 必须掌握，链表题万能模板 |
| 递归 | O(n + m) | O(n + m) | ⭐⭐ | 代码优雅，理解递归的好例子 |

> 🎯 **学习建议**：哑结点 `dummy` 是链表题最常用的技巧之一，只要题目可能修改"头结点"，就先想想要不要用它。
