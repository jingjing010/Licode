# COBS 数据区解码：题解

## 📖 先读懂题目

输入保证为9071定义的合法COBS编码，不包含帧分隔符。解码并返回原始字节数组；编码长度1到1030。

| 示例 | 输入参数 | 返回结果 |
|---|---|---|
| 1 | `[10,49,50,51,52,53,54,55,56,57]` | `[49,50,51,52,53,54,55,56,57]` |
| 2 | `[1]` | `[]` |

## 🧰 需要的 C 语言知识

`uint8_t`表示一个0到255的字节；`const uint8_t *`允许读取数据但不修改它。`size_t len`明确给出缓冲区长度，不能使用`strlen`计算二进制数据长度，因为数据中可能含0。

返回数组需要申请独立内存，并把有效元素数写入`*returnSize`。调用方释放结果，因此不能返回函数内的局部数组。输入数组长度与输出长度不一定相同。

## 💡 推导与实现

读码字后复制code−1个字节，非0xFF且尚未结束时补回被省略的零字节。

先按定义手工处理第一个示例，再确认每一步保存的状态足够决定下一步。循环结束时只返回题目要求的结果，不返回尚未处理的中间状态。

```c
int *cobsDecode(const uint8_t *data, size_t len, int *returnSize) {
    int *out = malloc((len + 1) * sizeof(int));
    size_t i = 0;
    int k = 0;
    while (i < len) {
        unsigned code = data[i++];
        for (unsigned j = 1; j < code; ++j)
            out[k++] = data[i++];
        if (code < 255 && i < len)
            out[k++] = 0;
    }
    *returnSize = k;
    return out;
}
```

## 📊 复杂度与取舍

| 方法 | 代价 | 用途 |
|---|---|---|
| 上述实现 | 时间 O(n)，输出空间 O(n) | 正式提交 |

## ⚠️ 常见错误

- 把二进制缓冲区当成以零结尾的字符串，遇到0便提前停止。
- 只返回指针却忘记设置`*returnSize`，平台无法知道输出多少元素。
- 忽略题面约束与特殊边界，直接把某个正常样例的结论推广到所有输入。
- 先用int乘法再转换到64位；溢出已经发生，转换无法补救。
