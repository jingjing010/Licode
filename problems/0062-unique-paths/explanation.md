# 62. 不同路径 —— 小白详细题解

> 这是**动态规划（DP）**最经典的入门题之一。学会它，你就掌握了"二维 DP 表格"的基本套路。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 有一个 `m` 行 `n` 列的棋盘，机器人站在左上角，只能**向右**或**向下**走，问走到右下角一共有几种走法。

拿示例 2（`m = 3, n = 2`）来说，棋盘是 3 行 2 列：

| | 第 0 列 | 第 1 列 |
|---|---|---|
| 第 0 行 | **Start** | |
| 第 1 行 | | |
| 第 2 行 | | **Finish** |

一共要走 2 步向下、1 步向右，三种走法分别是：右下下、下下右、下右下，所以答案是 3。

**几个需要注意的细节：**

1. 只能向右、向下，**不能回头**，所以不会出现"绕圈"的情况。
2. `m = 1` 或 `n = 1` 时只有一条直线，答案是 1。
3. 题目保证答案不超过 `2 * 10^9`，用 `int`（最大约 `2.147 * 10^9`）刚好放得下。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 二维数组 / 动态申请二维数组

`m`、`n` 最大 100，可以直接开一个固定大小的数组 `int dp[100][100];`。
如果想按实际大小申请，可以用 `malloc` 申请一维数组，再用 `dp[i * n + j]` 模拟二维下标。

### 2. 什么是"动态规划"？

把大问题拆成小问题，**把小问题的答案记在表格里**，后面直接查表，不重复计算。本题的"小问题"就是：走到格子 `(i, j)` 有几种走法？

### 3. 整数溢出

`int` 最大约 21 亿。本题答案保证不超过 20 亿，但如果用"组合数公式"做乘法，中间结果会超过 `int`，必须用 `long long`。

---

## 💡 第三步：思路一 —— 二维 DP 表格

### 思路

想一想：机器人要走到格子 `(i, j)`，**上一步**只能从哪来？

- 从**上面** `(i-1, j)` 向下走一步过来
- 从**左边** `(i, j-1)` 向右走一步过来

所以：**走到 `(i, j)` 的方法数 = 走到上面格子的方法数 + 走到左边格子的方法数**。

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

边界：第 0 行的格子只能一路向右走过来，方法数都是 1；第 0 列同理也都是 1。

### 手动模拟（示例 4：`m = 3, n = 3`）

| | 列 0 | 列 1 | 列 2 |
|---|---|---|---|
| 行 0 | 1 | 1 | 1 |
| 行 1 | 1 | 1+1=**2** | 1+2=**3** |
| 行 2 | 1 | 2+1=**3** | 3+3=**6** |

右下角是 6，就是答案。

### 代码

```c
int uniquePaths(int m, int n) {
    int dp[100][100];                    // m、n 最大 100，直接开固定大小的数组

    // 1. 第 0 列：只能一路向下走，方法数都是 1
    for (int i = 0; i < m; i++) dp[i][0] = 1;
    // 2. 第 0 行：只能一路向右走，方法数都是 1
    for (int j = 0; j < n; j++) dp[0][j] = 1;

    // 3. 其余格子：来自上面 + 来自左边
    for (int i = 1; i < m; i++) {
        for (int j = 1; j < n; j++) {
            dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
        }
    }

    // 4. 右下角就是答案
    return dp[m - 1][n - 1];
}
```

### 复杂度分析

- **时间复杂度 O(mn)**：表格里每个格子算一次。
- **空间复杂度 O(mn)**：一张 `m × n` 的表。

## 🚀 第四步：思路二 —— 一维滚动数组（省空间）

### 思路

观察公式 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`：算第 `i` 行时，**只用到了第 `i-1` 行和第 `i` 行本身**，更早的行都没用了。

所以只留一行 `dp[j]` 就够：

- 更新前，`dp[j]` 存的是**上一行**的值（相当于 `dp[i-1][j]`）
- `dp[j-1]` 已经被更新过，是**这一行**的值（相当于 `dp[i][j-1]`）

于是 `dp[j] = dp[j] + dp[j-1]`，也就是 `dp[j] += dp[j-1]`。

### 手动模拟（示例 4：`m = 3, n = 3`）

| 处理到第几行 | dp[0] | dp[1] | dp[2] |
|---|---|---|---|
| 初始（第 0 行） | 1 | 1 | 1 |
| 第 1 行 | 1 | 1+1=2 | 1+2=3 |
| 第 2 行 | 1 | 2+1=3 | 3+3=6 |

### 代码

```c
int uniquePaths(int m, int n) {
    // 只用一行，长度为 n
    int* dp = (int*)malloc(sizeof(int) * n);
    for (int j = 0; j < n; j++) dp[j] = 1;   // 第 0 行全是 1

    for (int i = 1; i < m; i++) {            // 一行一行往下推
        // dp[0] 永远是 1（第 0 列），从 j = 1 开始更新
        for (int j = 1; j < n; j++) {
            dp[j] += dp[j - 1];              // 上面（旧 dp[j]）+ 左边（新 dp[j-1]）
        }
    }

    int ans = dp[n - 1];
    free(dp);                                // 用完释放
    return ans;
}
```

### 复杂度分析

- **时间复杂度 O(mn)**
- **空间复杂度 O(n)**：只有一行。

## 🧮 补充：思路三 —— 组合数学

从左上走到右下，不管怎么走，一定是**向下 `m-1` 步 + 向右 `n-1` 步**，一共 `m+n-2` 步。
不同的走法，只取决于"哪几步是向下"，所以答案是组合数 `C(m+n-2, m-1)`。

```c
int uniquePaths(int m, int n) {
    long long ans = 1;                       // 中间结果可能超过 int，用 long long
    // 逐步计算 C(n-1+i, i)，i 从 1 到 m-1
    for (int i = 1; i < m; i++) {
        ans = ans * (n - 1 + i) / i;         // 先乘后除，每一步结果都是整数
    }
    return (int)ans;
}
```

> 💬 为什么每一步除法都能整除？因为每一步算出来的都是一个组合数 `C(n-1+i, i)`，组合数一定是整数。但**必须先乘再除**，写成 `ans * ((n-1+i) / i)` 就错了。

---

## ⚠️ 第五步：小白常见错误

1. **忘记初始化第 0 行、第 0 列** → `dp` 里是随机垃圾值，答案乱七八糟。
2. **循环从 `i = 0` 开始还访问 `dp[i-1][j]`** → `dp[-1]` 越界。
3. **把 `m`、`n` 搞反** → 本题对称所以碰巧能过，但在第 64 题（最小路径和）里就会出错：`m` 是行数，`n` 是列数。
4. **组合数写法用 `int` 存中间结果** → `ans * (n-1+i)` 会溢出变成负数。
5. **组合数写法先除后乘** → `ans * ((n - 1 + i) / i)` 中的整数除法会丢掉小数，结果偏小。
6. **一维写法里 `j` 倒着循环** → `dp[j-1]` 就变成了上一行的旧值，结果错误。这里必须**正着**循环。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 二维 DP | O(mn) | O(mn) | ⭐ | 先理解这个 |
| 一维滚动数组 | O(mn) | O(n) | ⭐⭐ | DP 省空间的常用技巧 |
| 组合数学 | O(m) | O(1) | ⭐⭐ | 需要一点数学，注意溢出 |

> 🎯 **学习建议**：重点掌握"上一步从哪来"这个思考方式，它是所有网格 DP 的核心。
