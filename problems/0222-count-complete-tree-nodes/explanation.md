# 222. 完全二叉树的节点个数 —— 小白详细题解

> 一句话题解：普通遍历 O(n) 就能过；但利用"**完全二叉树里总有一半是满二叉树**"，满的部分用公式 `2^h - 1` 直接算，可以做到 O(log² n)。

---

## 📖 第一步：先读懂题目

数一数树里有几个结点。特别之处是这棵树是**完全二叉树**：

- 除了最后一层，每层都是满的；
- 最后一层的结点都**靠左**排列，中间不留空。

```
        1
      /   \
     2     3
    / \   /
   4   5 6        <- 最后一层从左往右连续填了 3 个
```

它的层序表示 `[1,2,3,4,5,6]` 里没有任何 `null`，结点数就是 6。

**满二叉树**（每层都满）是完全二叉树的特例：高度为 h（有 h 层）的满二叉树结点数是

| 高度 h | 1 | 2 | 3 | 4 | h |
|---|---|---|---|---|---|
| 结点数 | 1 | 3 | 7 | 15 | 2^h − 1 |

**几个需要注意的细节：**

1. 树可以是空的，答案 0。
2. 结点最多 5×10⁴ 个，O(n) 的遍历也能通过；本题的价值在于**进阶**要求：比 O(n) 更快。

---

## 🧰 第二步：这道题需要的 C 语言知识

### 1. 用位运算算 2 的幂

`1 << h` 表示把 1 左移 h 位，等于 2^h。所以满二叉树结点数是 `(1 << h) - 1`。

注意 `<<` 的优先级比 `-` **低**，`1 << h - 1` 会被当成 `1 << (h - 1)`，一定要加括号。

### 2. 用循环求"一路向左"的长度

```c
int h = 0;
for (struct TreeNode* p = root; p != NULL; p = p->left) h++;
```

每走一步 `h` 加 1，走到空为止，`h` 就是最左边那条路径上的结点数。

---

## 💡 第三步：思路一 —— 普通递归计数（适用于任何二叉树）

### 思路

一棵树的结点数 = 1（根）+ 左子树的结点数 + 右子树的结点数；空树是 0。

### 手动模拟（示例 1）

| 子树根 | 左子树结点数 | 右子树结点数 | 结果 |
|---|---|---|---|
| 4、5、6 | 0 | 0 | 1 |
| 2 | 1 | 1 | 3 |
| 3 | 1 | 0 | 2 |
| 1 | 3 | 2 | 6 |

### 代码

```c
int countNodes(struct TreeNode* root) {
    if (root == NULL) return 0;                               // 空树没有结点
    return 1 + countNodes(root->left) + countNodes(root->right);
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个结点访问一次。
- **空间复杂度 O(log n)**：完全二叉树的高度是 log n 级别。

---

## 🚀 第四步：思路二 —— 利用"满二叉树"直接套公式

### 为什么能优化

对任意一棵完全二叉树，算两个高度：

- `lh`：从根一路向**左**走的结点数；
- `rh`：从根一路向**右**走的结点数。

完全二叉树的最后一层是靠左填的，所以：

- 若 `lh == rh`：最右边那条路径也到达了最底层，说明最底层是**满的**，整棵树是满二叉树，结点数 = `2^lh - 1`，**不用再往下数**。
- 若 `lh != rh`（只可能 `lh == rh + 1`）：不是满的，就按思路一的方法，`1 + 左子树 + 右子树` 递归。

关键是：**左右两棵子树中至少有一棵是满二叉树**（最后一层的"断点"要么落在左子树，要么落在右子树，另一边就是满的）。满的那一边一次就返回了，所以每一层只会真正往下递归一边，一共递归 O(log n) 层，每层求高度 O(log n)，总共 **O(log² n)**。

### 手动模拟（示例 1）

| 子树根 | lh（向左走） | rh（向右走） | 相等？ | 结果 |
|---|---|---|---|---|
| 1 | 3（1→2→4） | 2（1→3） | 否 | 1 + 左 + 右 |
| 2 | 2（2→4） | 2（2→5） | 是 | 2² − 1 = 3 |
| 3 | 2（3→6） | 1（3） | 否 | 1 + 左 + 右 |
| 6 | 1 | 1 | 是 | 1 |
| 3 的右（空） | — | — | — | 0 |

结点 3 的结果 = 1 + 1 + 0 = 2，根的结果 = 1 + 3 + 2 = **6**。

### 代码

```c
int countNodes(struct TreeNode* root) {
    if (root == NULL) return 0;

    int lh = 0, rh = 0;
    for (struct TreeNode* p = root; p != NULL; p = p->left) lh++;    // 一路向左的高度
    for (struct TreeNode* p = root; p != NULL; p = p->right) rh++;   // 一路向右的高度

    if (lh == rh) return (1 << lh) - 1;           // 满二叉树：直接用公式（注意括号）

    // 不满：左右子树里至少有一棵是满的，会在下一层直接返回
    return 1 + countNodes(root->left) + countNodes(root->right);
}
```

### 复杂度分析

- **时间复杂度 O(log² n)**：递归 O(log n) 层，每层求高度 O(log n)。
- **空间复杂度 O(log n)**：递归栈。

---

## ⚠️ 第五步：小白常见错误

1. **公式少了括号**：`1 << lh - 1` 等于 `1 << (lh - 1)`，结果差了一倍多；要写 `(1 << lh) - 1`。
2. **只比较左子树和右子树的"最左高度"**：两者相等时说明左子树是满的，不相等时说明右子树是满的——这也是一种正确写法，但很多人把哪一边是满的弄反。用"一路向左 vs 一路向右"判断整棵树是否满，更不容易出错。
3. **把 `lh` 当成"边数"**：本文的 `lh` 数的是结点个数（单结点树 `lh = 1`，公式给出 1）；如果你数的是边数，公式要变成 `(1 << (lh + 1)) - 1`。
4. **把普通二叉树也当成完全二叉树用思路二**：思路二依赖"最后一层靠左"，对普通二叉树（如第 104 题的输入）结果是错的。
5. **以为思路二每次都要递归两边**：不满的那一侧才会继续深入，满的一侧一次返回，所以才快。

---

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 难度 | 建议 |
|---|---|---|---|---|
| 普通递归计数 | O(n) | O(log n) | ⭐ | 任何二叉树都适用 |
| 满二叉树公式 + 递归 | O(log² n) | O(log n) | ⭐⭐ | 推荐，满足进阶要求 |
| 二分最后一层 + 位运算找路径 | O(log² n) | O(1) | ⭐⭐⭐ | 了解即可 |
