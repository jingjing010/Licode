# 9028. 16 位饱和加法（音频混音） —— 小白详细题解

> 整数溢出在普通程序里是 bug，在音频、电机控制里就是"爆音"和"飞车"。**饱和运算**是 DSP 领域最基本的安全手段：算不下的时候，宁可卡在边界，也不要绕回去。

---

## 📖 第一步：先读懂题目

用大白话说就是：

> 两个数组逐位相加，但结果必须"夹"在 `-32768 ~ 32767` 之间：太大就取 32767，太小就取 -32768。

拿示例 1 走一遍：

| i | a[i] | b[i] | 真实的和 | 是否越界 | out[i] |
|---|---|---|---|---|---|
| 0 | 1000 | 234 | 1234 | 否 | 1234 |
| 1 | -2000 | 500 | -1500 | 否 | -1500 |
| 2 | 30000 | 10000 | 40000 | 超过 32767 | **32767** |

如果不做饱和，`40000` 存进 `int16_t` 会变成 `40000 - 65536 = -25536`：

```
饱和：   ... 29000 → 30000 → 32767 → 32767 → 31000 ...   （顶部被削平，轻微失真）
回绕：   ... 29000 → 30000 → -25536 → ...                 （波形瞬间翻转，"啪"！）
```

**几个需要注意的细节：**

1. 只有**同号**相加才可能溢出：一正一负相加，结果一定在两者之间（示例 2 的 `32767 + (-32768) = -1`）。
2. 两个负数也会溢出，要饱和到 `-32768`，别只处理正方向。
3. `out` 已经由调用方分配好，函数里**不要 malloc**，直接写 `out[i]` 即可。

---

## 🧰 第二步：需要的 C 语言知识

### 1. `int16_t` 和整数提升

`int16_t` 是 `<stdint.h>` 里的"恰好 16 位的有符号整数"。C 语言在做 `a + b` 时，会先把比 `int` 小的类型**提升成 `int`** 再计算：

```c
int16_t x = 30000, y = 10000;
int     s = x + y;            // s = 40000，加法在 int 中进行，没问题
int16_t r = x + y;            // ❌ 40000 写回 16 位时被截断成 -25536
```

所以真正的"溢出"发生在**把结果存回 `int16_t` 的那一刻**。为了不依赖"`int` 一定比 16 位宽"（在 8 位 AVR、MSP430 上 `int` 只有 16 位！），我们显式写成 `(int32_t)a[i] + b[i]`。

### 2. `const` 指针和 `size_t`

- `const int16_t* a`：承诺"只读"，函数里写 `a[i] = ...` 会编译报错，防止误改输入。
- `size_t len`：无符号的"长度/大小"类型，循环变量也用 `size_t i`，避免有符号/无符号比较警告。

### 3. `INT16_MAX` / `INT16_MIN`

`<stdint.h>` 里定义好的常量：`INT16_MAX = 32767`，`INT16_MIN = -32768`。用它们比手写数字更清楚，也不会写错。

## 💡 第三步：思路一 —— 扩展到 32 位再夹紧

### 思路

1. 用 32 位算出真实的和 `s`，此时绝对不会溢出（范围 `-65536 ~ 65534`）
2. `s > 32767` → 写 `32767`；`s < -32768` → 写 `-32768`；否则原样写入

### 手动模拟（示例 2）

| i | a[i] | b[i] | s（32 位） | 处理 | out[i] |
|---|---|---|---|---|---|
| 0 | -32768 | -1 | -32769 | < -32768 | -32768 |
| 1 | -20000 | -20000 | -40000 | < -32768 | -32768 |
| 2 | 32767 | -32768 | -1 | 不变 | -1 |

### 代码

```c
void sat_add16(const int16_t* a, const int16_t* b, int16_t* out, size_t len) {
    for (size_t i = 0; i < len; i++) {
        int32_t s = (int32_t)a[i] + (int32_t)b[i];  // 先扩展成 32 位，求出真实的和

        if (s > INT16_MAX) {                         // 正向溢出：卡在最大值
            out[i] = INT16_MAX;
        } else if (s < INT16_MIN) {                  // 负向溢出：卡在最小值
            out[i] = INT16_MIN;
        } else {
            out[i] = (int16_t)s;                     // 没溢出：原样写入
        }
    }
}
```

### 复杂度分析

- **时间复杂度 O(n)**：每个采样点一次加法、两次比较。
- **空间复杂度 O(1)**：只用了一个临时变量（`out` 是调用方提供的）。

## 🚀 第四步：思路二 —— 不用更宽的类型，用符号位检测溢出

### 思路

如果要做的是 32 位饱和加法，就没有"更宽的类型"可用了（或者 64 位运算很慢），这时需要**直接检测溢出**。规律是：

> 两个数**同号**，而结果的符号却和它们**不同**，就是溢出了。

用位运算表示：`(a ^ r) & (b ^ r)` 的最高位为 1 ⇔ `r` 的符号同时和 `a`、`b` 不同（这也就意味着 `a`、`b` 同号）。

为了避免"有符号溢出是未定义行为"，加法先在**无符号** `uint16_t` 里做，无符号溢出在 C 标准中是有定义的（按 2^16 回绕）。

### 手动模拟（`a = 30000, b = 10000`）

| 步骤 | 十六进制 | 说明 |
|---|---|---|
| ua | 0x7530 | 最高位 0（正数） |
| ub | 0x2710 | 最高位 0（正数） |
| ur = ua + ub | 0x9C40 | 最高位 1，变"负数"了 |
| (ua ^ ur) & (ub ^ ur) & 0x8000 | 0x8000 | 非 0 → 溢出 |
| a 是正数 | — | 写入 32767 |

### 代码

```c
void sat_add16(const int16_t* a, const int16_t* b, int16_t* out, size_t len) {
    for (size_t i = 0; i < len; i++) {
        uint16_t ua = (uint16_t)a[i];
        uint16_t ub = (uint16_t)b[i];
        uint16_t ur = (uint16_t)(ua + ub);           // 无符号相加，溢出时按 65536 回绕

        if (((ua ^ ur) & (ub ^ ur) & 0x8000u) != 0) { // 结果符号与两个加数都不同 → 溢出
            out[i] = (a[i] < 0) ? INT16_MIN : INT16_MAX;
        } else {
            out[i] = (int16_t)ur;                    // 没溢出，按补码解释回有符号数
        }
    }
}
```

> 💬 这个判断方法和 CPU 里的 **V（溢出）标志位**原理完全相同，32 位、64 位饱和加法都能照搬。

## 🔌 嵌入式实战

- **ARM Cortex-M4/M7** 有专门的饱和指令：`QADD16` 一条指令同时完成**两对** 16 位饱和加法，CMSIS 里写作 `__QADD16(x, y)`；`__SSAT(x, 16)` 则把任意 32 位数饱和到 16 位。
- **CMSIS-DSP** 的 `arm_add_q15()` 就是本题的官方实现，混音、滤波器累加都用它。
- 混音更常见的做法是"先衰减再相加"，例如两路各乘 0.5，但遇到音量不对称时仍需要饱和兜底。

```c
/* Cortex-M4 上用内建函数实现单个采样点的饱和（示意） */
int16_t mix_one(int16_t x, int16_t y) {
    return (int16_t)__SSAT((int32_t)x + y, 16);   /* ❌ 本 OJ 的 gcc 没有这个内建函数 */
}
```

## ⚠️ 第五步：小白常见错误

1. **直接 `out[i] = a[i] + b[i]`**：存回 16 位时被截断，`30000 + 10000` 得到 `-25536`。
2. **用 `int16_t` 存中间结果**：`int16_t s = a[i] + b[i]; if (s > 32767) ...`——`s` 永远不可能大于 32767，判断形同虚设。
3. **只处理正方向**：忘了 `-20000 + (-20000)` 也会溢出，负数被绕成正数。
4. **有符号数直接相加后判断**：`int32_t` 版本的饱和加法写成 `int32_t r = x + y; if (x > 0 && y > 0 && r < 0)`——有符号溢出是未定义行为，编译器开 `-O2` 后可能直接把这个判断优化掉。应该像思路二那样先转无符号。
5. **在函数里 `malloc` 一个新的 `out`**：调用方拿不到你新分配的内存，`out` 里还是原来的内容。

## 📊 第六步：方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 特点 |
|---|---|---|---|
| 扩展到 32 位再夹紧 | O(n) | O(1) | 最直观，推荐 |
| 符号位检测溢出 | O(n) | O(1) | 不需要更宽类型，可推广到 32/64 位 |
| `QADD16` / `__SSAT` 硬件指令 | O(n)（常数最小） | O(1) | 依赖 Cortex-M4 等带 DSP 扩展的内核 |
| 直接相加 | O(n) | O(1) | ❌ 溢出回绕，产生爆音 |
